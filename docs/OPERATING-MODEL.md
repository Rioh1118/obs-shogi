# OPERATING MODEL — このプロジェクトの回し方

obs-shogi は個人開発で、界隈が小さく需要の直接観測が難しい。
**律速はコードを書く速さではなく、上流の意思決定の質と伝播速度**である。この文書はそこだけを扱う。

---

## 0. 設計原則

### 決定にも WIP 制限をかける

Little の法則はコードだけでなく決定にも効く。
2026-05-31 に5本の `feature/phase-N-*` ブランチが一度の作業で作られ、うち4本が**1週間後の方針転換で無効化**された。
決定をバッチで出すと、バッチで無効化される。

> **1サイクルにつき、確定させる決定は1件。**
> 12個まとめて決める設計セッション1回より、1週間ずつ現実に当てながら決める12週の方が、生き残る決定が多い。

### 確実性でなく、明示された不確実性を持つ

需要が読めない小さな界隈で「正確なキャッチアップ」を目指すのは無理筋。
代わりに、**何を仮定しているか・いつ確認したか・何が起きたら失効するか**を書く（`PREMISES.md`）。
実際、堀の前提（P-001）は誤りだったが、レジスタが無かったため30日以上気づかれなかった。

### 体感を信じない

熟練開発者が成熟リポジトリで AI 使用時に**19%遅くなったのに20%速いと感じていた**という対照実験がある（39ポイントの認知ギャップ）。
「進んでいる感じ」を進捗の証拠に使わない。**マージされた成果と、変わった決定**だけを数える。

## 1. 装置（どこに何を書くか）

| 置き場                    | 内容                               | 性質                                                                        |
| ------------------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| `docs/decisions/`         | **決めたこと**（ADR）              | append-only※。覆す時は新 ADR で supersede、既存は書き換えない               |
| `docs/proposals/`         | **決めるために書いた案**           | 番号を持たない。合意したら ADR へ起こし、**ここからは消す**※2               |
| `docs/OPEN-QUESTIONS.md`  | **まだ決めていないこと**           | 決まったら ADR に昇格して削除                                               |
| `docs/PREMISES.md`        | **仮定していること**               | 日付と失効条件つき。覆ったら依存 ADR を直すまでがワンセット                 |
| `docs/IDEAS.md`           | **6週間以内に着手しないこと**      | issue にしない。昇格するのは6週間以内に着手すると決めた時                   |
| GitHub issues             | **6週間以内に着手するもの**        | 単一軸。`track:` / `area:` / `type:` のみ                                   |
| `CLAUDE.md`               | エージェント向けの**命令形の制約** | 概観を書かない（過剰探索を招くため）                                        |
| `docs/state-transitions/` | **実装がいまどうなっているか**     | 埋まっていないセル＝未検証の経路。`stateTransitionIndex` のラチェットが見る |
| `docs/RELEASE.md`         | **リリースの手順**                 | 本文の語彙もここで決める                                                    |
| `docs/archive/`           | もう現役でない文書                 | 消さずに残す。参照先が切れないように                                        |
| `research/`               | **他実装の観測事実**               | 方針は持たない。版を固定して記録する                                        |
| `~/.claude/.../memory/`   | 上記への**ポインタ**のみ           | マシンローカルなので一次資料を置かない                                      |

※ append-only になるのは **`main` に入った後**。同じ PR の中では、
決定そのものを含めて書き直してよい（レビューはその PR の中で回るので、
実装が決定を覆すことがある）。

`main` に入った後、書き換えてよいのは次の3つだけ。

1. 実測値の更新
2. 誤記の訂正
3. **supersede の印**（状態行への `採用（<どの決定> だけ ADR-XXXX が supersede）` と、
   本文の該当行への `→ ADR-XXXX で撤回` の追記）

※2 **ADR 番号を先取りしない。** 未採用の案に番号を付けると、
`docs/decisions/` を grep した人が決まっていないものを規約として引く。
案のうちは `docs/proposals/<slug>.md`（番号なし・状態は「提案」）に置き、
採用が決まった時点で ADR 番号を採って `docs/decisions/` へ移す。
**案を参照する側は「未採用」であることを必ず書く。**

**決定そのもの**を変えるときは新しい ADR で supersede する。3を書き換えに含めるのは、
状態行だけを直しても本文を grep で当たった人が死んだ決定を拾うため
（→ `.claude/skills/weekly-review/SKILL.md`）。境界が無いと、同じ規約が都合よく引かれる。

**重要**: 決定・前提・問いは**リポジトリに置く**。以前はマシンローカルのメモにしか無く、PR でレビューできず共有もできなかった。

## 2. 着手の規律

- 新規 issue を立ててよいのは**6週間以内に着手するものだけ**。それ以外は `IDEAS.md` に1行
- **着手数の上限は持たない**（[ADR-0006](decisions/0006-drop-wip-limit.md)）。
  止めるのは件数ではなく「終わらせずに次を始めること」で、それは
  `/implement` の「指摘ゼロのラウンドが出るまで終わらせない」が見る
- Now は複数になりうる。**どれを先に終わらせるかは毎回の判断**で、
  週次レビューで見るのは「長く抱えたまま終わっていないものがあるか」

## 3. 週次レビュー（ループ本体）

**頻度: 週1回、30〜45分。** コミット毎ではない。上流の判断はコミットより遅い周期で動く。

### 入力

1. ドッグフーディング記録（実際に将棋の研究に使って気づいた摩擦、1行ずつ）
2. `OPEN-QUESTIONS.md`（🔴 が優先。🔴 が無ければ 🟡 / 🟢 を取る）
3. `ls docs/proposals/`（**対応する Q が無い案は孤児。取られないまま残る**）
4. `PREMISES.md` で `次回確認` を過ぎたもの
5. 現在の Now の状態

### 手順

1. **前提の点検** — 期限切れの前提を確認する。覆っていたら ❌ にし、依存する ADR を書き直す。_ここが最も飛ばされやすく、最も重要_
2. **決定を1件だけ確定させる** — `OPEN-QUESTIONS.md` の最上位を1つ。**`docs/proposals/` に案があって対応する Q が無ければ、先に Q を立てる。** ADR に書き、`OPEN-QUESTIONS.md` と `docs/proposals/` の**両方から消す**。決められないなら「決めるのに何が要るか」を更新して次週へ。**2件目に手を出さない**
3. **Now の確認** — 続けるか、差し替えるか。差し替えたなら理由を1行残す（差し替え頻度そのものが指標になる）
4. **摩擦の集計** — ドッグフーディング記録で**3回以上出た摩擦だけ**を issue 化候補にする。1回は雑音

### 出力（毎回1行、`docs/decisions/LOG.md` に追記）

```
YYYY-MM-DD | 決定: ADR-NNNN <一行> | Now: #NNN 継続 | 前提: P-NNN 未確認のまま
```

## 4. 数える指標（体感の代わり）

月1回、この3つだけ数える。増やさない。

- **完遂率** — Now に上げた issue のうち、差し替えでなく完了で終わった割合
- **決定の生存率** — 確定した ADR のうち、90日後も supersede されていない割合。低ければバッチが大きすぎる
- **note 率** — ドッグフーディングで import した棋譜のうち、note を書いたものの割合（→ P-003 の撤退基準に直結）

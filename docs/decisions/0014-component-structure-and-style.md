# ADR-0014: 部品の構造の基準を置き、書き方を1通りに揃える

- 状態: 採用
- 日付: 2026-11-01
- 決めたもの: `/decide`（人の確認なし）

## 文脈と問題

`/readable-code` の問いは置き場、名前、型、コメント、重複で、部品の構造と書き方の一貫性を扱っていなかった。
読み手は JSX から画面の構造を推測するので、名前と型が整っていても、ここが読めないと迷う。
`interface` と `type` は `.claude/knowledge/mechanization-backlog.md` で未決のまま残っていた。

## 判断の基準

1. 利用者の明示した言葉: 実測で多い形を確かめ、理由があれば少ない形を選ぶ。全ファイルを一度に書き換えない
2. R-DEC-1: 動作を変えないことを確かめられる
3. R-DEC-2: 既存の決定と形に揃う
4. R-DEC-3: 言語とフレームワークの慣例に沿う

## 検討した選択肢

書き方の形は実測で多い方を基本に比べた。数は基点 6545bcba、テストを除く `src/`。

| 点 | 多い形 | 少ない形 | 決定 |
| --- | --- | --- | --- |
| 部品の宣言 | `function` 202 | 矢印 2 | `function` |
| `props` の受け方 | 署名で分割代入 157 | 名前で受ける 11 | 署名で分割代入 |
| hook の順 | state が effect より前 29 | 後 3 | 前 |
| 片方が無い条件付き描画 | `&&` 176 | `? : null` 11 | `&&` |
| 2文以上のハンドラ | 名前つき 55 | その場 45 | 名前つき |
| 補助の関数 | 部品より前 18 本 | 後 7 本 | 前 |
| `.scss` の import | 最後 73 | 途中 36、先頭 20 | 最後 |
| React の型 | 名前の import 59 本 | `React.X` 54 箇所 | 名前の import |
| オブジェクトの形 | `type` 182 | `interface` 146 | `type` |
| 既定の export | 既定 146 | 名前つき 49 | 揃えない |

`interface` と `type` の案は3つ。

- `type` に揃える
- `interface` に揃える。TypeScript の Handbook と typescript-eslint の既定はこちら
- 未決のまま残し、触ったファイルに揃える

## 決定

「`type` に揃える」を選ぶ。R-DEC-2 で差がついた。`type` の方が多く、union と交差を別の語にせず1語で書ける。
宣言のマージを使う箇所は `declare` の中にしか要らない。未決のまま残すと、範囲ごとの整理で同じ判断を毎回読むことになる。
R-DEC-3 の慣例は `interface` を指すが、上の基準が先に差をつけたので従わない。

既定の export は揃えない。読み手のジャンプはどちらでも効き、書き換えると `import` の行が全域で動く。

規則は `docs/rules/ts.md` の R-TSC と R-TSW に置き、`src/__tests__/componentShape.test.ts` が字面で見える形を件数ラチェットで止める。
既存は範囲ごとに片付ける。

### 結果

- 良い: 読み手が同じことの書き方の違いに意味を探さなくて済む。新しい違反は検査で止まる
- 悪い: `interface` を全部書き換える間、範囲ごとにコミットが1つ増える。typescript-eslint の既定とは逆になる
- 悪い: `.scss` の import の順は既存を動かすと CSS の順が変わる。新しいコードだけに掛かり、揃えきらない

## 戻し方

`interface` と `type` は JS へ落とすと同じになるので、`.claude/skills/tidy-code/scripts/emit-unchanged.mjs` で確かめながら機械的に戻せる。
`docs/rules/ts.md` の R-TSW-2 を書き換え、`componentShape` の `typeInterface` の向きを逆にする。

# ADR-0003: SCSS のスケールは実測から導き、ラチェットで守らせる

- 日付: 2026-08-29
- 状態: 採用

## 文脈

見た目が整合しない。`src/index.scss` にあるのは色・`$default-font-size`・影2つ・stroke だけで、
タイポ・間隔・角丸・段階・モーションのスケールが無い。

実測（`src/**/*.scss`、2026-08-29）:

|                            |                                                                  |
| -------------------------- | ---------------------------------------------------------------- |
| `font-size` の異なり値     | 55種                                                             |
| `border-radius` の異なり値 | 40種（px と rem が混在。px 使用34ファイル / rem 使用39ファイル） |
| `box-shadow` の異なり値    | 45種                                                             |
| `transition` の異なり値    | 21種                                                             |

**この分布は不注意の結果ではない。**

- `$default-font-size: 1.6rem` は**定義されているだけで使用箇所が0**
- `body` にも `:root` にも `font-size` が無い。`html { font-size: 62.5% }` だけなので、
  **継承される基準文字サイズは 1rem = 10px**

つまり基準が存在しないため、各コンポーネントは `font-size` を自分で宣言しないと 10px になる。
**宣言せざるを得ない構造**があり、55種はその帰結である。

同じ役割に別々の値が当たっている:

| 役割名    | 使われている段数                                                                                    |
| --------- | --------------------------------------------------------------------------------------------------- |
| `__title` | 13種（1.15 / 1.20 / 1.25 / 1.35 / 1.40 / 1.45 / 1.55 / 1.75 / 1.80 / 1.85 / 1.90 / 1.95 / 2.40rem） |
| `__label` | 9種                                                                                                 |
| `__path`  | 6種                                                                                                 |
| `__hint`  | 5種                                                                                                 |

なお `features/settings` 配下には `$radius-sm/md/lg`（px 建て）が**ファイル内ローカルに既に存在する**。
スケールが要るという判断は一度されていて、全体に昇格していないだけである。

## 決定

### 1. 単位は rem に統一する

`html { font-size: 62.5% }`（1rem = 10px）を維持し、スケールは全て rem で置く。

pill（`$radius-pill: 999px`）と円（`$radius-circle: 50%`）は文字サイズに従属しないため rem 化しない。
実測には `9999px` と `99px` もあるが、いずれも pill の意図なので `$radius-pill` へ寄せる。

### 2. `body` に基準文字サイズを置く

```scss
body {
  font-size: $font-body; // 1.3rem
}
```

基準値は実測から取る。単独最多は 1.20rem（37件）だが、役割で見ると 1.20 は補助と本文の境界で
混ざっている。フォームのコントロール（`sui-input` / `sui-select__control` / `sui-radio__label` /
`sui-field__label`）が揃って乗るのは **1.30rem** で、こちらを本文とする。

`$default-font-size` は廃止し `$font-body` に置き換える。

### 3. タイポは8段、名前は役割で付ける

実測の山をそのまま段にする。段を間引かない代わりに、**役割名で選べるようにする**。
サイズ名（`sm` / `md`）だと選択がサイズ勘に戻り、55種になった構造が段8つの中で再現するため。

| トークン        | 値     | 吸収する実測      | 主な用途                       |
| --------------- | ------ | ----------------- | ------------------------------ |
| `$font-hint`    | 1.1rem | 1.05–1.15（67件） | `hint` `note` `count` `badge`  |
| `$font-aux`     | 1.2rem | 1.18–1.25（60件） | `desc` `sub` `meta` `path`     |
| `$font-body`    | 1.3rem | 1.28–1.35（44件） | 本文、フォームのコントロール   |
| `$font-lead`    | 1.4rem | 1.40–1.45（25件） | リード文、強調した本文、入力欄 |
| `$font-section` | 1.6rem | 1.50–1.68（16件） | 小見出し、カードの題           |
| `$font-title`   | 1.8rem | 1.75–1.95（10件） | ダイアログ・ペインの題         |
| `$font-display` | 2.4rem | 2.1–2.4（5件）    | 画面の主題                     |
| `$font-hero`    | 4rem   | 3.3–4.0（2件）    | ガイド画面の導入               |

**盤の中の文字はスケールに載せない。** 盤は独立した縮尺を持ち、アプリの文字の階層とは無関係。
`Hand` はコンテナ幅から導き、`BoardPreview` は `data-size` ごとに px で固定してある。
直値で残るものには `// scale-exempt` を付けて `exempt` の枠に置く。

### 4. 間隔・角丸・段階・モーションも実測から

間隔と角丸は既に 0.2rem 刻みにほぼ乗っている（`gap` の約89%、`border-radius` の約83%）。
乗っていない値をその刻みに寄せる。

- **間隔** `$space-1`…`$space-12` = 0.2rem から 2.4rem まで 0.2rem 刻み
- **角丸** `$radius-1`…`$radius-9` = 0.2rem から 1.8rem まで 0.2rem 刻み、
  加えて `$radius-pill`（`999px`）と `$radius-circle`（`50%`）。
  **同じ N が同じ値になるよう間隔と揃える。** 途中から始めると `$space-6` と `$radius-6` が
  別の値を指し、どちらもトークン参照なのでラチェットもレビューも気づけない

刻みは実測の山が途切れる 2.4rem まで**欠けなく張る**。段を飛ばすと、実測 51件の `1.4rem`
（モーダル・ダイアログの外殻）が 1.2 と 1.6 のどちらにも倒せてしまい、
同じ役割の部品が寄せ先の判断次第で割れる。

2.4rem を超える余白（3 / 4 / 5 / 8 / 10rem）はレイアウト固有なので段に載せない。
既存として据え置き、新規には書かない。

**連番にする。** サイズ名（`sm` / `md` / `2xl`）は §3 でタイポについて却下したのと同じ理由で
選択をサイズ勘に戻すうえ、両端に段を足せなくなる。
**役割名も付けない。** 役割と寸法が一対一に対応しないため、名前が嘘になる。

- **段階** 役割で3段。`$shadow-panel`（パネル・カード）/ `$shadow-overlay`（ポップオーバー・メニュー）/
  `$shadow-press`（押下）。値は実在する影から取る。
  `$shadow-panel` は既存の `$shadow-1` と同じ値で、使用中の4箇所
  （棋譜ペイン・盤の操作列・付箋・設定パネル）はいずれもパネルなので用途名に改めた。
  `$shadow-overlay` は `ContextMenu` の影から取る。暗い面の上に出るのでパネルより強い
- **モーション** `$duration-1`…`$duration-6` = 80 / 100 / 120 / 140 / 160 / 200ms、`$ease: ease`。
  長さと同じ理由で実測の山を全部段にする。**140ms は 120 と 160 のちょうど中間で 25件ある**ので、
  段を欠くと寄せ先が2つに割れる。fast / slow のような役割名を採らないのは、
  6段に対して役割が3つしか無く、残り3つがサイズ勘で選ばれるため。
  **反復するアニメーション（`animation` かつ `infinite`）は秒単位で回り続ける別系統**なので載せない
- **等幅** `$font-mono`。実測では2系統あり、多数派の `ui-monospace, SFMono-Regular, …` を採る

### 5. 意味色（warning / danger / success / info）はここでは決めない

現状 warning が3通り・danger が3通り発明されているが、**意味色の段数は通知の分類に従属する**。
分類より先に色の段数を決めると、実装都合の段数が分類を先取りする。
PR #73 が `info` / `warn` / `error` の3段だけを残した経路がこれにあたる。

→ `docs/OPEN-QUESTIONS.md` の Q-005（通知の種類をいくつに分けるか）が決まった後に回す。

### 6. 既存値は一括移行しない。ラチェットで守らせる

`src/__tests__/scssScaleRatchet.test.ts` が `src/**/*.scss` を走査し、
スケールに載るべきプロパティの直値を数える。**基準値と一致しなければ落ちる。**

枠は8つ。`font-size` / `border-radius` / `spacing`（`padding` `margin` `gap`）/
`elevation`（`box-shadow` `text-shadow`）/ `motion`（`transition` `animation`）/
`family`（`font-family`）/ `indirect`（ローカル変数・カスタムプロパティ・mixin 引数）/ `exempt`。

`indirect` は、寸法をプロパティ名から離れた場所へ移しても数え漏れないために要る。

- 新規に直値を書くと落ちる
- 既存の直値は基準値として許容する
- 直値をトークンへ寄せたら基準値を下げる。**7つの枠は下げる方向にだけ動かす**
- スケールに載らない寸法は、その宣言の行末に `// scale-exempt` を付けて `exempt` の枠へ移す。
  **除外はそれが効く場所に書く。** 除外の一覧を走査側に持つと、移行する人の目に入らない。
  **数えるのをやめるのではなく枠を移すだけ**にしてあるのは、印を増やす変更も基準値の差分として
  レビューに出すため。印は逃げ道であって、逃げ道は数えられていなければならない
- **`exempt` だけは上がる。** 印を1つ足すと元の枠が1減り `exempt` が1増えるので、
  基準値の2行を同じコミットで動かすことになる。
  「下げる方向にだけ」を `exempt` にも当てると、印は一度も使えない

走査器は `src/__tests__/scssScale.ts` に分けてあり、`scssScale.test.ts` が振る舞いを固定する。
宣言の切り出しは `postcss-scss` に任せる。
**走査器にテストが無いと、穴が「件数が減った」という形でしか現れず、
下げる方向にだけ動く基準値に固定されてしまう。**

## 理由

- **一括移行を採らない理由**: 40種と55種を一度に潰すと全画面の見た目が同時に変わる大きな差分になり、
  エラー表示の作業に入る前に1サイクルを使い切る。移行の価値は否定しないが、順番として後になる
- **規約だけにしない理由**: このリポジトリには既に `$default-font-size` を定義して誰も使わなかった実績がある。
  `CLAUDE.md` は「同じ失敗を2回するまでルールを足さない。1回目はルールではなくテストを書く」と定めており、
  これは1回目にあたる
- **stylelint を導入しない理由**: `npm run lint` は `vp lint .` で SCSS を見ない。
  SCSS を見るためだけに別のツールチェーンを足すより、既に `npm run verify` で走る vitest に載せる方が安い
- **構文解析はしないつもりだったが、それは誤りだった**。当初は正規表現で行を舐めれば足りると考えたが、
  レビューを3ラウンド回して**同じ場所に穴が出続けた**。1行ブロック・値の折り返し・大文字・
  値に含まれる `:`・文字列・`url()`・`@include` の入れ子・コメント中の `@include`・
  エスケープされた引用符・Sass の補間。しかもどれも「件数が減る」方向に働き、
  基準値が下がる方向にしか動かない運用と噛み合って**バグを恒久化する**性質を持っていた。
  `postcss-scss` で AST を取る形に替えてこのクラスごと消した。
  差し替えの前後で8枠すべての件数が変わらないことを確認している
- **rem を選ぶ理由**: a11y ではない。ウェブビューのページズームは px も等しく拡大するので、
  文字サイズ設定を持たない現状で rem の実利は無い。既存のグローバル規定（`62.5%`）との連続性が理由

## 結果

### 得られるもの

- 基準文字サイズが存在するので、コンポーネントが `font-size` を書かなくてよくなる
- 役割名で選べるので、サイズ勘で新しい値が発明されなくなる
- 直値が増えたら `npm run verify` が落ちる

### 諦めるもの

- 既存の見た目は揃わない。トークンに沿うのは新しく書く箇所だけで、既存の直値はそのまま残る
- **ただし `body` の基準追加は、既存の見た目を即座に変える。** `font-size` を1つも宣言していない
  SCSS が98本中24本あり、そこに載る文字は 10px から 1.3rem（13px）になる。
  影響が出るのは `widgets/app-layout-header` の `__meta` 系、`widgets/file-tree` のルートフォルダ名、
  `features/settings/ui/tabs/EngineTab.scss` の `__loading` / `__muted` など。
  固定高さのルールを全件走査した限り**入りきらなくなる箇所は無い**が、実機では確認していない
- 段が8つあるので、役割に当てはまらない用途が出たときに名前が嘘になる余地が残る
- ラチェットは件数を数えるだけで、**トークンを正しく選んでいるかは検査しない**。
  `$font-hero` を本文に使っても落ちない。既存の直値を1件寄せて別の場所に1件足す入れ替えも素通りする
- **ラチェットが見るのは SCSS だけ。** `.tsx` のインライン style は対象外。
  `style={{ … }}` は44箇所あり、`AppErrorBoundary.tsx` と `KifuImportForm.tsx` は寸法を直書きしている
- SCSS の補間（`#{…}`）の中の寸法は検出しない。値を評価しないと単位が現れないため。
  補間そのものは7箇所で使われている

### 失効条件

文字サイズ設定またはズーム設定を入れるとき、`$font-hero` のような固定 rem が破綻しないか見直す。

# ADR-0012: 画面の語を将棋 GUI の共通語に揃える

- 状態: 採用
- 日付: 2026-10-31
- 決めたもの: `/decide`（利用者の依頼「Shogi GUI のユビキタス言語として考える」に基づく）
- 関連: ADR-0010（ドックとビューの語）/ `docs/spec/design-language.md` の「将棋 GUI の語」

## 文脈と問題

画面はエンジンに読ませ続ける機能を「解析」と呼ぶ。将棋所・ShogiGUI・ShogiHome はどれも「検討」と呼び、
「解析」は棋譜全体を読ませる機能に当てている（`research/other-guis/shogidokoro.md`、
`research/other-guis/shogigui.md`、`research/shogihome/08-engine-behaviour.md`）。
他の GUI から来た人には別の機能に読める。棋譜解析を作るときに語が重なる。

## 判断の基準

1. 利用者の明示した言葉（将棋 GUI のユビキタス言語で考える）
2. R-DEC-3: 利用者が他の製品で慣れた形
3. R-DEC-5: 変えるのは画面の文字列だけにする

## 検討した選択肢

- 画面の語を共通語に揃え、コードの名前は残す
- 画面もコードも揃える
- 今の語のまま残す

## 決定

「画面の語を共通語に揃え、コードの名前は残す」を選ぶ。一覧は `docs/spec/design-language.md`。
`解析` → `検討`、`止める` → `中断`、`深度` → `深さ`、`探索局面` → `ノード数`、`止める条件` → `終了条件`、
`エンジンの設定` → `エンジン設定`。**「解析」は棋譜解析のために取っておく。**

ADR-0010 の決定の中身は変えない。画面の語だけをこの ADR が上書きする（タブの語は `検討`。コードの `analysis` はそのまま）。

### 結果

- 画面の語とコードの名前がずれる。対応は `CONTEXT.md` が持つ
- 文字列の置き換えと走査は実装の作業（エンジン標準化の仕様の AC-65 と AC-66）
- 棋譜解析を作るときは語を足すだけで済む

### 失効条件

利用者が他の GUI を知らない層へ軸を移したとき。

# ADR-0017: 詰み探索は検討の終了条件にせず、検討ペインの中で検討と切り替える別の探索にする

- 状態: 採用（2026-11-21 に改訂。改訂前は「ドックの別のビュー」）
- 日付: 2026-11-21
- 決めたもの: `/decide`。改訂は利用者との合意（2026-11-21）
- 関連: ADR-0010（ドックのタブとビュー）
- 入力: `docs/OPEN-QUESTIONS.md` の旧 Q-009、`research/engines/mate-engines.md`
- 仕様: `docs/spec/features/mate-search.md`

## 文脈と問題

旧 Q-009 は「詰み探索をプリセットの解析（検討）に持たせるか」を問い、決めるのに要るものとして
「詰将棋エンジンのビルドを1本測ること」と「AI 開発者の作業で要るか」を挙げていた。

2026-11-21 に利用者が詰将棋エンジンを仕様に組み込むことを求め、需要の側は満たした。
詰将棋エンジンの応答は KomoringHeights `kh-v1.1.0` のソースで確かめた（実行はしていない）。

**改訂の理由。** 最初の決定は「詰み探索の答えは `checkmate` の1行だけ」と読み、結果を出す場所を
ドックの別のビューにした。実際には、詰将棋エンジンは探索中も検討と同じ形の候補手の行
（`info ... score mate <手数> ... multipv <番号> pv <手順>`）を流し、結論の `checkmate` は最後の1行にすぎない。
ShogiHome も詰み探索の行を検討と同じ読み筋の欄に出している。

## 決定

**詰み探索は検討の終了条件にしない。検討ペインの中で検討と切り替える、別の探索にする。**

1. **結果は検討ペインの候補手の表に出す。** 探索中は詰将棋エンジンの候補手、終わったら表の上に結論の1行
2. **検討と同時には走らせない。** 押した側に切り替える。どちらのボタンも、もう一方が走っていることを理由に無効にしない
3. **詰み探索の後に検討を自動で再開しない。** ▶ で戻る
4. **使うエンジンは、設定で「詰み探索に使う」に指定したプリセット1つ**

検討の終了条件にしない理由は2つ。

- 結論の形が違う（`checkmate` の1行で、不詰・時間切れ・非対応がある）
- 詰将棋エンジンは通常の `go` では、詰みが無ければ `bestmove resign` を返して止まる

## 捨てた案

| 案                             | 捨てた理由                                   |
| ------------------------------ | -------------------------------------------- |
| 検討の終了条件に「詰」を足す   | 結論の形が違い、詰将棋エンジンは検討に使えない |
| ドックの別のビュー（改訂前）   | 出力は候補手の列で、検討ペインの表と同じ形     |
| 検討と同時に走らせて表を並べる | 1つの表に2つのエンジンの行が混ざる             |
| 走っている側の反対を無効にする | もう一方を止める操作が先に要る                 |

同時に走らせて表を並べる形（ShogiHome の形）は、検討ペインが複数のエンジンを並べる仕組みを持つまで採らない。
CPU とメモリの取り合いも起きる。

## 結果

- プリセット編集の詰み探索の欄は外す（エンジン標準化 AC-31）。保存された値は持ち回るが読まない
- `go mate` で始めた探索は `checkmate` の行で閉じる。状態遷移表 `engine.md` の Q3×L6 を詰み探索のときだけ変える
- 対応していないエンジンは、答え（`bestmove` か `notimplemented`）で見分ける。申告からは分からない

## 戻すとき

検討を止めずに詰みを確かめたい要望が出たら、検討ペインにエンジンごとの表のまとまりを持たせ、同時に走らせる形へ移す。

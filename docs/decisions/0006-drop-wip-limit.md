# ADR-0006: 着手数の上限（WIP=1）を運用の規約から外す

- 日付: 2026-08-30
- 状態: 採用
- 関連: **ADR-0001 の「着手中の issue は常に1件（WIP=1）」を supersede する** / `docs/OPERATING-MODEL.md` §2

## 文脈

ADR-0001 は「着手中の issue は常に1件（WIP=1）」を決めた。理由は
「過去に複数 issue を同時に抱えて進まなくなった経緯がある」。

この縛りは4箇所に書かれていた。`CLAUDE.md`（エージェントが毎回読む）/
`.claude/skills/implement/SKILL.md`（実装の手順）/ `docs/OPERATING-MODEL.md` §2 /
`.claude/skills/weekly-review/SKILL.md`（`assignee` が2件以上なら違反として指摘する）。

`fix/169-file-tree-error` の作業中に、**前2つからだけ削られた**。
残る2つはそのままなので、いま4つの文書が別々のことを言っている。
`/weekly-review` を回すと、意図的に外した縛りで違反を指摘される。

`docs/OPERATING-MODEL.md` は `docs/decisions/` を「append-only。覆す時は新 ADR で
supersede、既存は書き換えない」と定めているので、**運用文書側だけで撤回した形**になっている。
このプロジェクト自身が決めた覆し方に従っていない。

## 決定

**WIP=1 を規約として持たない。** ADR-0001 の該当する1行を supersede する。
ADR-0001 の他の決定（`main` 一本、`git worktree`、Stack PR を採らない）は変わらない。

`docs/OPERATING-MODEL.md` §2 と `.claude/skills/weekly-review/SKILL.md` から
着手数の上限を落とす。

**「Now が終わるまで、新しい issue を Now に上げない」も同時に外す。**
これは着手数の上限を別の言い方にしたもので、片方だけ残すと
「1件ずつ」を数えずに強制することになる。

## 理由

- **守られていない。** この作業自体、`.claude/worktrees/` に別セッションの作業ツリーがある状態で
  進んでいる。`git worktree` を使ってよいと ADR-0001 自身が決めており、
  worktree で並行させることと「着手中は1件」は両立しない
- **数で縛る意味が薄い。** ADR-0001 が挙げた失敗は「複数を抱えて進まなくなった」ことで、
  原因は件数ではなく**終わらせずに次を始めたこと**。件数の上限は、
  1件を終わらせないまま長く抱える形を止められない
- **止める装置は別にある。** `/implement` は「指摘ゼロのラウンドが出るまで終わらせない」を
  MUST にしており、こちらは終わらせることを直接見ている

## 結果

### 得られるもの

- 着手数について、4つの文書が同じことを言う状態に戻る
- `/weekly-review` が、意図的に外した縛りで違反を報告しなくなる

### 諦めたもの

- **着手を数で止める仕掛け。** 抱え込みが再発しても、機械では止まらない
- **「Now が終わるまで次を上げない」という順序の規律。** 代わりになるものは
  `/implement` には無い（あちらが見るのは1つの変更のレビューループ）。
  週次レビューで「長く抱えたまま終わっていないもの」を見るしかない
- 週次レビューの「Now は1つ」という単純な読み方。Now が複数あるとき、
  どれを優先するかは毎回の判断になる

### 依存する前提

- 終わらせることを見る装置（`/implement` の「指摘ゼロまで回す」）が働き続けること。
  これが形骸化したら、件数の上限を戻す判断が要る

## やらないこと

- `docs/decisions/0001-branch-and-pr-policy.md` の**決定の内容は書き換えない**。
  入れるのは supersede の印だけ（状態行と、撤回した1行への `→ ADR-0006 で撤回` の追記）。
  印まで入れないと、本文を grep で当たった人が死んだ決定を拾う。
  例外の範囲は `docs/OPERATING-MODEL.md` §1
- ブランチ名の規則（`issue-<番号>/<slug>`）はここでは扱わない。実態と食い違っているが
  別の決定なので → [#201](https://github.com/Rioh1118/obs-shogi/issues/201)

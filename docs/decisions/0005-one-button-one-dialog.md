# ADR-0005: 押すものと対話の面を1つに揃える

- 日付: 2026-08-29
- 状態: 採用
- 関連: ADR-0004（通知の分類）/ ADR-0003（SCSS のスケール）/ issue #169 のレビュー ラウンド1

## 文脈

同じ「押すもの」に対して定義が5系統あった。

| 系統                    | 場所                       | 角丸   | 無効化 | 主ボタンの文字                       |
| ----------------------- | -------------------------- | ------ | ------ | ------------------------------------ |
| `form__btn`             | `shared/ui/Form`           | 0.5rem | 0.5    | 白                                   |
| `sui-button`            | `features/settings/kit`    | 0.8rem | —      | 白                                   |
| `btn__icon`             | `shared/ui/IconButton`     | —      | —      | 定義の無い CSS 変数に依存（#180）    |
| `kifu-read-error__btn`  | `features/kifu-read-error` | 1rem   | 0.46   | 明るい文字（深緑のグラデーション面） |
| `file-conflict__button` | `features/file-conflict`   | 独自   | 独自   | 独自                                 |

**「danger の赤」も3通りあった**（`$color-danger` `#b5645c` / IconButton の `#dc3545` /
SButton の `#ff5a5a`）。

対話の面も割れていた。`KifuReadErrorDialog` と `FileConflictDialog` は
`theme="light"` で、暗いシェルの中に白いカードが出る。`ConfirmDialog` は
`Modal` を使わず自前の overlay を持っていて、Esc もオーバーレイのクリックも
portal も持っていなかった（#182 で入れたタイトルバーを覆わない指定も効かない）。

`FsError` を見せる構造（見出し・パス・技術的な詳細・ボタン）は3箇所が別々に書いていた。

## 決定

### 1. ボタンの定義は1つ。軸で選ぶ

`shared/ui/Button`。面の色と、大きさ・角丸・動きを**独立した軸**にする。

| 軸          | 値                                         | 既定      |
| ----------- | ------------------------------------------ | --------- |
| `tone`      | `primary` / `neutral` / `quiet` / `danger` | `neutral` |
| `size`      | `sm` / `md` / `lg`                         | `md`      |
| `radius`    | `sharp` / `soft` / `pill`                  | `soft`    |
| `motion`    | 真偽（ホバーの影と押下の沈み込み）         | 真        |
| `block`     | 真偽                                       | 偽        |
| `isLoading` | 真偽（押せなくして `aria-busy` を立てる）  | 偽        |

沈み込みは `form__btn` が持っていたものを引き継ぐ。**連続して押す場所では切れるように
独立した軸**にしてある。

### 2. 主ボタンの面には一段暗い銅を敷く

`$color-secondary-dark`（`#a27b5c`）に白文字を置くと **3.80:1** で本文の基準（4.5:1）を割る。
面用に `$color-secondary-solid`（`#8f6b4e`）を足すと **4.79:1** になり、
**白文字を保ったまま**基準を満たす。

文字を黒にする案（4.99:1）もあったが、銅に白という見え方を変えない方を採る。
`$color-secondary-dark` はアプリ全体のアクセントなので値は動かさない。

**ホバーの段も測る。** 主ボタンは押す直前に必ずホバーするので、ここで基準を割ると
読みにくくなるのが「押そうとしている瞬間」になる。

| 状態   | 面        | 白文字     |
| ------ | --------- | ---------- |
| 通常   | `#8f6b4e` | **4.79:1** |
| ホバー | `#866549` | **5.29:1** |

**ホバーは暗くする方向へ動かす。** 白文字を載せる面なので、明るくすると比が下がる。
「ホバーで比が上がる」を規則にして、面の明暗ではなく文字色から向きを決める。

数字は `src/__tests__/contrastRatchet.test.ts` が測り直す。手で書いた値が腐ったら落ちる。

### 3. 明暗の軸は持たない

ADR-0004 で「通知の面は暗い側を既定」と決めたので、
`KifuReadErrorDialog` / `FileConflictDialog` を暗い面に寄せた時点で
明るい面のボタンが要らなくなる。軸として残すと2系統を維持し続けることになる。

明るい面が要る画面が出たら、そのときに足す。

### 4. 質感（ガラス）は入れない

`KifuReadErrorDialog`（グラデーション）と `sui-button[primary]`（inset ハイライト＋影）が
別々のやり方で質感を出していた。1つの variant として残す案を作って見比べたが、
**主ボタンに乗せると重く見える**ので入れない。

### 5. `FsError` を見せる部品は1つ

`entities/file-tree/ui/FsErrorView`。見出し・パス・技術的な詳細を持ち、
**ボタンは呼び出し側が渡す**。何をすれば直るかは失敗ごとに違う（ADR-0004 の決定3）。

段（`fsErrorTier`）が `warning` なら読み直し、`danger` なら別の操作を出す。

### 6. 対話の面は `Modal` の上に載せる

`ConfirmDialog` も含めて全て `Modal` を使う。自前の overlay を持つと、
Esc・オーバーレイのクリック・portal・タイトルバーを覆わない指定を
それぞれ実装し直すことになる。

確認ダイアログの実行側は `danger`。同じ形のボタンを2つ並べると、
どちらが破壊的かが赤い文字だけで決まる。

### 7. 利用者に見せる文言は `describeFsError` だけが持つ

`FsError.message` は**開発者向けのログ**と決める。利用者向けの文は `code` から引く。

そのために名前の検証を原因ごとに割った（`invalid_name_empty` /
`invalid_name_reserved` / `invalid_name_separator` / `invalid_name_control`）。
1つの code に潰していると「その名前は使えません」しか出せず、
`a/b` と入力した利用者は区切り文字が原因だと分からない。

棋譜の読み込み失敗も `invalid_type` を借りていたので `kifu_format_unknown` /
`kifu_parse_failed` に分けた。ファイルとフォルダの取り違えと同じ code では、
出せる文が1つに縛られる。

## やらないこと

- **`IconButton` は今回触らない**（#180）。定義の無い CSS 変数を12個以上使っており、
  1つだけトークンへ寄せると同じファイルの中で2系統が混ざる
- **明るい面のボタンを作らない**（決定3）
- **質感の variant を作らない**（決定4）

## 影響

- ボタンの定義が5 → 1。削除は約1,100行
- SCSS の直値が **118件**減った（ADR-0003 のラチェット。`font-size` 251→218 /
  `spacing` 528→479 / `border-radius` 178→158 ほか）。#160 の残量がその分減る
- `CONTRIBUTING.md` の SCSS 節に意味色の選び方を書いた
- `IconButton` の棚卸しは #180 に残っている

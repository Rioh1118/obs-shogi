# ADR-0001: ブランチと PR の運用は main 一本 + 短命ブランチにする

- 日付: 2026-08-29
- 状態: 採用

## 文脈

運用ルールがどこにも書かれておらず、ブランチの切り方が回ごとに違っていた。
実際に、あるブランチを別の未マージブランチから切ってしまい、PR の差分に無関係な変更が混ざる状態が発生した。

同時に、複数の作業を並行させたいという要求がある。デスクトップアプリなのでポートの競合が無く、
別ウィンドウで別ブランチを同時に触れる。この要求を Stack PR で満たすか、別の手段で満たすかを決める必要があった。

## 決定

**切る元は常に `main`。出す先も常に `main`。**

- ブランチ名は `issue-<番号>/<slug>`
- 前の PR の成果に依存する作業は、**その PR がマージされるまで始めない**
- 着手中の issue は常に1件（WIP=1）
- 並行作業が必要なときは Stack PR ではなく `git worktree` を使い、**互いに依存しないブランチだけ**を並行させる

例外として、3つ以上の PR に分けたい大きな機能に限り統合ブランチ `feature/<name>` を立てることを許す。
ただしこれは例外であって既定ではない。

## 理由

- **Stack PR を採らない理由**: base ブランチの管理と rebase の連鎖が常につきまとう。
  レビュアーが1人しかいない状態でこの管理コストを払う見返りが無い。
  依存する作業を待てないほど急いでいる状況が、そもそも現状では発生していない
- **`git worktree` で足りる理由**: 並行作業の要求は「同時に複数の窓で作業したい」であって
  「依存する作業を待たずに進めたい」ではない。互いに独立したブランチなら worktree で満たせる
- **WIP=1 を維持する理由**: 過去に複数 issue を同時に抱えて進まなくなった経緯がある

## 結果

### 得られるもの

- どのブランチの差分も `main` との差分と一致する。PR に無関係な変更が混ざらない
- rebase の連鎖が無い

### 諦めたもの

- 依存する作業を待たずに着手すること。前の PR のマージが律速になる
- 大きな機能を細かい PR に刻んで同時に進めること

### 依存する前提

- レビュアーが実質1人であること。これが変われば Stack PR の再検討が要る

## 並行作業の手順

```bash
git worktree add ../obs-shogi-<slug> -b issue-<番号>/<slug> main
cd ../obs-shogi-<slug>
npm ci
```

終わったら削除する。

```bash
git worktree remove ../obs-shogi-<slug>
```

`npm ci` が worktree ごとに要る点と、Rust のビルドキャッシュが共有されない点に注意。

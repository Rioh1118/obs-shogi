# ADR-0011: 対局の語彙を先に決め、時計・結果・操作の置き場を責任から導く

- 状態: 採用
- 日付: 2026-09-16

## 背景

対局まわりの UI は PR #582 まで「いまの構造の中で辻褄を合わせる」形で積まれてきた。
語彙と責任を先に決めていないので、同じ症状が3つの形で出ている。

- **「閉じる」が3つの動作を名乗っている。** 面を畳む（`GameOverModal`）、
  エンジンを落として台帳から外す（`close_game`）、始め損ねた画面を片付ける
  （`PlayControls` の ✕。押した後の状態文が「閉じています…」）。
  押す前にどれかが読めない
- **時計がドックのタブの中に居る。** 時計は「走っている対局の説明」であって、
  解析・定跡と並ぶ作業面の中身ではない。タブを離れると残り時間が見えない
- **`Aborted` が2つの意味を兼ねる**（#362）。利用者の中断と、アプリが裁定を
  返せなかった故障が同じ値で届き、画面の語も「中断」1つ

先行 GUI の調査（`research/shogihome/`、ShogiGUI・将棋所の公開マニュアル）:

- ShogiHome は時計を**盤の枠内**（駒台の上）に置く。ドックの器（タブ）に
  対局の面そのものが無い —— 「時計はタブの中身ではない」という向きは一致する
- 将棋所は時計を**ウィンドウ右上**に置き、終局は面でなく「対局結果一覧」へ積む。
  操作は「投・待・急・入・中」——**入玉宣言がツールバーの1操作**
- ShogiGUI・将棋所とも**先後別の持ち時間**を持つ（→ Q-008）

## 決定1: 語彙を固定する

画面・フロント・Rust で同じ概念に同じ語を当てる。**この表が唯一の出典。**

| 語       | 意味                                                                      | Rust の綴り                                                      | 画面の語     |
| -------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------ |
| 対局     | 走っている1局（`game-session` の状態機械）。棋譜（`entities/game`）とは別 | `GameSession`                                                    | 対局         |
| 開始     | 棋譜を1枚作って対局を走らせる                                             | `start_game`                                                     | 対局を始める |
| 投了     | 席の意思で負けを認めて終局する                                            | `resign_game` / `Resign`                                         | 投了         |
| 中断     | **利用者の意思**で勝敗を付けずに終局する                                  | `abort_game` / `Aborted`                                         | 中断         |
| 進行不能 | **アプリの故障**。裁定が `RULING_TIMEOUT` の間返らず、Rust が畳んだ       | **新設**（案 `RulingTimeout`、wire は `rulingTimeout`。→ 決定7） | 進行不能     |
| 終局     | 結末が決まった状態。理由は問わない                                        | `over` / `Phase::Over`                                           | 終局         |
| 畳む     | エンジンを落として台帳から外す。**終局した対局では自動**（→ #582）        | `close_game`                                                     | **出さない** |
| 閉じる   | **面（モーダル）を畳む。** 対局にもエンジンにも触らない                   | —                                                                | 閉じる       |
| やり直す | 始め損ねた対局（V4）を捨てて、開始の面をもう一度開く                      | —（台帳に無いので Rust を通らない）                              | やり直す     |

終局の理由の残り4つは既に1対1で揃っている: 時間切れ `Timeout`・入玉宣言
`DeclareWin`・エンジンの異常 `EngineFailure`・規則による終局 `Rule`。

**「閉じる」は面にだけ使う。** 対局やエンジンを対象にする綴りが1つでも残ると、
「閉じる」を見た利用者は毎回どちらかを推測することになる。エンジンを落とす操作は
利用者の手から外れた（#582）ので、**「畳む」は画面に出る語ではない**。

**畳み損ねの復帰は「次を始める」が兼ねる。** `close_game` が断られた対局
（`closeFailure`）は台帳に残り、いまの判定（`heldSessionOf`）はそれを
「対局がある」と数え続ける —— 畳む口を画面から外した後、そのままだと
**次の対局を一度も始められず、復帰が再起動しか無くなる**。だから `start` の側が、
閉じ損ねた対局へ `close_game` をもう一度通してから始める。それも断られたら
その理由で始めるのを断る。押し直す口を独立に置かないぶん、
**始める操作が実質の再試行になる**。

**中断と進行不能は棋譜では同じ `CHUDAN`。** 棋譜の綴り（`JKFSpecial`）には
故障の概念が無いし、要らない —— 棋譜に残すのは「勝敗が付かずに終わった」ことだけで、
なぜ畳まれたかはアプリの故障記録の仕事。

## 決定2: 時計はヘッダの「対局の行」に出す

対局が走っている間（V1）だけ、アプリのヘッダ中央の下に1行生える。

```
┌────────────────────────────────────────────┐
│ [◧]│obs-shogi│2026-09-16.kif ▲68手目│…    │
│     △YaneuraOu 04:12│30  ▲あなた 07:48│30 │
└────────────────────────────────────────────┘
```

- **1行目は棋譜の行、2行目は対局の行。** 対局は棋譜が入れ替わっても走り続けるので、
  別の棋譜を見ている間もこの行は対局の時計を出し続ける。混同への注意は
  対局タブの帯が持つ（現状どおり）
- **終局で行は消える。** 最終の残り時間と消費時間はスタッツ（決定4）が持つ
- 時計の3規則（最初のイベントまで `—`・動いている時計があるときだけ毎秒描く・
  時間切れの判定に使わない）は `play-view.md` の現行仕様をそのまま移す

### 盤の枠内（ShogiHome 式）にしなかった理由

盤は対局が無い時間のほうが長い（研究環境なので、並べ替え・解析が主用途）。
盤の枠に対局専用の欄を足すと、**対局していない画面がその欄のぶんだけ空くか、
対局のたびに盤の寸法が動く**かのどちらかになる。ヘッダは既に
「開いている棋譜の説明」を出す行で、対局の行を足しても盤に触らない。

### 対局タブの中に残さなかった理由

タブは1度に1枚しか出ない（ADR-0010）。時計をタブに置く限り、
「解析を見ながら残り時間を知る」ができない。時計は対局が走っている間
**常に見えているべき値**で、これはヘッダの性質。

## 決定3: 対局はビューのまま。責任は「進行の記録と故障の説明」

ADR-0010 の判定（2つを同時に開きたいか）に照らして、対局はビューに留まる ——
対局中に解析タブを開きたい場面はあり、進行と故障を出す場所は他に無い。

時計をヘッダへ出した後にタブへ残るのは:

- **V1（対局中）**: 席2つ（名前・人/エンジン）・手数・「裁定中」・帯3種
  （棋譜へ積めない／裁定を返せない／別の棋譜の対局）
- **V3（終局）**: 結果とスタッツの本体（決定4）
- **V4（始められなかった）**: 断りと「やり直す」（決定5）

## 決定4: 終局の面は結末だけ。スタッツの本体は対局タブの V3

`GameOverModal` は「終わったこと」を知らせる面に徹する —— 勝敗・理由・手数・
故障の帯（裁定／棋譜／エンジン）・**棋譜に残っていないことの一文（#115 の決着まで）**と
「閉じる」1つ（ADR-0005）。席2つの並びは落とす（結末は席ごと対局タブの V3 に残る。
勝敗の1行は引き分けでは名前を出さないので、名前の出典にはしない）。

スタッツは V3 が本体として持つ:

| 出すもの         | 出典                                                        | 出せない席                 |
| ---------------- | ----------------------------------------------------------- | -------------------------- |
| 消費時間（合計） | `moveDecided` の `elapsedMs` の畳み込み                     | —                          |
| 平均思考時間     | 同上                                                        | —                          |
| 最終の残り時間   | `over` が必ず載せる `clocks`                                | —                          |
| 評価値の推移     | `searchInfo` の畳み込み（手番側の最後の評価値を手に付ける） | **人の席**（評価値が無い） |

**消費時間は `elapsedMs` の畳み込みだけでは閉じない。** 時間切れは `moveDecided` を
出さずに終局する（Rust は時計が尽きた時点で `finish` する）ので、
**最後の考慮時間が系列に入らない**。時間切れの回は補う —— 尽きた側は
`result`（`Timeout` の負け側）から引く。時計の残りでは引けない
（`byoyomiMs` は設定値で、秒読みの対局は両席とも `mainMs` 0 が普通）。
その手の消費は、直前のイベント時点の残りから `over` の時計への差分。

- **畳み込む先は `entities/game-session` の進行（`Session`）。** いま `searchInfo` は
  `apply` が捨てている。系列の寿命は対局セッションと同じ（次の対局で消える）
- **評価値推移ビュー（ADR-0010 が予定する棋譜全体の系列）とは合流させない。**
  あちらは棋譜に従属し開き直しても残る値、こちらは対局セッションに従属し閉じると
  消える値。寿命の違うデータを1枚に混ぜると、どちらの規則で消えるかが読めなくなる
- 人対人の対局は評価値の系列が空なので、グラフを出さず時間だけ出す

## 決定5: 操作列から ✕ を外す。V4 の復帰は本文の「やり直す」

操作列は「向き・投了・中断」の3つになる（将来、入玉宣言が足される。→ 着手順7）。

✕（V4 専用）は、**押せる状態が V4 しか無いのに常に見えている**うえ、
title は「片付ける」・押した後の状態文は「閉じています…」と、
**1つの口が2語を名乗っていて**語彙の表に居場所が無い。V4 は断りの本文が出る面なので、
復帰の口も本文に置く —— 「やり直す」を押すと `modal=game-start` が開く
（決定6の記憶が入れば前回の設定が入っている）。

- **「やり直す」は押した瞬間に捨てない。** 始め損ねた対局は次の `start` の上書きが
  捨てる（`failed` は「対局がある」に数えない —— 現行どおり）。押した瞬間に捨てると、
  開始の面を「やめる」で戻った人が**断りの文言をもう読めない**
- **V4 を消すためだけの口は持たない。** 断りは次の対局を始めるまで残る。
  断りを読めなくする操作に独立の口を割かない
- `PlayControls` の規則「押せなくなっても消さない」は**操作列の中の**規則で、
  ✕ は操作列から出て面の本文へ移るのでこの規則には当たらない

**失敗の帯と復帰の導線が同じ場所に並ぶ**（design-language の「エラーを出しても
復帰導線が無ければ行き止まり」に沿う）。

## 決定6: 開始の面は「チップ＋ステッパー」にし、設定を記憶する

### 持ち時間の入力

`TextInput` 3欄と形の `Select` をやめ、2段にする。

```
持ち時間
[3分切れ負け] [10分＋秒読み30] [1手30秒] [1分＋加算10]

持ち時間  [−] 10 分 [+]     秒読み  [−] 30 秒 [+]
```

- **チップは欄を埋めるだけの口。** 権威はステッパーの値で、チップを押すと
  形と3つの値がまとめて入る。ステッパーを触るとチップの選択は外れる
- ステッパーは分／秒の単位で刻み、**直打ちも受ける**（floodgate 等の特殊な
  持ち時間に当たっても行き止まらない）。入力の検証は現行の `msOf` 系のまま
- **欄の権威は文字列のまま**（`TimeControl` を変えない）。`[−]` `[+]` は `msOf` と
  同じ読み方で解釈できない欄には**書き戻さない** —— 全角の直打ちに `[+]` を当てて
  `NaN` を欄に書き戻す口を作ると、文字列保持が塞いでいた症状がそこから再発する
- 「0分」を打つ場面が消える —— 切れ負けのチップは形を `sudden` に入れるだけでよく
  （属さない欄は `toTimeLimit` が 0 にする）、秒読みだけの形は持ち時間の
  ステッパーを 0 まで下げれば済む
- 形（切れ負け／秒読み／フィッシャー）の排他は現行どおり
  （`toTimeLimit` が選んだ形に属さない欄を 0 にする）

### 記憶

`AppConfig` に**1欄のオブジェクト**（案 `game_start_defaults`）を足し、
席（人／プリセット ID）・名前・持ち時間・棋譜の形式を対局を始めるたびに記憶する。

- 置き場は ADR-0010 決定3（設定の置き場を2つにしない）に従う。条件は2つ ——
  **古い設定ファイルが読めること**（serde の既定値で欠けを許す）と、
  **知らない欄を書き戻しで消さないこと**。後者の守り（`#[serde(flatten)]` の控え）は
  いまトップレベルにしか無いので、**中身は Rust に型で持たせず opaque に運び、
  濾すのは読んだ側**（`dock_tabs` が「Rust は中身を見ない」としているのと同じ流儀）
- **開くときに濾す。** 記憶したプリセット ID は消えている・設定が失われていることが
  あるので、**名簿に無いか揃っていない**（席の選択肢と同じ述語 `isPresetConfigured`）
  なら人に落とす。在籍だけを見ると、揃っていないプリセットが選択肢に無い値として
  復元され、**押せない理由がどこにも出ないまま「対局を始める」が沈む**
- ファイル名と保存先は記憶しない —— どちらも回ごとの値で、
  保存先はツリーの起点（`dir=`）が既に運んでいる

席・持ち時間・ファイルの3つが1枚に同居する構成は**変えない**。記憶が入ると
毎回触るのは実質ファイル名だけになり、段を分ける（ウィザード化する）ほうが
押す回数が増える。

## 決定7: `Aborted` から「進行不能」を型で分ける（#362 の決着）

`GameOverReason` に故障の値（案 `RulingTimeout`。wire に出る綴りは
`rulingTimeout`）を足し、`RULING_TIMEOUT` で畳んだ終局はそちらで届ける。
`Aborted` は利用者の中断だけになる。

- 受け手の対処が正反対（中断は何も出さなくてよい、進行不能は故障として名乗る）
  なのに、いまは `detail` の英文でしか区別できない
- 語彙（決定1）が先に決まったので、値の名前はそこから導く
- TS 側は `GameOverReason` の写しと `REASON_LABEL`（`Record` なので綴りを
  足さないと tsc が落ちる）が連動する。**ただし連動が効くのは TS の union を
  編集した後だけ** —— 写しのラチェットは欄を持たない enum を見ないので、
  Rust に variant を足しただけの状態は誰も赤くしない。だから **Rust の enum と
  TS の写しは同一コミットで動かし**、同じ PR で「全 variant が TS の写しに在る」を
  見る検査を足す（wire の突き合わせが object しか覆っていない穴をちょうど塞ぐ）

## 結果

### 得られるもの

- 「閉じる」を読むのに文脈が要らなくなる（面を畳む以外の意味が無い）
- 残り時間が、どのタブを開いていても見える
- 終局の面が小さくなり、読む本体（スタッツ）は対局タブに残る
- `searchInfo` と `elapsedMs` を捨てなくなる —— 対局中の読み筋の表示（既知の欠落）
  にも同じ系列が使える
- 「0 をタイプさせる」入力が消え、2局目からは設定がほぼ触らずに済む

### 諦めたもの

- **盤のそばで時計を読むこと**（ShogiHome の形）。盤の寸法を対局の有無から独立に保つ
  ほうを取った
- **終局の面から詳細へ飛ぶ口。** ボタンは「閉じる」1つ（ADR-0005）。
  スタッツへの導線は文言（「結果は棋譜には書けていません。対局タブに残ります」）が指す
- **将棋所式の「対局結果一覧」。** 結果の永続は #115（終局を棋譜へ残す）の仕事で、
  セッションを跨ぐ一覧は連続対局（Q-003）が決まるまで持たない

### 依存する前提

- 対局は同時に1局だけ（`GameSessionProvider` が断る。Rust 側の上限は #382）。
  複数対局を持つときは、ヘッダの対局の行とスタッツの持ち方から見直しが要る
- `GameSessionProvider` がヘッダより上（`RuntimeProviders`）に居ること

## 着手順

依存が無い項は並行してよい（ADR-0001 が縛るのは依存のある組だけ）。

| 順  | やること                                                                                                | 依存 |
| --- | ------------------------------------------------------------------------------------------------------- | ---- |
| 1   | Rust: `Aborted` から `RulingTimeout` を分け、TS の写し・文言と同一コミットで動かす（#362）              | 無し |
| 2   | 操作列から ✕ を外し、V4 に「やり直す」を置く。終局の面を結末だけにする                                  | 無し |
| 3   | 時計をヘッダの対局の行へ移す（`clock.ts`・`useNow.ts`・`clocksOf` を `entities/game-session` へ下げる） | 無し |
| 4   | `elapsedMs` / `searchInfo` を進行の系列へ畳む（画面は変えない）                                         | 無し |
| 5   | V3 をスタッツの本体にする（消費時間・平均・最終の残り時間・評価値の推移）                               | 4    |
| 6   | 開始の面をチップ＋ステッパーにし、`game_start_defaults` を記憶する                                      | 無し |
| 7   | 入玉宣言の口を操作列に足す（`judgeDeclaration` の初めての呼び手）                                       | 1    |

- 7 が 1 に依存するのは順序の都合ではなく語彙の都合 —— 宣言が断られた回の文言が
  `GameOverReason` の日本語に乗るため、綴りが動く前に画面を書かない
- 2 には `REFUSAL_MESSAGE.held` の文言の修正を含める —— いまの案内が指す
  「対局タブの『閉じる』」は、**この案内が出る全ての回で押せない**
  （✕ が押せるのは `failed` だけで、`failed` は「対局がある」に数えない）うえ、
  2 で綴りごと消える。正しい案内は「中断か投了で終わらせてから」
- 2 には決定1の「畳み損ねの復帰は『次を始める』が兼ねる」（`start` 側の
  `close_game` 再試行）も含める —— ✕ を外すのと同じ経路の話で、
  これが入るまで `closeFailure` の復帰は現に再起動しか無い
- 3 で下げるものを `widgets/play-view` から import で参照し直さないこと ——
  widgets どうしの横断は検査が止める。複製もしない（同じ知識を2箇所に置かない）

# ADR-0012: 堀は「保守されているクロスプラットフォームの棋譜ライブラリ層」に置く

- 日付: 2026-10-14
- 状態: 採用
- 関連: 方針転換 2026-06（#112）の堀の定義を置き換える / `docs/PREMISES.md` P-001・P-002

## 文脈

方針転換 2026-06（#112）は、堀を「フォルダ横断の局面検索は ShogiHome が構造的に持てない領域」と定義していた。

この定義は 2026-07-27 に反証された（P-001）。棋譜エクスプローラー（ShogiGUI の作者製）が
2022年の時点で、完全一致・部分一致・左右反転・手番無視・手数制限・メタデータフィルタ・タグを実装している。
KifuBase も同種の機能を持つ。「横断局面検索」だけを名乗ると「棋譜エクスプローラーでよいのでは」と言われる。

P-001 の対応欄には「堀の再定義が必要。ADR 化すること」と書かれていた。
それから11週間 ADR が無く、**堀の定義が文書のどこにも無い状態**が続いていた。
`docs/spec/screens/position-search.md` などは P-001 の反証だけを引いていて、
代わりに何を拠り所にするかは書かれていない。

## 決定

1. **obs-shogi の堀は、保守されているクロスプラットフォームの棋譜ライブラリ層であること。**
   ここで言うライブラリ層とは、大量の棋譜を開き・索引し・横断して引ける層を指す。
   堀の根拠は機能の独自性ではない。**その層を、いま保守している実装が他に無い**ことにある
2. **横断検索は堀そのものではなく、ライブラリ層の中心となる機能として扱う。**
   「他に無い機能」とは名乗らない
3. **ライブラリ層の比較相手は、棋譜エクスプローラーと KifuBase。** ShogiHome ではない。
   ShogiHome の作者は「大量の棋譜から目的のファイルを検索したり統計情報を調べる機能はありません」と、
   この層をスコープ外だと明言している

## 理由

- 棋譜エクスプローラーの最終リリースは 2022-09-16 で、2026-10-14 の時点でも更新されていない。
  KifuBase の最終更新は 2019-01-06。
  ShogiGUI と将棋所は Windows 専用のクローズドソースである（P-002）
- ShogiHome は 2026 年に v1.27〜v1.29 を出し、分岐ツリーの表示と棋譜の連続解析を足した。
  それでも、フォルダをまたぐ検索は足していない。スコープ外とした宣言は保たれている
- 機能の独自性を堀にすると、同じ機能を持つ古い実装が1つ見つかるだけで崩れる。P-001 がまさにそれだった。
  「保守されている」「クロスプラットフォームである」の2点は、機能の一覧ではなく**実装の状態**についての主張なので、
  確かめる手段がはっきりしている（最終リリースの日付と、対応 OS）

## 結果

- **諦めたもの: 「この機能はここにしか無い」という主張。** 紹介文でも issue でも、横断検索を独自機能として書かない
- **堀は時間とともに変わりうる。** 棋譜エクスプローラーの更新が再開する、ShogiHome が横断検索を入れる、
  同種の新しいツールが出る——のどれか1つで消える。
  そのため P-002 を、失効条件つきの前提として定期的に確かめ続ける（`次回確認` を切らさない）
- この ADR は**研究家向けの層の堀**だけを決める。将棋AI開発者の需要をどこまで取りに行くか（P-008 / Q-003）は、
  別の軸として未決のまま残す
- 合流（DAG）は差別化の候補として `docs/IDEAS.md` と Q-002 に残す。この ADR では採らない

## 依存する前提

- **P-002**（保守されたクロスプラットフォームの棋譜ライブラリ層は存在しない）——これが覆れば、この ADR も見直す
- P-001（反証済み）——この ADR が置き換える定義の根拠だった前提

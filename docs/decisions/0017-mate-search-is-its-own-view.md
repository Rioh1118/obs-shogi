# ADR-0017: 詰み探索は検討の終了条件にせず、ドックの別のビューにする

- 状態: 採用
- 日付: 2026-11-21
- 決めたもの: `/decide`（人の確認なし。見てほしい点は PR の確認事項に残す）
- 関連: ADR-0010（ドックのタブとビュー）
- 入力: `docs/OPEN-QUESTIONS.md` の旧 Q-009、`research/engines/mate-engines.md`
- 仕様: `docs/spec/features/mate-search.md`

## 文脈と問題

旧 Q-009 は「詰み探索をプリセットの解析（検討）に持たせるか」を問い、決めるのに要るものとして
「詰将棋エンジンのビルドを1本測ること」と「AI 開発者の作業で要るか」を挙げていた。

2026-11-21 に利用者が詰将棋エンジンを仕様に組み込むことを求め、需要の側は満たした。
詰将棋エンジンの応答は KomoringHeights `kh-v1.1.0` のソースで確かめた（実行はしていない）。

## 決定

**詰み探索は検討の終了条件にしない。ドックの別のビュー「詰み探索」にし、既存のプリセットを1つ選んで使う。**

理由は3つ。

1. **応答の形が違う。** 詰み探索の答えは `checkmate` の1行で、`info` を流して `bestmove` で終わる検討とは
   結果の型が違う（手順1本か、不詰・時間切れ・非対応）
2. **詰将棋エンジンは検討に使えない。** 通常の `go` には候補手を出さず、詰みが無ければ `bestmove resign` を返す
3. **検討と同時に見たい。** ADR-0010 の問い「2つを同時に開きたいか」に当てると開きたいので、表示モードでなくビュー

## 捨てた案

| 案                                     | 捨てた理由                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------- |
| 検討の終了条件に「詰」を足す           | 理由1と2。候補手の表に詰みの答えを入れる欄が無い                           |
| 設定に「詰み探索のエンジン」を別に持つ | エンジンの置き場と設定の考え方が2つになる。プリセットで足りる              |

## 結果

- プリセット編集に詰み探索の欄は出さない（エンジン標準化 AC-31 のまま）。保存された値は持ち回るが読まない
- 対応していないエンジンは、答え（`bestmove` か `notimplemented`）で見分ける。申告からは分からない

## 戻すとき

詰み探索を検討の中で常に回したい要望が出たら、ビューをやめて検討の表示モードに移す。
そのときも結果の型は分けたまま持つ。

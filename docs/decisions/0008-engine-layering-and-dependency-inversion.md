# ADR-0008: エンジン層の責任境界と依存の向き

- 状態: 採用
- 日付: 2026-09-02

## 背景

`src/` は Feature-Sliced Design のレイヤを持ち、`import/no-cycle` と
`no-restricted-imports` が向きを強制している（`CLAUDE.md` の「依存の方向」）。

`src-tauri/src/engine/` には同じものが無かった。結果、次の3つが同時に起きていた。

1. **モジュールが環になっていた。** `AppState` が解析のファサードと同居し、
   対局のコマンドがそこを `use` する一方で、解析側は対局の `GameManager` を持つ
2. **対局の状態機械が `tauri::AppHandle` という具象に依存していた。**
   テストは `app: None` で組むしかなく、`emit` は黙って捨てる
3. **同じ判断が2箇所にあった。** `info` の間引き（`search.rs` と `session.rs`）、
   `STOP_GRACE` の2つの定義、`Kind` の一覧の写し

3つとも同じ形の故障を生んだ。**片方だけ直すと、もう片方が古いまま残る。**
13ラウンドのレビューで出た所見のかなりの部分がこれだった。

## 決定

### 1. 段を決め、依存は下向きだけ

| 段  | モジュール | 何を決める場所か                   |
| --- | ---------- | ---------------------------------- |
| 1   | `types`    | 線に出す形と失敗の型。何も決めない |
| 2   | `utils`    | USI の行を値に写す。何も決めない   |
| 3   | `protocol` | 1本のプロセスへ何を送れるか        |
| 4   | `registry` | どのプロセスが生きているか         |
| 5   | `game`     | 対局の状態機械と持ち時間           |
| 6   | `analyzer` | 解析の探索1回ぶん                  |
| 7   | `bridge`   | 解析のファサード                   |
| 8   | `state`    | Tauri が持つ持ち物                 |
| 9   | `commands` | Tauri コマンドの入口               |

- **下の段が上の段を `use` しない。** 共有したいものは共有できる段まで**下げる**
- **環を作らない。** 環があると「どちらが土台か」が言えず、片方を読むのに
  もう片方が要り、テストの継ぎ目も作れない
- 段に載っていないモジュールを残さない。新しく足す人は
  「何を決める場所か」を1行で書く

`src-tauri/tests/engine_layering.rs` が強制する。

### 2. 具象への依存は trait で逆転する

**上の段の具象型に、下の段が依存しない。** 依存させたくなったら、
**下が口（trait）を決め、上がそれに合わせる。**

最初の適用が `GameEventSink`（`engine/game/events.rs`）。

- 口を決めるのは `game`。`tauri` を知らない
- 実装（`TauriEvents`）は `commands::game`。上の段に置く

結果、`game/` から `tauri` への `use` が1本も無くなった。
**対局の状態機械はプロセスもランタイムも無しで回せる。**

適用する条件は「境界をまたぐ具象依存があること」。同じ段の中の具象は
そのままでよい——逆転は依存の向きを直すためのもので、抽象そのものが目的ではない。

### 3. 判断は1箇所に置く

同じ判断を2箇所に書かない。書いた時点で、片方だけ直る経路ができる。

- 「先読みの `info` を落とすか」→ `on_search_info` の `is_to_move` 1本
- 「`stop` の後に `bestmove` を待つか」→ `verdict_of_stop` 1本
- 「届かない理由の文言」→ `cannot_reach_text` 1本

一覧が要るときは**宣言から生やす**（`Kind::ALL` / `ReadyState::ALL`）。
手で書き写した一覧は、写しであるかぎり必ずずれる。

### 4. 上限どうしの関係は式で持つ

秒数を散文に書かない。大小関係は `the_watchdogs_are_ordered` に式で置く。

**同じ関係を固定する式が2つ並んだら、弱いほうに揃えない。**
`CLOSE_IDLE_TIMEOUT` が `> SEARCH_STOP_GRACE` という弱い式だったせいで、
畳みの最悪値（`WRITE_TIMEOUT + SEARCH_STOP_GRACE`）より短い値が緑で通っていた。

## 帰結

- モジュールを足すときに段を決めることになる。「置き場の都合」で足せなくなる
- `game` にテストの継ぎ目ができた。状態遷移表が「テストあり」の印を付けながら
  実体を持てなかったセルを、実際に埋められる
- `AppState` を受け取るのは `commands` だけ。下の段は Tauri を知らない

### 引き受けるコスト

- `Arc<dyn Trait>` は動的ディスパッチになる。対局の出来事は1手に数回〜
  毎秒数十回で、ここが問題になる規模ではない
- 口を1つ増やすと、実装とテスト用の実装で最低2つ書くことになる。
  **境界をまたぐときだけ**に限るのはこのため

## まだ逆転していない境界

- `game::search` / `analyzer` が `Arc<UsiProtocol>` に直に依存する。
  これがあるので、探索の待ち方を実プロセス無しでテストできない
  （レビューで2度、継ぎ目が無いことが所見として出ている → #371）
- `EngineRegistry` が `usi::UsiEngineHandler` に直に依存する

どちらも「口を決めてから逆転する」で直せるが、
**踏める経路が無いうちは足さない**（→ `/implement` の「対象を疑う」）。

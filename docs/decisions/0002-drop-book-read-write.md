# ADR-0002: 定跡(book)の read/write を自前で作らない

- 日付: 2026-08-29
- 状態: 撤回（2026-08-29）。判断の軸を P-008「将棋AI開発者の需要を取り込む」に置き直したため。
  close した17件の issue は全て open に戻してある。**本文は当時のまま残す。**
- 関連: `docs/PREMISES.md` P-006（反証）、`docs/OPEN-QUESTIONS.md` Q-003（この ADR で一度決着したが、撤回に伴い 🔴 に戻っている）、`research/findings/L3-book-solved.md`

## 文脈

open だった issue 31件のうち12件（#84 #90–#100 #101）が定跡の read/write/変換/UI で、
open issue の最大の塊だった。方針転換 2026-06 では T1-④ として「生存」扱いにしていた。

その根拠だった前提 P-006「定跡の read/write は自前で作る価値がある」は、
二次情報のまま6週間以上確認されていなかった。

## 決定

**定跡の read/write を obs-shogi で実装しない。** 12件を issue から外し `docs/IDEAS.md` に落とす。

`.db.bin` を前提にしていた #92 / #84 は、**そもそも実在しないフォーマットに対する実装計画**だった。

## 理由

ShogiHome が同じ領域を、追いつく見込みの無い水準で埋めている。

| 確認したこと                                                                                           | 出典                                                                   |
| ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 4形式の reader が実在する（`apery.ts` / `sbk.ts` / `yaneuraou.ts` / `ybb.ts` + Zobrist テーブル 62KB） | `sunfish-shogi/shogihome` の `src/background/book/` を `gh api` で列挙 |
| テストが実在する（7ファイル、`index.spec.ts` だけで 44KB）                                             | 同 `src/tests/background/book/`                                        |
| Windows / macOS / Linux で配布されている                                                               | リリース asset                                                         |

**やねうら王のバイナリ定跡は `.ybb` であり、`.db.bin` は存在しない。**
`source/book/book.h` を直接読んで確認した。`.bin` で当たるのは Apery の `book.bin`（`book.h:184`）だけで、
バイナリ定跡DBの実装は `find_ybb_bookmoves_*`（`book.h:246-248`）。

唯一の本物のギャップは **複数定跡の同時ロードと重ね合わせ**（#96）で、
ShogiHome 側でも issue #1456 として open のまま（2026-01-10 起票、確認日時点で未実装。
v1.29.0 stable が 2026-08-01 に出たがリリースノートに含まれない）。
ただし同リポジトリの定跡機能の実装速度を踏まえると、**先に実装される側に賭ける方が分が良い。**

## 結果

### 得られるもの

- open issue が 31 → 6件になり、「実装不備」と「構想」が区別できる器に戻る
- 存在しないフォーマットに対する実装に着手する危険が消える

### 諦めたもの

- 定跡を obs-shogi の差別化要素にすること
- #96（複数定跡の重ね合わせ）。IDEAS に残すが、ShogiHome #1456 が実装されたら消す

### 失効条件

- ShogiHome が定跡機能の保守を止める
- ドッグフーディングで「ShogiHome の定跡編集に足りないもの」が read/write 側に見つかる

### 未決のまま残ること

調査は「定跡編集の需要が AI 大会勢という狭い層に集中している」可能性を示したが、
**公開情報では決着しない。** これは自分の実利用でしか確かめられない。
この ADR は「自前で作らない」だけを決めており、「定跡に需要が無い」とは決めていない。

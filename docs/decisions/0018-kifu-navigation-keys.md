# ADR-0018: 棋譜の中の移動のキーは作業画面のどこでも受け、一覧で選ばれて見える行はいまの手だけにする

- 状態: 採用
- 日付: 2026-11-23
- 決めたもの: `/decide`
- 仕様: `docs/spec/screens/app-layout.md` の「キー操作」

## 文脈と問題

作業画面で矢印を受けていたのは、ドックのタブ列だけだった。棋譜の移動はボタンと行のクリックしか無く、
`docs/state-transitions/game.md` の「→ キー」には実装が無かった。

利用者は、見た目の作り直しで移動のボタンが小さくなることに対して、← → で動けること、
フォーカスも含めた条件と挙動を設計して入れることを求めた（2026-11-23）。

最初の実装は、行がフォーカスを持ち、いまの手が動いたときだけ追わせていた。利用者は実アプリで
「棋譜リストのフォーカス要素が2つ発生している。single source of truth が移動するだけにしたい」と直した。
右クリックや分岐のメニューのあとでは、フォーカスの輪だけが別の行に残る。行の上に止まったポインタのホバーも、
いまの手とほぼ同じ明るさで残る。どちらも、行を選ばれて見せる出どころが、いまの手のほかにもう1つあった。

他の GUI は次のとおり（2026-11-23 にソースを読んだ）。

- ShogiHome（`sunfish-shogi/shogihome` b9a61dd4 の `getRecordShortcutKeys`）:
  既定は ↑ ↓ が1手、← → が最初と最後。設定で ← → を1手にできる。対話が開いている間は効かない。フォーカスの場所で分ける処理は無い（打つ欄の扱いは使っているライブラリに任せている。そこは読んでいない）
- lichess（`lichess-org/lila` b071608b の `ui/analyse` の `keyboard.ts`）: ← → が1手、Home と End が最初と最後

## 決定

**キーは、押すボタンと同じことをする。** 書き込み中、検討中、成りの選択中の扱いも、ボタンと同じ。

1. **← → Home End は、作業画面のどこにフォーカスがあっても受ける。**
   ツリーで棋譜を開いた直後や、検討の操作を押した後に、一覧を押し直さずに動かせる
2. **↑ ↓ は、棋譜の一覧にフォーカスがあるときだけ受ける。** ほかの場所では、その場所のスクロールに残す
3. **行を選ばれて見せる出どころは、いまの手（`state.cursor`）の1つ。** フォーカスは一覧そのものが持ち、行には渡さない。
   輪も読み上げも、いまの手の行に出す（`aria-activedescendant`）
4. **矢印で棋譜を動かしたら、フォーカスも一覧へ移す。** 押した場所に残すと、動いていない部品に輪が出る
5. **一覧で Tab が止まるのは、一覧と、いまの手の行のボタンだけ。** ほかの行のボタンにフォーカスが来たら、一覧へ戻す
6. **指した行の背景は、ポインタを動かして載せた行だけに付ける。** `:hover` は使わない
7. **押し続けた移動は、1回描くごとに1手まで。** 溜めない
8. 受けない条件は、仕様の表が持つ

## 捨てた案

| 案 | 捨てた理由 |
| --- | --- |
| 一覧にフォーカスがあるときだけ受ける | ツリーで開いた直後に動かず、一覧を押す手間が要る |
| 行がフォーカスを持ち、動いたら追わせる | 行だけにフォーカスが残る経路がある |
| フォーカスを動かさない | 動いていないツリーに輪が出る |
| 輪を一覧の枠に描く | 動く行と枠とで、2つに見える |
| 行のホバーをやめる | 右端のボタンと手の対応が読みにくい |
| ↑ ↓ をフォーカスが無いときも受ける | 候補手の表を流そうとして盤が動く |
| ↑ ↓ を最初と最後にする | 縦に並ぶ一覧で、↑ が最初へ飛ぶ |
| ↑ ↓ で分岐を選ぶ | 操作が増える。局面ナビが持つ |
| 開いているかを `overlayStack` で見る | 付箋も載る。付箋は開いたまま動かしたい |
| 割り当てを設定にする | 求められていない |

## 結果

- 作業画面に矢印を自分で使う部品を足すときは、React の `onKeyDown` か `document` で受けて `preventDefault()` する。
  キーの側は `window` で聞き、それを見て降りる。`window` で後から聞く部品が止めても間に合わない
- ドックのタブは、マウスで押してもフォーカスを持たない。持つと、タブを押した直後の ← → が棋譜でなくタブを動かす
- メニューは `role="menu"`、モーダルは `aria-modal="true"` を名乗る。名乗らないと、開いている間も盤が動く
- 棋譜の行に `tabIndex` も `:focus` も足さない。行が受けていた Enter と Space は、届かなくなったので消した
- Tab で別の所を辿っている人は、矢印を押すとその位置を失う。引き換えに、↑ ↓ がそのまま続けて効き、
  動いた先の手が読み上げの対象になる
- 付箋・メニュー・削除の確認を閉じたら、開いた側へ戻す。戻す先が無くなっていれば一覧へ。表は仕様が持つ

## 戻すとき

↑ ↓ を作業画面のどこでも1手にしたい要望が出たら、候補手と定跡の表にフォーカスを持たせてから、
`features/kifu-navigation-keys` の `LIST_KEYS` を `SCREEN_KEYS` へ移す。

Tab の位置を保ちたい要望が出たら、`useKifuNavigationKeys` の `focusKifuList()` の呼び出しを外す（決定 4 だけが戻る）。

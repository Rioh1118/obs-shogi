# ADR-0009: Rust 側をスライス（crate）と段で組み、境界を機械に守らせる

- 状態: 採用
- 日付: 2026-09-04

## 背景

`src/` は Feature-Sliced Design を採り、`vite.config.ts` の `no-restricted-imports` を
レイヤごとの override で表現して lint が強制している（`CLAUDE.md`「依存の方向」）。

**`src-tauri/src/` には同じものが無かった。** ADR-0008 が `engine/` の中に段を定めたが、
その外は素のままで、着手時の実測（2026-09-04）で次が出た。

- **`file_system` と `config_dir` が環になっている。** どちらが土台かが言えない。
  しかも `file_system` 側は `use` の行ではなく式の中の完全修飾
  （`crate::config_dir::CONFIG_FILE`）なので、`use` だけを見る走査には最初から映らない
- **Tauri コマンドは50個あり、11ファイルに散っている。** `commands` と名乗る場所に
  居るのは `engine/` の22個だけ
- `search/` は19ファイルが平置き。`file_system/` は6ファイル平置き
- `engine/` から `crate::test_support` を引く行がある（`registry.rs`）。
  これも完全修飾なので `the_engine_does_not_reach_out_of_itself` に当たらない

**規則を書くだけでは守られない。** フロント側は lint で落とすようにしてから
上向きの import が止まった。`engine/` だけが段を保てているのも、
`layering.rs` が `use` の行と型の位置の完全修飾の両方を見ているから。

## 決定

### 1. スライスは crate。スライス同士の辺は Cargo が守る

`src-tauri/` を workspace にし、スライスを1つずつ crate にする。
**どの crate がどの crate を使ってよいかは、各 `Cargo.toml` の `[dependencies]` が持つ。**

環は cargo が拒む。走査を書く必要も、表を手で書く必要もない。

**crate の一覧をここに書かない。** 増えるたびに嘘になる。
`src-tauri/Cargo.toml` の `members` が現在値を持つ。

### 2. crate の中は段。依存は下向きだけ

**段の表はここに持たない。** `src-tauri/tests/layering.rs` の `LAYERS` が
「何を決める場所か」と「何を `use` してよいか」を持つ。ADR-0008 決定1 をそのまま引き継ぐ。

- 下の段が上の段を `use` しない。共有したいものは共有できる段まで**下げる**
- 上下が言えない2つは同位にする。全順序にしない
- 使うようになってから許可する。実体の無い辺を `may_use` に残さない

**`LAYERS` にスライス間の辺を書かない。** 書くと、同じ事実が `Cargo.toml` と
`LAYERS` の2箇所に載る。片方だけ直る経路ができる（決定3 が禁じている形）。
**crate の外への `use` は、走査から見れば全部「外部クレート」**で、
そこを許すか禁じるかは `Cargo.toml` と `forbids` が決める。

### 3. Tauri コマンドは各 crate の `commands` 段にだけ置く

**例外を作らない。** 中身がほとんどコマンドだけの小さい crate でも、
その段を `commands` と名乗らせる。例外を1つ許すと「どこを探せばコマンドが
全部見つかるか」が言えなくなり、`lib.rs` の登録漏れを目で確かめるしかなくなる。

`commands` 段より下は `AppState` を受け取らない。ここは ADR-0008 の
`engine/commands/mod.rs` の明文をそのまま crate 全体へ広げたもの。

### 4. `mod.rs` は宣言だけ。再輸出を置かない

**`pub use` の facade を置かない。** 世間では推奨されることが多いが、
再輸出があると `crate::file_system::create_directory` のように
**段の名前を通らずに到達できる経路**ができる。段の表は「いま何がどう分かれているか」の
記述でなくなり、走査は辺を1本も立てないまま緑になる。

`lib.rs` の登録行が `commands` 段を名指しすることになる。それが狙い——
どのコマンドがどの段の入口かを、登録の1行が言う。

`the_engine_root_only_declares_modules` を crate 全体へ広げて強制する。

### 5. 「何を決める場所か」を1行で言えること

段もファイルも、これが書けるかどうかで置き場を決める。

- 段は `LAYERS` の `decides`。空にできない（`every_module_is_placed_on_a_layer` が見る）
- ファイルは冒頭の `//!`

**言えないなら、それは段でもファイルでもなく置き場の都合。**
ADR-0008 が段について書いた基準を、ファイルにも同じ形で当てる。

### 6. ファイルは責務で割る。行数では割らない

**行数の上限を機械で強制しない。** 行数は責務の代理にならない。
上限に合わせて機械的に割ると、1つの判断が2ファイルに分かれ、
**片方だけ直せる形**ができる——ADR-0008 決定3 が禁じているものを自分で作ることになる。

割る合図は次の2つ。

- **1つのファイルに、段を跨ぐ責務が同居している**
- **冒頭の `//!` に「と」で並ぶものが増え、1行で言えなくなった**

着手時の `search/kifu_reader.rs`（本番1164行）と `engine/protocol.rs`（本番1410行）は
どちらも後者だった。読む・整形する・文字コードを取り直す・理由の文言を組む、が
1ファイルに同居していた。

### 7. 外部クレートの語彙は、段で止める

**境界は既に在る。** 実測すると `shogi_core` / `jkf` を綴っているのは
`search` の下半分（局面・読み・索引の組み立て）と `kifu` だけで、
索引の器から上（保存・検索・監視・コマンド）には1つも無い。
`usi` も `engine` の下半分に閉じている。

**その境界に名前を付け、`LAYERS` の `forbids` で戻させない。**
外部クレートの型を我々の型へ写す層を新しく作るのではない——
既に成り立っているものを、機械が見る形にする。

`forbids` は許可制にしない（`tokio` / `serde` を全部書くことになる）。
挙げるのは**戻させたくない境界だけ**。ADR-0008 決定2 の `game → tauri` と同じ扱い。

### 8. 可視性は最小にする

段を跨ぐ必要のない項目を `pub` のままにしない（`pub(crate)` / `pub(super)`）。
crate に割ったあとは、`pub` が「他の crate に見せる」という意味を持つ。
**`LAYERS` が許した辺と、実際に見えている範囲を一致させる。**

## 採らなかったもの

- **Clean Architecture の同心円**（entities / usecases / …）。フロントが FSD なのに
  Rust だけ別の語彙になる。往復して読む人が2つの地図を覚えることになる
- **行数の上限**（決定6 の理由）
- **`mod.rs` の facade / prelude**（決定4 の理由）
- **全境界を port にする（Hexagonal を全面適用）**。ADR-0008 決定2 の
  「境界をまたぐ具象依存があるときだけ」を崩さない。抽象そのものは目的ではない
- **`cargo-deny` / clippy の `disallowed_types`** を段の強制に使うこと。
  crate 間の禁止は書けるが、**crate の中の段は書けない**。今回の主題に届かない
- **安定依存原則を明文化すること**。「安定度」を機械で測れない。段の上下で代用できている

## 引き受けるコスト

- `Cargo.toml` が1つから増える。crate を1つ足すたびに版と依存を書く
- **コマンドを持つ crate は `tauri` に依存する。** 依存の向きとしてはきれいでないが、
  コマンドを app crate へ全部集めると、`AppHandle` を使う既存の実装
  （root の関門など）の引き回しが大きくなる。ADR-0008 が守った
  「対局の状態機械が `tauri` を知らない」は段の `forbids` で残る
- 段を1つ足すたびに `LAYERS` を触ることになる。それが ADR-0008 の
  「モジュールを足すときに段を決めることになる」

## 帰結

- **`use` の行だけを見る検査は書かない。** この repo は型の位置に完全修飾を書く。
  実測で見つかった `file_system → config_dir` と `engine → test_support` は
  どちらもその形で、`use` 走査に1本も映っていなかった
- 走査が空振りしていないことを見るテストを、広げた先ごとに持つ
  （`the_scanner_actually_walks_the_engine` と同じ形）

# 判断のルール

判断の手順は `/decide`。**人間には聞かず、AI が決めて記録する。** 人間は成果物と判断ログを見る。

## 判断基準の優先順位

上から順に当て、最初に差がついた基準で決める。下の基準を理由に上の基準を破らない。

| 順  | ID      | 基準                   | 問い                                                 |
| --- | ------- | ---------------------- | ---------------------------------------------------- |
| 1   | R-DEC-1 | 正しさ・安全           | 壊れないか。データを失わないか。嘘を表示しないか     |
| 2   | R-DEC-2 | プロジェクト内の一貫性 | 既存の決定、ルール、語、形に揃っているか             |
| 3   | R-DEC-3 | 標準・慣例             | 規格、言語の慣例、利用者が他の製品で慣れた形に沿うか |
| 4   | R-DEC-4 | 使いやすさ             | 利用者が迷わず、少ない手数で済むか                   |
| 5   | R-DEC-5 | 変更しやすさ           | 後で変えるときに触る場所が少ないか                   |
| 6   | R-DEC-6 | 洗練さ                 | 読んで、見て、美しいか                               |
| 7   | R-DEC-7 | 実装コスト             | 少ない手間で済むか                                   |

**利用者の明示した言葉は、この表より上にある。** 依頼の文、過去の決定（ADR）、利用者が却下した案を先に読む。

R-DEC-3 は Jakob の法則が根拠で、利用者は他の製品で覚えた動きを期待する。他の製品にあること自体は
「作る」「作らない」の理由にならない（`docs/PREMISES.md` P-008）。

## ドア

| 種類     | 定義                                   | 決め方                              |
| -------- | -------------------------------------- | ----------------------------------- |
| 双方向   | 戻せる。戻す手間と影響が小さい         | 速く決める。必要な情報の7割で足りる |
| 一方通行 | 戻せない、または戻す手間と影響が大きい | 双方向に変えられないか考える        |

見るのは3つ。戻す手間、戻す速さ、影響の広さ。**迷ったら一方通行として扱う。**

**双方向に変える手**: 試験導入（小さく試す）、段階化（確かめる点で止められる順に割る）、
分離（戻せる部分だけ先に決める）、撤退口（切り替えや移行の逆向きの道を先に作る）。

**戻せる判断も積もると戻せなくなる。** 同じ領域に判断が3つ重なったら、まとめて見直す。

## 止まって人に聞くのはこれだけ

| ID       | 条件                               | このリポジトリでの例                                      |
| -------- | ---------------------------------- | --------------------------------------------------------- |
| R-DEC-8  | データの削除                       | 利用者のファイルや設定の削除、履歴の消去                  |
| R-DEC-9  | 本番・共有システムの変更、外部送信 | `git push`、`gh` の書き込み、リリース、公開、外部への投稿。作業中の PR へ `/decide` の確認事項を残すコメントは除く |
| R-DEC-10 | 依頼の範囲そのものを変える         | 非ゴールを破る、頼まれていない領域へ広げる                |
| R-DEC-11 | 双方向に変えられない一方通行のドア | 既存データの移行が戻せない、公開した形式を変える          |

**これ以外は聞かない。** 事実は自分で調べ、足りない前提は置いて判断ログに書く。

## 記録

| ID       | ルール                                                                                    |
| -------- | ----------------------------------------------------------------------------------------- |
| R-DEC-12 | 判断は成果物の末尾の判断ログに書く。列は 判断／選択／理由と基準／戻し方                   |
| R-DEC-13 | 選択肢は最低2つ出す。1つしか無いなら、他が消えた理由を書く                                |
| R-DEC-14 | 一方通行だったもの、複数の領域に効くもの、後から読んで驚くものは `docs/decisions/` に残す |

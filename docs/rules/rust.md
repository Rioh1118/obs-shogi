# Rust のルール

[common.md](common.md) に足すもの。土台は [Rust API Guidelines のチェックリスト](https://rust-lang.github.io/api-guidelines/checklist.html)。
`C-` の ID はそちらの項目。公開ライブラリの作法である `C-METADATA` `C-RELNOTES` `C-STABLE` と、マクロの節は、
アプリなので採らない。`src-tauri/crates/` の中も同じ扱いにする。

## API（Rust API Guidelines から）

| ID       | ルール                                                                        | 土台                                | 機械                      |
| -------- | ----------------------------------------------------------------------------- | ----------------------------------- | ------------------------- |
| R-RSA-1  | 大文字小文字と語順を慣習に揃える                                              | `C-CASE` `C-WORD-ORDER`             | rustc（大文字小文字）     |
| R-RSA-2  | 変換は `as_` `to_` `into_`、取得は `get_` を付けない                          | `C-CONV` `C-GETTER`                 | —                         |
| R-RSA-3  | 型には使える共通 trait を実装する。公開する型は `Debug` を持つ                | `C-COMMON-TRAITS` `C-DEBUG`         | —                         |
| R-RSA-4  | 変換は `From` `AsRef` で書く。受ける側を最も具体的な型に置く                  | `C-CONV-TRAITS` `C-CONV-SPECIFIC`   | —                         |
| R-RSA-5  | エラー型は意味があり、`Error` を実装する。公開 API の失敗を `String` にしない | `C-GOOD-ERR`                        | —                         |
| R-RSA-6  | 受け手が明らかな関数はメソッドにする。出力は戻り値で返す                      | `C-METHOD` `C-NO-OUT`               | —                         |
| R-RSA-7  | 意味の違う値は newtype で分ける。`bool` と `Option` の引数で意味を運ばない    | `C-NEWTYPE` `C-CUSTOM-TYPE`         | —                         |
| R-RSA-8  | 引数は検証する。Tauri コマンドの引数はフロントから来る任意の値として扱う      | `C-VALIDATE`                        | —                         |
| R-RSA-9  | `Drop` は失敗しない。止まりうる処理には別の明示的な口を用意する               | `C-DTOR-FAIL` `C-DTOR-BLOCK`        | —                         |
| R-RSA-10 | 構造体の欄は非公開を基本にする。不変条件を持つ型は特に                        | `C-STRUCT-PRIVATE` `C-NEWTYPE-HIDE` | —                         |
| R-RSA-11 | 中間の結果を返し、呼び手が計算をやり直さなくて済むようにする                  | `C-INTERMEDIATE`                    | —                         |
| R-RSA-12 | 失敗と panic の条件を doc に書く                                              | `C-FAILURE`                         | `rustdoc-ratchet`（一部） |

## メモリと所有権

| ID      | ルール                                                                     | 判断の基準                                           | 機械           |
| ------- | -------------------------------------------------------------------------- | ---------------------------------------------------- | -------------- |
| R-RSM-1 | 所有が要らない引数は借用で受ける                                           | `String` より `&str`、`Vec<T>` より `&[T]`           | clippy（一部） |
| R-RSM-2 | コピーする場所は呼び手が決める。`clone` は理由を言える所だけ               | ループの中の `clone` を疑う                          | —              |
| R-RSM-3 | 上限の無い蓄積を作らない                                                   | キュー、キャッシュ、チャネルに上限か捨てる規則がある | —              |
| R-RSM-4 | 子プロセスの持ち主は1人にする。捨てれば落ちる形にする                      | `Arc` で持ち主を増やさない                           | —              |
| R-RSM-5 | 本番の経路で `unwrap` `expect` `panic!` を使わない。不変条件なら理由を書く | Tauri コマンドの panic はプロセスを巻き込む          | —              |
| R-RSM-6 | `unsafe` は理由と安全条件を `// SAFETY:` に書く                            | 無くせるなら無くす                                   | —              |

## 性能

| ID      | ルール                                       | 判断の基準                                                   | 機械 |
| ------- | -------------------------------------------- | ------------------------------------------------------------ | ---- |
| R-RSP-1 | 繰り返し走る経路は、回数と計算量を見積もる   | 根から組み直す形、2乗の形を避ける                            | —    |
| R-RSP-2 | 非同期の中で同期 IO を上限なしに呼ばない     | `spawn_blocking` と `timeout` に出す                         | —    |
| R-RSP-3 | 同期の `#[command]` の中でファイルを開かない | メインスレッドで動くので、応答しないボリュームで画面が固まる | —    |
| R-RSP-4 | 測らずに複雑にしない                         | 速くする変更には測った値を添える                             | —    |
| R-RSP-5 | 早く打ち切れる問いは打ち切る                 | 「1つでもあるか」を全件数えて判定しない                      | —    |

## trait と抽象

| ID      | ルール                                                                | 判断の基準                                               | 機械       |
| ------- | --------------------------------------------------------------------- | -------------------------------------------------------- | ---------- |
| R-RST-1 | trait は差し替えが実在するときに作る。実装が1つなら作らない           | テストの差し替えも実在に数える。推測の差し替えは数えない | —          |
| R-RST-2 | 段をまたぐ具象の依存は trait で逆転する                               | ADR-0008                                                 | `layering` |
| R-RST-3 | 静的ディスパッチを基本にする。`dyn` は異なる型を1つの列で持つときだけ | 理由が言えないなら総称で書く                             | —          |
| R-RST-4 | trait は小さく、呼び手が使う分だけにする                              | 実装が空のメソッドを持つなら割る                         | —          |
| R-RST-5 | 総称の境界は `impl` に書き、データ構造には書かない                    | `C-STRUCT-BOUNDS`                                        | —          |

## 並行性

| ID      | ルール                                                             | 判断の基準                                         | 機械           |
| ------- | ------------------------------------------------------------------ | -------------------------------------------------- | -------------- |
| R-RSC-1 | ロックを持ったまま `await`、IO、チャネル送信、別のロックを取らない | 全ての `lock()` について、持っている間の処理を見る | clippy（一部） |
| R-RSC-2 | 2つ以上のロックを取る順序を全域で揃える                            | 順序を doc に書く                                  | —              |
| R-RSC-3 | 受け手が消えたときに送り手が詰まらない                             | チャネルの終わり方を決めてある                     | —              |
| R-RSC-4 | 外部プロセスの死亡を待ち手へ必ず届ける                             | プロセスが死んだとき、待ちが全部ほどける           | —              |

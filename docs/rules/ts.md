# TypeScript と React のルール

[common.md](common.md) に足すもの。レイヤの向きは `CLAUDE.md`、SCSS は `CONTRIBUTING.md`「SCSS の書き方」が持つ。

## 型

| ID      | ルール                                             | 判断の基準                                       | 機械 |
| ------- | -------------------------------------------------- | ------------------------------------------------ | ---- |
| R-TST-1 | 取りえない状態を型で表せなくする                   | 欄の組み合わせより判別できる union を使う        | —    |
| R-TST-2 | 意味の違う値は型で分ける。文字列のまま渡さない     | 要求と観測のように混ぜると壊れる値は別の型にする | —    |
| R-TST-3 | `as` で黙らせない。外から来る値は境界で確かめる    | `as` が要るなら、型か検査を見直す                | —    |
| R-TST-4 | falsy になりうる正常値を `null` と同じ欄に載せない | `0` や `""` が正常な欄で `if (x)` と書かない     | —    |
| R-TST-5 | Tauri の境界の型は Rust と揃える                   | ADR-0007。呼び出しは `entities/*/api/` に閉じる  | —    |
| R-TST-6 | 公開する export は呼び手のいるものだけにする       | 未使用の export を残さない                       | knip |

## 状態の置き場

| ID      | ルール                                                       | 判断の基準                                         | 機械 |
| ------- | ------------------------------------------------------------ | -------------------------------------------------- | ---- |
| R-TSS-1 | 状態は読み手に一番近い共通の親に置く。導ける値は状態にしない | 持たずに計算できるなら持たない                     | —    |
| R-TSS-2 | 画面より長生きすべき値を `useRef` や widget に置かない       | ビューを作り直して消えるなら、置き場が間違っている | —    |
| R-TSS-3 | 状態の遷移は reducer か状態機械に寄せる                      | 状態が3つ以上絡むなら表で書ける形にする            | —    |
| R-TSS-4 | 同じ値の入れ物を2つ持たない                                  | 控えを持つなら、誰がいつ同期するかを言える         | —    |
| R-TSS-5 | Context は変わる頻度で割る                                   | 関係ない値の更新で下流を描き直さない               | —    |

## React

| ID      | ルール                                                 | 判断の基準                                     | 機械 |
| ------- | ------------------------------------------------------ | ---------------------------------------------- | ---- |
| R-TSR-1 | 描画中に ref や外部へ書かない                          | 描画は純粋に保つ                               | —    |
| R-TSR-2 | `useEffect` は外部との同期にだけ使う                   | イベントの処理と導ける計算を effect に置かない | —    |
| R-TSR-3 | 非同期の完了で古い結果を採らない                       | 世代、取り消し、宛先の確かめのどれかがある     | —    |
| R-TSR-4 | `key` は要素の同一性を表す。添字を使わない             | 並べ替えと削除で状態がずれない                 | —    |
| R-TSR-5 | 部品は表示とロジックを分ける。判定は `lib/` の純関数へ | 判定を部品の外でテストできる                   | —    |
| R-TSR-6 | 共通の部品は `shared/ui` のものを使う                  | 同じ役割の部品を2つ作らない                    | —    |
| R-TSR-7 | 繰り返し描く経路は、再計算の範囲を説明できるようにする | メモ化は測ってから足す                         | —    |

## 部品の構造

読み手は JSX から画面の構造を推測する。例と実測は `.claude/skills/readable-code/references/structure.md`。

| ID       | ルール                                                         | 判断の基準                                                                                   | 機械             |
| -------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ---------------- |
| R-TSC-1  | JSX の木で画面の親子を読めるようにする                         | 画面で中にあるものは JSX でも中に書く。奥の部品へ隠すなら、部品の名前で位置が言える          | —                |
| R-TSC-2  | 中身が1つの部品は `children` で受ける                          | 包むだけ、囲むだけの部品。`StepShell` の本文                                                 | —                |
| R-TSC-3  | 位置の決まった区画が2つ以上なら、名前つきの `props` で受ける   | `GameBoard` の `topLeft`。部品が持つ値を中身へ渡すときだけ関数で受ける（`renderChild`）      | —                |
| R-TSC-4  | 素通しが2段続いたら `children` で解く。Context はその後に選ぶ  | 素通しは自分で読まず子の部品へ渡す欄。Context は離れた複数の読み手が同じ値を読むときに使う   | —                |
| R-TSC-5  | 部品は1文で言える役割で割る。行数では割らない（ADR-0009）      | 呼び手が1つで、受けた欄を読まずに返すだけの部品は呼び手へ戻す                                | —                |
| R-TSC-6  | 分岐、state、effect は読める数に収める                         | effect 3本、state 5本、分岐20は調べる入口。組み合わせが余るなら union か reducer にする      | —                |
| R-TSC-7  | 共通の部品は呼び手が2つ実在してから作る。旗で使い回さない      | 描き分けの旗が2つ以上あるなら部品を分けるか呼び手へ戻す（R-DUP-4）                           | —                |
| R-TSC-8  | 取得、状態、描画を1つの部品に混ぜない                          | 取得は `api/`、状態は `model/`、描画は `ui/`。部品の役割が「と」で繋がるなら分ける           | —                |
| R-TSC-9  | 何を見せるかと、どこに並べるかを分ける                         | 並べる部品は中身の種類を知らない。呼び手の JSX だけで中身が読める                            | —                |
| R-TSC-10 | 部品の中で部品を定義しない                                     | 親が描くたびに別の部品になり、下の state が捨てられる                                        | `componentShape` |

## 書き方

同じことを1通りに書く。決めた理由と実測は ADR-0014。

| ID       | ルール                                                                       | 判断の基準                                                                   | 機械                   |
| -------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------- |
| R-TSW-1  | 部品は `function` で宣言する                                                 | `memo` で包むときも `memo(function Name() {})` にする                        | `componentShape`       |
| R-TSW-2  | オブジェクトの形は `type` で書く                                             | `interface` は `declare` の中で既存の宣言へ足すときだけ使う                  | `componentShape`       |
| R-TSW-3  | React の型は名前で import する                                               | `import type { ReactNode } from "react"`。`React.ReactNode` と書かない       | `componentShape`       |
| R-TSW-4  | 部品の本体は 外の値 → state と ref → 導く値 → ハンドラ → effect → 早期 return → JSX の順に書く | 依存が先の宣言を要るときは依存を優先する。hook の順を入れ替えない規則は React のもの | `componentShape`（一部） |
| R-TSW-5  | ハンドラは1文ならその場に、2文以上なら `handle` ＋動詞の名前で JSX の外に書く | props の `onX` と動詞の関数は包まずに渡す                                    | `componentShape`       |
| R-TSW-6  | 片方が無い条件付き描画は `&&`、両方あるときは三項で書く                      | 左辺が `0` や `""` になりうるなら真偽へ直す（R-TST-4）                       | `componentShape`       |
| R-TSW-7  | ファイルは import → 型 → 定数 → 補助の関数 → 部品の順に書く                  | 上から読んで、使う前に定義が見える                                           | `componentShape`（一部） |
| R-TSW-8  | `ref` は `props` で受ける                                                    | React 19 では `forwardRef` が要らない                                        | `componentShape`       |
| R-TSW-9  | `props` は署名で分割代入して受ける                                           | 丸ごと子へ渡すときだけ `props` の名前で受ける                                | —                      |
| R-TSW-10 | 空と失敗を先に返し、本流を入れ子にしない                                     | 1文の `if` は `if (x) return y;` と1行で書く                                 | —                      |
| R-TSW-11 | `.scss` の import は import の最後に書く                                     | 既存を動かすと CSS の順が変わるので、動作が変わりうる変更として扱う          | —                      |

| ------- | ------------------------------------------ | -------------------------------------------- | ------------- |
| R-TSX-1 | 振る舞いを見る。実装の詳細を固定しない     | リファクタで落ちるテストを書かない           | —             |
| R-TSX-2 | `vi.mock` は実モジュールの型に合わせる     | `satisfies typeof import("…")`               | `viMockShape` |
| R-TSX-3 | 走査型のテストには件数の下限を置く         | 見たものが0件で緑にならない                  | —             |
| R-TSX-4 | 前後の一致だけでなく、値そのものを固定する | 両方が同じ壊れ方をしても通るテストを書かない | —             |

# コミットのルール

PR に出す履歴の形。整え方は `/organize-commits`。

## 切り方

| ID      | ルール                             | 判断の基準                                                                               |
| ------- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| R-CMT-1 | 1コミット = 1つの論理変更          | 元に戻すときに一緒に戻したい塊。1つの変更が多くのファイルに及ぶなら1コミットのままでよい |
| R-CMT-2 | 各コミットでビルドとテストが通る   | `git bisect` がどのコミットで止まっても壊れていない                                      |
| R-CMT-3 | API の変更と、それを使う側は分ける | 壊す変更は、新しい形を足す → 呼び手を移す → 古い形を消す、に分ける                       |
| R-CMT-4 | ファイルの移動と中身の変更は分ける | 移動のコミットは git が rename と判定する。改名も同じ                                    |
| R-CMT-5 | 依存は先に置く                     | 後のコミットを読まないと意味が分からない形にしない                                       |
| R-CMT-6 | レビューの往復を履歴に残さない     | 指摘の修正は対象のコミットへ畳む。経緯はレビュー報告が持つ                               |

**R-CMT-2 が他に勝つ。** 分けると通らないなら分けない。とくに、足しただけで呼び手の無い export は
`ratchet:knip` を、未使用の Rust の項目は clippy を落とす。その土台は最初の呼び手と同じコミットに入れる。

## 並び順

| 順  | 段     | 中身                                       | 振る舞い |
| --- | ------ | ------------------------------------------ | -------- |
| 1   | 準備   | リファクタ、移動、改名                     | 変えない |
| 2   | 土台   | 型、trait、インターフェース                | 変えない |
| 3   | 本体   | ロジックとそのテスト                       | 変える   |
| 4   | 接続   | 画面、コマンド登録、呼び手                 | 変える   |
| 5   | 仕上げ | 文言、仕様、状態遷移表、コメント、後片付け | 変えない |

段が空なら飛ばす。

## メッセージ

| ID      | ルール                     | 判断の基準                                                 |
| ------- | -------------------------- | ---------------------------------------------------------- |
| R-CMT-7 | 1行目は `<type>: <命令形>` | `feat: 定跡の候補を読み込む`。言い切りの動詞で終える       |
| R-CMT-8 | 本文に「なぜ」を書く       | 何をしたかは差分にある。理由、捨てた案、壊しうるものを書く |
| R-CMT-9 | 依存があれば本文に書く     | 「#N の後に入れる」など                                    |

`<type>` は `CLAUDE.md`「進め方」の一覧から選ぶ。

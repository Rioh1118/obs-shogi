# デザインシステムへの移行計画

**デザインの言語化（性格・トークン・振る舞い・言葉）の正本を、obs-shogi から専用のデザインシステムへ移す。**
obs-shogi はそれを使う側になる。移した後、今の見た目を材料にして画面ごとに洗練させる。

- 基準: `origin/main` 0be56281（2026-11-08）
- デザインシステム: `~/dev/obs-shogi-ds`（`~/dev/lumen-ds` を複製。スキル名 `obs-shogi-design-system`）
- 今の画面の撮影と一覧: `~/dev/obs-shogi-ds/references/current-screens-2026-11-08/README.md`
- 状態: 案。工程1（brief）に入っている。合意した工程は ADR に起こし、この文書からは消す（`docs/OPERATING-MODEL.md` §1）

## 工程

**見た目が変わらない移し替えを先に終え、正本を切り替えてから、見た目を動かす。** 正本が2つある期間を短くするため。

| #   | 工程                                 | 場所      | 見た目         | 終わりの条件                                                                                                                 | 止まる点                                                                      |
| --- | ------------------------------------ | --------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 0   | 準備: 複製・撮影・計画               | 両方      | 変わらない     | この文書と撮影の一覧がある                                                                                                   | —                                                                             |
| 1   | **brief を埋める**                   | DS        | —              | `brief.md` が v0.1 になり、空欄が無い                                                                                        | モード B の質問（最大5問）に利用者が答える                                    |
| 2   | 既存の規則とトークンを移す（基準線） | DS        | 変わらない     | 振り分け表の「移す」が全部 DS にある。トークンの値は今の `index.scss` と同じ。`ds:check` 合格                                | 固定値（`locked.json`）と今の値の衝突（下記）は利用者の承認が要る             |
| 3   | obs-shogi へ導入し、正本を切り替える | obs-shogi | **変わらない** | `index.scss` の値が DS の CSS 変数を指す。CLAUDE.md・スキル・テストの参照が DS を向く。`design-language.md` は残りだけになる | —                                                                             |

工程2と3は見た目が変わらないので、画像の差分が無いことで確かめる（撮り直して 1 ピクセルも動かないこと）。

### 工程2で利用者の承認が要る衝突

DS の固定値（`design_system/tokens/locked.json`）は変えるのに ADR と利用者の明示的な承認が要る。今の obs-shogi と次が合わない。

| 固定値           | DS                                   | 今の obs-shogi                       | 出典                                         |
| ---------------- | ------------------------------------ | ------------------------------------ | -------------------------------------------- |
| 本文の文字       | 16px 以上                            | `$font-body` 13px                    | `src/index.scss` の `$font-body`             |
| 補助と全体の下限 | 14px 以上                            | `$font-hint` 11px / `$font-aux` 12px | `src/index.scss` の `$font-hint` `$font-aux` |
| フォーカス       | 白黒の二重リング 2px、オフセット 2px | 銅の 2px（`$focus-ring`）            | `src/index.scss` の `$focus-ring`            |

選択肢は「固定値を製品に合わせて変える（ADR）」と「製品の文字を上げる（見た目が大きく変わる）」。
**工程2では値を移すだけにし、どちらにするかは利用者に聞く。** 密度の高い研究用のデスクトップアプリなので前者が素直だが、
コントラストの固定値（4.5:1 / 3:1）は今の `index.scss` のコメントの実測で満たしているので残す。

### 製品の技術と DS の利用の規則のずれ

DS の雛形は「React と素の CSS、クラス名は `lm-`」を前提にしている。obs-shogi は SCSS で、クラス名は部品ごと（ADR-0014）。
**工程3では値だけを DS の CSS 変数に寄せ、SCSS とクラス名は変えない。** DS の `docs/consumer-claude-md.md` の規則を、
SCSS を許す形に複製側で書き換える。部品の見本実装（`implementations/react/`）へ obs-shogi の部品を寄せるかは工程5で画面ごとに決める。

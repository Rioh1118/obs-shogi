# やねうら王テキスト定跡 (.db) の読み取り

`src-tauri/src/book/yaneuraou_db.rs` の `parse`。

**この表は仕様の突き合わせのために置く。** 所見が「その形式は実際どう書かれて
いるか」ばかりになったら、1件ずつ潰しても次の綴りに置いていかれる合図。
行の種類を先に列挙し、**どの状態でその種類が来たらどうなるか**を全部書く。

## 一次資料

| 出典                                                 | 何を確かめたか                                                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |

| 同 `:750-756`、`BookMoves::insert`（`:123-149`）     | 同じキーへの追記。同じ指し手は追加しない（union で先勝ち）                                                    |

| `YaneuraOuBookLib.py` `count_yaneuraou_db_positions` | **`# NOE:N` ≡ `sfen ` 行の本数。** 無ければ `sfen ` 行を数える                                                |
| ShogiHome `src/background/book/yaneuraou.ts`         | score / depth を省くとき**空文字**を書き出す。重複局面は minPly 側で**丸ごと置換**（こちらの union とは違う） |

## 状態

| 記号 | 判定条件（式）                          | 意味                             |
| ---- | --------------------------------------- | -------------------------------- |
| S0   | `header.is_none()`                      | 見出しをまだ見ていない           |
| S1   | `header.is_some() && current.is_none()` | 見出し済み、局面をまだ見ていない |
| S2   | `header.is_some() && current.is_some()` | 局面を読んでいる最中             |

`buffered` は S2 でしか非空にならない（S1 で指し手行はエラーになる）。
`flush` の早期 return はこの不変条件に依存している。

## 行の種類（イベント）

判定は上から順。最初に当たったものになる。

| 記号 | 判定条件（式）                                             |
| ---- | ---------------------------------------------------------- |
| E0   | `line.trim().is_empty()`                                   |
| E1   | `line.trim().starts_with("#YANEURAOU-DB")`                 |
| E2   | `line.trim().starts_with("# NOE:")`                        |
| E3   | `line.starts_with('#')`（E1 / E2 以外）                    |
| E4   | `line.starts_with("//")`                                   |
| E5   | `line.strip_prefix("sfen ").is_some()`                     |
| E6   | 先頭トークンが `ABSENT_MOVE`（`none` / `None` / `resign`） |
| E7   | 先頭トークンが `looks_like_a_move` を満たす                |
| E8   | それ以外（形を満たさない）                                 |
| E9   | EOF                                                        |

## 遷移表

`✓` はそのセルを踏むテストがある。

|                         | S0（見出し前）                    | S1（局面なし）                          | S2（局面あり）                            |
| ----------------------- | --------------------------------- | --------------------------------------- | ----------------------------------------- |
| **E0** 空行             | 読み飛ばす ✓                      | 読み飛ばす                              | 読み飛ばす                                |
| **E1** 見出し           | → S1 ✓                            | 読み飛ばす ✓（2度目は注記と同じ）       | 読み飛ばす ✓                              |
| **E2** `# NOE:`         | 読み飛ばし、値を覚える ✓          | 同左 ✓                                  | 同左 ✓                                    |
| **E3** `#` 注記         | 読み飛ばす ✓                      | 読み飛ばす ✓                            | 読み飛ばす                                |
| **E4** `//` 注記        | 読み飛ばす ✓                      | 読み飛ばす ✓                            | 読み飛ばす ✓                              |
| **E5** `sfen `          | `InvalidContent`「見出しが無い」✓ | → S2 ✓                                  | flush して → S2 ✓                         |
| **E6** 指し手なしの綴り | `InvalidContent`「見出しが無い」✓ | `InvalidContent`「局面より先に指し手」✓ | 読み飛ばす（局面は数える）✓               |
| **E7** 指し手           | `InvalidContent`「見出しが無い」✓ | `InvalidContent`「局面より先に指し手」✓ | 候補手に足す ✓                            |
| **E8** 形を満たさない   | `InvalidContent`「見出しが無い」✓ | `InvalidContent`「局面より先に指し手」✓ | `InvalidContent`「指し手として読めない」✓ |
| **E9** EOF              | `InvalidContent`「空」✓           | flush → 申告の突き合わせ ✓              | flush → 申告の突き合わせ ✓                |

**F7 は拒否に使わない。** 本家は末尾の改行を要求しない（`book.cpp:705`）ので、
改行が無いだけの完全な定跡を拒否すると不変条件1と3を同時に破る。逆に、行境界で
ちょうど切れたファイルは素通りする（行単位で書き出す生成器が止まった場合は
**必ず**行境界で終わるので、その経路は 100% 検出できない）。切れの検出は F4 だけが担う。

**S0 で E5 / E6 / E7 / E8 が「見出しが無い」になるのは意図。** 本家は見出しを
検査しないが、こちらは検査する。別形式のファイルに `.db` を付けただけのものを
「0局面の定跡」として開かないため（空の定跡と見分けが付かなくなる）。
その代わり **S0 でも注記（E2 / E3 / E4）と空行は読み飛ばす**。本家が普通に読める
定跡を、先頭の1行のせいで拒否しないため。

## ファイル全体に掛かる検査

行の種類とは別に、読む前と読んだ後に掛かる。

| 記号 | 判定条件                                                | 結果                                                       |
| ---- | ------------------------------------------------------- | ---------------------------------------------------------- |
| F0   | `size > MAX_FILE_BYTES`                                 | `TooLarge` ✓                                               |
| F1   | `str::from_utf8` が失敗し、行が `#` / `//` で始まらない | `InvalidContent`「N行目に文字として読めないバイトがある」✓ |
| F2   | 先頭3バイトが BOM                                       | 落として読み進む ✓                                         |
| F3   | 行末が `\r` / `\n`                                      | 落とす ✓                                                   |
| F4   | `declared.is_some() && sfen_lines < declared`           | `InvalidContent`「途中で切れている」✓                      |
| F5   | `positions.is_empty()`                                  | `InvalidContent`「局面が1つも無い」✓                       |
| F6   | `total_moves > MAX_MOVES`                               | `TooLarge`「指し手が多すぎて開けない」✓                    |
| F7   | `!last_line_terminated`                                 | `log::warn!` のみ。**拒否しない** ✓                        |

**F5 を `declared` の側にぶら下げてはいけない。** `# NOE:0` と書いた 31 バイトの
ファイルが `sfen_lines < 0` を通り抜けて「0局面の定跡」として成功する。

**F4 は `positions.len()` と比べてはいけない。** NOE は `sfen ` 行の本数で、
`positions` は正規化して重複を畳んだ後のキー数。畳んだ後と比べると、
持駒の綴りが揺れているだけの正常な定跡が「途中で切れている。取得し直すこと」で
拒否される（何度取得し直しても直らない案内になる）。

## 不変条件

1. **本家が読める定跡は、こちらでも読める。** 例外は見出しの検査（S0 の E5〜E8）
   だけで、それは意図した差。注記・空行・綴りの揺れで拒否しない
2. **`lookup` が返す `usi_move` は、盤に適用できる形の綴りだけ。**
   「指し手が無い」の綴りも、形を満たさないテキストも候補手にならない
3. **失敗の message は必ず「次に何をすればよいか」で終わる。**
   ファイルが正しいのに拒否する経路を作らない（効かない復帰操作になる）
4. **確保は2つの上限で有界。** ファイルの大きさ（F0。1バイトも読まずに落とす）と、
   展開した指し手の数（F6）。**片方だけでは足りない。** バイト数の上限だけだと
   1字の指し手行で埋めたファイルが通り抜け、手数の上限だけだと `sfen ` 行しか
   無いファイル（指し手0手）が通り抜ける

## 照合

- 不変条件1: E3 / E4 の S0 セルと、綴りの揺れを含む定跡が F4 で落ちないこと ✓
- 不変条件2: E6 の S2 セル ✓（`resign` / `none` が候補手にならない）、E8 の S2 セル ✓
- 不変条件3: 各エラーの message を見るテストが `mod tests` にある ✓
- 不変条件4: F0 ✓ / F6 ✓。実物との関係はコンパイル時 assert が見るので、
  上限を実物へ近づけるとビルドが止まる ✓

## 埋まっていないセル

- **(S2, E0) / (S2, E3)**: 局面を読んでいる最中の空行と `#` 注記。実装上は
  S1 と同じ読み飛ばしだが、テストは S0 / S1 側しか踏んでいない
- **F6 の上限そのもの**: `MAX_MOVES` の境界は `parse_limited` に小さい上限を
  渡して見ている。**本物の 2,000 万手では一度も走らせていない**（2,000 万行の
  入力を組むテストは1本で 33 秒かかったので分けた）
- **F0 の上限そのもの**: `sfen ` 行だけのファイル（指し手0手）で F0 に当たる
  経路を踏むテストが無い。**F6 は `total_moves` しか数えないので、この形では
  一度も走らない**

## この表を消さないこと

**空のセルを消すと「表を作った」だけで安心してしまう。**
実装上は同じ経路に落ちるものも、テストが踏んでいなければ空のまま残す。

# やねうら王テキスト定跡 (.db) の読み取り

`src-tauri/src/book/yaneuraou_db.rs` の `parse`。

**この表は仕様の突き合わせのために置く。** 所見が「その形式は実際どう書かれて
いるか」ばかりになったら、1件ずつ潰しても次の綴りに置いていかれる合図。
行の種類を先に列挙し、**どの状態でその種類が来たらどうなるか**を全部書く。

## 状態

| 記号 | 判定条件（式）                          | 意味                             |
| ---- | --------------------------------------- | -------------------------------- |
| S0   | `header.is_none()`                      | 見出しをまだ見ていない           |
| S1   | `header.is_some() && current.is_none()` | 見出し済み、局面をまだ見ていない |
| S2   | `header.is_some() && current.is_some()` | 局面を読んでいる最中             |

`buffered` は S2 でしか非空にならない（S1 で指し手行はエラーになる）。
`flush` の早期 return はこの不変条件に依存している。

## 遷移表

`✓` はそのセルを踏むテストがある。

|                         | S0（見出し前）                | S1（局面なし）                          | S2（局面あり）                            |
| ----------------------- | ----------------------------- | --------------------------------------- | ----------------------------------------- |
| **E0** 空行             | 読み飛ばす ✓                  | 読み飛ばす ✓                            | 読み飛ばす ✓                              |
| **E1** 見出し           | → S1 ✓                        | 読み飛ばす ✓（2度目は注記と同じ）       | 読み飛ばす ✓                              |
| **E2** `# NOE:`         | 読み飛ばし、値を覚える ✓      | 同左 ✓                                  | 同左 ✓                                    |
| **E3** `#` 注記         | 読み飛ばす ✓                  | 読み飛ばす ✓                            | 読み飛ばす ✓                              |
| **E4** `//` 注記        | 読み飛ばす ✓                  | 読み飛ばす ✓                            | 読み飛ばす ✓                              |
| **E5** `sfen `          | 暗黙の見出しとして → S2 ✓     | → S2 ✓                                  | flush して → S2 ✓                         |
| **E6** 指し手なしの綴り | `InvalidContent`「読めない」✓ | `InvalidContent`「局面より先に指し手」✓ | 読み飛ばす（局面は数える）✓               |
| **E7** 指し手           | `InvalidContent`「読めない」✓ | `InvalidContent`「局面より先に指し手」✓ | 候補手に足す ✓                            |
| **E8** 形を満たさない   | `InvalidContent`「読めない」✓ | `InvalidContent`「局面より先に指し手」✓ | `InvalidContent`「指し手として読めない」✓ |
| **E9** EOF              | `InvalidContent`「空」✓       | flush → 申告の突き合わせ ✓              | flush → 申告の突き合わせ ✓                |

**E5 はさらに2つに割れる。** `sfen ` の後ろが `BookKey` の検査に落ちたら、
どの状態でも `InvalidContent`（行番号付き、**ファイル全体を拒否**）✓。

**F7 は拒否に使わない。** 本家は末尾の改行を要求しない（`book.cpp:705`）ので、
改行が無いだけの完全な定跡を拒否すると不変条件1と3を同時に破る。逆に、行境界で
ちょうど切れたファイルは素通りする（行単位で書き出す生成器が止まった場合は
**必ず**行境界で終わるので、その経路は 100% 検出できない）。切れの検出は F4 だけが担う。

**S0 で E6 / E7 / E8 が落ちるのは意図。** 別形式のファイルに `.db` を付けただけの
ものを「0局面の定跡」として開かないため（空の定跡と見分けが付かなくなる）。
その代わり **S0 でも E5 と注記（E2 / E3 / E4）と空行は通す**。本家は見出しを
検査しないし、見出しの無い `.db` は実在する。拒否すると、正しい定跡に対して
「別の形式のファイルかもしれない」と言いながら、引用する行は誰が見ても
やねうら王の局面行、という自己矛盾した案内になる。

**S0 の E5 で読んだ行は捨てないこと。** 読み直せないので、捨てると見出しの無い
定跡だけ先頭の1局面が消える。

## ファイル全体に掛かる検査

行の種類とは別に掛かる。**掛かる時点が3つに分かれる。**

- 読む前: F0（1バイトも読まずに落とす）
- 読んでいる最中: F1 / F2 / F3 / **F6** / **F8**（`sfen` 行と指し手行の2箇所で走る。
  読み切る前に止めることが上限の意味なので、最後に1回へまとめてはいけない）
- 読んだ後: F4 / F5 / F7

| 記号 | 判定条件                                                                                  | 結果                                                                                 |
| ---- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| F0   | `size > MAX_FILE_BYTES`                                                                   | `TooLarge` ✓                                                                         |
| F1   | `str::from_utf8` が失敗し、空白を飛ばした先頭が `#` / `//` でない                         | `InvalidContent`「N行目に文字として読めないバイトがある」✓                           |
| F2   | 先頭3バイトが BOM                                                                         | 落として読み進む ✓                                                                   |
| F3   | 行末が `\r` / `\n`                                                                        | 落とす ✓                                                                             |
| F4   | `declared.is_some() && sfen_lines < declared`                                             | `InvalidContent`「途中で切れている」✓                                                |
| F5   | `positions.is_empty()`                                                                    | `InvalidContent`「局面が1つも無い」✓                                                 |
| F6   | `held_positions * BYTES_PER_POSITION + total_moves * BYTES_PER_MOVE > MAX_EXPANDED_BYTES` | `TooLarge`「展開すると大きすぎて開けない」✓                                          |
| F7   | `!last_line_terminated`                                                                   | `log::warn!` のみ。**拒否しない** ✓                                                  |
| F8   | `take` で切った1行が `MAX_LINE_BYTES`（4 KiB）を超え、改行が来ない                        | **注記なら**残りを捨てて読み進む ✓ / それ以外は `InvalidContent`「N行目が長すぎる」✓ |

**F5 を `declared` の側にぶら下げてはいけない。** `# NOE:0` と書いた 31 バイトの
ファイルが `sfen_lines < 0` を通り抜けて「0局面の定跡」として成功する。

**F4 は `positions.len()` と比べてはいけない。** NOE は `sfen ` 行の本数で、
`positions` は正規化して重複を畳んだ後のキー数。畳んだ後と比べると、
持駒の綴りが揺れているだけの正常な定跡が「途中で切れている。取得し直すこと」で
拒否される（何度取得し直しても直らない案内になる）。

## 不変条件

1. **本家が読める定跡は、こちらでも読める。**

   **本家は中身では一度も失敗しない。** `#` / `//` を捨て、`sfen ` 行を検証せず
   キーにし、それ以外を `BookMove::from_string`（失敗しない）へ渡し、局面より先の
   指し手は黙って捨てる（`book.cpp:751-752`）。つまり「本家が読める」＝
   「`sfen ` 行が1本でもあるファイル全部」なので、**こちらの中身由来の拒否は
   すべて本家との差**になる。差は次の7つ。それぞれ理由を持つこと。

   | 差                                | なぜ拒否側に倒すか                                                                                                      |
   | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
   | (S1, E6/E7/E8) 局面より先の指し手 | 本家は読み飛ばす。黙って捨てると、途中で切れたファイルが「その手だけ引けない定跡」として開く                            |
   | (S0, E6/E7/E8) 局面も見出しも無い | 別形式のファイルが「0局面の定跡」として開けると、空の定跡と見分けが付かない                                             |
   | `sfen ` 行が `BookKey` に落ちる   | 本家はその1件だけ引けなくなる。こちらは**ファイル全体**を拒否する。壊れた局面行があるファイルは他の行も信用できないため |
   | F1 注記でない行の非 UTF-8         | 綴りを復元できない。読み進めても候補手が壊れる                                                                          |
   | F8 注記でない 4 KiB 超の行        | 確保の上限（不変条件4）。注記なら読み捨てて進む                                                                         |
   | F4 申告との不一致                 | 途中で切れたファイルを黙って開くと、利用者は「この局面は定跡に無い」と読む                                              |
   | F0 ファイルが大きすぎる           | 確保の上限（不変条件4）                                                                                                 |

   **見出しの有無は差にしない。** 見出しの無い `.db` は実在する（ShogiHome は
   `yaneuraou-no-header.db` を開ける側の回帰 fixture に置いている）。
   注記・空行・綴りの揺れでも拒否しない

2. **`lookup` が返す `usi_move` は、`ABSENT_MOVE` でない短い ASCII の綴りだけ。**
   紛れ込んだ日本語・HTML・長いテキストと、`sfen` は候補手にならない。

   **盤に適用できることは保証しない。** `looks_like_a_move` が見るのは形だけなので、
   `+` / `*` / `0` / `win` のような綴りは通る（1行だけの定跡を作ると、それが
   候補手の先頭＝best move の位置に返る）。綴りの文法まで狭めると、こちらが
   知らない綴りを使った定跡をファイルごと拒否することになり、不変条件1と衝突する。
   **`usi_move` を盤へ渡す側は、ここを通ったことを検査済みと読まないこと**（#311）

3. **失敗の message は必ず「次に何をすればよいか」で終わる。**
   ファイルが正しいのに拒否する経路を作らない（効かない復帰操作になる）
4. **確保は3つの上限で有界。** ファイルの大きさ（F0）、1行の長さ（F8）、
   展開後のバイトの見積もり（F6）。**どれが欠けても穴が空く。**
   - ファイルサイズだけだと、1字の指し手行で埋めたファイルが通り抜ける
   - **F8 が無いと、改行を1つも含まないファイルの1行ぶんが上限の外になる**
     （F6 は行を受理した後にしか走らない。実測でピーク 4.32 GB）
   - **F6 は局面と指し手の両方を数える。** どちらか片方しか数えないと、
     もう片方だけのファイル（`sfen ` 行だけ / 指し手だけ）が素通りする

## 照合

- 不変条件1: E3 / E4 の S0 セルと、綴りの揺れを含む定跡が F4 で落ちないこと ✓
- 不変条件2: E6 の S2 セル ✓（`resign` / `none` が候補手にならない）、E8 の S2 セル ✓
- 不変条件3: 各エラーの message を見るテストが `mod tests` にある ✓
- 不変条件4: F0 ✓ / F6 ✓ / F8 ✓。実物との関係はコンパイル時 assert が見るので、
  上限を実物へ近づけると `cargo test` が止まる ✓（assert は `mod tests` の中に
  あるので、`cargo build` では走らない）

## 埋まっていないセル

- **F6 の本物の境界**: `parse_limited` に小さい上限を渡して見ている。
  **`MAX_EXPANDED_BYTES` そのものでは一度も走らせていない**（その大きさの
  入力を組むテストは現実的でない）。F0 は `load` に大きさを引数で渡す形なので、
  `MAX_FILE_BYTES` ちょうどと +1 の両方を踏めている
- **単価（`BYTES_PER_POSITION` / `BYTES_PER_MOVE`）が実測と合っているか**:
  機械では守れない。合わなくなると、上限が名目値と実メモリでずれる

## この表を消さないこと

**空のセルを消すと「表を作った」だけで安心してしまう。**
実装上は同じ経路に落ちるものも、テストが踏んでいなければ空のまま残す。

# 状態遷移表: エンジンの状態（画面の語）

**これから満たす表。** 仕様は [`engine-standardization.md`](../spec/features/engine-standardization.md)。
いまの実装の表は [engine.md](engine.md)（プロセスの生死）と [analysis.md](analysis.md)（検討の席）で、
ここはその2つを**利用者が見る1つの語**へ畳んだもの。**実装の途中。** どのセルが入ったかは末尾の「検証済みのセル」。
語の判定は `entities/analysis/lib/engineStatus.ts`。

対局（`start_game`）はこの表の外。

## 状態（画面）

| 記号 | 操作列の語     | 判定                                                         |
| ---- | -------------- | ------------------------------------------------------------ |
| V0   | `エンジンなし` | `desiredRuntime === null`                                    |
| V1   | `起動中…`      | `phase === "initializing"`、または再起動の窓※0           |
| V2   | `待機中`       | 起動済み、検討の意思なし、探索していない                     |
| V3   | `検討中`       | 起動済み、検討の意思あり、探索中か局面の切り替え中           |
| V4   | `検討中`（語を変えない） | ■ か E14 の `stop` を送り、`bestmove` を待っている。■ は押せない |
| V5   | `検討完了`     | 検討の意思あり、エンジンが `bestmove` を返し、局面が同じ     |
| V6   | `応答なし`     | `stop` の待ちが `ANALYSIS_STOP_GRACE` を超えた、または書けない |
| V7   | `エンジン終了` | 起動済みのプロセスが終わった。こちらから落としていない       |
| V8   | `起動失敗`／`起動を中止しました` | `phase === "error"`。後の語は `cancelled` のときだけ    |

**検討の意思**は ▶ で立つ。下りるのは ■、選択が外れる（E2）、棋譜を閉じる（E14。**どの状態でも**）、「起動を中止する」（E7）、
自動の読み直しの失敗（E16）の5つだけ。設定の変更でも、起動の失敗でも、エンジン終了でも下りない。
再起動を跨いで残るので、戻ったエンジンが同じ局面を読み直す。**アプリに1つで、棋譜ごとには持たない。保存しない。**

※0 再起動の窓は E1 / E13 から新しい起動の結果（E5 / E6）まで。**窓の間に届く古いプロセスの E10 / E12 / E15 は捨てる**
（世代。[engine.md](engine.md) の ※1）。V1 の行の E12 / E15 は新しいプロセスのもの。

### 注

※1 ▶ を起動中に押したら断らずに受け、ボタンは ■ に変わる（押すと意思が下りる）。
`ENGINE_STARTING_MESSAGE` を出して押し直させるのをやめる。**表を埋めて出てきた論点。** 断る形だと、起動を待つ利用者が2回押すことになる。

※2 利用者には切り替わりを見せない。局面が続けて動けば最新の局面だけを読む（[engine-position-sync.md](engine-position-sync.md)）。
`stop` の答えを待たずに `go` を出す経路は持たない。上限を超えたら `EngineAnalyzer::unanswered` が立ち、
下りるまで `set_position` と `start_infinite_analysis` は断る。

※3 遅れて答えが来たらエンジンは生きていたので、V6 を抜ける。意思があれば V3 へ、無ければ V2 へ。

※4 **`quit` を待たずに落とす。** P5 は `quit` に答えないことを実測で確かめてある。
意思は残るので、戻れば読み直す。

※5 「もう一度起動」を出さない種類がある（`ENGINE_START_FAILURE_NOTICES` の `retry`）。その種類は「設定を開く」だけ。
意思は残るので、成功すれば読み始める。V1 の行の E12 / E15 の種類は `asStartFailure` が決める（既存）。

※6 **[analysis.md](analysis.md) の ※15 の枝の行き先。** ▶ の失敗は別の状態を作らず、`待機中` のまま帯に文を出す。

来なければ `quit` を待たずに落として進む。**

## この表が満たすべき不変条件

1. **`検討中` の語が出ている間、エンジンは探索中か、止め待ちの上限の内にある。** 終了したエンジンの前に `検討中` を出さない（#502 #356）
2. **探索中のエンジンに `position` と `go` を送らない。** 破ると P5 に落ちる
3. **どの状態にも抜ける操作がある。** V1 は設定の変更と、`SLOW_START_MS` の後の「起動を中止する」、V6 / V7 / V8 は操作列のボタン（#252 #172）
4. **表にある候補手は、盤の局面のもの。** エンジンが止まる前のものは薄く出す（#502）
5. **検討の意思があってエンジンが戻ったら、利用者が押さなくても読み始める。** 戻らなければ V6 / V7 / V8 の語が残る（#442）

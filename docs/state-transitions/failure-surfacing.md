## 3. 軸に落とす

F と G を「次の操作」×「残るか」で置くと、埋まるセルはこれだけ。

|                              | 消えてよい                 | 見るまで残る              | 操作するまで残る                  |
| ---------------------------- | -------------------------- | ------------------------- | --------------------------------- |
| **伝えるだけ**               | F-13, F-15, F-16(出さない) | F-11, F-17, G-9           | —                                 |
| **入力が悪い**               | —                          | —                         | F-14, G-2, G-4                    |
| **再試行すれば直るかも**     | —                          | F-6, F-10, F-12, G-5, G-8 | —                                 |
| **設定を変えないと直らない** | —                          | —                         | F-9, G-1, G-6, G-7                |
| **機能が死んだ／復帰不能**   | —                          | —                         | F-1, F-3, F-4, F-5, F-7, F-8, G-3 |

**行は5つ。** 列の「消えてよい」と「見るまで残る」は、
**同じ種類の強度違い**として畳める可能性がある。

## 4. 分類が決まる前でも言えること

分類に依存しないので、決定を待たずに直せる。

- **F-16 は通知にしてはいけない。** 意図的なベストエフォートなので、`console.error` をやめる方が正しい
- **F-14 は通知基盤の外。** 入力欄のインラインで、`ConflictDialog`（G-2）と同じ形
- **F-5 の unhandled rejection は、分類が何であれバグ。** issue #85 は preset 切替の
  進捗表示と再初期化の抑止が主題で、**保存の失敗はそこに入っていない**
- **F-3 の「ツリーが消える」も、分類が何であれバグ**。エラー表示の有無以前の問題

## 5. Q-005 で決めること

1. **種類は5つでよいか。** 畳めるとしたらどれとどれか
   - 「伝えるだけ」と「再試行すれば直るかも」の差は**再試行ボタンの有無だけ**
   - 「入力が悪い」は通知でなくインライン表示（§4）。**種類から外すか**
2. **意味色は何段要るか。** 種類が5でも色が5とは限らない
3. **`error` の置き場が6つある件（§1）は、分類が決まれば自動で埋まるか。**
   それとも「1つの出口に集める」ことを先に決めるか
4. **F-16 のような「意図的に出さない」を種類として明示的に持つか**

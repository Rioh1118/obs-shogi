# 失敗がどこへ出るか（横断表）

**どの失敗がどこへ出るかの台帳。** L0〜L2 のどの表からも参照される。
**ここが採番するのは `F-N`（ハイフンつき）だけ。**

**記号は表ごとに閉じている。採番を1箇所に集める規約は無い。**
`S` / `E` / `A` / `G` / `P` はどれも複数の表が別の意味で使っている。
**どれとどれが衝突しているかをここに数え上げない** —— 表が増えるたびに腐るし、
数え落とすと「他には無い」と読まれる。

だから**記号だけで書かない。** どの表かを添えること。
**1つの表の記号しか出てこないファイルは、module doc に表を1行書けば個別の注記では省いてよい**
（`session.rs` / `yaneuraou_db/expand.rs` がその形）。散らばるなら1つずつ添える。
**`F-N` はこの数に入れない** —— `docs/` と `src/` `src-tauri/src/` の中では採番がここ1箇所なので、
指し先が割れない。**`.claude/reviews/` は別**で、各報告書が自前で所見番号を採る
（台帳の `F-13` と `book-foundation-r1` の `F-13` は無関係）。
**`.claude/reviews/` の書き方をここで規定しない** —— この台帳が持つのは失敗の現在地で、
報告書どうしの引き方ではない。書いても現物に届かず、規約だけが偽になる。
`game-session.md` の `A3` と `app.md` の `A3` は別物で、しかも前者は
「上位は `app.md`」と書いて後者を指している —— **親子を宣言した2表の間でも重なる。**
`F-1` と `F1` のように、ハイフンの有無しか違わない対もある。

分類そのものは **ADR-0004 で決着済み**（段は「復帰に何が要るか」で4つ）。
ここが持つのは分類ではなく、**個々の失敗の現在地**。

**推測でなく現物から。** 初回の棚卸しは 2026-08-29、`main` `bb29884` の実測。
以降は失敗を直すたびに該当行を書き換える。**直したのに行が古いままなら、
この表は台帳として嘘をつく。**

**行を足したときも既存の行を書き換えたときも**、その記述の末尾に
`（測定日 / 測定したブランチかコミット）` を添える。
**ブランチ名で書くならワークツリーの branch を実際に読むこと**——
同じリポジトリの別のワークツリーが別の branch に居るので、
手元の記憶で書くと**その作業を含まないブランチ**を名乗ることになる。
迷ったらコミットハッシュで書く。

## 3. 段への割り当て

段は ADR-0004 が決めた4つ（`info` / `warning` / `danger` / `fatal`）。
どの F がどの段かは **ADR-0004 の「割り当て」節**が持つ。ここで二重に持たない
（2箇所に置くと、片方だけ直る）。

**例外は F-3。** ファイル操作の失敗は1つの段に収まらず、`code` ごとに
`warning` と `danger` に割れる。対応を持っているのは
`fsErrorTier`（`src/entities/file-tree/api/error.ts`）。ADR-0004 の表は
F-3 を1行で書いているので、そこだけでは `danger` の存在に気づけない。

**F-13 も1行要る。** 「次の操作: 要る（場所を確かめる）」は、ADR-0004 の割り当てと
衝突して見える。衝突しない理由は `revealFailureNotice`
（`src/features/settings/ui/tabs/AiLibraryTab.tsx`）の doc が持つ。
**段は ADR-0004、理由はコード。ここには持たない。**
F-37（`staleCreateNotice`）も理由は同じファイルの doc が持つが、**段は ADR-0004 に無い**
（F-19 以降なので）。段は §2 のこの表の行が持つ。

ADR-0004 が使う `F-12a` / `F-12b` は、**採番元がここ**。段が分かれる
（保存は `warning`、操作は `danger`）ので §2 でも2行にしてある。

**ADR-0004 の割り当ては 2026-08-29 の棚卸しに載っていた失敗の分。**
それより後に採番した行（F-19 以降）の段は §2 の「いま起きること」に書く
（凡例にも書いた）。ADR は決定の記録なので、あとから見つけた失敗を足すために
書き換えない。**F-19〜F-31 は段が書かれていない**——出口が無い行（§4）なので、
出口を作るときに段を決めることになる。

※5 F-12a のうち出口があるのは**2つ**。`entities/game` の書き換え操作
（`makeMove` / `swapBranches` / `deleteBranch` / `setCommentsByCursor` / `setCurrentComments`）が
`AsyncResult` を返すようになり、それを読んでいる2箇所が出す。

- **コメントの保存** — `KifuCommentNote` がノートの中に出す。書けていないので
  `baseText` を進めず、下書きは画面に残る。**閉じると失われる**。
  面をまたいで預かる形は → #314

  **ただし出るのは、ノート自身の閉じる操作（× / Escape / Cmd+Enter）を通ったときだけ。**
  分岐メニュー・手のメニュー・別の手のコメント・棋譜の差し替え・一覧ごとの unmount では、
  `KifuStreamList` が閉じる手続きを通らずにノートを外すので、そのあとに返った失敗は
  **本文もろとも無通知で消える**（5経路のうち塞がっているのは1つ）→ #315

- **分岐の削除** — `KifuStreamList` の `confirmDelete` が確認ダイアログの中に出す。
  **失敗したあとは実行ボタンを押せなくする**（押した時点の指定を撃ち直すので、
  失敗の間にメモリ側の棋譜が変わっていると別のものを指す）。閉じて選び直せば
  そのときの棋譜に対して指定が組み直される

**盤で1手指したときと分岐の入れ替えの保存の失敗は、依然としてどこにも出ない**
（`async-result-ignored` の印がある）。出口を作るのは #277。

## 4. まだ出口が無いもの

**抽出条件: §2 の「いま起きること」が `console.error` だけ / state に載るが読み手0 /
何も出ない、のいずれか。** 「復帰導線」の列ではない（そこに何か書いてあっても、
出口が無ければ利用者はその導線に辿り着けない）。

issue になっているもの:

| #    | issue | 内容                                                                       |
| ---- | ----- | -------------------------------------------------------------------------- |
| F-5  | #170  | プリセット保存の失敗が黙ってデータを捨てる                                 |
| F-9  | #171  | エンジン初期化に失敗すると復帰できない                                     |

まだ issue になっていないもの:

**F-1 / F-2 / F-4 / F-6 / F-8 / F-10 / F-11 / F-12b / F-18** と、
**F-19 〜 F-30**。

**後半は番号を写さない。** ここから先は Rust の経路が増えるたびに伸びるので、
1本ずつ並べると行を足すたびに写しを数え直す口が要る。**数を書かないのと同じ理由。**

**Rust 側の経路（F-19〜F-30 / F-33〜F-36）は出口が1つも無い**（2026-09-03 / `worktree-wt-game-engine`）。
フロント側の UI がまだ無いので、Rust の経路だけが先に増えた ——
対局とエンジン（F-19〜F-30）に加えて**定跡（F-33〜F-36）も同じ状態**。
UI を作るときは、それらの行を先に読むこと。**数はここに書かない**——
Rust 側の経路が増えるたびにずれる。

とくに **F-27 は対局まわりで最も起きやすい失敗**なのに、Rust の経路が増えた
という理由だけで後から足された。**「始められなかった」を落とすと、
エンジンのパスを選び直す導線そのものが設計から抜ける。**

とくに **F-19 は失敗が別の失敗として説明される**。`emit` が失敗すると
`MoveDecided` が届かず、フロントは裁定を返しようがないのに、`RULING_TIMEOUT` 後の `detail` は
「アプリが裁定を返さなかった」と書く。原因は Rust 側の送信失敗で、
利用者に届くのは「対局が中断されました」だけ。`Aborted` を型で割る件は #362。

F-12a は**コメントの保存と分岐の削除**に出口がある（§2 の ※5）。
盤で1手指したときと分岐の入れ替えの保存の失敗は残る。
issue は #227 / #200 と、出口をまとめて作る #277。

F-8（エンジン停止の失敗＝プロセスが残りうる）は ADR-0004 で `fatal` に
割り当てられている。F-6 と F-8 は「復帰導線」の列に何か書いてあるので、
条件を列で引くと落ちる。

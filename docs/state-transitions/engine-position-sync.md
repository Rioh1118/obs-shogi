# 状態遷移表: engine-position-sync

対象: `src/features/engine-position-sync/model/useEnginePositionSync.ts`

テスト項目を設計する前にこの表を埋める。**空のセルが、そのまま未検証の経路**になる。

## なぜこの形式か

issue #120 のレビュー3ラウンドで見つかった不具合は、**すべて (状態 × イベント) の1セル**だった。
どれも「その状態でそのイベントが起きたらどうなるか」を列挙していなかったために入っている。
テストケースを思いついた順に足すやり方では、思いつかなかったセルが残り続ける。

## 状態

送信に関わる内部状態の組み合わせ。UI から観測できるのは `syncedSfen` だけ。

| 記号   | 状態             | 判定                                                    |
| ------ | ---------------- | ------------------------------------------------------- |
| **S0** | 局面なし         | `currentSfen === null`                                  |
| **S1** | ready 待ち       | `isReady === false`、`pendingBeforeReadyRef` に保留あり |
| **S2** | 同期済み・待機   | `inFlightRef === null`、`syncedSfenRef === currentSfen` |
| **S3** | 送信中           | `inFlightRef !== null`、`queuedSfenRef === null`        |
| **S4** | 送信中・次が待機 | `inFlightRef !== null`、`queuedSfenRef !== null`        |

## イベント

| 記号   | イベント             | 発生源                                                       |
| ------ | -------------------- | ------------------------------------------------------------ |
| **E1** | 局面が変わる         | 盤操作・棋譜ナビ（`gameState.cursor`）                       |
| **E2** | エンジンが切り替わる | プリセット選択・更新（`engineKey`）                          |
| **E3** | ready になる         | `isReady` false→true。**engineKey が変わらない再起動を含む** |
| **E4** | ready でなくなる     | `isReady` true→false                                         |
| **E5** | 棋譜を閉じる         | `gameState.cursor === null`                                  |
| **E6** | 送信が成功する       | `setPositionFromSfen` の resolve                             |
| **E7** | 送信が失敗する       | `setPositionFromSfen` の reject                              |
| **E8** | 手動で呼ばれる       | `startInfiniteAnalysis` からの `syncPosition()`              |

## 表

`T` は固定しているテスト（`src/features/engine-position-sync/model/__tests__/useEnginePositionSync.test.tsx`）。
`—` はそのイベントがその状態で起きないか、状態が変わらないことが自明なもの。

|        | E1 局面変化      | E2 エンジン切替            | E3 ready                   | E4 not ready | E5 棋譜を閉じる    | E6 成功              | E7 失敗            |
| ------ | ---------------- | -------------------------- | -------------------------- | ------------ | ------------------ | -------------------- | ------------------ |
| **S0** | → S2/S3 送る     | 記録を捨てる               | —                          | —            | —                  | —                    | —                  |
| **S1** | 保留を更新 **T** | 記録を捨てる               | 現在局面を送る **T**       | —            | 保留を捨てる       | —                    | —                  |
| **S2** | → S3 送る **T**  | 記録を捨てて送り直す       | 記録を捨てて送り直す **T** | → S1         | 記録を捨てる       | —                    | —                  |
| **S3** | → S4 積む        | 世代を上げる **T**         | 記録を捨てる               | → S1         | 世代を上げる **T** | 書き戻す             | reject **T**       |
| **S4** | 最新で上書き     | 世代を上げてキューを捨てる | 記録を捨てる               | → S1         | 世代を上げる       | 書き戻して次へ **T** | 次を捨てない **T** |

### この表が満たすべき不変条件

1. **`syncedSfen` が非 null なら、その SFEN は現在のエンジンに実際に送れている。**
   世代ガードはこれを守るためにある。
2. **キューに積まれた局面は、必ずいつか送られるか、より新しい局面に置き換わる。**
   どのセルでもキューを黙って捨てない。
3. **記録を捨てる操作は必ず世代を上げる**（`invalidateSynced` に畳んである）。
   上げ忘れると 1 が破れる。

## 埋まっていないセル（既知）

- `(S3, E4)` / `(S4, E4)` 送信中に ready でなくなる
- `(S4, E2)` 次が積まれた状態でのエンジン切替
- `(S3, E8)` 送信中の手動呼び出しが同じ promise を返すこと

いずれも実装上は同じ経路に落ちるが、**テストは無い**。

## 外部の状態を忘れないこと

この表はフロントエンドの状態だけを扱う。**エンジンのプロセスは別の状態機械**であり、
そちらを列に入れ忘れたことが issue #120 のラウンド3で BLOCK になった
（React の `isAnalyzing` を落としても Rust の席が残り、以降の解析開始が
永久に弾かれた）。解析側の表を書くときは Rust のセッション状態を必ず列に入れる。

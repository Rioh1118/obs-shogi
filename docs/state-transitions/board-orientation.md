# 状態遷移表: 盤の向き（L2）

対象: `src/features/board-orientation/`。上位は [app.md](app.md)。
**合図（`loadedAbsPath` と `boardSeq`）の出どころは [game.md](game.md)**、
イベント（E2 / E4 / E5 / E6 / E7）の出どころは [file-tree.md](file-tree.md)。

読む側（`useBoardOrientation`）は盤の中に載る（`src/widgets/game-board/ui/GameBoard.tsx`）。
落とす側（`useResetOrientationOnKifuChange`）は盤より上
（`src/app/providers/bridges/BoardOrientationBridge.tsx`）。**なぜ上なのかはその doc。**

盤の向きは `?pov` 1つで決まる。表がこれだけのために在るのは、
**向きを戻す合図の選び方を間違えると、失敗も出さずに盤が回る**から。

## この表の軸

`pov` の値そのものではなく、**`pov` を落とす判断が何を見ているか**が軸。

「その棋譜を見ている」に見えるフィールドが4つあり、**どれも単独ではずれる。**

| フィールド            | 持ち主    | 意味                           | 動く条件                                                         |
| --------------------- | --------- | ------------------------------ | ---------------------------------------------------------------- |
| `state.loadedAbsPath` | game      | **盤に載っている棋譜**         | `game_loaded` / `reset_state` / 改名の張り替え（`path_renamed`） |
| `state.boardSeq`      | game      | **盤の中身が入れ替わった回数** | `game_loaded` と `reset_state`。単調増加で戻らない               |
| `activeKifuPath`      | file-tree | ツリーが開いたと言っているパス | `kifu_opened` / `kifu_closed` / 改名の張り替え                   |
| `selectedNode`        | file-tree | ツリーで選択されている行       | クリック即時。失敗すると巻き戻る                                 |

下2つは**盤の中身ではない。** `openKifuNode` は構文として読めれば `kifu_opened` を出すが、
盤に載せられない `initial` を持つ棋譜はその先の `loadGame` で落ちる（E9）。
そのとき `activeKifuPath` は動くのに盤は前の棋譜のまま。`selectedNode` はさらに手前で、
読み込みに失敗すると巻き戻る（E5）。

**合図に選ぶのは `loadedAbsPath` と `boardSeq` の組。** パス1つでは足りない——
改名・移動でもパスは動くが（`path_renamed`）、そこで変わったのは名前だけで
盤に並んでいる駒は同じなので、向きも同じままでよい。盤の中身が入れ替わったかを持つのは
`boardSeq` だけで、`path_renamed` では進まない。

## 状態

`記録` は `shownKifuRef.current`（パスと回数の組）の略。
`追いついた` は `記録.path === loadedAbsPath && 記録.seq === boardSeq` の略。

| 記号   | 状態         | 判定                                                                       |
| ------ | ------------ | -------------------------------------------------------------------------- |
| **B0** | 盤に何も無い | `追いついた` かつ `loadedAbsPath === null`※1                               |
| **B1** | 先手が手前   | `追いついた` かつ `loadedAbsPath !== null` かつ `params.pov === undefined` |
| **B2** | 後手が手前   | `追いついた` かつ `loadedAbsPath !== null` かつ `params.pov === "gote"`    |
| **B3** | 記録が古い   | `追いついた` でない                                                        |

**4つは排他。** B0〜B2 はどれも記録が追いついていることを要求するので、
B3 と重ならない。**記録の条件を落とすと、棋譜が載った
直後のレンダが B1 と B3 の両方を満たし、表が同じ観測に2つの結末を言うことになる**
（`(B1, E3)` は「→ B2」、B3 の行は「—」）。

**B3 はレンダとエフェクトの間にしか無い。** 合図が変わったレンダでは
まだ ref が前の値を持っていて、その差でリセットするかどうかが決まる。
エフェクトが走り終われば必ず B0〜B2 のどれかに落ちる。**B3 が残ったら不変条件3の破れ。**

## 表

`×` はそのイベントがその状態では**起きない**もの（注で根拠を書く）。
`—` は**起きるが状態が変わらない**もの。分けてあるのは、`—` は退行しうるが
`×` は退行しようが無いから。

**機械が要求するのは遷移（`→`）を書いたセルだけ**——✓ を持つか「埋まっていないセル」に
挙げるかのどちらか（`src/__tests__/stateTransitionCells.test.ts`）。
`—` のセルは ✓ の有無だけを見る。`—` で ✓ が無いセルは**誰も見ていない**が、一覧には
挙げていない（19セルあり、挙げると一覧が「実装が疑わしい経路」を指さなくなる）。
`✓` は踏むテストがあるセル
（`src/features/board-orientation/model/__tests__/useBoardOrientation.test.tsx`）。

**E4 / E5 / E9 の ✓ は還元した形を踏んでいる。** この feature は file-tree を読まないので、
「ツリーの選択だけが動く」「選択が巻き戻る」「開いたが盤に載らない」の3つは、
**どれも `loadedAbsPath` が動かない再描画**に潰れて互いに区別が付かない。テストは

### 注

※1 **B0 は `activeKifuPath` が非 null でも成立する。** 判定に入れているのは
`loadedAbsPath` だけ。E9（開いたが盤に載せられず落ちる）の後は、ツリーが壊れた棋譜を
掴んだまま盤が空という B0 になる。**その B0 では E2 / E6 / E7 が踏める**ので、
B0 の行でそれらを `×` にしてはいけない。

**B0 の E6 では、どちらの関門も塞がない**（※7）。クリックは `openKifuNode` まで届き、
また載せられなければ E9 になる。向きは B0 のまま動かないので `—` で正しいが、
**理由は「関門が飲み込むから」ではない**。

※2 **「閉じる」ボタンは無い。** `closeActiveKifu` は公開されているがスライス外の
呼び出し元が0で、E2 を踏めるのは上の3つだけ。**それでも E2 は実在する**ので、
落とすと `BoardOrientationBridge` を盤の外に置く理由（盤ごと unmount すると
落とす者が居なくなる）が読めなくなる。

※3 **B0 ではボタンが描かれない。** 向きを付ける口は `AnalysisPaneHeader` だけで、
それを含む `AnalysisPane` は `AppLayout` が `gameView.hasKifu` の真の枝でしか描かない。
盤に何も載っていない間は DOM に存在しないので、E3 は起きない。

**それでも B0 で `?pov=gote` になる経路はある。** B2 のままワークスペースを変えると
`window.location.reload()` が走り、`BrowserRouter` はクエリごと復元する。起動時に
棋譜を復元する経路は無いので盤は空で、マウント直後のエフェクトは記録と合致して
空振りするため `pov` が残る。次に棋譜が載るまでこの状態が続く。
（アドレスバーの無い Tauri のウィンドウでは、URL を直接打つ経路は利用者には無い）

※4 **B1 でも E7 は E1 と別物。** 改名では `boardSeq` が動かないので、このフックは
「名前だけが変わった」と読んで記録だけを追いつかせる。`pov` が既定の B1 では
落とすものが無いので結末は E1 と同じに見えるが、**通る枝は違う**——
E1 は `pov` を消しにいき、E7 は消さずに戻る。

※5 **改名・移動では、この feature の外を一周してから合図が動く。** 経路は3段:

1. `active_kifu_reconciled` が `jkfData` を `?? state.jkfData` で持ち越し、
   `activeKifuPath` だけを張り替える（`src/entities/file-tree/model/reducer.ts`）
2. `GameFileTreeBridge` は `jkfData` が前回と同じ参照なら `loadGame` を撃たず、
   `renameLoadedPath` で宛先だけを張り替える（`path_renamed`）
3. `loadedAbsPath` は新しいパスへ動くが、`boardSeq` は進まない
   → 組で見ているので「載せ直していない」と読める

**パス1つを合図にすると、ここで `pov` が落ちる。** 落ちてはいけないのは、
盤に並んでいる駒が同じだから。2 で `loadGame` を撃つ形にすると、
盤・棋譜一覧・カーソルまで開いた時点へ巻き戻る（[game.md](game.md) の E18）。

※6 **B3 で受けたイベントは、B3 の結末を変えない。** B3 はレンダとエフェクトの間だけの状態。
保留されているエフェクトが読むのは**そのエフェクトを登録したレンダで閉じ込めた合図**で、
現在値ではない。React は次のレンダを始める前に保留分を流すので、合図が n 個ぶん進んでいれば
n 回走り、各回が `shownKifuRef` を1段ずつ追いつかせる。**追いついた時点で必ず B0 か B1**
になり、途中でどのイベントを挟んだかに依らない。だから空欄ではなく `—`。

**この比較（記録と、いまの `loadedAbsPath` / `boardSeq`）を「常に最新どうしを
比べているのだから要らない」と読んで落とさないこと。** 落とすと不変条件1が破れ、
E8（`pov` 以外の URL 変更）のたびに `pov` が消える。

※7 **2つの関門は、同じ問い（開き直しを省いてよいか）に別の材料で答えている。**

| 関門                                   | 見るもの                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| `FileNode` の `canSkipReopen`          | `activeKifuPath === node.path && loadedAbsPath === node.path`                              |
| `selectNodeByAbsPath` の `canSkipOpen` | `activeKifuPath === node.path && jkfData !== null` を、呼び出し側が `forceReopen` で覆せる |

**盤（`loadedAbsPath`）を見られるのは呼び出し側だけ**——`entities/file-tree` から
`entities/game` は見えないので、後者は覆す口を持つ形になっている。

**どちらの関門も形式（`kifuFormat`）を見ない。** 改名で拡張子が変わった回は
ツリーが握る形式がずれるが、そこで開き直すと**中身と違う形式でパースされる**——
パーサは投げずに0手の棋譜を返すので、盤が空になったまま成功として載る。
ずれは発生源で直すもの → #507

※8 **同じパスで載り直す回は、E1 ではなく E6。** 関門を抜けたクリックは `game_loaded` を
撃つので `boardSeq` は進むが、パスは動かない。**そこでは `pov` を落とさない**——
向きは棋譜に付くので、同じ棋譜を開き直しても同じ向きでよい。

踏むのは E16 のあとの復帰導線。壊れた棋譜を開くと `activeKifuPath` だけが進んで
盤は前の棋譜のまま残るので、そこで前の棋譜をツリーで選び直すと、`FileNode` の関門
（ツリーと盤の両方を見る）がそのクリックを通し、**`loadedAbsPath` と同じパスで**
`game_loaded` が撃たれる。ここで落とすと、載せられない棋譜を1つ踏むたびに向きが戻る。

## この表が満たすべき不変条件

1. **`pov` が落ちるのは、盤に載っている棋譜が別の棋譜になったときだけ。**
   ツリーの選択・URL の他の変更・再クリック・改名では落ちない。
   「別の棋譜になった」は**パスと `boardSeq` の両方**が動いたこと（※5 / ※8）
2. **`isGotePov` は `params.pov` だけから決まる。** 別に真偽値を持たない。
   持つと URL と盤が食い違ったまま気付けない
3. **B3 はレンダを跨がない。** エフェクトが走れば必ず記録が追いつく。
   跨ぐと「棋譜が変わったのに向きが残る」か「変わっていないのに落ちる」のどちらかになる

## 埋まっていないセル

**無い。** 遷移を書いたセルはすべて ✓ を持つ。

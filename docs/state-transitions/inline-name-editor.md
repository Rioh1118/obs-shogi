# 状態遷移: 名前の入力欄（インライン編集）

対象は `src/widgets/file-tree/ui/InlineNameEditor.tsx`。
ツリーの行の上でそのまま名前を打つ欄で、**新規フォルダ・改名の両方**がここを通る。

確定の判定（何を入力欄に出すか）は `src/entities/file-tree/lib/commitName.ts`。
失敗の行き先そのものは [failure-surfacing.md](./failure-surfacing.md) と
[file-tree.md](./file-tree.md) を参照。ここが扱うのは**入力欄の中だけ**。

## なぜ表にするか

この欄は Enter でも blur でも確定する。加えて「送信中」と「一度落ちた名前」を
`useRef` で覚えていて、その2つが確定するかどうかを決める。
つまり**同じ操作（外をクリック）が、状態と打った内容で5通りに分かれる**
（Escape 由来の取り消し / 送信中の印 / 落ちた名前で閉じる / 空欄・同名で閉じる / 送信）。
表にしないと、埋まっていないセルが「行き止まり」として残る。
実際 E2 の blur は4ラウンドのあいだ空白のままだった。

## 状態

| 記号   | 状態                                       | 見分け方                                        |
| ------ | ------------------------------------------ | ----------------------------------------------- |
| **E0** | 閉じている                                 | 描かれていない（呼び出し側が unmount する）     |
| **E1** | 編集中。失敗なし                           | `error === null`、`inFlight === false`          |
| **E2** | 送信中                                     | `inFlight === true`                             |
| **E3** | 落ちた名前が入ったまま。欄にフォーカスあり | `rejected === draft.trim()`、フォーカスは欄の中 |
| **E4** | 落ちた名前が入ったまま。フォーカスは外     | `rejected === draft.trim()`、フォーカスは欄の外 |

**E4 は許す。ただし焦点で解かない。**

E4 から閉じるには「欄をクリックして戻し、もう一度外を押す」の2手が要る
（Escape は欄の上にしか張っていないので届かない）。これを嫌って確定が返った時点で
`focus()` を呼ぶと、**利用者が移った先から焦点を奪い返す**。確定は click より前の
マイクロタスクで返るので、押した行は開くのにキーボードは改名欄に残り、しかも
入力欄は `onKeyDown` を全て `stopPropagation()` するので Escape が他の受け口にも届かない。
奪い返さないほうが害が小さいので、2手を受け入れる。

打った文字列を捨てないことのほうが優先。E4 で閉じると、直すための入力欄が
直せという知らせに巻き込まれて消える（`isNameInputError` の TSDoc）。

## 事象

| 記号    | 事象                               |
| ------- | ---------------------------------- |
| **X1**  | Enter                              |
| **X2**  | blur（外をクリック / Tab で出る）  |
| **X3**  | Escape                             |
| **X4**  | 文字を打つ                         |
| **X5a** | 確定が返る（成功）                 |
| **X5b** | 確定が返る（名前を直せば通る失敗） |
| **X5c** | 確定が返る（それ以外の失敗）       |

## 遷移

|        | X1 Enter | X2 blur               | X3 Escape | X4 入力 | X5a 成功 | X5b 名前の失敗 | X5c それ以外 |
| ------ | -------- | --------------------- | --------- | ------- | -------- | -------------- | ------------ |
| **E0** | –        | –                     | –         | –       | –        | –              | –            |
| **E1** | → E2※3   | → E2※3                | → E0      | E1      | –        | –              | –            |
| **E2** | 無視     | **無視（E2 のまま）** | → E0      | E2      | → E0     | → E3 / E4※4    | → E0（※1）   |
| **E3** | 無視※2   | → E0                  | → E0      | → E1    | –        | –              | –            |
| **E4** | –        | –（blur は起きない）  | –         | → E3    | –        | –              | –            |

- **E2 の blur**: そこで確定し直さない（`inFlight` が握り潰す）。焦点も動かさない
- **※4**: 欄に焦点が残っていれば E3、外へ出ていれば E4。**どちらも閉じない。**
  欄そのものが無い（呼び出し側が畳んだ）ときだけ `onUnshowable` へ渡して E0 へ落とす。
  判定は `inputRef.current` の有無で、「外に出たか」は見ない
- **※1**: 名前を直しても通らない失敗は provider が通知か衝突の対話へ回し、
  reducer が編集行ごと畳む（`case "error"` / `conflict_opened`）。ここからは E0 に見える
- **※2**: 同じ名前を送り直さない（`rejected`）。送り直すと同じ失敗が出続けて閉じられない
- **※3**: 空欄か `initialName` と同じなら送らずに **E0**。送っても何も変わらない

## 失敗の箱

E3 と E4 で欄の下に出る。**行を押し広げる**（重ねない）。

重ねる形は2つとも成立しなかった。

- 1行に切って全文を `title` に逃がす → `pointer-events: none` の要素は
  ヒットテストの対象外なので、ツールチップは**出ない**。読む手段が画面に無くなる
- `pointer-events` を戻して重ねる → 下の行を覆い、その行が見えないまま押せる

押し広げると失敗のたびに下のノードが1行ぶん下がるが、動くのは
**利用者がいま見ている行の下だけ**で、失敗が消えれば戻る。

## 埋まっていないもの

- IME の変換中に Enter を押した場合。`isComposing` を見ていない（`Modal` は見ている）。**未追跡**

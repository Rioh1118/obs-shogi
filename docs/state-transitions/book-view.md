# 状態遷移表: 定跡ビュー

対象: `src/entities/book/` と `src/widgets/book-view/`、
`src/app/providers/gates/BookPositionGate.tsx`。

置き場の決定は [ADR-0010](../decisions/0010-dock-tabs-and-view-vocabulary.md)
（ドックのタブにする・盤を持たない）。ドックそのものの遷移は
[dock-tabs.md](dock-tabs.md) が持つ。Rust 側で定跡を開く／引くところは
[yaneuraou-db-parse.md](yaneuraou-db-parse.md) と
[book-key-failures.md](book-key-failures.md)。

**この表の難所は1つだけ。引くのは非同期で、盤は待ってくれない。**
局面を進めるたびに引き直しが走り、前の引きはまだ返っていない。

## 状態

**状態は1つの判別共用体（`BookViewState`）が持つ。** 真偽値を並べると、
画面が同時に2つのことを言える —— 引けなかった回に「この局面はこの定跡に
ありません」と断言する形が実際に出ていた。

| 記号   | 状態               | `view.kind`   |
| ------ | ------------------ | ------------- |
| **B0** | 定跡を開いていない | `closed`      |
| **BO** | 開いている最中     | `opening`     |
| **BN** | 盤に局面が無い     | `noPosition`  |
| **B1** | 引いている最中     | `looking`     |
| **B2** | 現局面が定跡にある | `rows`        |
| **B3** | 現局面は定跡に無い | `absent`      |
| **BU** | 引けなかった       | `unavailable` |

**`B3` と `BU` を混ぜない。** どちらも行が0本だが、前者は*定跡の中身についての
事実*で、後者は*何も分かっていない*。定跡ビューを見に来る理由がその事実なので、
取り違えると利用者は自分の定跡を誤って判断する。

**B4（開けなかった）は状態として持たない。** 開けなければ `closed` のままで、
失敗は `error` として帯に出る —— 復帰操作（別の定跡を開く）を踏める画面が
`closed` の画面だから。

**前の局面・前の定跡の行は入らない。** provider は引いた結果に
「どの定跡のどの局面か」を持たせ、両方が現物と揃うまで `looking` を出す。
局面だけで突き合わせると、**開き直しでは局面が動かないので素通りする。**

## イベント

| 記号    | イベント           | 発生源                                                  |
| ------- | ------------------ | ------------------------------------------------------- |
| **V1**  | 定跡を開く         | 操作列／空の画面 → `openBook(path)`                     |
| **V2**  | 閉じる             | 操作列 → `close()`                                      |
| **V3**  | 局面が変わる       | 盤・棋譜ナビ（`currentSfen` が動く）                    |
| **V4**  | 古い引きが届く     | 先に投げた `lookup_book_moves` が、局面が動いた後で返る |
| **V5**  | 辿った結果が届く   | `walk_book_lines` が返る                                |
| **V6**  | 辿るのに失敗する   | 同、`Err`                                               |
| **V7**  | 別のタブへ移る     | ドックのタブ列（**ビューは unmount、provider は残る**） |
| **V8**  | 棋譜が盤から降りる | `currentSfen === null` になる                           |
| **V9**  | 並べ替える         | 表の見出しを押す                                        |
| **V10** | 引くのに失敗する   | `lookup_book_moves` が `Err`                            |

## 表

印の意味。

- **✓** —— 踏むテストがある。**変異を当てて落ちることを確かめてある**
- **✗** —— 踏むテストが無い ／ **—** —— 起きるが状態は変わらない ／ **×** —— そもそも起きない

**行は開始状態。** ✓ は「**その状態から始まるテストがある**」を意味する ——
同じイベントでも、どこから入ったかで通る枝が変わる。

|              | V1 開く                    | V2 閉じる | V3 局面変化                     | V4 古い引き     | V5 辿り終えた  | V6 辿れない                  | V7 タブ移動        | V8 棋譜が降りる | V9 並べ替え      | V10 引けない         |
| ------------ | -------------------------- | --------- | ------------------------------- | --------------- | -------------- | ---------------------------- | ------------------ | --------------- | ---------------- | -------------------- |
| **B0**       | ✓ → BO → B1（失敗なら B0） | ×         | — 引く先が無い                  | ×               | ×              | ×                            | — provider は残る  | —               | ×                | ×                    |
| **BO**       | ×                          | ✓ ※D      | — 開き終えるまで引かない        | ×               | ×              | ×                            | ✗ 開くのは続く     | ✗               | ×                | ×                    |
| **BN**       | ✗ 開き直して → BN          | ✗ → B0    | ✗ → B1                          | ×               | ×              | ×                            | — provider は残る  | —               | ×                | ×                    |

## 注

※A **古い結果を当てない。**
局面が動いた回に effect の掃除が走り、前の引きの返り値は捨てられる
（`entities/book/model/provider.tsx` の `cancelled`）。
捨てないと、**盤に出ている局面とは別の局面の候補手が表に残る。**
出ている行が正しいかどうかは画面から確かめようが無い ——
定跡の候補手はどの局面でもそれらしく見える。

※B **タブを移っても引き直さない。**
`BookProvider` はドックより上（`RuntimeProviders`）に居るので、
定跡ビューが unmount されても開いている定跡と引いた行は残る。
ビューの中で開く形にすると、**タブを移るたびに定跡が閉じて開き直される** ——
GB 級のファイルではタブの移動そのものが止まる。

※C **辿るのに失敗しても表は消さない。**
引けてはいるので、埋まらないのは「この先」列だけ。
表ごと消すと、読める候補手まで見えなくなる。
**ただし列を「辿っています」のままにしない** —— 辿るのはもう終わっているので、
そのままだと利用者は待てば埋まると読み、局面を動かすまで解けない。
「まだ届いていない」と「辿れなかった」は `BookRowLine` が型で分ける。

※D **開いている途中でも閉じられる。**
`open_book` は上限も中断も持たないので、押せないと取り消す手段が1つも無くなる。
押した後に返ってきたハンドルは**捨てて閉じる** —— 捨てないと、
閉じたはずの定跡が数分後に開く。

※E **辿った結果は `B1` には届かない。**
`walk_book_lines` を投げるのは候補手を配った後（＝`B2`）で、
`B1` の間に飛んでいる walk は前の局面のものだから ※A が捨てる。

※F **閉じられたハンドル（`invalid_handle`）だけは `B0` へ。**
`BU` に留めると操作列が閉じた定跡の名前を出し続け、盤を動かすたびに同じ失敗が出る。
復帰操作（開き直す）を踏める画面は `B0` のほう。

## 不変条件

1. **表に出ている行は、いま盤に出ている「この定跡の」「この局面の」もの。**
   遅れて届いた結果は捨てる（※A）。**局面だけで突き合わせない** ——
   開き直しでは局面が動かないので、前の定跡の行が新しい定跡の行として出る
2. **画面が同時に2つのことを言わない。**
   引けなかったことを「この局面はこの定跡にありません」と言わない（`B3` と `BU`）。
   開いている最中に「定跡を開いていません」と言わない（`BO`）
3. **「この先」列が黙って空にならない。**
   辿り終えていないなら `…`、辿れないなら理由が出る
   （`entities/book/lib/lineLabel.ts`。上限に当たったのと定跡が切れたのを混ぜない）
4. **開いている定跡は1冊だけで、開き直したら前のものを必ず閉じる。**
   閉じないとハンドルとメモリが積み上がる（重ねて引くのは #96）
5. **全部を読んでいないことを画面が言い続ける。**
   収録局面数を「この局面の候補手の全部」と読ませない

## 埋まっていないセル

- **V4（古い引きが届く）を、実プロセスで踏んだテストは無い。**
  provider のテストが引く口を差し替えて返る順を作っている。
  実際の IPC がその順で返ることまでは見ていない
- **V7（タブ移動）は、ドックを組み立てた状態では踏んでいない。**
  provider が残ることは置き場（`RuntimeProviders`）が保証していて、
  それを固定する機械は `src/app/providers/__tests__/` に無い
- **`BN`（盤に局面が無い）から始まるテストが1本も無い。** そこから開く・閉じる・
  局面が入る、の3セルは ✗。`BN` へ入る遷移（V8）だけは踏んでいる
- **`B1` から閉じる／棋譜が降りる**（V2・V8）も ✗。対応するテストは
  先に引き終えてから（＝`B2` から）始めている
- **表の V 列と画面のテストが1対1で対応していない。**
  画面のテストが見るのは「状態 → 文言」の割り当てで、遷移そのものは見ない。
  どちらも変異を当ててあるが、**セルを名乗る規約はこの表に無い**
  （`src-tauri/tests/state_transition_cells.rs` が突き合わせるのは
  `game-session.md` だけ）

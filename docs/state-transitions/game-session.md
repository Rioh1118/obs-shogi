# 状態遷移表: game-session（L1）

対象: `src-tauri/src/engine/game/session.rs`（状態機械）、`search.rs`（1回の `go`）、
`clock.rs`（持ち時間）、`manager.rs`（台帳）、`bridge.rs`（Tauri コマンド）。

上位は [app.md](app.md)。エンジンプロセスの生死は [engine.md](engine.md)、
棋譜側のカーソルと分岐計画は [game.md](game.md) が持つ。
**[game.md](game.md) とは別物。** あちらは「棋譜を読む・辿る・編集する」で、
こちらは「対局が進む」。同じ `game` で始まるが状態機械は交わらない。

## 責任の切れ目

**Rust はここで将棋のルールを持たない。**

合法手と成りの判定は**既にフロントにある**
（`src/entities/game/lib/shogiMoveValidator.ts`、shogi.js）。盤の表示
（移動可能マスの強調・成り選択）にも要るので消せず、Rust に重ねると
合法手判定が2実装になる。ルールをフロント側に寄せるのはそのため。

**詰み・千日手・持将棋・最大手数の判定は、まだどちらにも無い** → #354。
`shogiMoveValidator.ts` が持つのは合法手と成りの6メソッドだけで、`src/` を
`千日手|repetition|持将棋|jishogi|最大手数` で引いても当たるのは
`entities/kifu/model/jkf.ts` の**棋譜の特殊手の文字列定数**だけ。

その帰結として、**Rust は手が決まっても次の `go` を自分では出せない**。
指した後の局面が終局かどうかを知る手立てを持たないため。`AwaitingRuling` で
止まり、フロントの裁定（`continue_game` / `end_by_rule`）を待つ。

**#354 が入るまで、この表の `end_by_rule` の列は「呼ばれる口があるだけ」で、
呼ぶ側が存在しない。**

|          | 持つもの                                                    |
| -------- | ----------------------------------------------------------- |
| Rust     | エンジンプロセス・USI・時計・手番・「いま誰が考えているか」 |
| フロント | 局面と指し手列（JKF）・ルール・表示                         |

**指し手列の権威はフロント。** Rust の `Runner.moves` は `go` を組むための写しで、
`continue_game` が毎手上書きする。書き込むのは `start`（`initial_moves`）と
`accept_continue` の2箇所だけ（不変条件6）。

## 状態（Rust セッション）

`session.rs` の `Phase`。

| 記号   | 状態                                   | 判定                                       |
| ------ | -------------------------------------- | ------------------------------------------ |
| **G0** | `side` が考えている。**時計が動く**    | `Phase::Thinking { side }`                 |
| **G1** | 手が決まり、裁定待ち。**時計は止まる** | `Phase::AwaitingRuling { last_mover, .. }` |
| **G2** | 終局                                   | `Phase::Over { result }`                   |

`G1` の `since` から `RULING_TIMEOUT`（30秒）で中断する。
時計が止まっているので、この打ち切りが対局者の持ち時間を削ることはない。

## 外部の状態（エンジンプロセス）

**この列を忘れたことが issue #120 の BLOCK だった**（→ [engine.md](engine.md)）。
`Player.activity` を先後それぞれが持つ。

| 記号   | 状態           | 判定                                                    |
| ------ | -------------- | ------------------------------------------------------- |
| **A0** | 何もしていない | `Activity::Idle`                                        |
| **A1** | 本番の思考中   | `Activity::Busy { kind: SearchKind::Search, .. }`       |
| **A2** | 先読み中       | `Activity::Busy { kind: SearchKind::Ponder { m }, .. }` |

`Player.restart_after_abort` が別に立つ。**先読みを打ち切った印**で、
捨てる `bestmove` が返ったら本番の思考を始める。

人間側の `activity` は常に `A0`（`engine` が `None` なので `spawn_search` を通らない）。

### 注

※1 `decide_move`。**時計を締めてから** `G1` へ入る（`elapsed_ms` は `Thinking` の
間しか動かないので、順序が逆だと 0 になる）。締めた結果が時間切れで、かつ
その側の時間切れが成立するなら（※10）、裁定を待たずに直接 `G2`（`Timeout`）へ落とし、
`MoveDecided` も出さない。**その手は指されなかったものとして扱う。**

※2 `accept_continue`。渡された `moves` で `Runner.moves` を上書きし、`G0` へ。
その中で `hand_turn_to` が相手側の先読みを見る。

- 先読みの手が実際に指された手と一致 → `ponderhit` を送り、`A2` → `A1`。
  **エンジンはそのまま考え続け、時計はここから動く**（先読みの時間は無料）
- 一致しない → 打ち切って `restart_after_abort` を立てる。
  実際の `go` は捨てる `bestmove` が返ってから（※8）
- `A0` → その場で `go`

指した側は、裁定が通ってから先読みへ入る（`start_ponder`）。
**裁定の前に始めないのは、指せない手の上で読ませないため。**

※3 `accept_continue` の検算は3つ。`moves` の末尾が直前に決まった手であること、
`moves.len()` の偶奇が次の手番と合うこと、各手の形が通ること。
**権威はフロントだが、受け取ったものが直前の手の続きであることは確かめる。**
確かめないと、食い違いに気付く経路がどこにも無くなる。
落ちると `G1` のまま留まるので、フロントが直さなければ ※14 の 30 秒で中断される。

※4 `GameManager::close`。`Arc::try_unwrap` が通らない（誰かが操作中）と
**中断だけ通してエンジンは残る**。残りは `close_all` が拾う。

※5 `G1` に入るのは手番側の探索が終わった直後なので、その側は既に `A0`。

※6 `on_search_outcome` は `Phase::Over` を見たら `gameover` を送って戻る。
**`finish` の時点では送らない。** 探索中のエンジンへ `gameover` を送るのは
プロトコル違反なので、`bestmove` が返って `A0` になるここまで待つ。
`finish` の時点で既に `A0` だった側にはその場で送る。

※7 先読みは自分から終わることがある（詰みを見つけた等）。その `bestmove` は
相手の手番に対する答えなので採らない。判定は `is_to_move(side)` 1本で、
`G1` では先後どちらも false になる。

※8 `restart_after_abort`。**捨てる `bestmove` を待ってから `go` を出す**のは、
USI が探索中の `position` / `go` を認めないため。
待ちの上限は `search.rs` の `STOP_GRACE`（5秒）で、超えたら `warn` を出して
`Aborted` として戻る。→ **穴。下の「埋まっていないセル」を見る**

※9 `info` は2箇所で落ちる。`search.rs` は**先読み中のものを送らない**
（相手の手番の画面に読み筋が出てしまうため）。`on_search_info` は
**手番が変わった後に届いたものを落とす**（いまの局面のものではないため）。
理由が別なので2つある。

※11 **踏めているのは先後とも人間の1局だけ。** `spawn_players` は人間側を飛ばすので、
その設定なら**エンジンを1つも起動せずに状態機械を通せる**。これが
`session.rs` のテストが使っている唯一の穴。

`△` は「その行のうち人間で踏める列だけ」の意。E2〜E5 の**エンジンが絡む列**
（先読みの当たり外れ、`gameover` の送り先、`close` でのプロセス停止）は
どれも未検証。E1 と E13 は人間だけで全列を踏める。

※10 `timeout_enforced`。**エンジンの時間切れは既定で成立しない**
（`GameSettings.enforce_engine_timeout` の既定が false）。この打ち切りが
当たるのはたいてい GUI 側の取りこぼしだから
（→ `research/shogihome/02-game.md` の `enableEngineTimeout` も既定 false）。
人間の時間切れは常に成立する。

## 1回の `go`（`search.rs`）

`go` **ごとに**リスナーを作り、終わったら外す。使い回すと、打ち切った探索の
`bestmove` が次の探索のものとして届く。届いた先で世代を照合するより、
そもそも届かないようにするほうが穴が少ない。

| 相  | 何をしているか                                                             |
| --- | -------------------------------------------------------------------------- |
| 1   | `position` → `go` を送り、`bestmove` か打ち切りのどちらかを待つ            |
| 2   | 打ち切られたなら `stop` を送り、捨てる `bestmove` を `STOP_GRACE` まで待つ |

第2相を置いてあるのは礼儀ではなく必要。次の `go` を出す前にエンジンを
idle に戻さないといけない。

## この表が満たすべき不変条件

1. **`G0` の間、`go`（本番）が出ているのは高々1つで、それは手番側のエンジン。**
   相手側は `A0` か `A2`。破れると、手番でない側の `bestmove` を着手として採る。
   `hand_turn_to` は `A1` を見つけたら `warn` を出す（起きない想定の枝）
2. **1つの `go` に対して採る `bestmove` は高々1つ。**
   リスナーが `go` ごとなので古いものは届かず、届いても `req` が合わなければ捨てる（E15）
3. **`G2` に入ったら、全エンジンに `gameover` が届く。**
   探索中だったエンジンには `bestmove` が返ってから送る（※6）
4. **時計が動くのは `G0` の間だけ。** `elapsed_ms` が `Thinking` 以外で 0 を返すことで守る
5. **`close_game` を呼ぶまでエンジンプロセスは落ちない。** 終局は落とさない
   （`gameover` の後に `usinewgame` で指し直せる形にしてあるため）。
   **呼び忘れるとプロセスが残る。** これはフロント側の契約
6. **`Runner.moves` を書くのは `start` と `accept_continue` の2箇所だけ。**
   権威はフロントにあり、Rust は写しを持つ

## 埋まっていないセル

**エンジンが絡むセルは1つも固定できていない。** 固定するには USI を喋る
偽エンジンが要るが、`EngineRegistry::spawn` が `UsiEngineHandler::spawn` を
直に呼んで実行ファイルを起動する作りなので、**プロセスを差し替える口が無い**。
`search.rs` / `manager.rs` には `#[test]` が0個。

人間だけで踏める分（※11）は `session.rs` のテストが押さえている。
**その範囲は表の3列のうち左2列の、エンジンを通らない経路に限られる。**

とくに危ないもの:

| セル                                                    | 状態                                                                                                                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `(G0/A2, E2)` 先読みが外れた後の `go` 出し直し          | **`STOP_GRACE`（5秒）で `bestmove` が返らないと、探索中のエンジンへ `go` を出す。** USI 違反で、その後の応答は保証されない。`warn` は出るが復帰の手立てが無い※8 |
| `(G1, E14)` 裁定が返らない                              | 30 秒で中断する。**踏んだことが無い。** フロント側から意図的に返さない手段がテストに無い                                                                        |
| `(G0, E10)` エンジンが応答しない                        | `EngineFailure` で終局。**エンジンを落とす手段がテストに無い**（[engine.md](engine.md) の `(S2,E8)` と同じ理由）                                                |
| `(G2, E7)` 終局後に返る `bestmove` と `gameover` の順序 | ※6 の待ちが正しいかを見ていない。**先後の片方だけが探索中だった場合**の分岐も踏んでいない                                                                       |
| `ponderhit` の当たり／外れ                              | ※2 の3分岐。**先読みは実機でしか踏めていない**                                                                                                                  |
| `E15` 世代違いの `SearchOutcome`                        | `req` の照合。**リスナーが `go` ごとなので実機で踏むのが難しく、意図的に作る口も無い**                                                                          |
| `close` を呼ばずにアプリを閉じる                        | 不変条件5 の裏。**プロセスが残ることを確かめていない**                                                                                                          |
| `(G0, E4)` エンジン側の投了を人間として撃つ             | `accept_resign` の `is_engine` の枝。**エンジンを起動しないと踏めない**                                                                                         |
| `enforce_engine_timeout` が true のとき                 | ※10 の分岐。既定 false 側しか通していない                                                                                                                       |

固定できた検算は `accept_continue` の3つ（末尾不一致・偶奇不一致・形の崩れ）と、
`validate_settings` の `startpos` 拒否・SFEN の手番欄の欠落、
`validate_usi_move` の形（制御文字は `0x00..=0x1F` を範囲で回す）。

# 状態遷移: 初期局面を組む面

対象は、ファイル作成の器（`modal=create-file`）の「新規作成」タブに載る**組む面**。
種から局面を1つ載せ、盤と両駒台のあいだで駒を並べ替えて、その局面を初期局面とする
**新しい棋譜ファイルを作る**。

並べ替えそのものの規則は `src/entities/position/lib/positionDraft.ts`、
規則に反する配置の検査は `src/entities/position/lib/inspectPosition.ts` が持つ。
**ここが扱うのは面の中だけ。** ファイルが実際に作られる経路は
[file-tree.md](./file-tree.md)、失敗の行き先は
[failure-surfacing.md](./failure-surfacing.md) を参照。

画面の説明は [create-file.md](../spec/screens/create-file.md) と
[position-edit.md](../spec/features/position-edit.md) が持つ。

## なぜ表にするか

**同じ Esc が5通りに分かれる。** 確認を閉じる／掴んでいる駒を離す／課題局面の面から戻る／
捨てる確認を出す／器を閉じる。段が1つずれると、**組んだものが黙って消える**か、
逆に何も組んでいないのに毎回確認が出て、確認そのものが読まれなくなる。

加えて、この面には**戻す口が無い**（Undo を持たない）。駒に駒を重ねると1手で駒台へ飛び、
戻すには2手かかる。だから「押す前に見せる」側にセルがあり、そこが埋まっていないと
「押しても何も起きない」か「押したら戻せない」のどちらかになる。

## 状態

盤の面・課題局面の面・インポートの面は**同時に1つ**しか出ない。掴んでいるものは
盤の面のときだけ在りうる。

| 記号   | 状態                             | 判定                                    |
| ------ | -------------------------------- | --------------------------------------- |
| **B0** | 盤の面。何も掴んでいない         | `face === "board"` かつ `held === null` |
| **B1** | 盤の面。盤の駒を掴んでいる       | `held.from === "square"`                |
| **B2** | 盤の面。駒台の駒を掴んでいる     | `held.from === "hand"`                  |
| **P**  | 課題局面の面（一覧＋プレビュー） | `face === "study"`                      |
| **I**  | インポートの面                   | `tab === "import"`                      |
| **C**  | 捨てる確認が出ている             | `confirm !== null`                      |
| **W**  | 作成中（Tauri の応答待ち）       | `isSubmitting === true`                 |

**C と W は他の状態に重なる。** 確認を閉じたら元の面へ戻り、作成が返ったら
器ごと閉じるか元の面へ戻る。どちらも「どこから来たか」を覚える。

## 直交する軸（セルに書かない）

セルに書くと、7状態 × 15事象がさらに4倍になって読めなくなる。**軸として別に持つ。**

| 軸           | 判定                                       | 何を変えるか                                                    |
| ------------ | ------------------------------------------ | --------------------------------------------------------------- |
| **断り**     | `inspectPosition(draft).issues.length > 0` | **遷移を変えない。** 右の列の上に出て、該当する升に枠が付くだけ |
| **組みかけ** | `serializeDraft(draft) !== baseline`       | 「種を選び直す」「閉じる」の行き先を **C（確認）** に変える     |

**断りは止めない。** 「作成」は押せるまま。押せなくすると詰将棋が作れない。
段は `danger`（[ADR-0004](../decisions/0004-notification-taxonomy.md) 決定1 ——
どれも同じ操作を繰り返しても直らず、直し方は配置ごとに違う）。
**ボタンは付けない**（同 決定3 の F-12b と同じで、押して直るものが無い）。

**組みかけは種を載せた時点との差。** `baseline` は種を載せるたびに置き直す。
ファイル名・先手名・タグを打っただけでは組みかけにならない（`serializeDraft` は
盤・両駒台・手番しか見ない）。**聞きすぎると聞かれること自体が意味を失う。**

## 遷移: 盤を触る（X1〜X4）

盤の面の中だけで閉じる。**P / I / C / W では盤も駒台も描かれていないので起きない。**

|        | X1 升を押す                                           | X2 駒台を押す                                    | X3 右クリック          | X4 手番の変更               |
| ------ | ----------------------------------------------------- | ------------------------------------------------ | ---------------------- | --------------------------- |
| **B0** | 駒があれば → **B1**。空升なら B0（※1）                | B0（掴んでいないので何も起きない）               | 裏返す。B0（※2）       | 手番を入れ替える。B0        |
| **B1** | 同じ升 → **B0**（離す）／別の升 → 置いて **B0**（※3） | 玉なら B1（沈めてある）／それ以外は送って **B0** | 離して裏返す。→ **B0** | 手番を入れ替える。B1 のまま |
| **B2** | 空升なら置いて **B0**／駒のある升は B2（沈めてある）  | 同じ側 → **B0**（離す）／反対側 → 移して **B0**  | 離して裏返す。→ **B0** | 手番を入れ替える。B2 のまま |
| **P**  | –                                                     | –                                                | –                      | –                           |
| **I**  | –                                                     | –                                                | –                      | –                           |
| **C**  | –（確認の背後は押せない）                             | –                                                | –                      | –                           |
| **W**  | –（作成中は押せない）                                 | –                                                | –                      | –                           |

- **※1**: 空升を押しても掴めない。**押す前に沈めてある**ので「押しても何も起きない」ではない
- **※2**: 右クリックは掴んでいなくても効く（近道）。不成 → 成 → 相手の成 → 相手の不成 で1周し、
  玉と金は2巡（`cycleFrom`）。`contextmenu` の既定の menu は止める
- **※3**: 移動先に駒があれば**動かす側と同じ側**の駒台へ入り、成りは落ちる。
  移動先が玉なら2つの升が入れ替わる（`movePieceOnBoard`）

  既定は root になる

## 不変条件

1. **既存の棋譜を1つも変えない。** この面の出口は「新しいファイルを作る」だけで、
   開いている棋譜にも課題局面にも書き戻さない
2. **押せる操作は必ず何かを変える。** 置けない升・送れない駒（玉）は押す前に沈める。
   押して何も起きない経路を作らない
3. **組みかけを黙って捨てない。** 種を載せ直すときと器を閉じるときは、必ず C を通す。
   逆に、組みかけでないときは C を通さない
4. **`Shogi` を状態として持たない。** 組みかけは `JKFState` で持ち、`Shogi` は
   SFEN と王手の判定に作って捨てる（`stateToShogi`）

## 埋まっていないセル

**消さないこと。** 実装上は同じ経路に落ちるが、テストが1つも踏んでいない。

1. **(B0〜W, X14) 組んでいる間にツリーが変わったら。** 保存先の root ごと入れ替わる形は
   `SfenKifuCreateModal` が root に戻して受けている。**選んでいたフォルダだけが消えた場合**に
   写せる形が無く、いまは root に戻す以上のことをしない。**未検証**
2. **(W, X10) 作成中に Esc を押したら。** 止められないので無視する。
   **止まらないことが利用者に見えるかは決めていない。未検証**
3. **(I, X11〜X12a) インポートの面で作成したら、組んだものはどうなるか。**
   器が閉じるので消える。タブの切替は URL に出ないローカルの state なので、
   組みかけであることは器の外から見えない。**未検証**
4. **盤の鍵盤操作。** 升は `div` で、`Modal` の焦点の閉じ込め
   （`button, [href], input, select, textarea, [tabindex]`）に引っかからない。
   **Tab が盤を素通りする。対局の盤も同じ状態**なので、ここだけ先に直すと2系統になる。

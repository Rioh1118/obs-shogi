# 状態遷移: 初期局面を組む面

追跡: #113 ／ main にあるか: **無い**

対象は `src/features/position-editor/`。ファイル作成の器（`modal=create-file`）の「新規作成」タブに載る。
種から局面を1つ載せ、盤と両駒台のあいだで駒を並べ替えて、その局面を初期局面とする
**新しい棋譜ファイルを作る**。

並べ替えそのものの規則は `src/entities/position/lib/positionDraft.ts`、
規則に反する配置の検査は `src/entities/position/lib/inspectPosition.ts` が持つ。
どちらも入っていて、テストも付いている。**この表が扱うのは面の中だけ。**
ファイルが実際に作られる経路は [file-tree.md](./file-tree.md)、失敗の行き先は
[failure-surfacing.md](./failure-surfacing.md) を参照。

画面の説明は [create-file.md](../spec/screens/create-file.md) と
[position-edit.md](../spec/features/position-edit.md) が持つ。

## なぜ表にするか

**同じ Esc が6通りに分かれる。** 段が1つずれると、**組んだものが黙って消える**か、
逆に何も組んでいないのに毎回確認が出て、確認そのものが読まれなくなる。

| 段      | そのとき                          | 起きること                  |
| ------- | --------------------------------- | --------------------------- |
| **段1** | 確認が出ている（**C**）           | 確認を閉じる。**捨てない**  |
| **段2** | 駒を掴んでいる（**B1** / **B2**） | 離す                        |
| **段3** | 課題局面の面（**P**）             | 盤の面へ戻る                |
| **段4** | 組みかけ                          | 捨てる確認を出す（→ **C**） |
| **段5** | それ以外                          | 器を閉じる                  |
| **段0** | 作成中（**W**）                   | 無視する。止められない      |

段0 を先頭に置かず末尾に書いてあるのは、他の5段が「内側から畳む」1本の並びで、
作成中だけがその外にあるため。**判定は段0 が最初に来る**（作成中は他のどれにも落ちない）。

加えて、この面には**戻す口が無い**（Undo を持たない）。駒に駒を重ねると1手で駒台へ飛び、
戻すには2手かかる。だから「押す前に見せる」側にセルがあり、そこが埋まっていないと
「押したら戻せない」形になる。

## 状態

**面は1つの変数で持つ。** `face` と `tab` を別に持つと、
「インポートタブに居るが `face` は盤」という、表に無い組み合わせが作れる。
そこから戻ったときの着地がどのセルにも書けない。

**出ていない面も木に残す（隠すだけ）。** 外すと、組みかけの局面も
フォームに打った名前も、確認を1つも通さずに消える。`face` は
「どれが見えているか」であって「どれが在るか」ではない。

| 記号   | 状態                             | 判定                                             |
| ------ | -------------------------------- | ------------------------------------------------ |
| **B0** | 盤の面。何も掴んでいない         | `face === "board"` かつ `held === null`          |
| **B1** | 盤の面。盤の駒を掴んでいる       | `face === "board"` かつ `held.from === "square"` |
| **B2** | 盤の面。駒台の駒を掴んでいる     | `face === "board"` かつ `held.from === "hand"`   |
| **P**  | 課題局面の面（一覧＋プレビュー） | `face === "study"`                               |
| **I**  | インポートの面                   | `face === "import"`                              |
| **C**  | 捨てる確認が出ている             | `pending !== null`                               |
| **W**  | 作成中（Tauri の応答待ち）       | `editorBusy \|\| importBusy`                     |

**C と W だけは他の状態に重なる。** 確認を閉じたら元の面へ戻り、作成が返ったら
器ごと閉じるか元の面へ戻る。どちらも「どこから来たか」を覚える。
B0 / B1 / B2 / P / I は `face` の値なので互いに排他。

**インポートの面にも作成がある。** `KifuImportForm` は送信中を `isSaving` で、
組む面は `EditorCreateForm` が `isSubmitting` で持つ。**同じ状態が2つの綴りを持つ。**
器（`CreateFileFace`）は両方を受けて論理和で持ち、タブと閉じる門はその1つを見る ——
片方しか見ないと、見ていない面で送信中に器が閉じて**失敗を出す場所ごと消える**。

## 直交する軸（セルに書かない）

セルに書くと、7状態 × 15事象がさらに4倍になって読めなくなる。**軸として別に持つ。**

| 軸           | 判定                                             | 何を変えるか                                                    |
| ------------ | ------------------------------------------------ | --------------------------------------------------------------- |
| **断り**     | `inspectPosition(state).issues.length > 0`       | **遷移を変えない。** 右の列の上に出て、該当する升に枠が付くだけ |
| **組みかけ** | `serializeDraft(draft.state) !== draft.baseline` | 「種を選び直す」「閉じる」の行き先を **C（確認）** に変える     |

**断りは止めない。** 「作成」は押せるまま。押せなくすると詰将棋が作れない。
段は `danger`（[ADR-0004](../decisions/0004-notification-taxonomy.md) 決定1 ——
どれも同じ操作を繰り返しても直らず、直し方は配置ごとに違う）。
**ボタンは付けない**（同 決定3 の F-12b と同じで、押して直るものが無い）。

**組みかけは種を載せた時点との差。** `baseline` は種を載せるたびに置き直す。
**載せた手合割の名前は組みかけになっても消さない** —— 消すと「何をもとに組んだか」が
画面から消える。ただし**出口に書かれるものは別**（※8）で、1升でも動かせば盤面そのものになる。
種を選ぶ行が名乗るのは「いま何が載っているか」だけ。
ファイル名・先手名・タグを打っただけでは組みかけにならない（`serializeDraft` は
盤・両駒台・手番しか見ない）。**聞きすぎると聞かれること自体が意味を失う。**

**裏返しの巡目は状態に入れない。** 升ごとに `CycleStep`（駒の姿と巡目の対）を覚えるが、
`cycleFrom` が升の駒と照合して食い違えば引き継がないので、**消す口が要らない。**
覚えが残っていても遷移は変わらない。

  **どちらの面から送っていても同じ**（器が2つの旗の論理和を持つ）

## 不変条件

1. **既存の棋譜を1つも変えない。** この面の出口は「新しいファイルを作る」だけで、
   開いている棋譜にも課題局面にも書き戻さない
2. **掴んでいる間だけ沈める。** 置けない升・受け取れない駒台（空／玉）は、
   置き先を探している最中にだけ沈める。**何も掴んでいないときは沈めない** ——
   空升を押しても何も起きないが、そこで沈めると平手でも 41 升が黒くなり、
   **盤が盤に見えなくなる**。沈めるのは「押せそうに見えるのに効かない」を
   防ぐためで、休んでいる盤の空升はその対象ではない
3. **組みかけを黙って捨てない。** 種を載せるときと器を閉じるときは、必ず C を通す。
   逆に、組みかけでないときは C を通さない
4. **`Shogi` を状態として持たない。** 組みかけは `JKFState` で持ち、`Shogi` を返す口は
   `positionDraft.ts` の外に無い（SFEN は `stateToSfen`、王手は `isCheckOn` が答えだけ返す）

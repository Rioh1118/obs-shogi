# 画面仕様: ファイルツリー

対象: `src/widgets/file-tree/` `src/entities/file-tree/`

状態遷移: [`docs/state-transitions/file-tree.md`](../../state-transitions/file-tree.md)
／ 名前の入力欄だけ [`inline-name-editor.md`](../../state-transitions/inline-name-editor.md)

## 目的

**ワークスペース（`root_dir`）の中身を出し、棋譜を開く。**
フォルダと棋譜の作成・改名・移動・削除もここが持つ。

## 出入口

サイドバーの中に常駐する（`/app/panel/filetree`）。閉じるのはサイドバーごと。

行を押すと棋譜が開き、盤・棋譜ストリーム・解析ペインがその棋譜に切り替わる。

## 画面構成

```
RootNode（ワークスペース名）           [＋ファイル][＋フォルダ]
 ├ DirectoryNode                       [＋ファイル][＋フォルダ]
 │   └ FileNode（.kif / .ki2 / .csa / .jkf）
 └ ScrollDropZone（末尾の余白もドロップ先になる）
```

- 行のアクション（`＋ファイル` `＋フォルダ`）は**ホバーで出る**
- 名前が枠に収まらない行は、ホバーで `popover` のツールチップを出す
- 右クリックで `ContextMenu`（`Rename` と `Delete`。ルートは `Rename` のみ）
- 改名とフォルダ作成は**行の中の入力欄**（`InlineNameEditor`）で行う。別窓を開かない

## 状態

| 記号 | 状態             | 判定                             | 見えるもの                               |
| ---- | ---------------- | -------------------------------- | ---------------------------------------- |
| T0   | 読み込み中       | `isLoading && !fileTree`         | `Spinner`                                |
| T1   | ツリーがある     | `fileTree !== null`              | 木                                       |
| T2   | ツリーが無い     | `!fileTree && !error`            | 「ファイルツリーがありません」＋選び直し |
| T3   | 失敗・ツリー無し | `error && !fileTree`             | `FileTreeErrorNotice`（面いっぱい）      |
| T4   | 失敗・ツリーあり | `error && fileTree`              | 木は残したまま `Modal` で通知            |
| T5   | 名前を編集中     | `renamingNodeId !== null`        | その行が入力欄になる                     |
| T6   | フォルダ作成中   | `creatingDirParentPath !== null` | 子に空の入力欄が挿さる                   |
| T7   | 削除の確認中     | `pendingDelete !== null`         | `ConfirmDialog`                          |

**T3 と T4 を分けているのは「復帰路が残っているか」。** 木があるうちはそれを消さない
（消すと、そこからの操作が全部できなくなって復帰路まで失う）。

## 操作と結果

| 操作                     | 結果                                                         |
| ------------------------ | ------------------------------------------------------------ |
| 棋譜の行をクリック       | `openKifuNode` → `activeKifuPath` が変わり、盤が読み込む     |
| フォルダの行をクリック   | 開閉                                                         |
| `＋ファイル`             | `modal=create-file&dir=<そのフォルダ>` を開く                |
| `＋フォルダ`             | その場に入力欄を出す（`startCreateDirectory`）               |
| 右クリック → Rename      | その行を入力欄にする                                         |
| 右クリック → Delete      | 確認を出す。**フォルダは中身ごと消える**                     |
| ドラッグ＆ドロップ       | 別フォルダへ移動。同じ親・自分の子孫への移動は**黙って無視** |
| 失敗通知の「再読み込み」 | ツリーを取り直す。**失敗した操作そのものはやり直さない**     |

### 削除の確認文

取り消せない操作なので、ファイルとフォルダで文言を変えている。

- ファイル: 「ファイルは完全に削除されます。この操作は取り消せません。」
- フォルダ: 「フォルダ内のファイルもすべて完全に削除されます。…」

### 名前の衝突

作成・改名・移動で同じ名前が既にある場合、`FileConflictDialog` が引き取る。
呼び出したフォーム側は**衝突を自分で描かない**（`isResolvedByConflictDialog`）。
二重に出さないため。 → [system-dialogs.md](system-dialogs.md)

## 失敗の見せ方

失敗は `FileTreeFailure` として `{ from, error }` の形で持つ。
`from` が `operation`（操作そのものが落ちた）か `reload`（操作は通ったが
一覧を取り直せなかった）かで**見出しが変わる**。

| `from` / 条件                    | 見出し                         |
| -------------------------------- | ------------------------------ |
| 操作が完了していて一覧だけ古い   | 「一覧を取り直せませんでした」 |
| 操作そのものが落ちた             | 「ファイル操作に失敗しました」 |
| 操作は済んだが設定に書けなかった | 「設定に保存できませんでした」 |

3つ目はルート改名で起きる。**ディスク上の名前はもう変わっている**ので、
「失敗しました」とだけ出すと利用者は改名されなかったと受け取る。

「再読み込み」を押した後にその読み直しも落ちると `from` が `reload` に化ける。
そのままだと**失敗した操作を「完了しました」と断言する**ので、
引き金が操作の失敗だったかを画面側が覚えている（`retriedFromOperation`）。

ルート自体が読めない場合、この widget の中に復帰路が無い。
そのため通知の下に「ワークスペースを選び直す」を出し、
`modal=settings&tab=workspace` へ送る。

## いま満たしていないこと

- **読み取れないサブフォルダが黙って消える** → #179
- **`truncated`（走査の打ち切り）を持っているのに、画面がそれを描いていない。**
  上限に当たったフォルダが「空のフォルダ」と同じ絵になる
- **設定だけ書けなかったあと、ツリーが古いルート名を出し続ける** → #254
- **開いている棋譜をリネーム／移動すると編集が巻き戻り、次の保存で消える** → #262
- **棋譜を続けてクリックすると、ツリーの選択と盤の棋譜が食い違う** → #223
- **ツリーの再レンダが行単位に絞られていない** → #216
- **`src-tauri/file_system` に既知の欠陥が9件ある**（symlink ループで起動できなくなる、
  保存経路が `FsError` の外にある、ほか）→ #215 #287

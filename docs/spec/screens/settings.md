# 画面仕様: 設定

対象: `src/features/settings/` `src/entities/app-config/` `src-tauri/src/ai_library/`
`modal=settings`

## 目的

**アプリが外の世界を指す先を決める。** 決めるのは2つのフォルダ
（ワークスペースと AI ライブラリ）と、エンジンのプリセット。

## 出入口

| 入口                         | `tab=`      |
| ---------------------------- | ----------- |
| ヘッダの歯車                 | `workspace` |
| 解析ペインの歯車             | `engine`    |
| ツリーの失敗通知「選び直す」 | `workspace` |
| エンジンの起動の失敗の帯     | `engine`    |

**解析ペインの歯車だけ `engine`。** そこから出る断りのうち **`RESTART_ENGINE_HINT`
（オプションを変えて保存する）が案内する操作はこのタブにしか無い**ので、開く先が別だと空振りする。
**ただし `no-engine` の断りは AI フォルダの確認も案内する**（→ [analysis.md](../../state-transitions/analysis.md)
の ※15）——そちらは AI ライブラリタブなので、この歯車では着かない。
**どちらの断りも読み手はまだ0**（→ #277 / #523）。

タブの切り替えは `updateParams({ tab }, { replace: true })` で URL に載る。
**綴りは型が持つ**（`shared/lib/router/useURLParams.ts` の `TabType`）。
`TABS` はそれに `satisfies` で合わせてあるので、**片方だけ増やすと tsc が落ちる。**

## タブ

`TABS`（`features/settings/model/tabs.ts`）は**3つ**。

| `key`       | 見出し         | 説明                                 |
| ----------- | -------------- | ------------------------------------ |
| `workspace` | ワークスペース | 保存場所・状態・メンテナンス         |
| `aiLibrary` | AIライブラリ   | engines/eval/book の置き場所とルール |
| `engine`    | エンジン管理   | 解析プリセットを編集                 |

左の一覧では `workspace` 以外に「要設定」と「注意」のバッジを**常に**出す。
**中身を見ていない**ので、設定が済んでいても消えない。

## ワークスペースタブ

3つの節。

### 「状態」

局面検索インデックスの進み具合。

| 出るもの     | 元                                                                                                                                                                                                                                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 状態バッジ   | `indexHealth`（`entities/search`）が決める。更新できていません／作成できませんでした／一部を読めていません／一部を索引に入れられていません／読めない場所と、入れられなかった棋譜があります／更新できず、入れられなかった棋譜もあります（ここまで警告色）／未作成／復元中・作成中・更新中／準備完了 |
| 対象ファイル | `idx.totalFiles`                                                                                                                                                                                                                                                                                   |
| 未同期       | `scanFailed` なら「確認できていません」、ほかは `idx.dirtyCount`                                                                                                                                                                                                                                   |
| 索引済み     | `idx.indexedFiles` / `idx.totalFiles`。**`Ready` の回にかぎり、差がそのまま「検索に出ない棋譜」の数。** 進行中は据わっている索引の数が出るので、差は「まだ当てていない分」                                                                                                                         |
| 警告         | `warns.length`                                                                                                                                                                                                                                                                                     |
| 進捗バー     | `indexHealth` が `building` のとき（＝ `Restoring` / `Building` / `Updating`）だけ                                                                                                                                                                                                                 |
| 読み取り警告 | **5件だけ**。場所の警告を先に取り、あとは新しい順。残りは「ほか N 件」として件数だけ出る（一覧を見る導線は無い）                                                                                                                                                                                   |

**索引の状態がまとまって見えるのはここだけ。** 局面検索の画面には
「結果が古いかもしれない」の印しか出ない。→ #350

### 「保存場所」

`root_dir` を出し、コピーできる。変更は危険な操作として扱う。

1. 「ワークスペースを変更…」を押す
2. `CHANGE` と打つまで実行ボタンが押せない
3. フォルダを選ぶ
4. **`window.location.reload()` でアプリを作り直す**

リロードするのは、`root_dir` に依存する provider が多く、
差し替えを個別に追いかけるより確実だから。

### 「更新」

アプリ本体の更新。**確認はここと起動時だけ。定期的には確認しない**ので、
起動しっぱなしの間に公開された版には次の起動まで気づかない。

| 出るもの         | 元                                                                                                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 現在のバージョン | `tauri.conf.json` の `version`。取れなければ「—」                                                                                                                                                                                                              |
| 最後に確認できた | `updater.json` の `lastCheckedMs`。**確認が通った回だけ動く。** 一度も通っていなければ「まだ確認できていません」                                                                                                                                               |
| 「更新を確認」   | 押すと確認する。確認中は押せない                                                                                                                                                                                                                               |
| 確認の結果       | 押したときだけ出る。最新版を使っています／新しいバージョン v◯ が公開されています。この画面を閉じると案内が出ます。／新しいバージョン v◯ がありますが、この版は飛ばす設定になっています。／更新を確認できませんでした。通信を確かめて、もう一度お試しください。 |
| 飛ばしている版   | 「v◯ を飛ばす設定になっています」と「解除」。飛ばしていなければ出ない                                                                                                                                                                                          |

**取得と適用はここでは出来ない。** 更新のカードは設定モーダルの下に出る
（重なりの順は [design-language.md](../design-language.md)）ので、ここに取得の
ボタンを置くと進捗と失敗の面が2つに割れる。見つかったことだけを伝えて、
あとはカードに渡す。

**起動時の確認が失敗しても何も出ない。** 断線は日常で、起動のたびに失敗を出すと
利用者は読まずに閉じる癖がつく。失敗したことは「最後に確認できた」が古いまま
止まることでしか分からない。段と遷移は
[updater.md](../../state-transitions/updater.md)。

## AI ライブラリタブ

エンジン本体・評価関数・定跡 DB を置く1つのフォルダ（`ai_root`）を決める。

### 期待するフォルダ構成

```
<ai_root>/
├ engines/              エンジンの実行ファイル（YaneuraOu* だけを列挙する）
└ <AI名>/               プロファイル。ai_root 直下のディレクトリが1つ1つ
   ├ eval/              評価関数（nn.bin を優先して先頭に出す）
   └ book/              定跡（.db だけを数える）
```

- `engines` という名前のディレクトリは**プロファイル一覧から除く**
- プロファイルとして数えるのは `eval` か `book` を持つディレクトリだけ。
  条件を緩めると、`eval` しか持たない普通の形に同じ名前で「作成」を押したとき
  既存の中へ黙って `book` が足される
- 列挙の上限は `eval` / `book` それぞれ200件

### 画面構成

左に `ai_root` の入力欄（**読み取り専用**。選択ダイアログでしか変えられない）と
`engines/` の作成・オープン。右に `SetupGuide` —— 4段の手順書。

**「開く」が開くのは親フォルダ**（`reveal_item_in_dir`）で、渡したものが選択された状態になる。
中は開かないので、**「中に置いてください」と案内する文言は「場所を表示する」と書く**。

**`engines` の扱いは4つに割れている。** 判定は**そのルートの**スキャン結果で決まる。

| 索引から読める `engines` の状態                            | 「engines/ を開く」 | 「engines/ を作成」 | 手順書                        |
| ---------------------------------------------------------- | ------------------- | ------------------- | ----------------------------- |
| フォルダとして在る                                         | 押せる              | 出ない              | Step 2 は済み                 |
| 無い                                                       | 押せない            | 出る                | Step 2 が主動作               |
| **フォルダではない**ものが在る（ファイル・リンク）         | **押せる**          | **出ない**          | Step 2 は塞ぐ（先に外させる） |
| **読めていない**（未スキャン・ルートを読めない・切替直後） | 押せない            | **出ない**          | Step 2 は塞ぐ（hero が診断）  |

フォルダでないものが在る回に「開く」を残すのは、**それを見に行くのが唯一の直し方**だから。
作成はファイルが居れば失敗するので出さない。**読めていない回に作成を出さない**のは、
その回が「フォルダでないものが在る」と区別が付かないから（ルートごと読めない回なら、
作成もルートの存在を確かめるので同じ失敗が返る）。

| 段     | 内容                 |
| ------ | -------------------- |
| Step 1 | ルートを選ぶ         |
| Step 2 | `engines/` を作る    |
| Step 3 | エンジンを置く       |
| Step 4 | 評価関数・定跡を置く |

**失敗の振り分けを code で決めている。** AI フォルダの作成が落ちたとき、
名前で直せる失敗（`isNameInputError`）は名前の欄へ返し、
それ以外はスキャン側の診断へ回す。全部をスキャン側に出すと
「フォルダを確認できませんでした／再スキャン」という、読み取りは成功しているのに
嘘で、しかも押しても何も変わらない画面になる。

**`already_exists` はこの振り分けから漏れている** → #456。同名の AI フォルダを打つと、
名前の欄ではなくスキャン側の診断へ回る。

**行き先は3つある。** 3つ目は、作り終える前に AI ルートが変わった回。
画面はもう別のルートを指していて一覧にも出ないので、**欄にも診断にも出さず、通知に出す**
（自分で消える toast。段と見せ方は F-13 と同じ）。打った名前も欄の赤字も動かさない——
直すべき理由だけを消すと、直すべき文字列だけが残る。

## エンジン管理タブ

プリセットの一覧（カード）。1枚が1プリセット。

| カードに出るもの                | 元                                                                          |
| ------------------------------- | --------------------------------------------------------------------------- |
| 名前                            | `label`（空なら「（無名プリセット）」）                                     |
| 適用中                          | `selectedPresetId` と一致                                                   |
| 要設定／設定済み                | `isPresetConfigured`（`aiName` `enginePath` `evalFilePath` が揃っているか） |
| AI名／エンジン／評価関数        | パスは basename だけ                                                        |
| MultiPV / Threads / Hash / Book | `options` と `bookEnabled`                                                  |

`MultiPV >= 2` のときだけ「幅 vs 深さ」の注意書きを出す。

並びは**適用中を先頭**にし、残りは名前順。

| 操作         | 結果                                                                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| カードを押す | そのプリセットを適用（エンジンを再起動する）                                                                                                                                                       |
| 編集         | プリセット編集の別窓 → [engine-preset-dialog.md](engine-preset-dialog.md)                                                                                                                          |
| 複製         | 複製し、**その複製を適用中にする**（一覧の先頭へ移る）。**エンジンは起こし直らない**——複製は起動の設定が元と同一なので同値と見なされる（→ [`engine.md`](../../state-transitions/engine.md) の ※4） |
| 削除         | `window.confirm` で確認。**最後の1枚は消せない。適用中の1枚を消すと、走っている解析が1回切れる**（→ [`analysis.md`](../../state-transitions/analysis.md) の ※5 / #518）                            |
| 再読み込み   | ファイルから読み直す                                                                                                                                                                               |
| 追加         | 「新規プリセット」を作る                                                                                                                                                                           |

## 失敗の見せ方

| 失敗                            | どこに出るか                                 |
| ------------------------------- | -------------------------------------------- |
| 設定の更新                      | ワークスペースタブの上部（`error`）          |
| AI ルートのスキャン             | AI ライブラリタブの中（`role="alert"`）      |
| プリセットの読み書き            | エンジン管理タブの上部                       |
| エンジンの起動                  | 通知（帯。ADR-0004 の F-9）                  |
| フォルダを開けなかった          | 通知（自分で消える toast。ADR-0004 の F-13） |
| AI フォルダの作成が宛先を失った | 通知（同上。台帳の F-37）                    |

「エンジンの起動」は**このタブには出ない。** 出るのは帯で、押すとこのタブへ戻ってくる
（`EngineFailureBridge`。現在地は
[`failure-surfacing.md`](../../state-transitions/failure-surfacing.md) の F-9）。
**このタブが出す `error` はプリセットの読み書きのほうで、エンジンが起動できたかは見ていない。**
解析の断りも復帰手段としてこのタブでの操作を案内するが、**着いた先に理由は1文字も出ない**
——`entities/engine` の `state.error` を描画する行は `src/` に0（→ #523）。

**この画面が出す通知は下の2つ。**（エンジンの起動の失敗を出すのは橋のほうで、
この画面ではない。）どちらも**スキャンの診断へは回さない**
（読み取りは成功しているので「フォルダを確認できませんでした／再スキャン」は嘘になる）。

### 「フォルダを開けなかった」（F-13）

- **どのフォルダかは題で言う**（「AI ルートを開けませんでした」／「engines/を開けませんでした」）。
  自動で消える通知は6秒なので、本文にパスを足すと読み切れない
- **本文で原因を1つに決めない。** そこに無いのか、ファイル管理ソフトを呼べないのかは
  環境で変わる（Linux で D-Bus の相手が居なければ、在るフォルダでも毎回失敗する）
- **「自分で開いてください」と書かない。** 消えたフォルダを探させることになる
- 失敗したら索引を読み直す。消えていれば「engines/ を作成」がその場に現れる

### 「AI フォルダの作成が宛先を失った」（F-37）

- **題で成否を言う**（「前のフォルダに『〜』を作成しました」／「〜できませんでした」）
- **段も成否で割る。** 作れた回は `info`、作れなかった回は `warning`。
  同じ段にすると、記号も面も段が決めるので、6秒で消える2枚の差が**題の末尾の1語**だけになる
- **旧ルートのパスは題にも本文にも書かない。** 6秒で読み切れない（F-13 と同じ理由）
- 本文は1行。失敗側は次の一手を書く。**名前で落ちた回とそれ以外を分ける**——
  名前の失敗は同じ名前では何度やっても通らないので「同じ名前で作り直せます」は嘘になり、
  欄に残っている赤字と正面から食い違う
- 打った名前も欄の赤字も動かさない

## いま満たしていないこと

- **削除に `window.confirm` を使っている。** ADR-0005 が揃えた `ConfirmDialog` を通っていない
- **`console.log(selectedId)` が `useEffect` で毎回走る**（`EngineTab.tsx`）
- **「要設定」「注意」のバッジが中身を見ずに常に出る**
- **プリセットの保存に失敗しても画面は保存済みのまま**になる → #170
- **読み取り警告の一覧を全部見る導線が無い**（件数は出るが、5件より先を読む方法が無い）
- **研究まわりの設定が Settings の中で散らばっている** → #101
- **USI オプションを GUI から編集できない**（編集できるのは MultiPV / Threads / Hash の3つだけ）
  → #83
- **AI フォルダ作成の「同名が既にある」が、名前の欄でなく診断に出る** → #456
- **作成の口を出す条件が、判断（`canCreateProfile`）とその中身の2段になっている** → #475
- **エンジンの列挙とプリセットの候補で、接頭辞の条件がずれている**（`YaneuraOu` と
  `YaneuraOu_`）。この画面が「検出済み」と言うエンジンが、プリセット編集では候補に出ない → #492

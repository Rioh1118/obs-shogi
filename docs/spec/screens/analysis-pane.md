# 画面仕様: 解析ペイン

対象: `src/widgets/analysis-pane/` `src/entities/analysis/` `src/entities/engine/`
`src/features/engine-position-sync/`

状態遷移: [`analysis.md`](../../state-transitions/analysis.md)
／ [`engine.md`](../../state-transitions/engine.md)
／ [`engine-position-sync.md`](../../state-transitions/engine-position-sync.md)

## 目的

**いまの局面をエンジンに読ませ、読み筋と評価値を出す。**
盤まわりの道具（向き・ナビ・検索・課題局面・設定）の入口も、いまここに集まっている。

## 出入口

棋譜が開かれている間、本体の下のドックに常駐する。畳めない。

**畳めないが、消えることはある。** 棋譜を閉じるとペインごと消え（▶ も ■ も無くなる）、
ワークスペースの差し戻し（`RequireRootDir`）は `RuntimeProviders` ごと unmount する。
どちらも走っていた解析には停止を投げる（**失敗しても誰にも届かない**
——出す場所が無い → F-7）。

## 画面構成

```
┌ ヘッダ ────────────────────────────────────────────────┐
│ ● 解析中  1m 12s          [⟳][🧭][🔍][▶/■][🔖][⚙]      │
├ 本体 ──────────────────────────────────────────────────┤
│ 最善手：▲２六歩 △８四歩 ▲２五歩 …      評価値 +123    │
│ 候補：  ▲７八金 …  / ▲６八玉 …                         │
├ 脚注 ──────────────────────────────────────────────────┤
│ depth 28   nodes 12,345,678   time 12,000ms             │
└────────────────────────────────────────────────────────┘
```

ヘッダのボタン6つ:

| ボタン | 動き                                                | 無効になる条件              |
| ------ | --------------------------------------------------- | --------------------------- |
| ⟳      | 盤の向きを反転（`pov`）                             | なし                        |
| 🧭     | `modal=navigation`                                  | `currentSfen` が無い        |
| 🔍     | `modal=position-search`                             | `currentSfen` が無い        |
| ▶ / ■  | 解析の開始・停止                                    | 停止中で `currentSfen` 無し |
| 🔖     | `modal=study-position-save`。登録済みなら塗りつぶす | `currentSfen` が無い        |
| ⚙      | `modal=settings&tab=engine`                         | なし                        |

読み筋は **`convertCandidateToSenteView` で先手視点に揃えてから**表示する。
評価値の符号が手番で反転しないようにするため。

## 状態

| 記号 | 状態             | 判定                              | 出るもの                           |
| ---- | ---------------- | --------------------------------- | ---------------------------------- |
| N0   | 停止中・結果なし | `!isAnalyzing` かつキャッシュ無し | 空欄                               |
| N1   | 停止中・結果あり | キャッシュに当たりがある          | 直前の候補（**古い可能性がある**） |
| N2   | 解析中           | `state.isAnalyzing`               | 届いた候補を順次更新               |

### 結果のキャッシュ

**持ち主は `entities/analysis`**（`entities/analysis/lib/candidateCache.ts`）。
`AnalysisProvider` が ref で握り、context の `candidateCache` として渡す。
`AnalysisPane` はエンジン・ツリーの選択・カーソルの3つを繋いだ鍵
（`` `${engineKey}${fileKey}:${tesuuPointer}` ``。`engineKey` は未選択なら `"no-engine"`）を
組んで読み書きするだけで、**保存場所を持たない。この画面が作り直されてもキャッシュは残る。**

**`ref` に置くのは、キャッシュが読み手より長生きする必要があるから。** `useMemo` は
React の仕様で覚えた値を捨てうるので使わない。`state`（`useReducer`）でも寿命は同じだが、
キャッシュは表示を駆動する state ではなく、`clear_results` の対象にもしない。

- **ツリーの選択が変わったら全部捨てる**（`scopeTo`）。**棋譜を跨いだ持ち越しを断つだけ**で、
  同じ棋譜のままなら局面数 × エンジン数だけ積まれ、件数の上限は無い
- 解析中は生の `state.candidates` を出し、停止中はキャッシュを出す
- 保存を見送るのは `state.analyzedSfen` が今の局面と**違う**ときだけ（まだ解析していない回は保存する）

**キャッシュはメモリだけ。** アプリを閉じると消える。永続化は
`docs/IDEAS.md`（旧 #86–#89）にあり、着手しない。

**鍵と表示は一致を保証していない。** 鍵は盤ではなくツリーの選択から棋譜を取るので、
盤に載る前の1レンダで前の棋譜の候補手が新しい鍵へ入る。改名すると鍵ごと変わって全部消える。
木を編集すると同じ `tesuuPointer` が別の局面を指す。→ #568
控えを読むのはレンダ、書くのは effect なので、鍵が変わった回は控えが出ない。→ #569

### 経過時間

ヘッダのタイマーは `isAnalyzing` が立った時刻からの経過。
**局面が変わると 0 に戻る**（解析中でも）。

## 操作と結果

| 操作               | 結果                                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ▶ を押す           | `startInfiniteAnalysis()`。エンジンが ready でなければ理由ごとの断りを立てて throw（→ [`analysis.md`](../../state-transitions/analysis.md) の ※15）。**画面に出す読み手はまだ0** |
| ■ を押す           | `stopAnalysis()`                                                                                                                                                                 |
| 局面を動かす       | 解析中なら新しい局面を送り直す → [`engine-position-sync.md`](../../state-transitions/engine-position-sync.md)                                                                    |
| プリセットを変える | エンジンを再起動する → [`engine.md`](../../state-transitions/engine.md)                                                                                                          |
| 棋譜を閉じる       | **解析を止めて席を返す。** 開き直しても再開しない → [`analysis.md`](../../state-transitions/analysis.md) の E14                                                                  |
| 画面が畳まれる     | **走っている解析に停止を投げる。** 返さないと以降どの解析も断られる → [`analysis.md`](../../state-transitions/analysis.md) の E13                                                |

## 失敗の見せ方

**レンダ例外を除き、このペインには失敗を出す場所が1つも無い。**

| 失敗                                                                                                         | いま起きること                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ■ の停止が失敗                                                                                               | 表示は停止中になるので**成功したように見える**。断りは `state.error` に載るが読み手は0 → F-7                                                                                                                   |
| 席を返す停止が失敗                                                                                           | どこにも出ない（`console.warn` だけ）。畳まれた後は、席を指した停止なら1回だけ撃ち直す → F-7                                                                                                                   |
| ▶ が失敗した（前置きの門・席を返せない・局面を送れない・開始の拒否・同期の上限切れ・席を取る間の起こし直し） | `state.error` に**枝ごとの断り**が載るが**読み手は0**。枝と次の一手は [`analysis.md`](../../state-transitions/analysis.md) の ※15 → F-2 / F-6                                                                  |
| 解析結果の購読に失敗（起動時1回）                                                                            | `state.error` に断りが載るが**読み手は0**。**張り直す口が無い**ので、以後 ▶ は `go` を出さず断りを立て直す。復帰はアプリの起動し直し → [`analysis.md`](../../state-transitions/analysis.md) の ※15 / F-4       |
| 自動再開が落ちた／同期が上限まで追いつかない（盤を動かした後）                                               | `state.error` に断りが載るが**読み手は0**。**ボタンを1つも押していない**のに停止中になるので、成功した停止と見分けが付かない。枝と次の一手は [`analysis.md`](../../state-transitions/analysis.md) の ※15 → F-2 |
| 起こし直しの最中に自動再開が走った                                                                           | **何も出ない。** 断りを立てずに降りるので「解析中」の表示のまま数字が止まる。エンジンが戻れば同期の追従が張り直す（戻らない回は → [`analysis.md`](../../state-transitions/analysis.md) の ※5 / #502）          |
| エンジンが落ちた                                                                                             | 「解析中」の表示が残ることがある                                                                                                                                                                               |

`entities/analysis` の `error` が立つ口は [`analysis.md`](../../state-transitions/analysis.md) の ※1 が持つ。**UI の読み手は0**。
→ ADR-0004 の実測表 ／ [`failure-surfacing.md`](../../state-transitions/failure-surfacing.md) F-6 F-7

**例外はエンジンの起動の失敗だけ。** これはこのペインではなく帯に出る
（画面に依らない。F-9）。エンジンが要るのはこのペインで、直せるのは設定なので、
どちらを開いていても届く必要がある。**このペインが出せないのは解析の開始・停止の失敗**
（F-6 / F-7）のほう。

レンダ中に throw した場合は解析ペインを包む `AppErrorBoundary` が受け、**畳まれるのは
ドックの中だけ**になる。盤と棋譜一覧は残る。エンジンの応答は形が保証されていないので、
この画面はいちばん落ちやすい面でもある。→ [app-layout.md](app-layout.md) の「失敗の見せ方」

## いま満たしていないこと

- **解析が始められない理由が出ない**（上記）→ #277 ADR-0004
- **停止が届かなかった回に席が残る。** ▶ が握った席を返してから始めるので画面からは
  戻れるが、その停止も落ちた回、棋譜を閉じた回（開き直してから ▶）、
  畳まれた後に落ちた回は残る（エンジン側の失敗では席は空く → F-7）→ #172
- **エンジンを起こし直すボタンが画面に無い。** `restart` は context に出ているが、
  UI から呼ぶ口は1つも無い。席が残って ▶ も効かない回の復帰は、設定タブで
  `runtimeConfig` を動かすこと——**選択中のプリセットのオプションを1つ変えて保存する**
  でもよい（判定は [engine.md](../../state-transitions/engine.md) の ※5）。
  プリセットが1つしか無い利用者にはこれしか無い → #172
- **エンジンが起動していないことが、帯を閉じたあとはどこにも残らない** → #523
- **エンジンが USI に応答しないと、停止も再初期化もできなくなる** → #252
- **`entities/analysis` に未検証の状態遷移が残っている** → #158
- **候補手のキャッシュの鍵が、盤に載っている棋譜と食い違う** → #568
- **キャッシュを読むのがレンダ、書くのが effect なので、鍵が変わった回は出ない** → #569
- **完了もエラーも画面へ飛ばない。** `analysis-complete` / `engine-error` を emit する行が
  Rust に無い。エンジンが探索を終えても「解析中」の表示が残る → #356
- **解析は infinite しか無い。** 時間・深さ・ノード・詰の指定が preset から届かない
  → #107 #110
- **盤の道具（向き・ナビ・検索・課題局面・設定）が解析ペインのヘッダに同居している。**
  解析と関係のないものが混ざっている

## これからの要件

- **このペインはドックのタブの1つ（解析ビュー）になる**
  → [ADR-0010](../../decisions/0010-dock-tabs-and-view-vocabulary.md)
  ／ [dock-tabs.md](../../state-transitions/dock-tabs.md)。
  盤の道具（⟳ 🧭 🔍 🔖）はヘッダから盤ペイン側へ返す（#562）
- **候補手の見せ方を3つの表示モードにする**（行 / 表 / 一覧＋詳細）。
  読み筋が右端で切れて `title` 属性でしか読めないのと、入りきらない候補手に
  スクロールで届かないのを、ここで解く → #563
- **評価値バーは既定で出さない。実装は残す**（設定「表示」から出せる）。
  目盛が ±3000 の線形で勝率と対応しないため、隣の数字より読める情報が無い
- **有限モードの解析**（`go movetime` / `depth` / `nodes` / `mate`）。
  プリセットの「解析の既定値」は入力欄まで用意されているが、実行へ届いていない
  → [features/engine-options.md](../features/engine-options.md)
- **定跡の当たりを出す。** 現局面が定跡内かどうかと、その手の勝率・採用数
  → [features/book.md](../features/book.md)

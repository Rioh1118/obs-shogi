# 画面仕様: 棋譜ストリーム

対象: `src/widgets/kifu-stream/` `src/features/kifu-comment-note/`
（枝の編集は `src/entities/kifu/lib/branchEdit.ts`）

状態遷移: [`docs/state-transitions/game.md`](../../state-transitions/game.md)
／ 枝を指す値の分類は [`branch-index.md`](../../state-transitions/branch-index.md)

## 目的

**手の一覧を出し、局面を選ばせる。** 分岐の切り替え・入れ替え・削除と、
手ごとのコメントもここが持つ。

## 出入口

棋譜が開かれている間、本体の右側に常駐する。棋譜が無いときは
「棋譜ファイルを選択してください」の1行だけ。

## 画面構成

```
手数 12/57                      ← 現在地／終端（分岐計画こみ）
┌────────────────────────────┐
│    開始局面           [💬]  │
│ 1  ▲７六歩           [💬2] │
│ 2  △３四歩      [⑂3 2][💬]│  ⑂ = 分岐の数と選択中の番号
│ 3  ▲２六歩           [💬]  │
└────────────────────────────┘
```

各行が持つもの（`RowModel`）:

| 欄                  | 内容                                         |
| ------------------- | -------------------------------------------- |
| `te`                | 手数。0行目は「開始局面」で数字を出さない    |
| `text`              | 読める形の指し手。投了・中断も同じ欄に入る   |
| `forkCount`         | その手数の分岐の本数。0 ならバッジを出さない |
| `selectedForkIndex` | いま選んでいる変化の番号（本譜なら `null`）  |
| `commentCount`      | コメントの本数                               |

行を押すとその手数へ移る。**現在行は自動でスクロール位置に戻る**
（`scrollToRowSafeZone`。連続移動中は `smooth` をやめて追従を優先する）。

## 状態

| 記号 | 状態                 | 判定                      | 見えるもの                   |
| ---- | -------------------- | ------------------------- | ---------------------------- |
| K0   | 棋譜なし             | `view.player` が無い      | 案内の1行                    |
| K1   | 一覧                 | 上記以外                  | 行の並び                     |
| K2   | 分岐メニューを開いた | `openFork !== null`       | 分岐の候補＋上へ／下へ／削除 |
| K3   | 手の操作メニュー     | `openMoveMenu !== null`   | 「ここから削除」             |
| K4   | コメントを編集中     | `openComment !== null`    | `FloatingNote`（Markdown）   |
| K5   | 削除の確認中         | `pendingDelete !== null`  | `ConfirmDialog`              |
| K6   | 削除の実行中         | `deleting === その query` | 確認の中が「削除中...」      |

**面は同時に1つしか開かない。** どれかを開くと他の2つを閉じる。
Escape は最上位の1枚だけが受ける（`overlayStack`）。

## 操作と結果

| 操作                               | 結果                                                       |
| ---------------------------------- | ---------------------------------------------------------- |
| 行をクリック                       | その手数へ移る                                             |
| 分岐バッジをクリック               | 分岐メニューの開閉                                         |
| 分岐メニューで候補を選ぶ           | その変化へ乗り換える（同じ手数なら `applyCursor`）         |
| 分岐メニューの「上へ」「下へ」     | 枝の順番を入れ替える。**失敗しても画面には出ない**（#277） |
| 分岐メニューの「削除」             | 確認を出す                                                 |
| 手の操作メニュー →「ここから削除」 | 同じ確認を出す                                             |
| コメントバッジ                     | その手のコメント欄を開く                                   |

### 削除の確認

取り消しは無く（ADR-0004 決定8 は undo を採らない）、削除は
**そのまま元のファイルへ書き込まれる**。誤クリックでも同じ結果になるので、
「上へ」「下へ」と区切り線1本しか隔てていない「削除」には必ず確認を挟む。

確認文は「**何が**消えるか」を必ず含む。

> `▲２六歩 から先（14手）が消えます。この操作は取り消せません。棋譜ファイルもすぐ書き換わります。`

- 1手目が読めなければ「本譜」「変化N」で代える
- 手数が数えられなければ「手数は数えられませんでした」と書く。
  **数が出ないことを理由に確認を飛ばさない**

確認を出したまま棋譜が変わったら、確認は閉じる（別のファイルの枝が消えるのを防ぐ）。

### コメント

`KifuCommentNote` は `FloatingNote` の上に立つ Markdown の入力欄。

- 打鍵が止まって **900ms** で自動保存する
- 保存中／保存済みの印を出す。失敗したら本文と原因を出し、**閉じない**
- 保存は直列に繋ぐ（`chainRef`）。並行して撃たない
- コメントの保存は **`isLoading` を立てない**（利用者を待たせていないため）。
  立てると自動保存のたびに行のクリックが死ぬ

## 失敗の見せ方

| 失敗                     | どこに出るか                               |
| ------------------------ | ------------------------------------------ |
| 枝の削除                 | 確認ダイアログの中（閉じていても開き直す） |
| コメントの保存           | コメント欄の中                             |
| 枝の入れ替え             | **出ない** → #277                          |
| 再生できない手を含む棋譜 | **一覧がまるごとエラー表示になる** → #295  |

削除は「書けたときだけ閉じる」。先に閉じると、失敗しても画面からは
枝が消えたように見える（メモリ上は巻き戻るのでファイルには残る）。

## いま満たしていないこと

- **`buildStreamRowsFromCursor` は再生できない手で投げる。** レンダ中なので
  `AppErrorBoundary` が受け、棋譜ペインが行き止まりになる → #295
- **枝の入れ替えの失敗に出口が無い** → #277
- **矢印キー1打ごとに全行が作り直され、行の memo が効かない** → #205
- **行が持つ分岐パスが計画から作られるため、削除・入れ替えが例外で失敗する** → #196
- **コメントを保存すると、見ていた変化の計画が消える** → #226
- **空の変化の `forkIndex` の付け方が Rust の索引と食い違う** → #199
- **分岐メニュー・操作メニューの開閉と位置決めに未解決の問題がまとまっている** → #278

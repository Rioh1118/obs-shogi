# 画面仕様: アプリのシェル

対象: `src/pages/AppLayout.tsx` `src/widgets/app-layout-header/`
`src/widgets/sidebar/ui/Sidebar.tsx` `src/pages/WelcomeScreen.tsx`
`src/shared/ui/TitleBar.tsx` `src/features/board-orientation/`
`src/features/clear-board-selection/`

**「失敗の見せ方」だけはこの画面の外も持つ**（段構えの出典をここに置いているため）:
`src/app/App.tsx` `src/app/routing/RuntimeShell.tsx` `src/app/RootErrorFallback.tsx`
`src/pages/AppModalLayer.tsx` `src/shared/ui/AppErrorBoundary.tsx`
`src/shared/ui/error-fallback/ErrorFallbackBody.tsx`

## 目的

**棋譜を開いている間ずっと出ている枠。** どの棋譜を見ているか、いま何手目か、
手番はどちらかを常に示し、ツリー・盤・棋譜・解析ペインの位置を決める。

## 出入口

`/app` に入ると必ずこれが出る。閉じる導線は無い（ワークスペースを変えると
`window.location.reload()` で作り直される）。

## 画面構成

```
┌────────────────────────────────────────────────────────────┐
│ TitleBar（Tauri のウィンドウ枠。ドラッグ領域）             │
├────────────────────────────────────────────────────────────┤
│ AppLayoutHeader                                            │
│  [◧] │ obs-shogi │ ファイル名 ▲手番 N手目 │ 先手・後手 │ [📚][⚙] │
├──────────────┬─────────────────────────────────────────────┤
│ Sidebar      │ 本体                                        │
│ （ツリー）    │  ┌─ 盤ペイン ────────┬─ 棋譜ペイン ──┐    │
│              │  │ 後手駒台           │                │    │
│              │  │ 盤（9×9）          │ 棋譜ストリーム │    │
│              │  │ 先手駒台           │                │    │
│              │  │ ◀◀ ◀ ▶ ▶▶ 操作列   │                │    │
│              │  └────────────────────┴────────────────┘    │
│              │  ┌─ ドック ────────────────────────────┐    │
│              │  │ 解析ペイン                           │    │
│              │  └──────────────────────────────────────┘    │
└──────────────┴─────────────────────────────────────────────┘
```

棋譜を開いていないときは、本体まるごとが `WelcomeScreen` に置き換わる。

### ヘッダの中身

| 位置   | 中身                                                                         |
| ------ | ---------------------------------------------------------------------------- |
| 左     | サイドバーの開閉トグル                                                       |
| 中央左 | アプリ名                                                                     |
| 中央   | ファイル名／手番バッジ／手数バッジ／対局者名（`useHeaderCenterInfo` が組む） |
| 右     | 課題局面（本アイコン）／設定（歯車）                                         |

対局者名が入っていない棋譜では、名前の代わりに「棋譜表示中」とだけ出る。

### サイドバー

`Sidebar` は器で、`isOpen` が偽なら `null` を返す（アンマウントする）。
**中身は自分では決めない。** `AppLayout` が `<Outlet />` を `children` として渡し、
いま入るのは `/app/panel/filetree` だけ。→ [file-tree.md](file-tree.md)

### WelcomeScreen

棋譜が開かれていないときだけ出る。読める形式（`.kif` `.ki2` `.csa` `.jkf`）を
並べ、**「棋譜を作る」を1つだけ置く**（`modal=create-file` を開く）。

置いてあるのは、棋譜が1本も無いワークスペースだと**この面が行き止まりになる**ため。
「ツリーから選べ」としか言わないのに、ツリーには選べるものが無い。
開く側の導線はツリーが持つので、ここは作る側だけを持つ。

**保存先は渡さない。** ここからは `dir=` が決まらないので、
組む面の保存先の欄が受け持つ → [create-file.md](create-file.md)

## 状態

| 記号 | 状態         | 判定                      | 本体に出るもの           |
| ---- | ------------ | ------------------------- | ------------------------ |
| L0   | 棋譜なし※    | `gameView.hasKifu` が偽   | `WelcomeScreen`          |
| L1   | 棋譜あり     | 同上が真                  | 盤・棋譜・解析ペイン     |
| Ls   | サイドバー閉 | `isSidebarOpen === false` | サイドバーがアンマウント |

※ **L0 は「まだ開いていない」だけではない。** 開いたが盤に載せられなかったとき、
**前に載せていた棋譜が無ければ** L0 のまま（下の「失敗の見せ方」）。
前の棋譜があれば `state.jkf` はそれを保つので `hasKifu` は真——**L1 のまま動かない**。

`isSidebarOpen` は `AppLayout` のローカル state。**URL にも設定にも残らない**ので、
リロードすると開いた状態に戻る。**持ち越さないのが意匠。** どのパネルを出すかは
URL（`panel/*`）が持つが、開閉はそちらへ揃えない。

## 操作と結果

| 操作                   | 結果                                                         |
| ---------------------- | ------------------------------------------------------------ |
| サイドバーのトグル     | 開閉。ツリーはアンマウントされ、展開状態は provider 側に残る |
| ヘッダの本アイコン     | `modal=study-positions` を開く                               |
| ヘッダの歯車           | `modal=settings&tab=workspace` を開く                        |
| 盤・駒台の**外**を押す | 駒の選択を解除する                                           |
| 別の棋譜が盤に載る     | `pov` を落とす（盤の向きは棋譜をまたいで持ち越さない）※      |

※ 落ちるのは**盤に載っている棋譜**が変わったときだけ。ツリーの選択が動いただけ、
開いたが盤に載せられなかった、開いている棋譜を改名・移動しただけ、では落ちない。
→ [board-orientation.md](../../state-transitions/board-orientation.md)

### 盤の外を押すと選択が解除される

`onPointerDownCapture` が盤の内側の外を拾って `clearSelection()` を呼ぶ。
**キャプチャ段階で拾う**ので、下にあるボタンの `onClick` より先に走る。

捕まえるのはページの根（盤より広い範囲を見ないと「外」を判定できない）だが、
**何が内側かは `src/features/clear-board-selection/` が持つ**。升と駒台に付ける
目印もそこから来るので、ページは盤の目印の綴りを知らない。

## 失敗の見せ方

**レンダ例外は段構えで受ける。レンダ例外なら、ウィンドウを閉じる手段は画面に残る。**
（`createRoot` に入る前に落ちた場合はこの限りではない → #513）
**この節が段構えの出典。** 台帳（[failure-surfacing.md](../../state-transitions/failure-surfacing.md)）は
ここを指すだけで、同じことを書かない（2箇所に置くと片方だけ直る）。

（レンダ例外以外の失敗はこの下に1つある）

| 境界                                          | 名乗り       | 畳まれる範囲                                              |
| --------------------------------------------- | ------------ | --------------------------------------------------------- |
| `App` の `.app-root` の内側                   | アプリ       | **最後の砦。** `/` と `/app` の全部（更新の知らせを除く） |
| `App` の `UpdaterScreen` を包む               | 更新の知らせ | 更新のカードだけ                                          |
| `RuntimeShell` の `.app-content` の内側       | 作業画面     | `/app` の中身。ヘッダとサイドバーもここ                   |
| `ModalLayerContent` を包む（`AppModalLayer`） | モーダル     | モーダルの層だけ（9枚まとめて）                           |
| 盤ペインを包む（`AppLayout`）                 | 盤           | 盤と操作列                                                |
| `KifuStreamList` を包む（`AppLayout`）        | 棋譜一覧     | 棋譜一覧だけ                                              |
| 解析ペインを包む（`AppLayout`）               | 解析         | ドックの中だけ                                            |

**いちばん内側の境界が受ける**ので、畳まれるのは落ちた部分だけ。畳んだ範囲は
**その境界が名乗る**（「盤を表示できませんでした。」）。同じ文言だと、内側の1枚を外しても
外側が同じ画面で受けて退行が見えない。

**枠が残るかは、どの境界が受けたかで決まる。** ウィンドウ枠は自前（`decorations: false`）で
`TitleBar` は `RuntimeShell` の中に居るので、`.app-content` 以下で受けたぶんには本物の枠が残る。
root まで上がるのは**境界の外に居るもの**が落ちたとき —— provider・guard・ルータ自身、
`TitleBar` そのもの、そして `RuntimeShell` の外に居る `/` の起動画面
（→ [boot.md](boot.md)）。そのときは `RootErrorFallback` が**自前のドラッグ領域と
閉じるボタン**を描く。

**出口は3つあり、境界によって持っているものが違う。**

| 出口        | 何をするか                                               | どの境界が持つか                            |
| ----------- | -------------------------------------------------------- | ------------------------------------------- |
| `再表示`    | 境界の `error` を消して描き直す                          | 全部                                        |
| `resetKeys` | 鍵が動けば**利用者の操作なしに**解ける                   | 作業画面・モーダル層                        |
| `閉じる`    | 箱を画面から消す（**畳んだままにする**ので子は戻らない） | 浮かせて出す2枚（更新の知らせ・モーダル層） |

**`再表示` は効かないことがある。** 原因が境界の外（provider の state）にあれば
同じ行で落ち直し、画面は変わらない。逆に原因が消えても、鍵を渡していない境界はそれを知らない。
**何を鍵にしているか・ほかにどんな出口を並べているかは各境界の呼び出し側が持つ**
（モーダル層は `useModalLayerResetKeys` と、立っている知らせを捨てる出口）。ここに写さない。

**見せ方は境界が決めない。** `AppErrorBoundary` が持つのは「捕まえたか」と `resetKeys` だけで、
何をどう出すかは呼び出し側が `fallback` に組む。置き方は3通り。

| 置き方           | 何を使うか                                | どの境界が使うか             |
| ---------------- | ----------------------------------------- | ---------------------------- |
| 流れの中         | `ErrorFallbackBody`                       | 作業画面・盤・棋譜一覧・解析 |
| 浮かせる         | `FloatingErrorFallback`（器へ `portal`）  | 更新の知らせ・モーダル層     |
| ウィンドウ枠ごと | `RootErrorFallback`（帯と閉じるを自前で） | アプリ                       |

**浮かせる2枚は自分で座標を持たない。** `index.html` の `#error-overlay-root` が縦に積むので、
同時に何枚出ても重ならない。平常時 in-flow の箱を作らない部品（`createPortal` で出す更新の知らせ、
閉じている間 `null` を返すモーダル層）を、流れの中の箱で置き換えないための逃がし先でもある。

### 棋譜を開いたが盤に載せられなかったとき、動くのはツリーの選択とモーダルだけ

`openKifuNode` は構文として読めれば通すので、ツリーの選択と `activeKifuPath` は動く。
その先の `loadGame` が落ちると `GameFileTreeBridge` がモーダルを出す（`danger`）。

盤・棋譜一覧・ヘッダのファイル名・ヘッダの対局者名・盤の対局者名は、どれも
`game` の `state.loadedAbsPath` / `state.jkf` 由来なので、盤が動かない回は見出しも動かない。起動直後なら本体は `WelcomeScreen` のままで、
前の棋譜を開いていたならその棋譜がそのまま残る。**モーダルがどのファイルの話かを言う。**

ツリーの行のハイライトだけは載せられなかったファイルへ移る。`openKifuNode` が選択を
戻すのは読み込みかパースが失敗した回だけで、`loadGame` の失敗はそこまで届かない。

**もう一度クリックすれば開き直しに行く。** 関門（`FileNode` の `canSkipReopen`）が
省くのは、**ツリーと盤の両方**がそのパスを指しているときだけ
（→ [board-orientation.md](../../state-transitions/board-orientation.md) の ※7）。
載せられなかったファイルは盤が指していないので押し直せるし、盤に残っている前の棋譜も
`activeKifuPath` が別を指している間は押し直せる。**前の棋譜を押し直すのが、
編集できる状態へ戻す唯一の操作。**
→ [game.md](../../state-transitions/game.md) の E16、
[failure-surfacing.md](../../state-transitions/failure-surfacing.md) の F-31

## いま満たしていないこと

- **サイドバーに入る面が1つしか無い。** `panel/*` の形だけがある
- **ウィンドウを既定より小さくするとレイアウトが破綻する** → #32
- **ウィンドウを閉じると、実行中のファイル操作と未保存の入力が確認なしで消える** → #176
- **`再表示` は原因が境界の外にあると効かない。** 押しても画面が変わらない → #511
- **ヘッダとサイドバーに個別の境界が無い。** ツリーが落ちると作業面ごと畳まれる → #512
- **`createRoot` に入る前に落ちると、いまも閉じられない白い窓になる** → #513
- **閉じる操作そのものの失敗は画面にもログにも出ない**（`TitleBar` の3つ）→ #514

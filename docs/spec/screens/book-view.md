# 定跡ビュー

対象: `widgets/book-view/` `entities/book/` `app/providers/gates/BookPositionGate.tsx`。
置き場の決定は [ADR-0010](../../decisions/0010-dock-tabs-and-view-vocabulary.md)、
遷移は [book-view.md](../../state-transitions/book-view.md)、
機能全体は [features/book.md](../features/book.md)。

## 目的

**いま盤に出ている局面について、開いている定跡が何を登録しているかを見る。**
自分のエンジンに食わせている定跡が、この局面で何を返すのかを確かめる面。

## 出入口

ドックのタブ（`dock=book`）。タブ一覧に出すかは設定「表示」が決める。
**閉じる導線は無い**（タブを移るだけ）。

## 画面構成

```
┌─ ドック ─────────────────────────────────────────────┐
│ [解析] [定跡]                                        │  ← タブ列（器のもの）
│ user_book1.db · 1,284,551 局面        [📂] [✕]      │  ← 操作列
├──────────────────────────────────────────────────────┤
│ 指し手   評価   深さ   出現回数   応手    この先     │
│ △８六歩  +42    32     15,204     ▲同歩   → 14手目  │
│ △３四歩  +38    32     28,801     ▲２五歩 → 22手目  │
│ △７二銀  +55    30         12     —       行き止まり │
└──────────────────────────────────────────────────────┘
```

**盤を持たない。** 盤は `AppLayout` のものが現局面で、ここが出すのはその局面に対する
指し手の一覧。「その手を指した先も定跡にあるか」は2枚目の盤ではなく**「この先」列**が出す。

**行は押せない。** 押した先に出すものが無い（詳細ペインを持たない。判断は ADR-0010 決定2）。

### 列

| 列       | 中身                                | 欠けているとき              |
| -------- | ----------------------------------- | --------------------------- |
| 指し手   | 日本語表記                          | 読めなければ USI のまま出す |
| 評価     | 手番側から見た評価値。符号つき      | `—`                         |
| 深さ     | その手を決めたときの探索深さ        | `—`                         |
| 出現回数 | 数字と、一覧の最大値を 1 とするバー | `—`（バーは長さ 0）         |
| 応手     | 定跡が持つ相手の応手                | `—`                         |
| この先   | 定跡を辿った長さ                    | 辿り終える前は `…`          |

**出現回数のバーは相対。** 回数の桁は定跡によって違うので、絶対値では比べられない。
比べたいのは「この局面の中でどれが多く選ばれたか」。

**「この先」の綴りは4つ。** `→ N手目`（そこで定跡が切れる）／`行き止まり`（その手の
先は載っていない）／`N手目以降`（辿る手数の上限に当たった。**まだ続きうる**）／
`読めない手`（定跡の手をこの局面に当てられない）。

### 並べ替え

**既定は定跡ファイルに書かれている順。** 辿る先を決めているのもその順なので
（Rust の `walk_line`）、既定を評価値にすると「この先」列の根拠と画面の並びが食い違う。

評価・深さ・出現回数の見出しを押すと大きい順、もう一度押すと小さい順。
指し手の見出しを押すと定跡の順へ戻る。
**欄が欠けている行は、向きに関わらず必ず下。**

並べ替えは**この画面の持ち物**で、局面を跨いで保つが設定には残らない。

## 状態

**1つの値（`BookViewState`）が決める。** 真偽値を並べると画面が同時に2つのことを
言えてしまう —— 引けなかった回に「この局面はこの定跡にありません」と断言する形が
作れる。

| 状態               | 出るもの                                           |
| ------------------ | -------------------------------------------------- |
| 定跡を開いていない | 押せば開く一覧（下）                               |
| 開いている最中     | 「〈ファイル名〉 を開いています…」                 |
| 盤に局面が無い     | 見出しだけの表と「盤に局面がありません」           |
| 引いている最中     | 見出しだけの表と「引いています…」                  |
| 現局面が定跡にある | 候補手の表                                         |
| 現局面は定跡に無い | 見出しだけの表と「この局面はこの定跡にありません」 |
| 引けなかった       | 見出しだけの表と「この局面は引けませんでした」     |

**「定跡に無い」と「引けなかった」を混ぜない。** どちらも行が0本だが、前者は
*定跡の中身についての事実*で、後者は*何も分かっていない*。定跡ビューを見に来る
理由がその事実なので、取り違えると利用者は自分の定跡を誤って判断する。

**開けなかったときは「開いていない」に留まる。** 別の定跡を開き直す導線が
その画面にあるため。失敗は帯に出る。

網羅は [state-transitions/book-view.md](../../state-transitions/book-view.md)。

## 操作と結果

| 操作                       | 結果                                                      |
| -------------------------- | --------------------------------------------------------- |
| 空の画面の1件を押す        | その定跡を開く。開けたら「最近開いた定跡」の先頭になる    |
| 「別の定跡を開く…」        | ファイルダイアログ（`.db` `.bin` `.sbk` `.ybb`）          |
| 操作列の 📂                | 同上                                                      |
| 操作列の ✕                 | 閉じる。行も消える                                        |
| 盤・棋譜ナビで局面を動かす | 引き直す。**前の局面の行は残さない**                      |
| 別のタブへ移って戻る       | **開いている定跡も行もそのまま**（provider はドックの外） |

### 定跡を開く導線

**AI ライブラリの一覧を出さない。** そちらは*エンジンに食わせる*定跡を選ぶ場所で、
ここが覗くのは任意のパス。混ぜると、プリセットの設定欄とビューが見ている定跡が
同じものに見える（用途が別なので UI で混ぜない。#96）。

空の画面に出るのは2つの束。

- **このエンジンの定跡** —— 選んでいるプリセットが `BookFile` として指しているパス。
  `bookEnabled` が偽なら出さない
- **最近開いた定跡** —— `AppConfig.book_recent_paths`。**開けたものだけ**が残る

**起動時に勝手に開き直さない。** 定跡は GB 級になりうるので、開くのは必ず押されてから。

## 失敗の見せ方

表の上に `InlineNotice`。**閉じる口は持たない**（出ているあいだはその場所の状態が
直っていないということなので、閉じても状態は変わらない）。消えるのは引き直したときと
開き直したとき。

段は「復帰に何が要るか」で切る（ADR-0004）。読み書きの失敗は `warning`、
ファイルが無い・読めない・形式が違うは `danger`。**閉じられたハンドルも `danger`**
——「開き直す」は別の操作で、同じ操作の再試行では永久に直らない。
そのときは定跡を閉じた扱いに戻し、開き直す一覧がある画面へ返す。

**辿るのに失敗しても表は消さない。** 引けてはいるので、埋まらないのは「この先」列だけ。
**ただし列は「…」のままにしない** —— 辿るのはもう終わっているので、
そのままだと利用者は待てば埋まると読む。帯の題も「定跡の先を辿れませんでした」にして、
行が並んでいるのに「読めませんでした」と言わない。

レンダ例外は `Dock` の境界が受け、**タブ列より内側**（操作列と本体）が畳まれる
（→ [app-layout.md](app-layout.md) の「失敗の見せ方」）。
**開いている定跡は閉じない** —— provider はドックの外に居る。

## いま満たしていないこと

- **読めるのは `.db` だけ。** 他の3形式は選べるが `unsupported_format` で落ちる（#93 #94）
- **重ねて引けない。** 開けるのは1冊で、「出どころ」列も無い（#96）
- **編集できない。** 追加・封じ・評価値の直しは無い（#99 #97）
- **掘れない。** 選んだ局面をエンジンに読ませて書き戻す導線は無い
- **大きい定跡に上限も進捗も中断も無い。** 開いている間、画面は待つだけ（#197）
- **勝率を出さない。** やねうら王テキスト定跡に勝率の欄が無い
- **辿る手数に上限がある。** 上限に当たったことは列に出るが、その先は辿らない

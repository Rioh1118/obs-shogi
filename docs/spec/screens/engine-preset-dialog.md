# 画面仕様: エンジンプリセットの編集

対象: `src/features/settings/ui/engine-preset-dialog/`
`src/entities/engine-presets/`
URL を持たない（設定の「エンジン管理」タブの上に重なる別窓）

## 目的

**1つのエンジンを「どう起動して、どう読ませるか」を1枚にまとめる。**
エンジン本体・評価関数・定跡・USI オプション・解析の既定値が1つのプリセットになる。

## 出入口

エンジン管理タブのカードの「編集」で開く。閉じるのは「保存」か「キャンセル」か Esc。

**URL に乗らない**ので、リロードすると閉じる。
編集中の内容は下書き（`draft`）にしか無いので、閉じると消える。

編集中にそのプリセットが消えたら、自動で閉じる。

## 画面構成

4つの節を縦に並べる。

| 節                 | 中身                                                   |
| ------------------ | ------------------------------------------------------ |
| 基本               | 名前 / AI プロファイル（`ai_root` 直下のディレクトリ） |
| エンジンとファイル | エンジン本体 / 評価関数 / 定跡の有無と定跡ファイル     |
| 重要なオプション   | MultiPV / Threads / USI_Hash                           |
| 解析の既定値       | 時間 / 深さ / ノード / 詰み探索                        |

### 候補の集め方

開いたとき `scanAiRoot(ai_root)` を1回走らせ、その結果から候補を作る。
`ai_root` が未設定なら候補は空になり、節の中から選び直せる。

| 選択肢          | 元                                                                                                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| AI プロファイル | `index.profiles`                                                                                                                 |
| エンジン        | `index.engines` の全部。**名前で絞らない**（列挙は engines/ の直下と1段下のフォルダの実行ファイルを見る）。`presetEngineOptions` |
| 評価関数        | 選んだプロファイルの `eval/`（`nn.bin` を先頭へ寄せる）                                                                          |
| 定跡            | 同じプロファイルの `book/` の `.db`                                                                                              |

起動できない見込みのエンジンも**外さずに**、名前の後ろに理由を添える（選んだときは「選択:」の行にも）。

| 見込み（`launchability`） | 添える理由                           | 選べるか |
| ------------------------- | ------------------------------------ | -------- |
| `ready`                   | —                                    | 選べる   |
| `notExecutable`           | 実行権限がありません                 | 選べる   |
| `quarantined`             | macOS がまだ開くのを許可していません | 選べる   |
| `unreadable`              | 読めません                           | 選べない |
| `wrongPlatform`           | 別の OS 向けです                     | 選べない |

ファイルでないもの（開けないフォルダ）も選べない。`notExecutable` / `quarantined` はアプリの外で直せば
動くので選べる（直さずに起動すれば、起動の失敗の帯が確かめる場所を言う。`quarantined` は macOS の許可、
`notExecutable` は場所か実行権限）。

候補に無い現在の選択（手で入れたパス、消えたエンジン）は、候補の先頭に「（現在の選択）」として残す。
落とすと選択が消えて画面が壊れる。

### オプションの定義の取得

エンジンを選んだとき（一覧から選ぶ）と「オプションを読み込む」を押したときに、そのエンジンを起こして
申告（名前・作者・オプションの定義）だけを取り、すぐ落とす（`probe_engine`）。**開いただけでは起こさない。**
手でパスを打ったときも起こさない（打鍵のたびに起こさないため。読み込むボタンで取る）。

- 取った定義は下書きに入り、保存でプリセットに残る（`definitions` / `definitionsFor` / `probedAt` /
  `engineName` / `engineAuthor`）。**画面に出すためだけのもの**で、送る側は起動のたびの申告を見る
- 定義は取ったエンジン（`definitionsFor`）が選んでいるエンジンと同じときだけ「取得済み」と言う
- 取得中は保存できない。最後に撃った取得の結果だけを使う（前のエンジンの取得が後から返っても使わない）
- 失敗は起動の失敗と同じ種類で届き、理由を欄の下に出す（`probeStatus.ts`）
- **利用者の値はまだ定義に当てない**（丸め・外しは画面のオプションの節と一緒に入れる）

### 空欄だけの自動補完

候補が揃った時点で、**空の欄だけ**を埋める。

1. AI プロファイルが空 → `eval` を持つ最初のプロファイル
2. エンジンが空 → **選べる候補がちょうど1つのときだけ**それ。2つ以上なら埋めない（先頭は並びの都合でしかない）
3. 評価関数が空 → `nn.bin`、無ければ最初のファイル
4. 「解析で定跡を使う」にしていて定跡が空 → 最初の `.db`

**すでに入っている値は上書きしない。** 定跡を「解析で使わない」にしても、選んだ定跡は残す
（定跡ビューが出す。切ったことは起動のたびに Rust が送る）。

**1つも埋めなかったら同じ下書きをそのまま返す**（`autofillPreset`）。新しい値を返すと、
この補完を出している effect が自分の出力を依存に持っているので回り続ける。

### 数値の3欄

| 項目     | 取りうる値                           | 「自動」の意味   |
| -------- | ------------------------------------ | ---------------- |
| MultiPV  | 1〜`MULTIPV_MAX`。よく使う値はボタン | —（自動は無い）  |
| Threads  | 1〜論理コア数                        | `min(コア数, 8)` |
| USI_Hash | 128〜65536 MB                        | 既定値 1024 MB   |

「自動／手動」は**保存する値ではない**。開いたときに
「いまの値が推奨値と一致するか」で決め直す。

## 状態

| 記号 | 状態           | 判定                        | 出るもの                        |
| ---- | -------------- | --------------------------- | ------------------------------- |
| G0   | 閉             | `open === false`            | 何も描かない（Hook も走らない） |
| G1   | スキャン中     | `indexStatus === "loading"` | 候補が空のまま                  |
| G2   | スキャン失敗   | `indexStatus === "error"`   | `AI_ROOT のスキャンに失敗…`     |
| G3   | 編集中         | `indexStatus === "ok"`      | 候補が入った状態                |
| G4   | 入力の誤りあり | `errors` が空でない         | 欄ごとに赤字                    |

`open === false` のときは Hook を1つも呼ばない
（`EnginePresetEditDialogPanel` が Hook 無しのラッパになっている）。

### `engines/` の見せ方

`engines` が何として在るかで帯が変わる（分類は `classifyEnginesDir`）。
**4つとも表に載せる**——文言は `Record` で持っているので、状態が増えた日に tsc が落ちる。

| `engines` が   | 帯                                    | 押せる口                 |
| -------------- | ------------------------------------- | ------------------------ |
| 読めていない   | 出ない                                | —                        |
| フォルダ       | 出ない                                | —                        |
| 無い           | `engines/ ディレクトリが存在しません` | 「作成」／「再スキャン」 |
| フォルダでない | `engines がフォルダではありません`    | 「再スキャン」だけ       |

帯が映すのは**いま指しているルートの索引だけ**。選び直した直後は走査が返るまで
「読めていない」に落ちる（前のルートの絶対パスを名乗りながら、隣のボタンが
新しいルートに対して働く形を避ける）。同じルートを読み直している間は前の索引のままなので、**帯の「作成」は押せない**
（押せると「効かなかった」と読まれてもう一度押される）。
**「再スキャン」はどちらも押せるまま**——この帯は `engines` が無い／フォルダでない回にしか
出ないので、常設の再試行の口は基本の節の側が持つ。走査が返らない環境（応答しないボリューム）で
そこを塞ぐと、閉じて開き直す以外に出口が無くなり、編集中の下書きが消える。

**同じフォルダを選び直した回は、この画面が自分で読み直す。** `ai_root` が変わらないので
走査の effect は再走しない——効かなくなった外付けを繋ぎ直した人が、唯一押せる口を押しても
画面が変わらないことになる。

**「作成」を出すのは無いときだけ。** フォルダでないものが在る回に作成を押させても
`ensureEnginesDir` の存在検査が英文で落ちるだけで、何も直らない。
どちらの帯もその絶対パスを本文に書く。**この画面には開く口が無い**ので、
外しに行くには設定の AI ライブラリタブを使う（#485）。

## 操作と結果

| 操作                | 結果                                         |
| ------------------- | -------------------------------------------- |
| 「保存」            | 検証 → `updatePreset` → 閉じる               |
| 「キャンセル」／Esc | 下書きを捨てて閉じる                         |
| 「再スキャン」      | `scanAiRoot` をやり直す                      |
| 「AI ルートを選ぶ」 | フォルダ選択。**失敗したら AI 名の欄に出す** |
| 「engines/ を作成」 | `ensureEnginesDir` → 再スキャン              |

### 保存時の検証

| 欄           | 条件                             | 文言                                   |
| ------------ | -------------------------------- | -------------------------------------- |
| 名前         | 空でない                         | 名前は必須です                         |
| AI 名        | 空でない                         | AI名（プロファイル）を選択してください |
| エンジン     | 空でない                         | エンジンを選択してください             |
| 定跡ファイル | 「解析で定跡を使う」なら空でない | 定跡ファイルを選択してください         |

**評価関数は必須でない。** 指定できないエンジンがある。どの名前（`EvalDir` / `EvalFile` /
`DNN_Model` …）で送るかは、起動のたびにエンジンの申告から Rust が決める
（[`option-binding.md`](../../state-transitions/option-binding.md)）。定跡の「解析で使う」は
解析のときにエンジンが定跡を引くかで、定跡ビューに出すかとは別。

保存時の整形:

- 解析の既定値は **0 以下を落とす**。時間 0〜3600 / 深さ 0〜999 / ノード 0〜999,999,999
- 4つとも空なら `analysis` 自体を持たせない
- USI オプションの**空文字は保存しない**
- MultiPV / Threads / USI_Hash は画面の値で上書きする
- 最後に `{ ...DEFAULT_USI_OPTIONS, ...options }` で既定値を敷く

保存が通ると、必要ならエンジンが再起動される。

## 失敗の見せ方

| 失敗                 | どこに出るか              |
| -------------------- | ------------------------- |
| `ai_root` のスキャン | 基本の節（`indexError`）  |
| `engines/` の作成    | 同上                      |
| AI ルートの選び直し  | AI 名の欄                 |
| 入力の誤り           | 欄ごと                    |
| **保存そのもの**     | **出ない。** 閉じてしまう |

最後の1つが #170。`updatePreset` は楽観的に画面を更新するので、
ディスクへの書き込みが落ちても画面は保存済みのままになる。

## いま満たしていないこと

- **保存の失敗が出ない**（上記）→ #170
- **編集できる USI オプションが3つだけ**。エンジンが申告する `option` 行を
  読んで欄を作る仕組みが無い → #83
- **定跡の候補が `.db` だけ** → #84
- **解析の既定値を入力できるのに、解析の実行へ届いていない** → #107 #110
- **URL を持たないのでリロードで消える**

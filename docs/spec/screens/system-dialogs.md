# 画面仕様: 横断のダイアログ

対象: `src/features/file-conflict/` `src/features/kifu-read-error/`
`src/features/updater/` `src/shared/ui/Modal.tsx` `src/shared/ui/ConfirmDialog.tsx`

どれも URL を持たない。**呼び出した画面に依らず、同じ形で出る。**

関連: ADR-0005（押すものと対話の面を1つに揃える）／
ADR-0004（通知は復帰に何が要るかで4段）

## 共通の決まり

| 決まり             | 中身                                                             |
| ------------------ | ---------------------------------------------------------------- |
| 面                 | `theme="dark"`。**明るい面に載るのは局面ナビだけ**（#183）       |
| ボタン             | `shared/ui/Button` 1つ。`tone` / `size` / `radius` / `isLoading` |

## 名前の衝突（`FileConflictDialog`）

### 目的

**同じ名前があって操作が通らなかったとき、その場で別名を決めさせる。**
やり直しのために元のフォームへ戻さない。

### いつ出るか

`useFileTree()` の `conflict` が立ったとき。7つの操作が同じ対話を通る。

| `request.kind`     | 見出し                                 | 実行ボタン     |
| ------------------ | -------------------------------------- | -------------- |
| `create_file`      | 同名のファイルが既に存在します         | 名前を変える   |
| `import_file`      | 同名のファイルが既に存在します         | 名前を変える   |
| `create_directory` | 同名のフォルダが既に存在します         | 名前を変える   |
| `rename_file`      | 変更先のファイル名が既に使われています | 名前を変える   |
| `rename_directory` | 変更先のフォルダ名が既に使われています | 名前を変える   |
| `move_file`        | 移動先に同名のファイルが既に存在します | **別名で移動** |
| `move_directory`   | 移動先に同名のフォルダが既に存在します | **別名で移動** |

### 動き

- 開いたとき、要求した名前を入力欄に入れ、**拡張子の手前まで選択する**
- 初期化は**対話が開いたとき1回だけ**（`sessionKey` で判定）。
  `conflict` オブジェクトの同一性で回すと、別名でもう一度衝突したときに
  入力と失敗の理由がその場で消える
- 実行できるのは「空でない」かつ「元の名前と違う」とき。
  **送信中かどうかはここに含めない**（`Button` の `isLoading` が持つ）
- 解決に成功して、発端がモーダル（作成フォーム）なら**そのモーダルも閉じる**

### 失敗の見せ方

**この対話が自分で出す。** reducer は `state.error` に積まないので、
ここで出さないと開いている間の失敗は誰も出さない。

## 棋譜を開けなかった（`KifuReadErrorDialog`）

### 目的

**「棋譜を開こうとして失敗した」という文脈を足す。**
`io` や `permission_denied` は code だけでは何をしていて失敗したのかが分からない。

### 中身

- 見出し「棋譜を開けませんでした」＋ファイル名
- `FsErrorView`（失敗そのものの見せ方はこちらが持つ）
- 「エラーをコピー」——`code` / `message` / `file` / `cause` を整形してクリップボードへ
- 「閉じる」

コピーできない環境では、畳んだ詳細から手で拾える。

### 復帰

**無い。** 閉じるだけ。開けなかった棋譜をどうするか（再試行・別の文字コードで開く）
の導線は無い。→ #325 #210

## 更新（`UpdaterScreen`）

`document.body` へ portal で出す。相は6つあり、**見えるのは4つ**。

| 相            | 見出し                     | 押せるもの        |
| ------------- | -------------------------- | ----------------- |
| `idle`        | —                          | 何も描かない      |
| `checking`    | —                          | 何も描かない      |
| `available`   | 新しいバージョンが利用可能 | 後で / 今すぐ更新 |
| `downloading` | ダウンロード中…            | （進捗バーのみ）  |
| `ready`       | 更新の準備ができました     | 再起動して適用    |
| `error`       | 更新に失敗しました         | 閉じる            |

`available` と `error` のときだけ閉じられる。
**ダウンロード中は閉じられない。**

## 確認（`ConfirmDialog`）

取り消せない操作の前に挟む。使っている場所は3つ。

| 場所                 | 何を確認するか           |
| -------------------- | ------------------------ |
| ファイルツリー       | ファイル／フォルダの削除 |
| 棋譜ストリーム       | 分岐の削除               |
| 課題局面の登録・編集 | 課題局面の削除           |

`title` / `subtitle` / `error` / `isLoading` を持つ。
**`error` があるときは実行ボタンを押せない**ので、
失敗を出したまま開き直しても古い要求が再実行されることはない。

**エンジンプリセットの削除だけは `window.confirm` を使っており、ここを通っていない。**
→ [settings.md](settings.md)

## いま満たしていないこと

- **プリセット削除が `window.confirm`**（上記）
- **棋譜を開けなかったときの復帰導線が無い**
- **更新の失敗に再試行が無い**（閉じるだけ）
- **ウィンドウを閉じると、実行中のファイル操作と未保存の入力が確認なしで消える** → #176
- **ADR-0004 が定めた4段（`info` / `warning` / `danger` / `fatal`）を実際に載せる
  通知の土台がまだ無い** → #277

## これからの要件

ADR-0004 の決定に沿った通知の土台（#277）が入ると、
ここに挙げたダイアログのいくつかは段と `{ label, run }` の組で表される。
**段ごとの見せ方は ADR-0004 が持つので、ここには書かない。**

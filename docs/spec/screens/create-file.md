# 画面仕様: ファイルの作成とインポート

対象: `src/features/create-file/` と `src/features/position-editor/`
`modal=create-file`（新規作成／インポート）
`modal=sfen-kifu-create`（課題局面から作成）

## 目的

**棋譜ファイルを作る。** 作り方は3通りある。

| 経路         | 起点                                                  | 初期局面の決まり方                   |
| ------------ | ----------------------------------------------------- | ------------------------------------ |
| 新規作成     | ツリーの `＋ファイル` ／ ようこそ画面の「棋譜を作る」 | **盤で組む**（種を載せて並べ替える） |
| インポート   | 同上（タブを切り替える）                              | 貼り付けた棋譜が持っている           |
| 課題局面から | 課題局面の詳細の「棋譜作成」                          | `sfen=` で渡された局面               |

## 出入口

| モーダル           | 入口                                                                              | 閉じ方                                 |
| ------------------ | --------------------------------------------------------------------------------- | -------------------------------------- |
| `create-file`      | ツリーの `＋ファイル`（`dir=` 付き）／ようこそ画面の「棋譜を作る」（`dir=` なし） | 作成成功／やめる／Esc                  |
| `sfen-kifu-create` | 課題局面の詳細（`sfen=` `returnTo=` 付き）                                        | 同上。取り消しなら課題局面の一覧へ戻る |

`create-file` は `tab=import` で開くとインポート側から始まる。
**タブの切り替えはローカル state** なので、切り替えても URL は変わらない。

器は `variant="workspace"` の `size="xl"`（`min(1100px, 92vw) × min(760px, 100%)`）。
盤を載せるので広い。**インポートの面は中身の幅を `min(52rem, 100%)` で絞って中央に置く**
——棋譜テキストを貼る欄が幅いっぱいに広がると、1行が長すぎてどこまで貼れたのかが読めない。

## 新規作成タブ ＝ 組む面

左に**局面**（種を選ぶ行・手番・盤・駒台2つ）、右に**ファイルの欄**を置く。
操作・検査・Esc の段は [features/position-edit.md](../features/position-edit.md) と
[state-transitions/position-editor.md](../../state-transitions/position-editor.md) が持つ。
**ここに写さない。**

| 欄         | 種類                    | 既定           | 必須 |
| ---------- | ----------------------- | -------------- | ---- |
| ファイル名 | 1行                     | 空             | ○    |
| 形式       | `kif` `ki2` `csa` `jkf` | `kif`          | —    |
| 保存先     | ツリーを平らにした一覧  | `dir=` か root | ○    |
| 先手名     | 1行                     | 空             | —    |
| 後手名     | 1行                     | 空             | —    |
| タグ       | `TagsInput`             | 空             | —    |
| メモ       | 複数行                  | 空             | —    |

**保存先の欄は両方のタブが持つ。** ようこそ画面から開くと `dir=` が来ないので、
欄が無い面では保存先を一度も選んでいないのに「その場所は扱えません」で行き止まる。
既定はツリーの根。根が入れ替わったときも、選んでいたフォルダだけが消えたときも根へ戻す。

種は2通り —— 手合割13（平手・香落ち・右香落ち・角落ち・飛車落ち・二枚落ち・三枚落ち・
四枚落ち・五枚落ち・左五枚落ち・六枚落ち・八枚落ち・十枚落ち）と、登録済みの課題局面。
**手合割は選んだ瞬間に載る。課題局面は1回目で選び、2回目で載る。**
載せた手合割の名前は、盤を直した後も「（編集済み）」を添えて残る。
開いた瞬間は平手（空盤から始めると、駒箱が無いので駒を1枚も足せない）。

拡張子は選んだ形式が決める（`<名前>.<format>`）。

**タグとメモはここで一度だけ入力できる。** 作成後にこの2つを編集する画面は無い。
→ [features/kifu-metadata.md](../features/kifu-metadata.md)

## インポートタブ

1. 棋譜テキストを貼る（**このタブが出た時点**でこの欄に焦点が入る。
   面は外さずに隠してあるので、隠れているあいだは移さない —— `display: none` への
   `focus()` は何も起きず、そのあと焦点を動かす口が無い）
2. **貼った瞬間に解析する**（`parseKifuStringToJKF`）。結果を欄の下に出す
3. ファイル名・フォーマット・保存先を決める
4. 「作成」

| 状態         | 判定              | 出るもの                 |
| ------------ | ----------------- | ------------------------ |
| 未入力       | `rawContent` が空 | 何も出さない             |
| 読めた       | 解析が通った      | 通った印                 |
| 読めなかった | 解析が投げた      | 例外の文言をそのまま出す |

**読めないうちは「作成」で何も起きない**（`parseOk !== true` で弾く）。
入っている拡張子（`.kif` など）はファイル名から落とす。

送信中の二度押しは `isSaving` で止める。止めないと
1回目が成功し2回目が `already_exists` になる。同じ旗を器へ上げてタブを沈め、
閉じる口も止める —— 止めないと、送信の途中で器が閉じて**失敗を出す場所ごと消える**。

「キャンセル」は器の閉じる門を通る。隣のタブで局面を組みかけていたら確認が出る。

## 課題局面から作成（`sfen-kifu-create`）

| 欄              | 種類                               |
| --------------- | ---------------------------------- |
| 保存先フォルダ  | ツリー全体を平らにした一覧から選ぶ |
| ファイル名      | 1行（必須）                        |
| フォーマット    | 4種類                              |
| 先手名 / 後手名 | 1行ずつ                            |
| （左側）        | 盤のプレビューと手番バッジ         |

初期局面は `stateFromSfen(sfen)` で組み、`{preset: "OTHER", data}` として書く。手合割は選べない。

保存先が1つも無い（ツリーが無い）ときは
「保存先がありません。先にワークスペースを開いてください」を出し、送信を止める。

**開くたびにフォームを初期化する。** `AppModalLayer` が常時マウントしているので、
初期化しないと前回の入力が残る。

## 失敗の見せ方

| 失敗                   | どこに出るか                                       |
| ---------------------- | -------------------------------------------------- |
| 名前の衝突             | `FileConflictDialog`。**このフォームには出さない** |
| それ以外の作成失敗     | フォームの中（`FsErrorView`）。**入力欄は残す**    |
| 棋譜テキストが読めない | 貼り付け欄の下                                     |

衝突を自分で描かないのは、対話の背後に二重に出るため
（`isResolvedByConflictDialog` で判定する）。

**フォームは失敗しても差し替えない。** 差し替えると入力欄が消え、
キーボードの利用者は自分がどこにいるか分からなくなる。

衝突を別名で解決したら、発端のモーダルも閉じる（`AppModalLayer` が行う）。
閉じないと、ファイルは作られたのに**入力がそのまま残ったフォーム**が下から出てきて、
もう一度押すと同じ棋譜の2本目ができる。

## いま満たしていないこと

- **タグとメモは作成時にしか入力できない。** 後から編集する画面が無い → #114
- **駒の増減ができない。** 駒の顔ぶれは種が決めきる → [#548](https://github.com/Rioh1118/obs-shogi/issues/548)
- **盤を Tab で辿れない。** 升は `div` なので `Modal` の焦点の閉じ込めに引っかからない
- **インポートは貼り付けだけ。** ファイルを選ぶ／ドロップする経路が無い
- **インポートの解析エラーが例外の文言そのまま**で、どの行が読めなかったかは出ない
- **文字コードの判定が3層に散っている** → #325。
  UTF-8 / Shift_JIS 以外の棋譜が「0手」として開き、1手指すと元ファイルを上書きする → #210

# 画面仕様: 盤・駒台・操作列

対象: `src/widgets/game-board/` `src/entities/position/`
（指し手の受理・保存は `src/entities/game/`）

状態遷移: [`docs/state-transitions/game.md`](../../state-transitions/game.md)

## 目的

**局面を出し、手を指す。** 指した手は棋譜に入り、そのままファイルへ書かれる。

## 出入口

棋譜が開かれている間、`AppLayout` の本体左側に常駐する。
盤だけを閉じることはできない。

## 画面構成

```
┌ 後手の駒台 ┐┌──────────┐
│            ││          │
└────────────┘│  盤（9×9）│
 ☖ 対局者名   │          │ 先手番
   後手番     │          │ ☗ 対局者名
              │          │┌ 先手の駒台 ┐
              │          ││            │
              └──────────┘└────────────┘
```

**盤の大きさを先に決め、残りを駒台に回す。** 盤の幅は、ペインの幅と高さのどちらで詰まるかで決まり、
駒台の幅（盤の 0.295 倍）と段の高さ（盤のマス）もそこから取る。手の移動のボタンは棋譜の下にある
（[app-layout.md](app-layout.md)）。

**盤の道具（向き・ナビ・検索・課題局面）はここに無い。** ドックの操作列にある
→ [analysis-pane.md](analysis-pane.md)。

- **駒台の並べ方は枚数で変わる**（`arrangeHand`）。12枚までは1枚ずつ、それより多いと種類ごとに1枚と枚数。
  どちらでも、駒は盤の駒と同じ大きさのまま
- 対局者名は JKF ヘッダの `先手` / `後手` を出す。無ければ `—`。長い名前は省かず、盤の左右の空きまで
  広がってから折り返す
- 手番の側は、名前を太くし、外側に「先手番」「後手番」を添える。出ても名前は動かない
- `pov=gote` のとき盤ごと反転する。**駒台の上下も入れ替わる**

盤のマスには次の3つの印が付く。

| 印       | 条件                                     |
| -------- | ---------------------------------------- |
| 選択中   | `selectedPosition` がそのマス            |
| 着手可能 | `view.legalMoves` にそのマスへの手がある |
| 直前の手 | `view.lastMove.to` がそのマス。銅の塗りと、右下の角 |

## 状態

| 記号 | 状態             | 判定                                 | 見えるもの                   |
| ---- | ---------------- | ------------------------------------ | ---------------------------- |
| P0   | 盤が組めない     | `view.player?.shogi` が無い          | **到達しない**※              |
| P1   | 何も選んでいない | `selectedPosition === null`          | 局面だけ                     |
| P2   | 盤の駒を選択中   | `selectedPosition.type === "square"` | 選択＋着手可能マスの強調     |
| P3   | 持ち駒を選択中   | `selectedPosition.type === "hand"`   | 同上（打てるマスの強調）     |
| P4   | 成りを聞いている | `pendingPromotion !== null`          | 移動先のマスに成／不成の選択 |

※ `Board` の中に「盤面を読み込み中...」を返す分岐は在るが、**そこへは来ない。**
`AppLayout` が同じ `view` の `hasKifu` で検査していて、`Board` が描かれた時点では
`player` があり、`player` があれば `shogi` もある（`GameView` の doc）。
`.board-loading` の CSS 規則もリポジトリに1つも無い。**盤に載せられない棋譜を開いた
ときも、ここは通らない**——`state.jkf` が前の棋譜のまま残るので盤も前の棋譜のまま
（`docs/spec/screens/app-layout.md`）。

`P4` の間、盤のクリックは**すべて無視される**。

## 操作と結果

| 操作                         | 結果                                             |
| ---------------------------- | ------------------------------------------------ |
| 自分の手番の駒をクリック     | 選択（P2）。着手可能マスが光る                   |
| 同じ駒をもう一度クリック     | 選択解除                                         |
| 着手可能マスをクリック       | 指す。成れる場合は先に成／不成を聞く             |
| 着手可能でないマスをクリック | そのマスを選び直す（`selectSquare` に落ちる）    |
| 持ち駒をクリック             | 選択（P3）。**手番でなければ選択を解除するだけ** |
| 盤・駒台の外を押す           | 選択解除（`AppLayout` が拾う）                   |
| ◀◀ / ◀ / ▶ / ▶▶              | 最初 / 前の手 / 次の手 / 最後                    |
| `Home` / `←` / `→` / `End`   | 同上。受ける条件は app-layout.md の「キー操作」  |

### 成りの確認

`mustPromote` なら聞かずに成る。`canPromote` なら移動先のマスの上に
`PromotionDialog` を出し、答えを待ってから指す（`Promise` で待つ）。

**待っている間に局面が変わったら取り消す。** 手数（`player.tesuu`）の変化を
監視していて、変わっていれば選択ごと捨てる。

### 指した手の行き先

`makeMove` は棋譜（`state.jkf`）を書き換え、`GamePersistence` を通して
**ファイルへ即書き込む**。分岐の途中で指した場合は変化が1つ増える。
失敗すると棋譜はメモリ上で元に戻る。

## 失敗の見せ方

**盤の中には失敗を出す場所が無い。**

| 失敗                     | いま起きること                                        |
| ------------------------ | ----------------------------------------------------- |
| 手が不正                 | 何も起きない（`legalMoves` に無いので指しに行かない） |
| 棋譜への書き込みが落ちた | メモリ上の棋譜は戻る。**画面には何も出ない**          |
| 局面が組めない           | **起きない**（P0 の※）。盤は前の棋譜のまま残る        |

`makeMove` は `Err` を返し `state.error` にも積むが、**それを描いている場所が無い**
（`entities/game` の `error` の読み手は0）。→ #277 ／ ADR-0004

レンダ中に throw した場合は盤ペインを包む `AppErrorBoundary` が受け、**unmount されるのは
盤と駒台だけ**になる。棋譜一覧と手の移動と検討ペインは残る。
→ [app-layout.md](app-layout.md) の「失敗の見せ方」

## いま満たしていないこと

- **書き込み失敗が利用者に届かない**（上記）→ #277
- **駒をクリックしても手番でなければ何も起きない。** 理由は出ない
- **`JKFPlayer.logs` に再生ログが無制限に積まれる** → #211

## これからの要件

盤は**局面編集モード**の入口になる。編集中は次が変わる。

- クリックの意味が「指す」から「置く／取る／裏返す」へ変わる
- 手番と持ち駒を直接いじれる
- 駒落ちの配置を選べる

→ [features/position-edit.md](../features/position-edit.md)

**対局中の着手には門がある。** 盤はそのままだと手番の所有者を見ずに棋譜へ積むので、
対局中は `features/game-move` の門を通し、**Rust が採るまで積まない**。
門は `entities/game` へ注入で渡る（渡さない呼び手は素通し）。
→ [features/game-play.md](../features/game-play.md) の「対局中の盤は、門を通った手しか積まない」

**いま門は必ず素通しする** —— 対局を始める口が画面に1つも無いので、
走っている対局が存在しない。門そのものは残してある。

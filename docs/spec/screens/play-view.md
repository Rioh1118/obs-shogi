# 画面仕様: 対局ビュー

対象: `src/widgets/play-view/` `src/entities/game-session/model/`
`src/features/game-ruling/` `src/app/providers/bridges/GameSessionBridge.tsx`

機能要件は [game-play.md](../features/game-play.md)、
Rust 側の状態機械は
[game-session.md](../../state-transitions/game-session.md)。
ドックの器は [ADR-0010](../../decisions/0010-dock-tabs-and-view-vocabulary.md)。

## 目的

**走っている対局の進行を出し、止める口を置く。**

**始める口はここに無い。** 対局を始めるのは棋譜を1枚作る作業なので、
起点はツリーとようこそ画面で、本体は `modal=game-start`
——`create-file` が既にそうしている形（→ [create-file.md](create-file.md)）。

## 出入口

ドックのタブ（`dock=play`）。**既定で一覧に出る**が、設定「表示」から外せる。

**終局だけは面から出る。** 対局が終わると `GameOverModal` が前に出て、勝敗・理由・手数・
席2つを並べる。**タブを開いていない人は終局に気づけない**ため。

**勝敗の1行は「引き分け」と「勝敗なし」を分ける。** 中断とアプリの異常は
勝敗を付けずに終わった回（ADR-0011 決定1）で、引き分けたのではない。
本物の引き分けは千日手と最大手数（理由は「規則による終局」）。

**押せる口は「閉じる」ひとつだけ。** 畳むのはその面だけで、結末は対局タブに残り、
盤はそのまま触れる。エンジンを落とすのは進行の側の仕事なので、ここに口を置かない ——
置くと**利用者が押すまでプロセスが残る**。口を2つ並べると、どちらが何を畳むのか
（この面だけか、対局ごとか）が押す前に読めない。

**この面は `modal=` に載らない。** 終局は `game-event` で届く一度きりの出来事で、
再読み込みしても同じ状態には戻らない（走っていた対局が居ない）ので、URL に載せると
**開けない面を指す URL** が残る。状態から開く対話は既に同じ層に2枚ある
（`FileConflictDialog` / `KifuReadErrorDialog`）。

見送りは **`gameId` で控える**。真偽で持つと、下ろしたままの旗が
次の対局まで残って**2局目以降の終局が一度も出ない**。

**綴りが `game` ではなく `play` なのは、`game` を棋譜側が持っているため**
（`entities/game`、`state-transitions/game.md`）。対局は `game-session` の側で、
2つの状態機械は交わらない。

## 画面構成

```
┌─ タブ列（器のもの） ─────────────────────────────┐
│ [解析][定跡][対局]                                │
├─ 操作列 ─────────────────────────────────────────┤
│ △後手の手番              [向き][投了][中断]      │
├─ 本体 ───────────────────────────────────────────┤
│ （帯: 別の棋譜の対局 ／ 裁定を返せなかった）      │
│ △ YaneuraOu 8.20                                  │
│ ▲ あなた                                          │
│ 68手                                              │
└───────────────────────────────────────────────────┘
```

**時計はここに無い。** 残り時間はヘッダの「対局の行」が出す
（→ [app-layout.md](app-layout.md)、ADR-0011 決定2）。

**盤は無い。** 盤は `AppLayout` のものが現局面で、定跡ビューが盤を外したのと同じ理由。

席は**上が後手・下が先手**で盤の並びに合わせる。手番の側は帯（`$marker-bar`）と
面の濃さの2つで示す（面の濃さだけだと隣と見分けが付かない）。

### 進行を持つのはこのビューではない

**`GameSessionProvider` が持ち、`RuntimeProviders` に居る。**

Rust は将棋のルールを持たないので、手が決まると裁定待ちで止まり、
フロントが `continueGame` か `endGameByRule` を返すまで進まない。
**どちらも返さないと `RULING_TIMEOUT` で対局が畳まれる**（理由は「アプリの異常」）。

ドックのタブは選ばれていない間アンマウントされるので、
**裁定を返す購読をこのビューに置くと、別のタブを開いただけで対局が畳まれる。**
利用者から見れば「タブを移ったら対局が壊れた」で、原因は画面のどこにも出ない。

終局の判定（`judgeGameOutcome`）は `entities/game` に在るが、
**進行の側から直に読めない** —— あちらが `Side` を `entities/game-session` から
取っているので、読み返すと互いを読み合う組ができて
`src/__tests__/crossSliceImports.test.ts` が落ちる。
`GameSessionBridge` が `features/game-ruling` の裁定器を prop で渡す
（`AnalysisBridge` が `features/engine-position-sync` を渡しているのと同じ形）。
**2つのスライスを束ねるので、置ける最下層が `features/`。**

裁定器は**対局の間ずっと同じものを持ち回る**。`judgeGameOutcome` は呼ばれるたびに
根から棋譜を組み直すので、毎手呼ぶと合計が手数の2乗で効く（実測は
`entities/game/lib/gameOutcome.ts` の doc）。持ち回る側（`createOutcomeJudge`）は
進んだぶんしか積まない。**前に裁定した列の続きでなければ黙って組み直す**ので、
別の対局が始まっても取り違えない。

**ルール（持将棋の規則・最大手数）を持つのも橋の側。** `GameRules` は
`entities/game` の型なので、進行に持たせると同じ辺ができる。

### 時計はこの画面が持たない

**持ち主はヘッダの「対局の行」** ——規則も含めて
→ [app-layout.md](app-layout.md) の「対局の行」。

タブは1度に1枚しか出ない（ADR-0010）ので、時計をここに置く限り
「解析を見ながら残り時間を知る」ができない。時計は対局が走っている間
**常に見えているべき値**で、それはヘッダの性質（ADR-0011 決定2）。

描く材料（`clockDisplay` / `useNow` / `clocksOf`）は `entities/game-session` に在る。
**この画面から参照し直さない** ——widgets どうしの横断は
`src/__tests__/crossSliceImports.test.ts` が止める。

## 対局を始める面（`modal=game-start`）

**このビューの外にある。** 起点はツリーの行の操作（時計の記号）とようこそ画面の「対局する」。

**ようこそ画面にも要るのは、押せる行が無いことがあるため** ——
ワークスペースに棋譜が1本も無ければツリーに行が出ないし、サイドバーを閉じていれば
ツリーごと居ない。ドックの寿命とは関係が無い（始める面はモーダルなので、
棋譜が開かれているかを問わない）。

| 欄                       | 宛先                                            |
| ------------------------ | ----------------------------------------------- |
| 先後の席（人／エンジン） | Rust（`GameSettings.black` / `.white`）         |
| 持ち時間の形と値         | Rust（`blackTime` / `whiteTime`）               |
| ファイル名・形式・保存先 | ワークスペース（棋譜を1枚作る）                 |
| 持将棋の規則・最大手数   | **選べない**（`features/game-ruling` の既定値） |

**持ち時間は形を選ばせて組み立てる。** 数値欄を並べて自由に入れさせると、
通らない組み合わせ（秒読みと加算の併用）を押した後に知ることになる。
選んだ形に属さない欄は 0 にする —— 欄を触ってから形を切り替えただけで
その組み合わせになるため。

**値の範囲も押す前に見る。** 断るのは `start_game` の中なので、そこまで行くと
**棋譜のファイルが既に作られている** —— 使われない棋譜が1枚残り、断りは Rust の英文で出る。
見るのは下限（3つとも 0）と上限（1日）の2つで、**理由ごとに文言を分ける**
（まとめると、長すぎる値に「半角数字で入れてください」と出る）。
上限の値は Rust と同じものを持ち、食い違わないことを機械が見ている。

**エンジンの席に名前の欄を出さない。** 棋譜と画面に出るのは利用者が付けた
プリセットの見出しで、エンジンが名乗る `id name` は使わない
（長さを見ずに保持される値なので、長い名乗りを返す実行ファイルを選ぶと
利用者が1文字も入力していないのに `start_game` が落ちる）。

**`setoption` は解析と同じ合成を通す**（`usiOptionsOf`）。別々に組むと、
片方だけ `BookDir` を送るような食い違いが**エンジンが起動してからしか出ない**。

**押した後は待たない。** 棋譜を作るところまでは待つ（失敗を欄の下に出すため）が、
`start_game` は評価関数の読み込みを待つので数十秒かかりうる。
モーダルを閉じて対局タブへ移し、待ちも失敗もそちらが出す。

## 状態

Rust の `Phase` は3つ（思考中・裁定待ち・終局）だが、画面が描き分けるのは5つ。
増えるのは**対局が無い状態**と、**始められなかった状態**。

| 記号 | 状態             | 判定                   | 見えるもの                    |
| ---- | ---------------- | ---------------------- | ----------------------------- |
| V0   | 対局が無い       | `view.kind === "idle"` | 案内だけ                      |
| Vs   | 起こしている     | `"starting"`           | 「エンジンを起こしています…」 |
| V1   | 対局中           | `"live"`               | 席2つ・手数                   |
| V3   | 終局             | `"over"`               | 結果と理由                    |
| V4   | 始められなかった | `"failed"`             | 断りの文言（`role="alert"`）  |

**Vs は数十秒続きうる。** `start_game` は評価関数の読み込みを待つうえ、
**取り消す口が無い**。無言で待たせると押し損ねたと読まれるので、
`role="status"` の一文を出し続ける。

**裁定待ちは段として描かない。** 正常なら人が知覚できない長さしか続かないので、
毎手ちらつく帯になる。出るのは手数の脇の「裁定中」だけで、
**返せなかったとき**にだけ帯（`role="alert"`）が立つ。

**「もう終わっていた」は帯を立てない。** 「中断」は裁定中も押せて、押すと
飛んでいた `continue_game` が断られる。故障として立てると、**自分で中断した人に
アプリの故障だと名乗る**ことになる。結末は `over` イベントが持っている。

**棋譜へ積めなかったことは V1 と V3 の両方で帯に出す。** 対局は Rust の写しで進むので
止まらず、止まるのは棋譜だけ。黙ると**終局後に開き直したとき初めて**
後半が無いことに気づく。文言は「対局は続いている」を先に言う
——「失敗しました」だけだと対局そのものが壊れたと読んで中断されてしまう。

## 操作と結果

**指す操作はここに無い** —— 着手は盤で行う。

| 操作   | 押せる状態                               | 結果                                                                 |
| ------ | ---------------------------------------- | -------------------------------------------------------------------- |
| 向き   | **常に**                                 | 盤の視点を入れ替える（`pov`）。対局には触らない                      |
| 投了   | V1 かつ**人が座っている席がちょうど1つ** | エンジンの席は Rust が断る。双方が人なら誰の投了かを選ばせる口が要る |
| 中断   | V1                                       | 勝敗が付かずに終わる                                                 |
| 閉じる | **V4 のみ**                              | 画面を片付けるだけ（落とす相手は居ない）                             |

**「向き」だけは投げている間も沈めない。** 見え方を変えるだけでセッションに触らないので、
下の「3つとも沈める」には入らない。入れると、十数秒かかる「閉じる」の間だけ盤を戻せなくなる。
記号と文言は解析側の同じ操作（`AnalysisControls`）と揃える ——
同じことをする口が2つあるので、別の図案を当てると別の操作に見える。

**押せなくなっても消さない。** 消すと押しどころが状態ごとに動く。
沈んでいる理由は `title` が名乗る。

**投げている間は3つとも沈め、状態行に「閉じています…」を出す。**
沈めないと往復の間ずっと押せたままになる —— `disabled` の根拠は `view` で、
`view` が動くのは Rust が投げ返してから。「閉じる」は探索を畳めないエンジンで
最大十数秒かかるのに画面が変わらないので、効いていないと読んで押し直され、
2発目の断り（英文と UUID）が**成功した1発目の結果の上に貼り付く。**

**V3 に「閉じる」は無い。** 終局はエンジンを畳まないが、`close_game` を通すのは
進行の側（`retireEngines`）で、結末が決まった時点で自分で落とす。
押させる形にすると、押し忘れがそのままプロセスの残りになる ——
1局あたり最大2本が起きたままになり、気づく手段が画面のどこにも無い。

**落とせなかったことは V3 の帯に出す。** 押し直す利用者が居ないので、
黙ると起きたままのプロセスに気づけない。

**V4 では落とす相手が居ない** —— Rust は起動に失敗した対局を台帳に載せず、
起こしたプロセスも自分で落とす。だから V4 は「閉じる」を通さずにそのまま
`start` をやり直せる（押せば画面を片付けるだけ）。

### 対局中の盤

**Rust が採った手しか棋譜へ積まない。** 盤はそのままだと手番の所有者を見ずに積んで
自動保存まで走るので、相手の手番で指せてしまうと **Rust は着手を受けていないのに
棋譜だけが1手先へ進む**。次の裁定に渡す指し手列が Rust の写しと食い違って断られ、
**呼び直しても直らないまま `RULING_TIMEOUT` で対局が畳まれる。**

門は `features/game-move` が持ち、`entities/game` へ**注入で渡す**
（盤と対局の2つを束ねるので、置ける最下層がそこ）。**門を渡さない呼び手は素通し**
——盤だけを立てる場所に対局を持ち込まないため。

止めるのは6つ。**盤が対局の先端に居ない**・**まだ始まりきっていない**・
**終局した対局の先端**・**相手の手番**・**エンジンの席**・**綴れない手**。
どれも `submit_game_move` を呼ぶ前に落とす。

**終局した対局（V3）の盤は止めない。** 結末が決まった時点でエンジンは落ちていて、
出す先がもう無いので、止めても Rust の写しを守ることにはならない。
止めた版は、盤に断りの出し先が無い（#277）せいで**押しても何も起きない盤**になった ——
利用者からは故障と見分けが付かない。呼んだ結果が断られた場合も積まない
（着手が届くのと持ち時間が尽きるのが同じ tick に入ると断られる）。

**先端に居るかは手数で見ない。** 遡って分岐を並べるのは対局中も止めていない普通の操作で、
同じ深さの別の線と手数では区別が付かない。根からの USI の綴りを丸ごと突き合わせる
（Rust の `accept_continue` と同じ形）。手数で見ると、**分岐で指した手が
「対局の次の1手」として Rust へ出て**、写しに異物として載ったまま
`continue_game` で弾かれ、対局そのものが「アプリの異常」で畳まれる。

**始まりきる前（Vs）も止める。** `start_game` は評価関数の読み込みを待つので
数十秒あり、その間の手は Rust の写しに無い。対局は Rust 側で進むので壊れないが、
**棋譜だけが1手多いまま終局まで進む。**

**別の棋譜を触っているだけの操作は止めない。** 対局は棋譜が入れ替わっても走り続けるので、
止めると対局中は他の棋譜を1手も並べ替えられなくなる。

**盤には断りを出す場所がまだ無い**（#277）。押しても何も起きないので、
「自分の手番でだけ指せる」ことは対局タブの手番の表示から読むしかない。

### 別の棋譜の対局

**対局は棋譜が入れ替わっても走り続ける。** 盤に出ている棋譜と対局の棋譜が違うときは、
そのことを一言出す（出さないと、いま見ている棋譜の対局に見える）。

対局がどの棋譜のものかを持てるのはこちら側だけ
——`GameSettings` にも `GameSnapshot` にも棋譜を指す欄が1つも無い。

**印を出す面は2つ。** この本文と、ヘッダの対局の行の印
（→ [app-layout.md](app-layout.md)）。**判定式は `isForeignKifuSession` 1つで、
2面がそれを読む** ——別々に組むと #538 の直しが片面にだけ入る。

## 失敗の見せ方

| 失敗                           | どこに出るか                                                                | 復帰                                                           |
| ------------------------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| ビューが描画で落ちた           | ドックの境界「対局」（→ [app-layout.md](app-layout.md) の「失敗の見せ方」） | 「再表示」。**走っている対局は止まらない**（進行はドックの外） |
| 対局を始められなかった         | V4 の帯（`role="alert"`）                                                   | 設定を見直してもう一度始める                                   |
| 裁定を返せなかった             | V1 の帯（`role="alert"`）                                                   | **無い。**30秒後に Rust が畳む（理由は「アプリの異常」）       |
| 終局後も裁定の断りが残っていた | V3 の帯                                                                     | —（理由を残すためだけに出す）                                  |
| エンジンを落とせなかった       | V3 の帯と、終局の面（`role="alert"`）                                       | **無い。**押し直す口が無いので、名乗るだけ                     |
| 投了・中断・閉じるが断られた   | **操作列**（押した場所に返す）                                              | そのまま押し直せる                                             |
| 出来事の購読が張れなかった     | V0 の帯（`role="alert"`）                                                   | **無い。**アプリの再起動を案内するだけ                         |

**裁定の断りを終局と一緒に消さない。** 判定器が投げて `endGameByRule` が通った回、
理由の欄は「規則による終局（判定できなかった…）」までしか言えないので、
**投げた中身を出せる欄はこの帯しか無い**。
**帯は終わり方を言い直さない** —— どう終わったかは理由の欄が言う（ADR-0011 決定7）。

**段を文字の色で持たせない。** 暗い面に置ける危険色（`$color-danger-text`）は
暗いカード（#1c2325）に合わせて決めてあり、ドックの面では基準を割る。
段を持つのは帯（`border-left`）と `role="alert"` と文言。

## いま満たしていないこと

- **開始局面を選べない。** 平手固定。盤で組む面（`create-file` の新規作成タブ）は
  まだ繋いでいないので、途中局面からの対局と手合割を選べない
- **終局が棋譜に残らない。** 特殊手を挿す経路が1つも無いので（#115）、
  投了した棋譜を開き直すと投了が無い。画面はそのことを言い続ける
- **対局中のエンジンの読み筋を出していない。** `searchInfo` は届いているが捨てている
  （畳み込む先は決まった。ADR-0011 決定4）
- **同時対局は1局だけ。** 走っている対局があるうちは `start` が何もしない。
  Rust 側には上限が無い（#382）
- **中断した対局を再開できない**（#358）。時計は必ず満額から始まる
- **終局の理由に Rust の英文がそのまま出る。** `detail` は自分が渡した和文とは限らない
- **持将棋の規則と最大手数を選べない。** 既定値のまま
- **消費時間を出していない。** `moveDecided` の `elapsedMs` を畳み込んでいない
  （畳み込む先は決まった。ADR-0011 決定4）
- **別の棋譜かの判定が改名で誤検知する。** パスを単独の合図にしているので、
  対局中の棋譜をツリーで改名すると「別の棋譜の対局」と出続ける（#538）

## これからの要件

**置き場と語彙の作り替えは [ADR-0011](../../decisions/0011-game-vocabulary-and-placement.md)

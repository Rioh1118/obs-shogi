# 機能要件: 局面編集モード

追跡: #113（親は #289）
main にあるか: **無い**

## なぜ要るか

**任意局面から研究を始める入口が無い。** いまできるのは3つだけ。

| いまできること         | 限界                                               |
| ---------------------- | -------------------------------------------------- |
| 手合割から新規作成     | 13種類のプリセットしか選べない                     |
| 課題局面から棋譜を作成 | その SFEN が既に課題局面に登録されている必要がある |
| 棋譜をインポート       | 棋譜テキストを持っている必要がある                 |

つまり「本で見た局面を並べて調べる」ができない。
issue #113 はこれを「SFEN 貼り付け頼み」と書いている。

## 受入条件（#113）

- 局面編集モードの開始／終了
- 盤上・駒台への任意配置（ドラッグ＆ドロップ）
- 手番の変更
- 駒落ちプリセットの投入（香落ち〜十枚落ち、詰将棋）／駒の増減
- 編集結果から新規棋譜を作成できる

## 設計案がある（未採用）

`.claude/plans/position-editor.plan.md`（grill-me セッション 2026-06-27）。
**ADR ではないので採用ではない。** ただし1点を決めており、それがこの機能の形を決める。

> **既存棋譜は mutate しない。** 初期局面を変えるのは別の対局なので別ファイルになる。

この不変条件を採ると、「モード」ではなく**独立した画面**になる。

| 案が置くもの                             | 中身                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `features/position-editor/` の新スライス | 編集盤・駒箱・作成フォームを持つ大画面オーバーレイ                   |
| 種（seed）の入口3つ                      | ①空白 ②現局面から派生 ③課題局面から                                  |
| 出口                                     | `createNewFile(dir, { initialPosition: { preset: "OTHER", data } })` |
| `ModalType` に `position-editor`         | → [navigation-map.md](../navigation-map.md)                          |

**着手ロジック（`entities/game` の moveValidator）は使わない。**
作成の文脈に進行中の対局は無いため。

参考: `research/shogihome/04-position-editing.md`

## 盤の道具は既にある

**自前の盤 state を作る必要は無い。** いま入っている `shogi.js@5.4.1` が
編集用の口を公開している。

| 口                             | 何ができるか                                     |
| ------------------------------ | ------------------------------------------------ |
| `editMode(true)`               | 手番の確認と着手可能かの確認を**両方とも止める** |
| `move(fx, fy, tx, ty)`         | 盤上の駒を任意の升へ動かす                       |
| `drop(x, y, kind, color)`      | 持ち駒を任意の升へ置く                           |
| `captureByColor(x, y, color)`  | 盤上の駒を指定した側の持ち駒にする               |
| `flip(x, y)`                   | 先手 → 先手成 → 後手 → 後手成 と回す             |
| `setTurn(color)`               | 手番を決める                                     |
| `toSFENString(moveCount?)`     | いまの盤から SFEN を出す                         |
| `initializeFromSFENString`     | SFEN から組み直す                                |
| `initialize({ preset, data })` | 盤と両持ち駒を丸ごと与えて組み直す               |

`editMode(true)` は `checkTurn` と `getMovesFrom` の確認を素通りさせるだけで、
**次の2つは編集中も効いたままになる。**

- `move` は毎回 `nextTurn()` を呼ぶ。**駒を1つ動かすたびに手番が入れ替わる**ので、
  編集を終えたら `setTurn` で決め直す
- 行き所のない駒は**編集中でも強制的に成る**（`deadEnd` の判定は編集モードの外にある）

`set` / `pushToHand` は private なので、**盤にも駒台にも無い駒を足す口は無い**。
駒箱（無限供給）を作るなら `initialize({ preset: "OTHER", data })` で組み直す形になる。

## 決まっていないこと

- **入口をどこに置くか。** 上の案は3箇所（ようこそ画面・盤の操作列かヘッダ・課題局面）を
  挙げているが、ヘッダにも解析ペインにも余っている場所が無い
- **出来上がった局面をどこまで検査するか。** `editMode(true)` は確認を止めるので、
  玉が2枚ある・二歩・行き所のない駒（強制成りで回避される場合を除く）を作れてしまう。
  **止めるのか、警告だけ出して通すのかを決める**（詰将棋の局面は玉が1枚しか無い）
- **駒箱をどう出すか。** 盤にも駒台にも無い駒を足す口が `shogi.js` に無いので、
  `initialize` で組み直すことになる。組み直すたびに `Shogi` を作り直してよいか

# 機能要件: 初期局面を組んで、新しい棋譜を作る

追跡: #113（親は #289）
main にあるか: **無い**

## なぜ要るか

**任意局面から研究を始める入口が無い。** これまでできたのは3つだけ。

| これまでできたこと     | 限界                                               |
| ---------------------- | -------------------------------------------------- |
| 手合割から新規作成     | 13種類のプリセットしか選べない                     |
| 課題局面から棋譜を作成 | その SFEN が既に課題局面に登録されている必要がある |
| 棋譜をインポート       | 棋譜テキストを持っている必要がある                 |

つまり「本で見た局面を並べて調べる」ができない。
issue #113 はこれを「SFEN 貼り付け頼み」と書いている。

## 語彙

画面に出す語を固定する。**同じものを2通りに呼ばない。**

| 使う                                                                 | 使わない                                                     |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| 棋譜 ／ 初期局面 ／ 局面 ／ 手合割 ／ 駒台 ／ 課題局面 ／ 手番 ／ 種 | 空の棋譜 ／ 盤面 ／ 編集モード ／ プリセット ／ 駒箱 ／ 先後 |

- 器の名前（`Modal` の `label`）は **「棋譜を作る」**。面が変わっても動かさない
- タブは **「新規作成」「インポート」**
- 確定は **「作成」**（「保存」と言わない。上書きではない）
- 捨てる確認は **「組んだ局面は保存されません。」**／実行側は「捨てる」／戻る側は「組み続ける」

## 決めたこと

### 置き場は3つだけ。駒箱を作らない

駒の顔ぶれは**種**が決める（手合割13 ／ 登録済みの課題局面）。
盤にも駒台にも無い駒を足す口を持たない。

|          |                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------ |
| 良いこと | 玉3枚・駒余り・歩19枚が**構造的に作れない**。断りの対象が減る                                                            |
| 悪いこと | **#113 の受入条件のうち「駒の増減」と「詰将棋」を満たさない** → [#548](https://github.com/Rioh1118/obs-shogi/issues/548) |

### 器は `create-file`。`ModalType` を増やさない

「棋譜テキストから作る」と「局面から作る」はやることが別だが、**出口は同じ**
（新しい棋譜ファイルが1本できる）。器を分けると入口だけが2つになる。
「新規作成」タブが組む面に置き換わる → [create-file.md](../screens/create-file.md)

入口は2つ。ファイルツリーの `＋ファイル`（`dir=` 付き）と、
ようこそ画面の「棋譜を作る」（`dir=` なし）。**盤・ヘッダ・解析ペインには置かない**
——それらは「いま開いている棋譜」を扱う面。

### 組んでいるあいだ `Shogi` を状態として持たない

**`editMode(true)` を張っても足りない。** 編集モードが緩めるのは一部だけで、
残りは効いたまま。**内訳はここに写さない** ——
`src/entities/position/lib/positionDraft.ts` の冒頭が持つ。

| 効いたまま残るもの                                    | この面との食い違い                         |
| ----------------------------------------------------- | ------------------------------------------ |
| `move` の強制成り（`deadEnd` の判定は編集モードの外） | 行き所のない駒を**置けたうえで断りに出す** |
| `capture` が取られた駒を反対側の駒台へ入れる          | 重ねた駒は**動かす側**の駒台へ入れる       |
| `drop` が二歩と行き所のない駒を `throw` で弾く        | どちらも通して断りに出す                   |
| `initialize` が末尾で `flagEditMode` を落とす         | —                                          |

組みかけは `JKFState`（ただの配列とカウンタ）で持ち、`Shogi` は SFEN と王手の判定に
1つ作って捨てる → `src/entities/position/lib/positionDraft.ts`

### 検査は止めない。断りに出すだけ

「作成」は押せるまま。押せなくすると詰将棋が作れないし、研究のために規則から
外れた局面を組むこともある。

| 出すもの       | 条件                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| 盤が空         | 盤に駒が1枚も無い                                                              |
| 二歩           | 同じ筋に同じ側の**不成の**歩が2枚以上（と金は数えない）                        |
| 行き所のない駒 | 歩・香が最終段／桂が最終2段                                                    |
| 王手放置       | **両方に玉が1枚ずつあるときだけ。** 手番でない側の玉に手番側の利きが通っている |

**玉の枚数は断りにしない**（詰将棋が正当）。

文言は**用語を頭に出す**（「二歩：7筋に…」）。断りは複数並ぶので、
頭で種類が読めないと「どれを直すか」を選ぶのに全文を読むことになる。

### 操作

|                |                                                                                     |
| -------------- | ----------------------------------------------------------------------------------- |
| 入力           | **クリックで掴み、クリックで置く。** D&D は別に切る                                 |
| 掴んでいる表現 | カーソルに駒が付く（ゴースト）＋ 元の升に残像                                       |
| 置けない場所   | **掴んでいる間だけ沈める。** 休んでいる盤は沈めない（盤が盤に見えなくなる）         |
| 移動先に駒     | **動かす駒と同じ側**の駒台へ。成駒は不成に戻す                                      |
| 移動先が玉     | 2つの位置を**入れ替える**（玉は駒台に載らない）                                     |
| 重ねる予告     | 取る先にホバーすると、行き先の駒台と升が名乗る                                      |
| 裏返す         | **盤の駒への右クリックだけ。** 不成 → 成 → 相手の不成 → 相手の成 で1周。玉と金は2巡 |
| 手番           | 盤の上に1行。**枠も面も持たせない**（囲うと4つ目の置き場に見える）                  |

**Undo を持たない。** 代わりに「重ねる予告」を入れてある —— 駒に駒を重ねると
1手で駒台へ飛び、戻すには2手かかるので、押す前に見せる。

### Esc は6段で畳む

段と遷移は [position-editor.md](../../state-transitions/position-editor.md) が持つ。
**ここに写さない。**

## 出口

```
createNewFile(dir, { fileName, format, gameInfo, initialPosition })
```

`initialPosition` は**組みかけかどうかで変わる**。

- 種が手合割のままなら `{ preset }`
- 並べ替えたなら `{ preset: "OTHER", data }`

常に `OTHER` にすると平手をそのまま作っただけの棋譜から手合割が消え、
常に手合割にすると並べ替えが黙って落ちる。

**既存の棋譜を1つも変えない。** この機能の唯一の不変条件。

## まだできないこと

- **駒の増減**（駒箱）→ [#548](https://github.com/Rioh1118/obs-shogi/issues/548)
- **盤の鍵盤操作。** 升は `div` なので `Modal` の焦点の閉じ込めに引っかからず、
  Tab が盤を素通りする。**対局の盤も同じ状態**なので、ここだけ先に直すと2系統になる
- **D&D。** クリックの経路を壊さずに乗るエンハンス
- **Undo / Redo**
- **SFEN の貼り付けを種にする。** 「棋譜テキストを貼る」と別の場所になるのが分かりにくい
- **組んだ局面をそのまま課題局面に登録する。** 出口が2つになるので
  ADR-0005 に照らして形を決める必要がある → [study-positions.md](../screens/study-positions.md)

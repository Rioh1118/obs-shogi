# 機能要件: 局面編集モード

追跡: #113（親は #289）
main にあるか: **無い**

## なぜ要るか

**任意局面から研究を始める入口が無い。** いまできるのは3つだけ。

| いまできること         | 限界                                               |
| ---------------------- | -------------------------------------------------- |
| 手合割から新規作成     | 13種類のプリセットしか選べない                     |
| 課題局面から棋譜を作成 | その SFEN が既に課題局面に登録されている必要がある |
| 棋譜をインポート       | 棋譜テキストを持っている必要がある                 |

つまり「本で見た局面を並べて調べる」ができない。
issue #113 はこれを「SFEN 貼り付け頼み」と書いている。

## 受入条件（#113）

- 局面編集モードの開始／終了
- 盤上・駒台への任意配置（ドラッグ＆ドロップ）
- 手番の変更
- 駒落ちプリセットの投入（香落ち〜十枚落ち、詰将棋）／駒の増減
- 編集結果から新規棋譜を作成できる

## 設計案がある（未採用）

`.claude/plans/position-editor.plan.md`（grill-me セッション 2026-06-27）。
**ADR ではないので採用ではない。** ただし1点を決めており、それがこの機能の形を決める。

> **既存棋譜は mutate しない。** 初期局面を変えるのは別の対局なので別ファイルになる。

この不変条件を採ると、「モード」ではなく**独立した画面**になる。

| 案が置くもの                             | 中身                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `features/position-editor/` の新スライス | 編集盤・駒箱・作成フォームを持つ大画面オーバーレイ                   |
| 種（seed）の入口3つ                      | ①空白 ②現局面から派生 ③課題局面から                                  |
| 出口                                     | `createNewFile(dir, { initialPosition: { preset: "OTHER", data } })` |
| `ModalType` に `position-editor`         | → [navigation-map.md](../navigation-map.md)                          |

**着手ロジック（`entities/game` の moveValidator）は使わない。**
作成の文脈に進行中の対局は無いため。

参考: `research/shogihome/04-position-editing.md`

## 触ることになる画面

| 画面                                      | 何が変わるか                                             |
| ----------------------------------------- | -------------------------------------------------------- |
| **新しい面**                              | 編集用の盤（`Board` を流用するが着手ロジックを持たない） |
| [ファイル作成](../screens/create-file.md) | 初期局面の決め方に「編集した局面」が増える               |
| [課題局面](../screens/study-positions.md) | 課題局面を種にして開く（**入れ子にせず置き換える**）     |
| [盤](../screens/board.md)                 | 「この局面から派生」の入口が要る                         |

## 決まっていないこと

- **入口をどこに置くか。** 上の案は3箇所（ようこそ画面・盤の操作列かヘッダ・課題局面）を
  挙げているが、ヘッダにも解析ペインにも余っている場所が無い
- **入玉・詰将棋の局面で合法性をどこまで見るか。** 玉が2枚ある・
  二歩になっている局面を作れてしまうと、そこから指した手が壊れる
- **編集中の盤をどの型で持つか。** `shogi.js` の `Shogi` をそのまま持てば
  SFEN は `toSFENString()` で出る（main では3箇所が使っている）。
  ただし `Shogi` は合法手の規則を持つ型なので、
  「玉を2枚置く」ような編集をそのまま通せるかは確かめていない。
  自前の盤 state を持つなら SFEN への変換を書くことになる

## 先に片付けるべきもの

**#276（棋譜の編集が黙って失われる）が先。**
#289 が明記している通り、局面編集は棋譜を書き換えるので、
保存経路が直る前に着手すると「編集したのに消える」経路を増やすことになる。

- #210 UTF-8 / Shift_JIS 以外の棋譜が「0手」として開き、1手指すと元ファイルを上書きする

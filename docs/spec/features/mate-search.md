# 機能要件: 詰み探索

追跡: #747（エピック） #745 #746
main にあるか: **無い。** `checkmate` の行を受け取る経路だけがある

**一文の目的。** 現局面に詰みがあるかを、詰将棋エンジン（df-pn 系）に調べさせ、
「詰み（手順）」「不詰」「時間切れ」「このエンジンは詰み探索をしない」を言い分けて見せる。

**事実:** `research/engines/mate-engines.md`（詰将棋エンジンの応答）、
`research/engines/usi-measurements.md`（通常のエンジンが `go mate` に返すもの）、
`research/usi-spec/01-usi-original.md` §2（`go mate` の引数の意味）

## いまどうなっているか

| できること                                                       | できないこと                                                                                     |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| エンジンが出した `checkmate` の行を、その探索の行として受け取る    | `go mate` を送る経路が無い。プリセットの詰み探索の値は保存されるだけで読まれない       |
| 詰み手順を解析の結果の1欄として持つ                              | 不詰・時間切れ・非対応が**同じ空の手順**に潰れていて、画面が言い分けられない                     |
| 詰将棋エンジンを検討のプリセットに選べる                         | 詰将棋エンジンは通常の `go` に候補手を出さず、詰みが無ければ `bestmove resign` を返す。検討には使えない |

使っている USI ライブラリ（`usi` 0.6.2）は `go mate <ミリ秒>` と `go mate infinite` を組める。
**読む側は足りない。** `checkmate notimplemented` を `nomate` と同じ値に読み、`checkmate none` を
「`none` という1手の詰み」に読む。どちらも AC-M2 と AC-M4 を満たせない。

**状態機械は `checkmate` で探索を閉じない。** `docs/state-transitions/engine.md` の Q3×L6 は「探索は続く」で、
`bestmove` を待つ。詰将棋エンジンは `go mate` に `bestmove` を返さないので、今のままでは探索が終わらない。

## 範囲

| 範囲 | 中身                                                                       |
| ---- | -------------------------------------------------------------------------- |
| 第1  | `go mate` を送り、4つの答え（詰み・不詰・時間切れ・非対応）を言い分けて返す |
| 第2  | 現局面に対して詰み探索を始める・中止する操作と、結果の表示                 |

**非ゴール。** 検討（候補手）の中で詰みを調べること／詰み手順を棋譜の変化として書き込むこと／
複数のエンジンの合議／詰将棋の局面を組むこと（局面編集 #548）。

## 受入条件

### 第1: 送って受ける

- **AC-M1** 現局面と上限時間を受け、`go mate <ミリ秒>` を送る。上限なしなら `go mate infinite`。
  `go mate` で始めた探索は `checkmate` の行で閉じる（`bestmove` を待たない）。
  `engine.md` の Q3×L6 を、詰み探索のときは「閉じる」に書き換える
- **AC-M2** `checkmate` の行を自前で読み、答えを4つに分けて返す: 詰み（手順）／不詰（`nomate`）／時間切れ（`timeout`）／
  非対応（`notimplemented`、または `checkmate` でなく `bestmove` が返った）
- **AC-M3** 中止すると `stop` を送り、答えを時間切れとして扱わず「中止した」として返す
- **AC-M4** 結果不明の答え（`checkmate` の後が4つのどれでもない）は非対応と混ぜず、「答えを読めなかった」として返し、行をログに残す
- **AC-M5** 詰み探索は検討とは別のプロセスで動かし、検討を止めない

AC-M1〜AC-M5 → #745

### 第2: 操作と表示

- **AC-M6** ドックのタブ「詰み探索」から、現局面で始める。使うプリセットをタブの中で1つ選ぶ（前回の選択を覚える）
- **AC-M7** 上限時間を選べる（10秒・30秒・60秒・無制限。既定 30 秒）
- **AC-M8** 探索中は経過時間と「中止」を出す
- **AC-M9** 詰みなら「N手詰」と手順を出す。手順の表記は検討の読み筋と同じにする
- **AC-M10** 不詰・時間切れ・中止・非対応は、それぞれ別の1文で言う。非対応は「このプリセットのエンジンは詰み探索をしない。詰将棋エンジンのプリセットを選ぶ」で終える
- **AC-M11** 局面を動かしたら探索を中止し、表示を空に戻す
- **AC-M12** 手番の側に王手が1つも無い局面でも探索は送る（判断はエンジンに任せる）

AC-M6〜AC-M12 → #746（#745 の後）

## 判断ログ

| 判断                                   | 選択                                              | 理由と基準                                                                                                                    | 戻し方                                        |
| -------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 検討の終了条件に入れるか、別の操作か（旧 Q-009。ADR-0017） | **別の操作**                                      | 応答の形が違う（`checkmate` の1行と、`info` を流して `bestmove`）。詰将棋エンジンは通常の `go` に候補手を出さない（ソースで確認） | 検討の終了条件へ移す                          |
| 置き場                                 | **ドックのビュー**（ADR-0010）                    | 「検討と同時に開きたいか」に当てると、開きたい（読み筋と詰みの有無を並べて見る）。同時に開くならビュー                          | 検討ビューの表示モードにする                  |
| 使うエンジン                           | 既存のプリセットを選ぶ                            | エンジンの置き場と設定の考え方（プリセット）を増やさない。詰将棋エンジンもプリセットとして登録できる                          | 設定に「詰み探索のエンジン」を足す            |
| 局面を動かしたとき                     | 中止して空に戻す                                  | ドックのビューは現局面に従属する（ADR-0010 の決定1）。古い局面の結果を残すと、どの局面の答えか分からなくなる                | 結果を局面に紐づけて残す                      |
| `checkmate` の読み方                   | ライブラリに頼らず自前で読む                      | `usi` 0.6.2 は `notimplemented` と `nomate` を同じ値にし、`none` を手と読む。ライブラリを替えると他の行の読み方まで動く | ライブラリが4つを区別したら戻す               |
| 非対応の見分け方                       | 答えで判定する（`bestmove` か `notimplemented`）  | エンジンは詰み探索に対応しているかを申告しない                                                                                | 申告の方式が規格に入ったら起動時に判定する    |

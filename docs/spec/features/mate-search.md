# 機能要件: 詰み探索

追跡: #747（エピック） #745 #746
main にあるか: **第1（送って受ける）はある**（#745。`engine/mate_search.rs` と、Tauri コマンド `start_mate_search` / `stop_mate_search`）。**第2（画面）もある**（#746。`entities/mate-search`、`widgets/analysis-pane`）

**一文の目的。** 現局面に詰みがあるかを、検討ペインの中で詰将棋エンジン（df-pn 系）に調べさせる。
探索中は検討と同じ候補手の表で経過を見せ、終わったら「詰み（手順）」「不詰」「時間切れ」
「このエンジンは詰み探索をしない」を言い分ける。

**事実:** `research/engines/mate-engines.md`（詰将棋エンジンの応答と、他の GUI の見せ方）、
`research/engines/usi-measurements.md`（通常のエンジンが `go mate` に返すもの）、
`research/usi-spec/01-usi-original.md` §2（`go mate` の引数の意味）

## いまどうなっているか

| できること                                                     | できないこと                                                                                 |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `go mate` を送り、途中の候補手と結論を受けて流す（`engine/mate_search.rs`） | 詰将棋エンジンの実機では確かめていない |
| 詰将棋エンジンを検討のプリセットに選べる                       | 通常の `go` では、詰みが無ければ `bestmove resign` を返して止まる。検討の代わりには使えない |

**詰将棋エンジンは探索中も候補手の行を流す。** 根の候補手ごとに `score mate <手数>` か `score cp <値>` と
読み筋を、`MultiPV` の数だけ定期的に出す。形は検討の `info` と同じで、終わりに結論の `checkmate` が1行来る。

使っている USI ライブラリ（`usi` 0.6.2）は `go mate <ミリ秒>` と `go mate infinite` を組める。
**読む側は自前で持つ**（`usi_machine` の `MateAnswer`）。ライブラリは `checkmate notimplemented` を `nomate` と同じ値に読み、
`checkmate none` を「`none` という1手の詰み」に読むので、AC-M2 と AC-M4 を満たせない。

**詰み探索は `checkmate` の行で閉じる**（`docs/state-transitions/engine.md` の Q3×L6。中止の `stop` への答えは Q4×L6）。
詰将棋エンジンは `go mate` に `bestmove` を返さない。通常の探索に来た `checkmate` は、今までどおり探索を閉じない。

## 範囲

| 範囲 | 中身                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 第1  | `go mate` を送り、途中の候補手と、結論（詰み・不詰・時間切れ・非対応）を返す |
| 第2  | 検討ペインの中で、検討と詰み探索を切り替える操作と、結論の表示               |

**非ゴール。** 検討と詰み探索を同時に走らせること／詰み手順を棋譜の変化として書き込むこと／
複数のエンジンの合議／詰将棋の局面を組むこと（局面編集 #548）。

## 受入条件

### 第1: 送って受ける

- **AC-M1** 現局面と上限時間を受け、`go mate <ミリ秒>` を送る。上限なしなら `go mate infinite`。
  探索中の `info` は検討と同じ候補手として返す。
  `go mate` で始めた探索は `checkmate` の行で閉じる（`bestmove` を待たない）。
  `engine.md` の Q3×L6 を、詰み探索のときは「閉じる」に書き換える。
  **上限を5秒過ぎても終わらなければ、こちらから `stop` を送る**（通常のエンジンは `go mate` の上限を読まずに続ける。実測）。
  `bestmove` で答えれば非対応、`checkmate` で答えればその結論
- **AC-M2** `checkmate` の行を自前で読み、結論を4つに分けて返す: 詰み（手順）／不詰（`nomate`）／時間切れ（`timeout`）／
  非対応（`notimplemented`、または `checkmate` でなく `bestmove` が返った）
- **AC-M3** 中止すると `stop` を送り、結論を時間切れとして扱わず「中止した」として返す
- **AC-M4** 結果不明の答え（`checkmate` の後が4つのどれでもない）は非対応と混ぜず、「答えを読めなかった」として返し、行をログに残す
- **AC-M5** 詰み探索は検討のエンジンとは別のプロセスで動かす。**同時には探索しない。** 詰み探索を始める前に検討の探索を
  中断する。検討のエンジンは落とさない（▶ で戻ったときに起動し直さない）。中断が `応答なし`（V6）になったら
  詰み探索を始めず、表は検討のまま V6 を出す

AC-M1〜AC-M5 → #745

### 第2: 操作と表示

- **AC-M6** 検討ペインの操作列に「詰み探索」のボタンを足す。押すと現局面で詰み探索を始め、走っている間に押すと中止する。
  使うのは、設定のエンジン管理で「詰み探索に使う」に指定したプリセット（1つ）。指定が無ければボタンは無効で、
  ツールチップに「詰み探索に使うプリセットを設定で選択してください」と出す
- **AC-M7** **どちらのボタンも、もう一方が走っていることを理由に無効にしない。** 押した側に切り替える:
  - 検討中に「詰み探索」を押すと、検討を中断してから詰み探索を始める
  - 詰み探索中に ▶ を押すと、詰み探索を中止してから検討を始める
  - 詰み探索を始めると検討の意思は切れる。詰み探索が終わっても検討は自動で再開しない（▶ で戻る）
- **AC-M8** 詰み探索の間の操作列の語と本体は、下の「詰み探索の状態」の表に従う。
  評価値の列は `score mate` を検討と同じ表記（`Mate+7` など）で出す
- **AC-M9** 上限時間を設定で選べる（10秒・30秒・60秒・無制限。既定 30 秒）
- **AC-M10** 終わったら、候補手の表の上に結論を1行出す。文は下の「結論の文」の表の7つで、それぞれ別の文にする
- **AC-M11** 局面を動かす・▶ を押す・棋譜を閉じる・ワークスペースを差し戻す、のどれでも、詰み探索を中止し、
  結論と詰将棋エンジンの候補手を消して表を検討に返す。検討は ▶ を押したときだけ始まる。
  タブを移っても詰み探索は止まらない（検討と同じ）
- **AC-M12** 手番の側に王手が1つも無い局面でも探索は送る（判断はエンジンに任せる）

AC-M6〜AC-M12 → #746（#745 の後）

## 詰み探索の状態

**表を持つ側は1つ。** 検討か詰み探索のどちらかで、操作列の語と本体はその側が決める。
詰み探索が表を持つ間（M1〜M3）は、検討の状態（V0〜V8。`engine-standardization.md`）を語に出さない。
検討のエンジンの状態は裏で動き続け（例: 詰み探索中に検討のプリセットを替えると、裏で起動し直す）、
表が検討に戻ったときにその時点の語を出す。

| 記号 | 操作列の語            | 本体                                     | 詰み探索のボタン |
| ---- | --------------------- | ---------------------------------------- | ---------------- |
| M1   | `詰み探索の起動中…`   | 空                                       | 押すと中止       |
| M2   | `詰み探索中 12s`      | 詰将棋エンジンの候補手（生の結果だけ）   | 押すと中止       |
| M3   | `詰み探索完了 12s`    | 結論の1行と、最後の候補手                | 押すと始め直す   |

- M1 は詰将棋エンジンのプロセスが無いときだけ通る。プロセスは最初に押したときに起こし、アプリを閉じるか
  「詰み探索に使う」プリセットを替えるまで残す
- 詰将棋エンジンの候補手は検討のキャッシュ（`candidateCache`）に書かない。表が検討に戻ると、検討の
  「候補手の見え方」の規則でキャッシュから出す
- 詰将棋エンジンの失敗（起動できない・探索中に終わる・`stop` に答えない）は M3 に移り、結論の1行で言う。
  プロセスは落とし、次に押したときに起こし直す。検討の V6〜V8 は使わない
- ▶ / ■ の位置は M1〜M3 の間も ▶（押すと詰み探索を中止して検討を始める）。検討のエンジンが動いていないとき
  （エンジンなし・応答なし・終了・失敗）は、表を検討に返すだけにする。返した操作列に次の一手（再起動など）が出る
- 検討の中断を待っている間（最大3秒）の表と語は検討のもの。この間に押すと始めるのをやめる

## 結論の文

| 結論             | 本体の先頭の1行                                                         |
| ---------------- | ----------------------------------------------------------------------- |
| 詰み             | `7手詰` と手順（検討の読み筋と同じ表記）                                |
| 不詰             | 詰みはありません。                                                      |
| 時間切れ         | 時間内に詰みを見つけられませんでした。                                  |
| 中止             | 詰み探索を中止しました。                                                |
| 非対応           | このエンジンは詰み探索に対応していません。設定の「エンジン管理」で、詰将棋エンジンのプリセットを選択してください。 |
| 答えを読めない   | エンジンの答えを読めませんでした。                                      |
| エンジンの失敗   | 起動できない・終了した・中止に答えない・開始できない、の4つを分け、次にすることを添える（`mateOutcomeText`） |

文言は `design-system/design_system/content/` の規則で整えてよい。7つを別の文に保つ。
中止の文は、利用者が詰み探索のボタンで中止したときだけ出す。局面を動かすなど AC-M11 の中止では表ごと検討に戻るので出さない。

## 判断ログ

| 判断                   | 選択                       | 戻し方                         |
| ---------------------- | -------------------------- | ------------------------------ |
| 検討の終了条件にするか | しない。別の探索にする     | 検討の終了条件へ移す           |
| 結果を出す場所         | 検討ペインの候補手の表     | ドックの別のビューにする       |
| 検討と同時に走らせるか | 走らせない。押した側に切替 | エンジンごとに表を分けて並べる |
| ボタンを無効にするか   | しない                     | 走っている間は無効にする       |
| 詰み探索の後           | 検討を自動で再開しない     | 終わったら元の検討に戻す       |
| 使うエンジン           | 設定で指定したプリセット   | 押すたびにプリセットを選ぶ     |
| 局面を動かしたとき     | 中止して消す               | 結果を局面に紐づけて残す       |
| `checkmate` の読み方   | 自前で読む                 | ライブラリが4つを区別したら   |
| 非対応の見分け方       | 答えで判定する             | 申告が規格に入ったら起動時に   |
| 上限を読まないエンジン | 上限＋5秒で `stop` を送る  | 送らず、利用者の中止を待つ     |

- **別の探索にする**: 結論の形が違う（`checkmate` の1行）。詰将棋エンジンは通常の `go` では詰みが無いと止まる。ADR-0017
- **検討ペインの候補手の表**: 詰将棋エンジンは探索中に検討と同じ形の候補手を流す。他の GUI（ShogiHome）も読み筋の欄に出す
- **同時に走らせない**: 検討ペインは1つのエンジンの行だけを出す。2つのエンジンの行を1つの表に混ぜない。
  同時に走らせると CPU とメモリも取り合う
- **無効にしない**: 無効だと、もう一方を止める操作が先に要る。押した側に切り替えれば1回で済む
- **自動で再開しない**: 詰み探索の結論を読んでいる間に、検討の行で表が上書きされない
- **設定で指定したプリセット**: 操作列はボタンだけの段で、選ぶ欄を置く場所が無い。詰み探索に使うエンジンは検討と別物で、
  毎回選ぶものではない
- **中止して消す**: 候補手の表は現局面のもの。古い局面の結論を残すと、どの局面の答えか分からなくなる
- **自前で読む**: `usi` 0.6.2 は `notimplemented` と `nomate` を同じ値にし、`none` を手と読む
- **答えで判定する**: エンジンは詰み探索に対応しているかを申告しない
- **上限＋5秒で `stop` を送る**: 通常のエンジンは `stop` まで `bestmove` を返さないので、待つだけでは「非対応」に着かない。
  上限が無制限のときは利用者が中止するまで続く

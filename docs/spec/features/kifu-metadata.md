# 機能要件: 棋譜メタデータの編集

追跡: #114（親は #289）
main にあるか: **作成時だけ入力できる。作成後に編集する画面が無い**

## いまどうなっているか

`FileCreateForm`（新規作成）で入力できるのは4つ。

| 欄     | 保存先               |
| ------ | -------------------- |
| 先手名 | JKF header の `先手` |
| 後手名 | JKF header の `後手` |
| タグ   | `gameInfo.tags`      |
| メモ   | `gameInfo.note`      |

`SfenKifuCreateModal`（課題局面から作成）は先手名・後手名の2つだけ。

**読む側は2箇所ある。**

- ヘッダの対局者名（`useHeaderCenterInfo`）
- 盤の駒台の見出し（`GameBoard` が `jkfData.header` を直接読む）

つまり**書けるのは作るときの1回だけで、あとは読むだけ**になっている。

## なぜ要るか

issue #114 は「メタデータは横断検索／課題局面の**絞り込みの燃料**」と書いている。
対局者・戦型で横断フィルタを掛けたいが、そもそも入力する場所が無いので
燃料が溜まらない。

いまの局面検索の条件は「完全一致の局面」1つだけで、
メタデータでの絞り込みは無い。→ [screens/position-search.md](../screens/position-search.md)

## 受入条件（#114）

- 対局者名（先後・省略名）／手番／開始終了日時
- 棋戦／戦型／表題／持ち時間
- JKF header への保存・読み出し
- **将来の横断フィルタが参照できる形で永続化**

## 触ることになる画面

| 画面                                       | 何が変わるか                               |
| ------------------------------------------ | ------------------------------------------ |
| [ファイル作成](../screens/create-file.md)  | 入力欄が増える。作成後の編集と同じ形にする |
| [ファイルツリー](../screens/file-tree.md)  | 行に出す情報の元になる（`kifuInfo`）       |
| [局面検索](../screens/position-search.md)  | 絞り込みの条件が増える                     |
| [アプリのシェル](../screens/app-layout.md) | ヘッダに出す情報が増える                   |

## 決まっていないこと

- **編集の入口をどこに置くか。** 棋譜ごとの設定を開く場所がいまは無い
- **タグをどこに持つか。** いまは `gameInfo.tags` として JKF に入れているが、
  課題局面のタグは**アプリの設定ディレクトリ**に持っている。
  2つのタグ空間が別々にあることになる
- **横断検索が参照する形。** Rust の索引（`src-tauri/src/search/`）は
  いま局面（`PositionKey`）しか持たない。メタデータを引けるようにするなら
  索引の構造が変わる

## 注釈機能との関係

「棋譜の枝に重要度と note を付ける」機能（`docs/OPEN-QUESTIONS.md` Q-001）は
**これとは別物**。あちらは手に付き、こちらは棋譜1本に付く。

Q-001 の「競合する2実装」という前提は誤りと判明している
（系統B は存在しない）。**未マージのブランチの識別子を既存として参照しないこと。**

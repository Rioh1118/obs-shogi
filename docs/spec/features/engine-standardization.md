## 骨格

**エンジンの不具合はほぼ起きない。** だから状態の表示に画面を使わない（利用者の判定、2026-10-31）。
正常な間の見た目は今の操作列のままで、**段も行も足さず、本体も置き換えない。**
異常のときも変わるのは**操作列の1語とボタン1つだけ**で、文は既存の帯が持つ。

| 案                               | 中身                                                 | 諦めるもの                                   |
| -------------------------------- | ---------------------------------------------------- | -------------------------------------------- |
| **D. 語とボタンだけ**            | 操作列の語が変わり、▶ の位置が次の一手になる。文は帯 | 帯を閉じた後は、語を押すまで理由が見えない   |
| A. 操作列に1語＋本体に1行        | 候補手の上に文とボタン                               | 起きない失敗のために行の仕組みを持つ         |
| B. エンジンの段を足す            | タブの下にエンジン名と状態の段を常設                 | 読む面の高さ。常に画面を使う                 |
| C. 本体を置き換える              | 失敗は候補手の面ごと差し替える                       | 直前の読み筋が見えなくなる                   |

**D を採る。** プリセット編集の骨格は変えない（名前／使うもの／検討／エンジン設定、1つのリスト）。

判定と遷移は[状態遷移表](../../state-transitions/engine-standardization.md)。ここは見え方と文言。

**右のボタン1つが次の一手。** ▶ の位置に出る。語の領域は今のまま。▶ は「検討を開始」、■ は「検討を中断」。

| V2   | `待機中`                       | なし      | ▶                                        | ▶ が断られた回だけ（`analysis.md` の ※15 の文）                                                                         |

| V8   | `起動失敗`。中止した回は `起動を中止しました` | 帯と同じ段 | `もう一度起動`。`retry` の無い種類は `設定を開く` | `ENGINE_START_FAILURE_NOTICES` の本文のまま（今の帯）                                                     |

- **V6 / V7 / V8 の語は押せる。** 押すと小さなポップオーバーに帯と同じ文、「設定を開く」、エンジンが最後に出した行（`child.rs` の `RECENT_LINES` の範囲。受けたままの形。
  無ければ出さない）が出る。**帯を閉じた後に理由へ戻る口はこれだけ**で、普段は画面を使わない
- 帯は V6 / V7 に足す以外は今のまま。**帯を閉じても語とボタンは残る**
- 経過時間は語の中で、局面を読み始めてからの実時間。形は今のまま（`12s` / `1m 12s` / 1時間を超えても分で `61m 5s`）。
  局面が変わると 0 に戻る。検討完了は止まった時点の値で止まる。#566 はこの仕様で扱わない
- 「設定を開く」の行き先は設定のエンジン管理タブ（`useOpenSettings`）
- V0 はプリセットが選ばれていない回だけ。選んだプリセットのエンジンが無い回は V8 に入る
- 脚注は既存の規則のまま、どの状態でも4つの欄を出す。値が無ければ `—`
- 文言は `docs/spec/design-language.md` の「言葉」に揃える。`refusals.ts` の「起こし直す」は「再起動する」へ替える

### 候補手の見え方

**見るのは2つ。局面が盤と同じか、エンジンがいま動いているか。** この表が全状態を決める。状態遷移表の `—` のセルも従う。
注記の行は足さない。語が操作列にあるので、薄くするだけで足りる。

| 候補手の局面 | V2 / V3 / V4 / V5（エンジンが動いている） | V1 / V6 / V7 / V8（動いていない、または再起動中） |
| ------------ | ----------------------------------------- | ------------------------------------------------------ |
| 盤と同じ     | そのまま                                  | 薄く出す                                               |
| 盤と違う     | 出さない                                  | 出さない                                               |

- 局面を動かすと、その局面の控え（`candidateCache`）があれば同じ表で出す。控えは今のまま鍵（エンジン・棋譜・局面）で引く
- V3 の局面の切り替え中は、新しい局面の候補手が届くまで表を空にする。控えは使わない（読んでいる間は生の結果だけを出す、という今の規則）
- 空のときの本体は今のまま空欄。文を足さない

## 受入条件

### 第1範囲: 起動・停止・再開

- AC-1: エンジンを選んでいない状態で検討ペインを見ると、操作列に `エンジンなし` と出て、▶ が押せない。
- AC-2: プリセットを選んだ直後に検討ペインを見ると、起動が終わるまで操作列に `起動中…` と出る。
- AC-3: `起動中…` の間に ▶ を押すとボタンが ■ になり、起動が終わると押し直さずに読み始める。
- AC-4: 起動に失敗すると、操作列に `起動失敗` と出て、ボタンが「もう一度起動」（押しても直らない種類は「設定を開く」）になり、種類ごとの文が帯に出る。
- AC-5: 起動の失敗の帯を閉じても、操作列の語とボタンは残る。「起動を中止する」を押した回は語が `起動を中止しました` になる。
- AC-6: `起動失敗` の状態でプリセットの選択を外すと、帯が消え、操作列は `エンジンなし` になる。
- AC-7: `待機中` で ▶ を押すと、操作列が `検討中` になり、候補手が届き始める。
- AC-8: `検討中` で ■ を押すと、エンジンが止まった時点で `待機中` になる。止まるまで語は変わらず、■ は押せない。
- AC-9: `検討中` にエンジンが中断の指示に3秒応答しないと、操作列が `応答なし` になり、ボタンが「再起動する」になって帯に文が出て、エンジンに次の局面を送らない。
- AC-10: `応答なし` で「再起動する」を押すと、固まったエンジンが落ち、`起動中…` を経て、検討を入れていれば同じ局面を読み始める。
- AC-11: `応答なし` の後でエンジンが止まったと答えたら、語が `応答なし` から外れ、検討を入れていれば読み始める。
- AC-12: `検討中` にエンジンが終了すると、操作列が `エンジン終了` になり、ボタンが「再起動する」になって帯に文が出て、`検討中` の語と経過時間が残らない。
- AC-13: `待機中` にエンジンが終了しても、操作列が `エンジン終了` になる。
- AC-14: `エンジン終了` で「再起動する」を押すと、`起動中…` を経て、検討を入れていれば今の局面を読み始める。
- AC-15: エンジンが終了した状態が続いても、アプリは自分では再起動しない。
- AC-16: エンジンが終了した直後の候補手は薄くなり、局面を動かすと消える。
- AC-17: V6 / V7 / V8 の語を押すと、帯と同じ文と「設定を開く」が出て、エンジンの最後の出力が読める。出力が無いときは出力の欄が出ない。
- AC-18: `検討中` に局面を続けて動かすと、最後の局面の候補手だけが出て、操作列は `検討中` のまま変わらない。
- AC-19: `検討中` に局面を動かしている間、探索中のエンジンへ次の局面を送らない（やねうら王 V8.30 / V9.00 で固まらない）。
- AC-20: `検討中` にプリセットのオプションか、エンジン・評価関数・定跡を変えて保存すると、`起動中…` を経て、押し直さずに同じ局面を読み始める。
- AC-21: `検討中` に棋譜を閉じて開き直すと、`待機中` になり、自分では読み始めない。どの状態から閉じても、検討は入っていない状態に戻る。
- AC-22: 候補手の表に、盤と違う局面の結果が出ない。エンジンが止まる前の結果は薄く出る。
- AC-23: ▶ が断られると、操作列は `待機中` のまま帯に文が出る。
- AC-24: ■ が届かなかったとき、操作列は `待機中` にならず `応答なし` になる。
- AC-58: `起動失敗` で「もう一度起動」が成功すると、検討を入れていれば押し直さずに読み始める。
- AC-59: 起動が30秒を越えると、ボタンが「起動を中止する」になり、帯を閉じても残る。
- AC-66: ドックのタブ、操作列、設定の検討の語が `検討` で揃い、`解析` は画面に残らない（棋譜全体を読ませる機能を作るまで `解析` の語を使わない）。
- AC-65: アプリの画面の文字列に `docs/spec/design-language.md` の用語表の「使わない語」が残っていない（エンジンの綴り、コード、ログへ出す文は除く）。
- AC-64: 検討ペインは、エンジンが正常な間、今の操作列より多くの段も行も持たない。
- AC-60: `検討中` に設定を変えてエンジンが中断の指示に応答しないと、3秒後に落として新しい設定で起動する。
- AC-61: ドックの別のタブへ移っても、状態の語と検討の入り切りは変わらない。

### 第2範囲: 終了条件

- AC-25: プリセットの終了条件が空なら、▶ の検討は ■ を押すかエンジンが自分で探索を終えるまで止まらない。
- AC-26: プリセットに時間・深さ・ノード数のどれかがあれば、その条件に届いたところで操作列が `検討完了` になり、候補手が残る。
- AC-27: 2つ以上の条件があれば、先に届いた条件で `検討完了` になる。
- AC-28: `検討完了` で局面を動かすと、▶ を押さずに新しい局面を読み始める。
- AC-29: `検討完了` で ■ を押すと `待機中` になり、局面を動かしても読まない。
- AC-30: 終了条件のある検討では、やねうら王 V8.30 / V9.00 と zermelo が指定の時間・深さ・ノード数で止まる。
- AC-31: プリセット編集に詰み探索の欄が出ない。詰み探索の値を持つプリセットを保存し直しても、ファイルの値は残る。
- AC-32: プリセット編集の終了条件の説明に「まだ読まない」の文が残っていない。
- AC-62: `検討中` に終了条件だけを変えて保存すると、エンジンは再起動せず、次に読み始める局面から効く。

### 第3範囲: オプションの部品

- AC-33: オプションの行の値の左端が、部品の種類を問わず揃う。
- AC-34: `check` の行は ON / OFF の区切りボタンで出て、既定の値が押された形で見える。
- AC-35: `check` を既定の値へ戻すと、変えた値の印が消え、保存しても値を持たない。
- AC-36: 申告に既定の無い `check` には「指定しない」が足され、選ぶと値を持たない。
- AC-37: `spin` の行は数の欄と増減で出て、範囲の外を入力すると欄を離れたときに端へ丸まる。欄を空にして離れると初期値に戻る。
- AC-38: `spin` の欄に全角数字か桁区切りを入力しても、欄を離れたときに数として読まれる。
- AC-39: `spin` の欄に数値でないものを入力すると、欄を離れたときに元の値へ戻る。
- AC-40: 増減のボタンは申告の範囲の端で押せなくなる。増減は1刻みで、つまみの段を持つ行は次の段へ動く。
- AC-41: 幅（max − min）が 100 以下の `spin` にはつまみが付き、動かすと欄の値が同時に変わる。
- AC-42: スレッド数のつまみの範囲は申告の下限から、この機械の論理コア数と申告の上限の小さい方までで、申告の範囲まで入力できる。
- AC-43: ハッシュのつまみは申告の下限から2倍刻みで、上限はこの機械の全メモリと申告の上限の小さい方（2の累乗でなければ最後の段にする）で、申告の範囲まで入力できる。
- AC-44: つまみの段に無い値を入力すると、つまみは近い段（等距離なら小さい方）に寄り、欄の値は入力したまま残る。コア数やメモリが取れない機械では、つまみを出さない。
- AC-45: `combo` の行は選択で出て、先頭に「初期値（…）」がある。
- AC-46: `string` の行は文字の欄で出て、空にすると初期値に戻る。
- AC-47: `filename` の行は文字の欄と「選択…」で出て、ファイル選択画面を開けなければ理由が出て、パスを入力できる。
- AC-48: `button` の申告は画面に出ない。
- AC-49: 既定が `<empty>` の `string` / `filename` は、欄が空で出る。
- AC-50: `USI_MultiPV` を申告するエンジンでは、候補手の数がその名前で届く。`MultiPV` と両方を申告するエンジンでも `USI_MultiPV` だけに届く。
- AC-51: `MultiPV` も `USI_MultiPV` も申告しないエンジンでは、検討の節に候補手の数が出ず、検討の候補手は1つになる。保存済みの候補手の数は消えず、送られない。
- AC-52: `NumberOfThreads` を申告するエンジンでは、スレッド数が先頭に出て、設定のカードにもその値が出る。`Threads` と両方あれば `Threads` を使う。
- AC-53: 設定を枠で割らず、すべてのオプションが1つのリストのまま探せる。

### 互換

- AC-54: 既存の `engine_presets.json`（v1 / v2）をこの版で開くと、全件が読め、版が上がらない。
- AC-55: 申告に合う値だけを持つプリセットを開いて何も変えずに保存すると、オプションの値と終了条件が変わらない。申告に合わない値は今のとおり読み込みが知らせて直す。
- AC-56: 既存の ai_root のフォルダ構成のまま、エンジン・評価関数・定跡の候補が同じように出る。
- AC-57: 既定と同じ値を保存済みのオプションは、型を問わず印が出ないまま同じ値で送られる。
- AC-63: どの型でも、既定と同じ値を入れ直すと値を持たなくなる。

**更新の案内は出さない。** 終了条件を保存済みのプリセットは更新の後に止まり始めるが、画面が元から言っていたとおりに動くだけなので、

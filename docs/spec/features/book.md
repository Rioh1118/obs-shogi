> **注意:** #283 の本文は「`main` には #90 で作った境界があるだけ」と書いているが、

## どこに何があるか

| もの                                          | 所在                                    |
| --------------------------------------------- | --------------------------------------- |
| `BookReader` trait と開く経路、Tauri コマンド | `feature/book`（PR #237 #250）          |
| やねうら王テキスト定跡 `.db` の reader        | `feat/91-yaneuraou-db-reader`（作業中） |

`feature/book` が持っているもの（`src-tauri/src/book/`）:

- `BookFormat` —— **拡張子で判別する4形式**
  （`.db` / `.bin` / `.sbk` / `.ybb`）。知らない拡張子は**拒否する**
  （ShogiHome は既知3拡張子以外を Apery と見なすが、
  それをすると別物のファイルを固定長レコードとして読み進めてしまう）
- `BookHandle` —— 開いた定跡を指す値。close 後も配り直さない
- コマンド6本 —— `open_book` / `lookup_book_moves` / `get_book_info` /
  `list_books` / `close_book` / `close_all_books`

**読める形式は1つも無い。** trait と開く経路だけがある。

## 形式について確定していること

`docs/PREMISES.md` P-006 が一次資料で確認済みとして持っている事実。

- **`.db.bin` というフォーマットは存在しない。**
  やねうら王のバイナリ定跡は `.ybb`、`book.bin` は Apery のもの
- **#92 と #84 は仕様の訂正が要る**（`.db.bin` を数えている）

## なぜ作るのか（判断の軸）

`docs/PREMISES.md` P-006 が正面から書いている。

- ShogiHome は4形式の read/write/変換を**テスト付きで実装済み**（2026-08-29 に一次資料で確認）
- **それは反証にならない。** 判断の軸は「ShogiHome と張り合えるか」ではなく
  「AI 開発者の需要を取れるか」（P-008）
- **確かめるべきは**「obs-shogi の定跡機能が zermelo のような AI 開発の実作業で使われるか」。
  ShogiHome の定跡 UX で足りるなら自前で持つ意味は薄い
- 傍証: ShogiHome 作者本人が「定跡機能は将棋AI大会用」と書いている

**この判断は `docs/OPEN-QUESTIONS.md` Q-003 が未決のまま。**
Q-003 が決まるまで、T1（局面編集・メタデータ・特殊手）と定跡の
どちらを先にするかも決まらない。

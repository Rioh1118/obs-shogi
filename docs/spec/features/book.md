# 機能要件: 定跡（book）

追跡: #283（エピック） #747（エピック: やねうら王の配布物）
main にあるか: **ある**（#446）。`src-tauri/src/book/` と、`lib.rs` に登録した6本のコマンド。

**見る画面はある。** ドックのタブ1枚（#95。→ [screens/book-view.md](../screens/book-view.md)）。
開いて、現局面の候補手を出して、その先を辿るところまで。
**書く側・重ねる側・編集する側はまだ無い**（#97 #96 #99）。

## どこに何があるか

`src-tauri/src/book/` が持っているもの:

- `BookFormat` —— **拡張子で判別する4形式**
  （`.db` / `.bin` / `.sbk` / `.ybb`）。知らない拡張子は**拒否する**
  （ShogiHome は既知3拡張子以外を Apery と見なすが、
  それをすると別物のファイルを固定長レコードとして読み進めてしまう）
- `BookHandle` —— 開いた定跡を指す値。close 後も配り直さない
- コマンド7本 —— `open_book` / `lookup_book_moves` / `walk_book_lines` /
  `get_book_info` / `list_books` / `close_book` / `close_all_books`
- `walk_book_lines` —— 候補手の先を、定跡が続くかぎり辿る。
  **盤を持たないビューが「その手の先も定跡にあるか」を出す唯一の手段**

**読めるのは `.db` と `.ybb` の2つ。** 残る2つは `UnsupportedFormat` で落ちる。
`.ybb` は開くときに頭の 32 バイトだけを読み、引くたびに索引を二分探索する（`book/yaneuraou_ybb.rs`。
形式の出典はやねうら王の公開ソースで、reader の冒頭が節を指している）。手数は見ない（鍵が手数を持たないため。
エンジンの `IgnoreBookPly` を有効にしたときと同じ引き方）。
**文面をここへ写さない** —— 写した引用を突き合わせる検査が無いので、
次に文言を直した人がここを置き去りにする。
出典は `formats.rs` の `open_reader` で、`an_unsupported_format_tells_the_user_what_to_expect` が
「利用者が次にやることで終わる」ことを見ている。

## 形式について確定していること

`docs/PREMISES.md` P-006 が一次資料で確認済みとして持っている事実。

- **`.db.bin` というフォーマットは存在しない。**
  やねうら王のバイナリ定跡は `.ybb`、`book.bin` は Apery のもの
- **#92 と #84 は仕様の訂正が要る**（`.db.bin` を数えている）

## エンジンに定跡を渡す（やねうら王）

事実は `research/engines/yaneuraou-files.md`（2026-11-21 に実測）。**やねうら王の配布物は
`.ybb` だけになった**（`book/` に `user_book1.ybb` の1ファイル）ので、ここが通らないと
配布物をそのまま置いても定跡が効かない。

**いまは通らない。** AI ライブラリは `book/` の `.db` しか拾わないので、`.ybb` だけのフォルダは
「定跡が未検出です」になり、プリセットで選べない。

### 要件

- **R-B1** AI ライブラリは `book/` の `.ybb` も定跡として拾い、プリセットの候補に出す
- **R-B2** `.ybb` を選んだプリセットは、`BookFile` に**拡張子を `.db` に替えた名前**を送る。
  やねうら王は `.db` が無ければ同じ名前の `.ybb` を読む。`.ybb` の名前やパスを送ると
  選択肢に無い値として捨てられ、**定跡なしで黙って指し続ける**
- **R-B3** 送った名前が `BookFile` の選択肢に無いときは、`.db` と同じ扱い（今の
  「選択肢に無い名前」の警告）にする。名前を `user_book1.ybb` などに変える案内で終える
- **R-B4** 同じ名前の `.db` と `.ybb` が並ぶフォルダで `.ybb` を選んだら、エンジンは `.db` を読む。
  候補に「`.db` が読まれる」と出し、`.ybb` を読ませたいなら `.db` を外すと案内する
- **R-B5** 読めたかは起動時の `info string` で確かめる。`.ybb` を読んだなら
  `read book file : <.ybb の絶対パス>` の行が出る（実測）。載らなければ今の「定跡を読めたか確かめられない」警告を出す。
  **いまの照合は、定跡をパスで送ったときしか走らない。** 名前で送る経路でも、照合の相手として `.ybb` のパスを渡す
  （R-B1〜R-B5 → #741）
- **R-B6** 定跡ビューが `.ybb` を開ける。配布物は 1.5 GB 級なので、丸読みせずに引く → #742（済み）

**#84 の完了条件「エンジンに渡す `BookFile` の値はパス文字列のまま」は、やねうら王の `.ybb` には当てない**
（R-B2 が優先する）。

### 優先定跡（いまは扱わない）

やねうら王は `<名前>-000.db`（`.ybb` も可）から番号順に、本体の定跡より**先に**引く。
同じフォルダに置かれていると、エンジンの指す手と定跡ビューが出す手が食い違う。
扱いは `docs/IDEAS.md` の「優先定跡」に置いた（6週間以内に着手しない）。

## 定跡ファイルをどこに置くか

**用途で決まる。同じファイルが両方の用途を持つ。**

- **エンジンに食わせる定跡**は AI ライブラリ（`<ai_root>/<AI名>/book/`）に置き、
  プリセットの `BookFile` がそこを指す。**ワークスペースのツリーには出さない**
- **定跡ビューが開けるのは任意のパス。** ライブラリの中も外も開ける ——
  いま回しているエンジンが食っている定跡を覗くのが最短の場面もあれば、
  落としてきた公開定跡や `makebook` の出力を覗く場面もある

**混ぜてはいけないのは操作のほう。** 「プリセットの `BookFile` 欄」（エンジンに何を
食わせるか）と「ビューがいま見ている定跡」（自分が何を覗いているか）を同じ
コントロールにしない —— 片方を変えたらもう片方も変わる、が起きる（#96 の注意書き）。
**ファイルそのものは同じでよい。**

他の GUI も置き場の規約を持たない。ShogiHome はファイルダイアログで任意のパスを
開き、最後に開いたパスだけを設定に残す。ShogiGUI は「定跡管理」に登録した一覧から
選ばせる。`<engine>/book/` はやねうら王の `BookDir` + `BookFile` が読む側の規約で、
GUI の規約ではない。

## なぜ作るのか（判断の軸）

`docs/PREMISES.md` P-006 が正面から書いている。

- ShogiHome は4形式の read/write/変換を**テスト付きで実装済み**（2026-08-29 に一次資料で確認）
- **それは作らない理由にならない。** 判断の軸は「AI 開発者の需要を取れるか」（P-008）
- **確かめるべきは**「obs-shogi の定跡機能が zermelo のような AI 開発の実作業で使われるか」。
  既存の GUI の定跡編集で足りるなら、自前で持つ意味は薄い
- 傍証: ShogiHome 作者本人が「定跡機能は将棋AI大会用」と書いている

**この判断は `docs/OPEN-QUESTIONS.md` Q-003 が未決のまま。**
Q-003 が決まるまで、T1（局面編集・メタデータ・特殊手）と定跡の
どちらを先にするかも決まらない。

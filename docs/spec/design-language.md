# デザインの決め方

**新しい UI を書くときに、上から順に答える。** ほとんどは既に決まっていて、
ここはその索引。**新しい体系を作らない。**

規則そのものは `CONTRIBUTING.md`「SCSS の書き方」、根拠は `docs/decisions/`、
値は `src/index.scss`（コメントに実測のコントラスト比が併記してある）。

## 0. 性格

**このトンマナは新しい見た目を作るためのものではない。** 今の画面にある雰囲気を言葉にし、揃っていない箇所を
合わせる基準にする（利用者の言葉「今のスタイルをうまく言語化して、揃っていないところを合わせる」、2026-10-31）。

### 2つの層

| 層     | 中身                       | 決め方                                                                 |
| ------ | -------------------------- | ---------------------------------------------------------------------- |
| 素材   | 盤・駒台・駒               | **実物の画像が主役。** 榧の盤と濃い木の駒台で、研究の時間をリッチにする。UI のトークンを当てない。そのまま残す |
| 額縁   | それ以外の全部             | 暗い緑黒の面、砂色の文字、銅の印。**素材を引き立てる側に回り、自分で質感を主張しない** |

スタイリッシュに見えているのは、この2層の対比があるから。額縁に木目や装飾を足さない。素材をフラットな色に置き換えない。

### 額縁の性格

**額縁は記録係のように振る舞う。** 対局室の隅で手と時間を正確に書き留め、聞かれたことに短く答え、
盤の主役を奪わない。見た目と言葉で迷ったら、この人ならどうするかで決める。

| 語         | 意味                                         | 行き過ぎた形                                 |
| ---------- | -------------------------------------------- | -------------------------------------------- |
| 正確       | 起きたことだけを、数と語を揃えて書く         | 内部の段や綴りをそのまま見せる               |
| 寡黙       | うまくいっている間は何も言わない             | 何が起きたか分からないまま黙る               |
| 行き届く   | 手を打てるときは、次の一手を同じ場所に添える | 案内の文で画面を埋める。押せない操作を見せる |

**迷ったときの順は 正確 → 行き届く → 寡黙。** 嘘にならないことが先で、手が打てることが次で、短さはその後。

## 1. 置き場

レイヤは Feature-Sliced Design。`app → pages → widgets → features → entities → shared`。
import は下向きだけ。**lint が強制する**（`CLAUDE.md`「依存の方向」）。

新しい画面を足したら `docs/spec/README.md` の一覧に行を足す。

## 2. 寸法

**直値を書かない。** `src/index.scss` のトークンから選ぶ。

- **文字は用途で選ぶ。サイズで選ばない。** `$font-hint`（注記・件数）/ `$font-aux`（説明文・パス）/
  `$font-body`（本文。`body` に入っているので本文なら書かなくてよい）/ `$font-lead` / `$font-section` /
  `$font-title` / `$font-display` / `$font-hero`
- **間隔と角丸は同じ N が同じ値。** `$space-6` と `$radius-6` は両方 1.2rem。片方だけ別系統にしない
- ラチェットが見るのは**スケールに載るプロパティだけ**。`min-height` / `width` / `top` は
  素通りする。**緑で通ったことを「規約に沿っている」と読まない**（ADR-0003）

### 角丸は役割で選ぶ

**今の画面で多い形を基準にした。** 外の面ほど大きく、内側は1段以上小さい。素材の層は対象外。

| 役割                                     | トークン         | 値     |
| ---------------------------------------- | ---------------- | ------ |
| 行（ツリー、一覧、メニューの項目）       | `$radius-2`      | 0.4rem |
| 押す・打つもの（ボタン、入力、選択）     | `$radius-3`      | 0.6rem |
| 面（ドック、カード、ポップオーバー、メニュー） | `$radius-4`  | 0.8rem |
| モーダル                                 | `$radius-5`      | 1rem   |
| 札（バッジ、チップ）                     | `$radius-2`      | 0.4rem |
| 進捗の棒、丸ボタン列                     | `$radius-pill`   | —      |
| 印（状態の点、丸い記号）                 | `$radius-circle` | —      |

### 文字の太さは4段

`$weight-regular`（本文）/ `$weight-medium`（欄の名前、タブ）/ `$weight-strong`（小見出し、ボタン、選ばれた行）/
`$weight-title`（ダイアログとペインの題）。**650 や 760 のような中間を作らない。** 太さで段を作りすぎると額縁がうるさくなる。

### 揃える作業の範囲

**基準ができた時点で、既存の画面を一度に書き換えない。** 見た目の差が出ない置き換え（`12px` → `$radius-6` など）と、
基準へ寄せて見た目が動くものを分け、後者は画面単位で見て決める。**盤・駒台・駒には触らない。**

## 3. 色

**意味色は4つから選ぶ。発明しない。** 段は**深刻度ではなく「復帰に何が要るか」**で切ってある（ADR-0004）。

| トークン         | 意味                                   |
| ---------------- | -------------------------------------- |
| `$color-info`    | 伝えるだけ                             |
| `$color-warning` | 再試行で直る                           |
| `$color-danger`  | 別の操作が要る。危険な操作の確認もここ |
| `$color-fatal`   | アプリ再起動                           |

見た目の派手さで選ばない。**段の区別を色だけに持たせない**——
`$color-danger-text` と `$color-fatal-text` は暗い面で基準を満たすまで持ち上げると必然的に寄る。
区別は**記号と文言、そして出す動作**が持つ。

文字と面で使うトークンが違う。面に敷くなら `$color-*-solid` / `$surface-*`、
暗い面に載る文字なら `$color-*-text`。**コントラスト比は index.scss のコメントに実測がある。**

### ホバーの向き

**面に載る文字の色で決まる**（ADR-0005 決定2）。

- 白文字を載せる面 → **暗くする**（明るくすると比が下がり、押す瞬間に最も読みにくくなる）
- 暗い文字を載せる面 → **明るくする**

## 4. 重なりと影

**離れたファイル同士で大小が意味を持つものだけ**にトークンがある。
部品の中で閉じた重なりは局所の直値でよい。

並びは下から: 部品の中（1桁〜100）→ 選択肢の一覧（1000）→ 付箋（1200）→ 更新カード（9000）
→ タイトルバー・モーダル（9999）→ 通知（10000）→ 棋譜のポップオーバー（100000台）。

**通知はモーダルより上**（下にすると overlay にぼかされて読めず、クリックが overlay に当たって
モーダルごと閉じ、編集中の入力が消える）。

影は**浮き上がりの高さでなく、何が浮いているかで選ぶ**。
`$shadow-panel`（パネル・カード）/ `$shadow-overlay`（ポップオーバー・メニュー）/
`$shadow-control` と `$shadow-control-press`（押せるもの。ホバーで浮かせ押下で落とす対）。

## 5. 振る舞い

### 状態の見せ方

- **いまの状態は語で言う。** 色と記号は語を支えるだけで、語を置き換えない（ADR-0004 と同じ理由）
- **まず起きないことに画面を使わない。** 常設の段や行を足さず、起きたときだけ既存の場所の語とボタンが変わる。文は帯が持つ
  （利用者の判定、2026-10-31）
- **帯を閉じても状態の語は残る。** 帯は知らせるもので、状態そのものではない
- **うまくいった段は出さない。** 読み込み・確かめ・当てる、は成功したら黙る。**失敗して手を打てるときだけ出す**
  （利用者の判定「内部の段が画面に出て分かりにくい」、2026-09-30）
- **空は理由と次の一手を言う。** 「何もありません」で終えない
- **待っている間は何を待っているかを言い、長引いたら止める口を出す。** 止める口が無い待ちを作らない
- **古い結果は古いと書く。** 消すか、いつのものかを添える。今のもののように並べない

### 動き

**利用者の操作に応える動きだけを使う。** 値は `$duration-*`。

- 押す・開く・選ぶに応えるのは `$duration-3`〜`$duration-5`
- **反復する動きは待ちの表示（`Spinner`）だけ。** 解析中の印は脈打たせない——読む面の隣で動くと視線を奪う。
  解析中であることは語と進む経過時間が言う
- 数字が更新されるときに動かさない。候補手は置き換えるだけで、並び替えを滑らせない

### 密度

- 読む面は `$color-primary-dark` の上で詰める。1行に1項目、表は列で揃える
- **数は等幅**（`font-variant-numeric: tabular-nums`。読み筋と綴りは `$font-mono`）。桁が揃わないと並びを読めない
- 名前の下にエンジンの綴りを `$font-hint` で添える。**綴りを主にしない**

### 部品の選び方

**部品は入力の種類で決める。同じ種類を別の部品にしない。** 新しい画面でもこの表から選ぶ。

| 入力の種類         | 部品                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| 2〜4の択一         | 区切りボタン。全部見えて1回で変えられる                              |
| 5つ以上の択一      | 選択                                                                 |
| 数                 | 数の欄と増減。範囲と段が決まるならつまみを欄の下に足す。**欄が正**   |
| 文字               | 文字の欄                                                             |
| パス               | 文字の欄と「選択…」。選べなくても打てる                              |

**ボタンは役割で選ぶ。** 迷ったら `neutral`。`primary` は1画面に1つ。`もう一度読み込む` は失敗の第一手なら `accent`、他に次の一手があれば `neutral`（利用者の判定、2026-10-31）。

| 役割 | `tone`    | 見た目                 | 例                         |
| ---- | --------- | ---------------------- | -------------------------- |
| 確定 | `primary` | 砂色の面に暗い文字     | 保存、作成                 |
| 進める | `accent` | 銅の枠に銅の文字       | フォルダを作成、選択…      |
| 中立 | `neutral` | 枠のボタン             | キャンセル、閉じる         |
| 危険 | `danger`  | 赤の面                 | 削除                       |

**部品は `Button` の値に揃える。** 同じ行に並ぶ部品が別の高さや枠を持たない。

| 項目   | 基準                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| 高さ   | `Button` の `sm` 2.8rem / `md` 3.2rem / `lg` 4rem。**フォームの行は `md`**（入力の 32px / 36px / 40px はここへ寄せる） |
| 角丸   | `$radius-3`                                                                              |
| 枠     | `$stroke`。打つ欄の面は `$surface-field`                                                 |
| 文字   | 押すものは `$font-aux` の `$weight-strong`。打つ欄は `$font-body` の `$weight-regular`    |
| ホバー | 押すものは `rgba($color-white, 0.06)` を `$duration-3` で。`accent` は面を敷かず枠を明るくする                                |
| 押下   | 1回押すボタンは `motion`。増減と区切りは連続で押すので沈ませない（ADR-0005）             |
| 無効   | 不透明度 0.45 だけ。色を変えない                                                         |
| フォーカス | `$focus-ring` の2px。枠の中で切れる部品は外側の器に出す（`:focus-within`）            |
| 不正   | 枠は `$color-danger`、文字は `$color-danger-text`                                        |
| つまみ | 軌道 `$space-2`、満たした側は `$color-secondary-dark`、持ち手は `$color-text-primary`。ブラウザ既定のまま出さない |
| 幅     | 押すものは文字の幅。**行の余りを押すもので埋めない。** 余りは入力欄が受け持つ（利用者の判定、2026-10-31） |
| 記号   | 増減も `lucide-react`（`Minus` / `Plus`）。文字で代用しない                              |

**選択は左の銅のバーで見せる。** `index.selected-bar` で独立した棒を描き（影で引くと角丸に沿って曲がる）、面は `$color-primary-light` の濃淡。
白透明の面を選択に使わない（利用者の判定「白透明はダサい」、2026-10-31）。盤の下の面は `$color-primary-black`。

文字の濃さは3段。`$color-text-primary`（本文）/ `$color-text-muted`（名前の添え書き・説明）/
`$color-text-faint`（無効・範囲の注記）。**`rgba(…, N)` で薄くしない。**

## 6. 言葉

**画面の文章は、標準的な業務アプリの日本語で書く。** 言い回しで個性を出さない。和語に開いた独自の言い方より、利用者が
他のアプリで見慣れた語を選ぶ（利用者の修正「数を入れてください」→「数値を入力してください」、2026-10-31）。

### 文の型

| 項目         | 規則                                                                                                         | 理由                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------ |
| 文末         | 文は です・ます で句点を打つ。状態の語、欄の名前、ボタンは句点なし                                            | 長さが揃い、操作列に載る                   |
| ボタン       | **漢語は体言止め**（`保存` `削除` `再起動` `棋譜を作成`）。和語は言い切り（`開く` `閉じる` `もう一度読み込む`）。`〜する` を付けない。`OK` と `はい` を使わない | 利用者の判定（2026-10-31）。短く、同じ形で並ぶ |
| 題           | 名詞か「〜を＋漢語」（`設定` `局面検索` `局面を保存`）。**同じ操作の題とボタンは同じ語** | 題を読めばボタンの結果が分かる |
| 欄の名前     | 名詞                                                                                                         | 値の入れ物を名乗る |
| 別の画面へ   | ボタンの語に `…`（`選択…`）                                                                                  | 押すと確認か選択が挟まる |
| 失敗文       | **何が起きたか。次にすること。** の2文。起きたことは `〜できませんでした。` に揃える。`〜に失敗しました` を使わない。謝らない | ADR-0004                                   |
| 理由を添える | 文の後に全角括弧 `（…）`。`: ${e}` の形にしない                                                               | 文の形を崩さない                           |
| 入力の断り   | **直し方だけを1文で。** 起きる動作の説明を足さない（`数値を入力してください`）                                | 寡黙                                       |
| 待ち         | `〜しています…`。項目の状態なら `〜中…`                                                                      | 終わる見込みのあるものだけに使う           |
| 内部の語     | 画面に出さない: 申告、取得、プローブ、席、セッション、ランタイム、ready、`isready`                            | 利用者の判定（2026-09-30）                 |

### 用語

**左の語だけを使う。** 右は使わない語。

| 使う語             | 意味                                 | 使わない語                               |
| ------------------ | ------------------------------------ | ---------------------------------------- |
| 入力する           | 欄に打つ                             | 入れる、打つ、記入する                   |
| 選択する           | 一覧から選ぶ                         | 選ぶ（文の依頼で）                       |
| 確認する           | 利用者に見てもらう                   | 確かめる                                 |
| 押す               | ボタンを操作する                     | クリックする                             |
| 再起動する         | エンジンやアプリを立て直す           | 起動し直す、起こし直す                   |
| もう一度〜         | 同じ操作をやり直す                   | 再試行、リトライ                         |
| 読み込む           | ファイルやエンジンの情報を取り込む   | ロード（ダウンロードは別の語）、読込     |
| 検索する           | 文字や局面で見つける                 | 探す                                     |
| もう一度読み込む   | AI ライブラリを読み直す              | スキャン、再スキャン、探し直す           |
| キャンセル         | 開いた画面の編集を捨てて閉じる       | 破棄                                     |
| 中止する           | 起動など進行中の処理を打ち切る       | やめる                                   |
| 中断する           | 検討を止めてエンジンは残す（■）      | 止める、停止する                         |
| 取り消す           | 確定した操作を元に戻す               | 元に戻す（文の依頼で）                   |
| 削除する           | ファイルや項目を無くす               | 消す、外す（削除の意味で）               |
| 保存する           | 課題局面やファイルに残す             | 登録                                     |
| 作成する           | 新しく作る                           | 作る、新規作成（`新規プリセット` の名前は可） |
| 初期値             | エンジンや画面の出荷時の値           | 既定、デフォルト                         |
| 設定               | 利用者が変える項目                   | オプション、プリファレンス               |
| フォルダ           | ディレクトリ全般                     | ディレクトリ、フォルダー                 |
| 場所               | ファイルやフォルダのある所           | パス（文字を直接扱う欄では `パス`）      |
| AI ライブラリ      | エンジンと評価関数を置くフォルダ     | AI ルート、AI のフォルダ、AI の置き場    |
| ワークスペース     | 棋譜を置くフォルダ                   | ルート、ルートディレクトリ               |
| 数値               | 欄の数                               | 数、数字                                 |
| 手目 / 手数        | 手目は位置、手数は数                 | —                                        |
| エンジン           | 将棋の思考エンジン                   | プロセス                                 |

| 手番、先手、後手     | 共通の語                                     | 共通                          | 黒、白                   |

**プリセットと AI ライブラリはこのアプリの語で、他の GUI に無い。** 利用者の決定（「プリセットの考え方を活かす」）に従って残す。
`初期値` も残す（他の GUI は `既定値` と `デフォルト` に割れている）。

### 表記

| 項目             | 規則                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 省略記号         | `…` 1文字。`...` を使わない                                              |
| 括弧             | 日本語の文では全角 `（）`。引用とボタン名は `「」`                       |
| 英数字           | 半角。日本語との間に半角スペース（`AI ライブラリ`）。数字と単位は続ける（`3秒`） |
| 感嘆符           | 使わない                                                                 |
| ひらがな         | `ください` `かかる` `そろう` `つながる` `できる` `とき` `もの`           |
| 数の単位         | 語に括弧で添える（`ハッシュ（MB）`）。値の側で繰り返さない               |
| 記号             | `lucide-react` だけ。絵文字を画面に使わない                              |

**1語が2つの動作を指さない。** 中断する（検討）／中止する（処理）／キャンセル（画面の編集）／閉じる（画面）を混ぜない。

**表の右の語は `screenVocabulary.test.ts` が画面の文字列から止める。** 語を足したら綴りも足す（足さないと同じ検査が赤になる）。
[エンジン標準化の仕様](features/engine-standardization.md)の AC-65 と AC-66 はこの走査で閉じる。

## 7. まだ決まっていないこと

**決まっていないものは `/decide` を通して決める。** 次の2つは他をブロックしている。

- **空状態 / 読み込み中 / エラー表示を共通化するか。**
  決まるまで、失敗を利用者に伝える口がどこにも無い状態が続く。
  決めるときは「どこに出すか」（トースト / ペイン内 / モーダル）と
  「復帰の導線を持たせるか」まで含める。**エラーを出しても復帰導線が無ければ行き止まり**になる
- **どのレベルがスクロールを受け持つか。** 長い文字列（棋譜コメント、ファイル名、
  エンジン名、エラー）は省略か折り返しか。**1つに決める**

決める必要が出たら、まず `docs/OPEN-QUESTIONS.md` に Q を立てる。
決めるのは `/decide` で1件ずつ。**1サイクルで2件以上を確定させない**
（`docs/OPERATING-MODEL.md`）。

## やらないこと

- **既存の余白・大きさを「大きい / 小さい」で評価する。** 意図して決められたものとして扱う。
  指摘してよいのは (a) 同じ役割の部品が別々のトークン・直値で書かれている
  (b) その値が原因で中身が入りきらない・操作できない、のどちらか。
  **利用者が画面を名指して違和感を言ったときは `/design-rework` で見直す**（利用者の判定、2026-10-31）
- **スクロールバーの非表示を不具合として扱う。** 意匠として決まっている
- スマホ・タブレット対応。対象は幅1280px 以上。ただし「縮めたら操作不能」は幅に関係なく許さない

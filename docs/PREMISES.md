# PREMISES — 前提レジスタ

方針は前提の上に建つ。**前提が黙って腐ると、方針全体が黙って腐る。**
将棋界隈は小さく需要の直接観測が難しいため、確実性を求める代わりに「何を仮定しているか」「いつ確認したか」「何が起きたら失効するか」を明示する。

**運用**: `次回確認` を過ぎた前提があれば、週次レビュー（`docs/OPERATING-MODEL.md`）で必ず扱う。
確認したら日付を更新する。**覆ったら方針側（ADR）を直すまでがワンセット。**

| 状態      | 意味                                   |
| --------- | -------------------------------------- |
| ✅ 確認済 | 一次情報で裏を取った                   |
| ⚠️ 未確認 | 仮定のまま使っている                   |
| ❌ 反証   | 誤りと判明。依存する決定の見直しが必要 |

---

## P-001 ❌ 「フォルダ横断の局面検索は ShogiHome が構造的に持てない領域」

- **依存する決定**: 方針転換 2026-06（堀の定義そのもの）
- **確認日**: 2026-07-27
- **判定**: **反証。** 棋譜エクスプローラー（ShogiGUI 作者製）が2022年時点で完全一致・部分一致・左右反転・手番無視・手数制限・メタデータフィルタ・タグを実装済み。KifuBase も同種。「横断局面検索」だけを名乗ると「棋譜エクスプローラーでいいのでは」と言われる
- **差し替え後の前提** → P-002
- **対応**: 堀の再定義が必要。ADR 化すること

## P-002 ⚠️ 「保守されたクロスプラットフォームの棋譜ライブラリ層は存在しない」

- **依存する決定**: 堀の再定義（P-001 の後継）
- **根拠**: 棋譜エクスプローラー 最終リリース 2022-09-16 / KifuBase 最終更新 2019-01-06 / ShogiGUI・将棋所は Windows 専用クローズドソース / ShogiHome 作者が「大量の棋譜から検索・統計する機能はありません」と明示的にスコープ外宣言
- **確認日**: 2026-07-27（二次調査。一次確認は未）
- **失効条件**: 棋譜エクスプローラーが更新再開する / ShogiHome が横断検索を実装する / 新規の同種ツールが出る
- **次回確認**: 2026-10（3ヶ月）

## P-003 ⚠️ 「研究家は棋譜に note を書く」

- **依存する決定**: 製品の一文（「ナレッジベース」であること）、T1 の注釈機能全体
- **根拠**: 未検証。**この製品で最も重い未検証前提。**
- **失効条件**: ドッグフーディング2週間で自分自身が note を一度も書かなければ、赤信号
- **撤退基準**: ユーザーが棋譜を import するのに note を書かないなら、作ったのはナレッジベースでなく検索ツール。その場合は「クロスプラットフォーム版 棋譜エクスプローラー」に軸を寄せる
- **次回確認**: ドッグフーディング終了時

## P-004 ⚠️ 「合流(transposition)を扱えないことは研究家にとって実際に痛い」

- **依存する決定**: 差別化の方向（IDEAS.md の最有力候補）
- **根拠**: ShogiHome issue #236（2022年、30コメント＝同リポジトリ最多議論）が「木構造では千日手や局面の合流に対応できない、グラフを直接可視化・編集したい」と要求。定跡フォーマット対応のみで閉じられ本体は未解決。KIF/KI2/CSA いずれも仕様として合流を持たない
- **未確認部分**: 30コメントは「声の大きい少数」かもしれない。実際に困っている頻度は不明
- **次回確認**: #236 のコメント主に直接あたる / ドッグフーディングで自分が合流に遭遇する頻度を数える

## P-005 ⚠️ 「対象ユーザーは 50〜300 人規模」

- **依存する決定**: 「名前の分かる20人向けに作る」という規模観、機能の作り込み深度
- **根拠**: 将棋人口 430万人・過去最低（レジャー白書2025）からの推定。体系的な定跡研究家 2,000〜5,000人 → 現実的な有料ユーザ 50〜300人。**推定であって実測ではない**
- **次回確認**: 2027-01（レジャー白書2026 公開後）

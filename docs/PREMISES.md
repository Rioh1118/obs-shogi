# PREMISES — 前提レジスタ

方針は前提の上に建つ。**前提が黙って腐ると、方針全体が黙って腐る。**
将棋界隈は小さく需要の直接観測が難しいため、確実性を求める代わりに「何を仮定しているか」「いつ確認したか」「何が起きたら失効するか」を明示する。

**運用**: `次回確認` を過ぎた前提があれば、週次レビュー（`docs/OPERATING-MODEL.md`）で必ず扱う。
確認したら日付を更新する。**覆ったら方針側（ADR）を直すまでがワンセット。**

| 状態      | 意味                                   |
| --------- | -------------------------------------- |
| ✅ 確認済 | 一次情報で裏を取った                   |
| ⚠️ 未確認 | 仮定のまま使っている                   |
| ❌ 反証   | 誤りと判明。依存する決定の見直しが必要 |

---

## P-001 ❌ 「フォルダ横断の局面検索は ShogiHome が構造的に持てない領域」

- **依存する決定**: 方針転換 2026-06（堀の定義そのもの）
- **確認日**: 2026-07-27
- **判定**: **反証。** 棋譜エクスプローラー（ShogiGUI 作者製）が2022年時点で完全一致・部分一致・左右反転・手番無視・手数制限・メタデータフィルタ・タグを実装済み。KifuBase も同種。「横断局面検索」だけを名乗ると「棋譜エクスプローラーでいいのでは」と言われる
- **差し替え後の前提** → P-002
- **対応**: 堀の再定義が必要。ADR 化すること

## P-002 ⚠️ 「保守されたクロスプラットフォームの棋譜ライブラリ層は存在しない」

- **依存する決定**: 堀の再定義（P-001 の後継）
- **根拠**: 棋譜エクスプローラー 最終リリース 2022-09-16 / KifuBase 最終更新 2019-01-06 / ShogiGUI・将棋所は Windows 専用クローズドソース / ShogiHome 作者が「大量の棋譜から検索・統計する機能はありません」と明示的にスコープ外宣言
- **確認日**: 2026-07-27（二次調査。一次確認は未）
- **失効条件**: 棋譜エクスプローラーが更新再開する / ShogiHome が横断検索を実装する / 新規の同種ツールが出る
- **次回確認**: 2026-10（3ヶ月）

## P-003 ⚠️ 「研究家は棋譜に note を書く」

- **依存する決定**: 製品の一文（「ナレッジベース」であること）、T1 の注釈機能全体
- **根拠**: 未検証。**この製品で最も重い未検証前提。**
- **失効条件**: ドッグフーディング2週間で自分自身が note を一度も書かなければ、赤信号
- **撤退基準**: ユーザーが棋譜を import するのに note を書かないなら、作ったのはナレッジベースでなく検索ツール。その場合は「クロスプラットフォーム版 棋譜エクスプローラー」に軸を寄せる
- **次回確認**: ドッグフーディング終了時

## P-004 ⚠️ 「合流(transposition)を扱えないことは研究家にとって実際に痛い」

- **依存する決定**: 差別化の方向（IDEAS.md の最有力候補）
- **根拠**: ShogiHome issue #236（2022年、30コメント＝同リポジトリ最多議論）が「木構造では千日手や局面の合流に対応できない、グラフを直接可視化・編集したい」と要求。定跡フォーマット対応のみで閉じられ本体は未解決。KIF/KI2/CSA いずれも仕様として合流を持たない
- **未確認部分**: 30コメントは「声の大きい少数」かもしれない。実際に困っている頻度は不明
- **次回確認**: #236 のコメント主に直接あたる / ドッグフーディングで自分が合流に遭遇する頻度を数える

## P-005 ⚠️ 「対象ユーザーは 50〜300 人規模」

- **依存する決定**: 「名前の分かる20人向けに作る」という規模観、機能の作り込み深度
- **根拠**: 将棋人口 430万人・過去最低（レジャー白書2025）からの推定。体系的な定跡研究家 2,000〜5,000人 → 現実的な有料ユーザ 50〜300人。**推定であって実測ではない**
- **次回確認**: 2027-01（レジャー白書2026 公開後）

## P-006 ⚠️ 「定跡(book)の read/write は自前で作る価値がある」

- **依存する決定**: 定跡（issue #84 #90–#101）
- **状況**: ShogiHome が4形式（`.db` / `.bin` / `.sbk` / `.ybb`）の read/write/変換をテスト付きで実装済み。3 OS で配布している。**これは 2026-08-29 に一次資料で確認した**（`src/background/book/` の reader 4本、`src/tests/background/book/` のテスト7ファイル）
- **ただしこれは反証にならない。** 判断の軸が「ShogiHome と張り合えるか」ではなく「AI開発者の需要を取れるか」（→ P-008）だから。同等機能が他所にあることは、自前で持たない理由にならない
- **本当に確かめるべきこと**: obs-shogi の定跡機能が **zermelo のような AI 開発の実作業で使われるか**。ShogiHome の定跡 UX で足りるなら自前で持つ意味は薄い
- **次回確認**: zermelo の開発で定跡が要るようになったとき。**そのとき ShogiHome を実際に使ってみて足りない点を数える**
- **確定している事実の訂正**: **`.db.bin` というフォーマットは存在しない。** やねうら王のバイナリ定跡は `.ybb`（`source/book/book.h:246-248`）、`book.bin` は Apery のもの（同 `:184`）。**#92 と #84 は仕様の訂正が要る**

## P-007 ⚠️ 「エンジン UX 系（旧 Phase 0）は AI 開発者にとって中核の装置」

- **依存する決定**: #83 #85 #107 #110
- **根拠**: USI オプションの GUI 編集・preset 切替・解析モード（時間/深さ/ノード/詰）の配線は、エンジンを開発しながら回す作業の中心にある。**研究家向けの「あると良い」ではない**
- **未確認部分**: #107 の実装は `feature/phase-0-engine-ux` にあるが main から67コミット遅れており、#120 のレイヤ再配置を丸ごと被る。**救出コストが新規実装を上回る可能性がある**（これは価値の問題ではなく在庫の問題）
- **次回確認**: 着手時に rebase を試して見積もる

## P-008 ⚠️ 「将棋AI開発者の需要を取り込める」

- **依存する決定**: 定跡 / 対局 / floodgate / CSA を作るかどうか、つまり方針転換 2026-06（#112）の「不採用（永久ロック）」リストそのもの
- **根拠**: **未検証。いまの最上位の前提。** `~/zermelo`（αβ + NNUE の USI エンジン。SPRT・datagen・trainer を持つ）の開発で実際に要る装置が、そのまま他の AI 開発者にも要るはず、という推定
- **傍証**: ShogiHome 作者本人が「定跡機能は将棋AI大会用」「定跡の勉強は書籍やブログをメインに」と書いている（`research/findings/L3-book-solved.md`）。**これは「定跡編集の需要は AI 開発者側に寄っている」ことの裏付けになる**
- **未確認部分**: この層の規模。P-005（研究家 50〜300人）は**別の層の推定**であって、ここには使えない
- **失効条件**: zermelo の開発で obs-shogi を使わずに済んでしまう
- **次回確認**: zermelo の開発で obs-shogi を実際に使ったとき

> **注意**: 方針転換 2026-06（#112）は「対局・CSA・SPRT」を**不採用（永久ロック）**と書いていた。
> P-008 はこれと正面から衝突する。**#112 の記述は現在の方針ではない。**

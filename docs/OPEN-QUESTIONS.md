# OPEN QUESTIONS — 未決の問い

**まだ決めていないこと**を、決めていないと分かる形で置く場所。

なぜ必要か: 注釈機能の2実装分裂（Q-001）は数ヶ月にわたり存在したのに、issue にも無く、メモには「両方とも実装済み」と書かれていた。
**未決事項が「未決」として可視化されていないと、暗黙のうちに実装が二重化し、T1 が止まる。**

**運用**: 1問いにつき「決めるのに何が要るか」を必ず書く。それが無い問いは問いではなく不安。
決まったら ADR（`docs/decisions/`）に昇格させ、ここからは消す。

## Q-001 🔴 注釈機能をどちらの設計で行くか（T1 のブロッカー）

同じ「棋譜の枝に重要度と note を付ける」機能に、別ブランチで**競合する2実装**が存在する。どちらも main 未マージ。

|                 | 系統A: marks / tone                        | 系統B: meta / importance                                 |
| --------------- | ------------------------------------------ | -------------------------------------------------------- |
| ブランチ        | `feature/26-Zettelkasten`                  | `feature/zettelkasten`                                   |
| Rust            | `marks.rs` + `file_registry.rs`            | `meta.rs`                                                |
| fileId の持ち方 | **外部レジストリ**（`file-registry.json`） | **棋譜ファイルに埋込**（JKF header `x-obsShogi:fileId`） |
| 保存先          | `marks.json`（単一）                       | `meta/<fileId>.json`（分割）                             |
| 段階            | tone 0-4 + inherit/off/set の3状態         | importance + `computeRanks` 2パス                        |
| UI              | SecondBrainModal（3ペイン）                | branch-view モーダル（3ペイン）                          |

**本質的な分岐点**: fileId を外部で採番するか、棋譜ファイル自体を書き換えて埋め込むか。
後者は「ユーザーの棋譜ファイルを勝手に書き換える」ことを意味し、他アプリとの相互運用・バックアップ・git 管理に影響する。

**決めるのに要るもの**:

- 棋譜ファイルを書き換えることの是非を決める（相互運用性の観点。これは単独で ADR に値する）
- rename/mv 追従の実挙動を両系統で比較（外部レジストリは追従コードが必要、埋込は不要）
- 合流(DAG)対応（→ Q-002）とどちらが相性が良いか

**期限**: #113 局面編集モードの完了まで。それ以降 T1 が進まない。

## Q-002 🟡 棋譜内の枝構造を木のままにするか、DAG にするか

横断検索インデックスは `PositionKey`（SFEN由来）でキーを張っており**合流に強い**。
一方、棋譜内の枝表現は `tesuuPointer` キーの**木**。この非対称がある。
（`normalizedTree.ts` は `main` に**存在しない**。未マージの `feature/26-Zettelkasten` 系統にある）

- 木のまま = KIF/KI2/CSA の仕様に忠実、既存実装の延長
- DAG = ShogiHome #236 が要求し続けている未解決領域（→ P-004）。**差別化の最有力候補**だが、注釈の紐付け先が「手」から「局面」に変わるため Q-001 と連動する

**決めるのに要るもの**: `main` の枝表現（`src/entities/kifu/model/cursor.ts` の `KifuCursor`）を読み、DAG 化のコストを見積もる。ドッグフーディングで合流に遭遇する頻度を数える（→ P-004）

## Q-003 🔴 AI開発者向けの装置をどこまで作るか（製品定義の変更）

**軸は「将棋AI開発者の需要を取り込む」**（→ P-008）。定跡・対局・floodgate は開発予定。
これは方針転換 2026-06（#112）の「不採用（永久ロック）: 対局・CSA・SPRT」と**正面から衝突する**。

決まっていないのは範囲。

- 定跡（#84 #90–#101）— read/write/変換/UI。**`.db.bin` は実在しないので仕様の訂正が要る**
- 対局 — エンジン同士 / 人対エンジン / 持ち時間管理。**Rust 側の API としては入った**（`docs/state-transitions/game-session.md`。人対エンジン・エンジン同士・持ち時間・先読み）。UI と終局判定（#354）は未着手。floodgate も未着手
- floodgate — 接続、棋譜の取得、結果の追跡
- CSA プロトコル — 対局と floodgate の前提
- 棋力測定まわり — `~/zermelo` は SPRT・pentanomial・独立審判を**自前で持っている**。
  obs-shogi が重ねて持つ意味があるのか、それとも zermelo の結果を**見る**側に徹するのか

**決めるのに要るもの**:

1. **`~/zermelo` の開発で、いま実際に何が無くて困っているかを数える。** 推測でなく実作業から
2. zermelo が既に持っている装置（`ops/` `bench/` `datagen/` `trainer/`）と重複しない線を引く
3. 研究家向け（T1 の局面編集・メタデータ編集・注釈）との優先順位。**両方は同時に進まない**

**この問いが決まるまで、T1 と定跡のどちらを Now にするかも決まらない。**

## Q-006 🟡 Tauri コマンドの名前を一度に揃えるか

案: `docs/proposals/naming-and-module-layout.md`（**未採用**。ただし置き場の話は ADR-0009 が決着済み）

取得に `load` / `get` / `read` / `scan` の4語、書き込みに `save` / `write` / `create` / `import` の4語、
移動に `mv` と `rename` の両方がある。棋譜の書き込みは3経路あって名前から区別が付かない。
`aiName` は USI のエンジン名ではなく AI プロファイルのディレクトリ名で、**名前が実態とずれている**。

**残っているのは名前だけ。** モジュールの置き場（案の決定3）は ADR-0009 が引き取った。

**決めるのに要るもの**:

- **一度に全部やるか、触るたびに直すか。** 案は一度にやる側に立っている
  （半分だけ揃っている状態は、揃っていない状態より悪い）
- コマンド名と全呼び出し側を書き換えるコストを、**対局に着手する前に払うか後にするか**
- 設定ファイルの `serde(alias)` をいつ消すか

**期限**: 対局の実装に着手するまで。対局はコマンドを10本以上増やすので、
揃えるなら**その前**でないと割れが固定される。

## Q-007 🟢 issue とラベルの規約を成文化するか

案: `docs/proposals/issue-and-label-conventions.md`（**未採用**）

現物の issue は「事実の表 → 利用者から見た症状 → 付随 → 直し方の案 → 出どころ」という
決まった形をしているが、**どこにも書かれていない**。
ラベルは定義されているのに **open 60件中45件・closed 直近20件は全件が無ラベル**（2026-09-01 実測）。

**決めるのに要るもの**:

- `area:` を4つから8つへ増やすか（増やすなら open 60件に付け直す作業が要る）
- `wontfix` / `duplicate` / `invalid` を消すか（消すと過去の close 理由が読めなくなる）
- `blank_issues_enabled: true` のまま「種類・領域を必須」にできるか
- 外向けの必須項目を Issue Forms に一本化し、`CONTRIBUTING.md` をリンクに置き換えてよいか

**期限**: 無し。ただし `.claude/skills/write-issue/SKILL.md` が
「実在するラベルから選ぶ」で暫定運用しているので、決まるまでその状態が続く。

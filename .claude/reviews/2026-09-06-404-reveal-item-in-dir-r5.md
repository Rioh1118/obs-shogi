## 所見

### R5-01 [HIGH] 検査を絞ったときに「呼んでいる口には許可がある」まで落ちていた（architecture、実測）

`畳み込み済み` は ACL の解決を模すのをやめたが、**識別子の集合の突き合わせも一緒に落としていた**。
その結果 `opener:allow-reveal-item-in-dir` の1行を消しても検査は緑のままで、
**#404 の症状（押しても何も起きないボタン）がリポジトリ全体緑で戻せる**。
集合の突き合わせは ACL の解決を1行も模さずに書ける。

- 結果: 対応済み（畳み込み済み）`GRANTS` と「呼んでいる口には許可がある」を戻した。
  capability は JSON として解かず、綴りだけを見る（書式に依らない）

### R5-02 [HIGH] `onEnsureEngines` の**成功**側に関門が無い（architecture / react / robustness の3名、実測）

`畳み込み済み` で塞いだのは `catch` だけ。成功して返る普通の経路では、A のスキャンが世代を進めて
B の結果を捨て、画面のルートと索引のルートがずれる——バッジは「OK」なのに中身は空で止まる。

- 結果: 対応済み（畳み込み済み）`await ensureEnginesDir(root)` の直後に関門を置き、
  成功の経路をテストで固定した

### R5-03 [HIGH] `engines` がシンボリックリンクだと「同名のファイルがある」に落ちる（architecture）

`kind_of` は `symlink_metadata` を使うのでリンクを辿らず `Symlink` を返すが、
`engines::read_all` は `is_dir()`（辿る）で走るので**エンジンは検出できている**。
同じ画面が「エンジン N 件（ok）」と「フォルダではない」を同時に出す。
壊れたリンクは逆に `exists()` が false で「無い」に落ち、作成が `EEXIST` で失敗する。

- 結果: 対応済み（畳み込み済み）**文言だけ**——「同名のファイル」を「フォルダではない」に直した。
  判定（リンクを辿るか）は Rust 側なので **issue #469**

### R5-04 [HIGH] `unknown` が StatusCard と木で「なし」に畳まれる（react / robustness）

4状態に割ったのに、表示側は三項の連鎖で最後の枝が `unknown` を吸っていた。
読めていないだけの状態に対して「engines フォルダ: なし（warn）」と言い、
推測のパスを hint に出す。作成ボタンは出ないので「無いと書いてあるのに作る口が無い」に見える。

- 結果: 対応済み（畳み込み済み）`Record<EnginesDir, …>` にして、状態を必ず綴らせる

# ラウンド7 — `search` の欠陥（ラウンド6の修正をレビューした）

対象は `review/388-on-429-all`。観点は rust / robustness。どちらも各自の worktree。

## このラウンドの共通の原因

**割り方の根拠を、1つの形式にしか無い検査に置いていた。**

R6 は「`Ok` で返った」と「索引に局面が入った」を分け、**警告の有無**で
「本当に空の棋譜」を割った。だが警告を出す口があるのは **CSA だけ**
（`warn_if_moves_were_dropped`）。KIF / KI2 / JKF は `NothingToIndex` に落ちる回の
`warns` が**構造上必ず空**なので、割れ目そのものが存在しない。

レビュアーが実測した:

```
empty.kif     Ok indexed=true  warns=[]   ← 0バイト
empty.ki2     Ok indexed=true  warns=[]   ← 0バイト
trunc.csa     Ok indexed=true  warns=[]   ← "+7776F"（6バイトなので指し手と数えない）
```

同期の途中で置かれた0バイトの `.kif` が40件あっても、**緑の「準備完了」で
警告欄は空**。R3〜R6 が4ラウンドかけて閉じようとした穴が、
**利用者がいちばん多く持つ2形式でそのまま開いていた**。

## 残している穴（直していない）

**`warn_if_moves_were_dropped` が黙る形は、いまも真に落ちる。**
最初の `%` 行で数を打ち切る回と、UTF-16 の CSA。0バイトでなければ
「本当に空の棋譜」として数えられる。`FileBuild::indexed` の doc に書いた。

レビュアーもこの2つは**実ファイルで再現していない**（doc と実装からの推論）。

## 新しく足したテスト

| どこ                                   | 何を固定したか                         | 当てた変異                      |
| -------------------------------------- | -------------------------------------- | ------------------------------- |
| `file_build.rs` `a_zero_byte_file_…`   | 0バイトを「本当に空」と読まないこと    | 警告の有無だけで割る（R6 の形） |
| `file_build.rs` `a_csa_cut_mid_move_…` | 切れた CSA を「本当に空」と読まない    | 指し手行に7バイトを要求する     |
| `file_build.rs` `a_header_only_kifu_…` | 初期局面だけの棋譜を数えること         | （新設。当てていない）          |
| `announce.rs` `a_count_larger_than_…`  | 対象を超えた数を丸めること             | 丸めない                        |
| `indexHealth.test.ts`                  | `scanFailed` が gap を飲み込まないこと | 飲み込む形（R6 の形）           |

`write_and_build` は形式を**名前から取る**ようにした。`KifuKind::Csa` を直に
書いていたので、**他の形式の腕を落とす変異が緑で通っていた**——割り方の穴は
いつも CSA 以外に空く。

## 自分が作った退行

**変異が通ったのに、テストが弱いと決めつけなかった。** `Indexable` の腕を
`!entries.is_empty()` に変えたときの変異は生き残るが、それは**この式が偽になる
入力がいま無い**から（初期局面が必ず入る）。守りであって直した不具合ではない、と
コミットにも doc にも書いた。

## ラウンド8を待たずに見つけたもの

**「中身が無い」を大きさ0で定義したのが狭すぎた。** レビュアーが0バイトを
見つけた場所の隣を自分で当たったら、改行1つと BOM だけのファイルが素通りしていた
——同じ穴が一段狭くなっただけ。中身で見る形に直した（`6b7d8917`）。

**同じ形が8ラウンド続いている。** 直した回は目の前の場合には正しく、
その1つ隣で破れる。今回早く見つかったのは、**前の回に穴が見つかった場所の
隣を探しに行った**から。

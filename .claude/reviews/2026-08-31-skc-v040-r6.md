## 所見

### [HIGH] R6-01 「UTF-16 の NUL は片側の番地にだけ現れる」が偽

- 場所: `search/kifu_reader.rs` の `utf16_by_nul_layout`
- reviewer: comment / rust（どちらも実測）
- 低位バイトが `0x00` の文字（**`　` U+3000 / `一` U+4E00**）は
  UTF-16LE で**反対側の番地に NUL を置く**。`一` は一段目への指し手すべてに出る

  | 題材（UTF-16LE）                | even | odd | 判定     |
  | ------------------------------- | ---- | --- | -------- |
  | 一段目へ指す KI2                | 5    | 15  | **None** |
  | r5 が足した `zenkaku_heavy_ki2` | 1    | 15  | UTF-16LE |
  | 同上に `一` を1文字足す         | 2    | 15  | **None** |

- **r5 が足した題材自身が境界から1文字。** 「並びは中身に依らない」は成り立たず、
  `minor * 8 >= major` は「U+xx00 の文字が ASCII の 1/8 未満」という
  **中身の量の閾値そのもの**だった
- R3-01 / R5-01 で2度塞いだのと同じ故障が、3つ目の門で再発

### [MEDIUM] R6-02 r5 が足した3つの行/定数は、どれも変異が生き残る

- 場所: 同上
- reviewer: robustness / rust（**変異を実際に当てた**）

  | 変異                                | 結果                           |
  | ----------------------------------- | ------------------------------ |
  | `bytes[..len & !1]` → `bytes[..]`   | 42 passed                      |
  | `MIN_NUL = 8` → 3 / 4 / 12 / 15     | 42 passed（16 で初めて落ちる） |
  | `minor * 8` → `* 1` / `* 2` / `* 4` | 42 passed                      |

- 奇数長を拾えるようになったのは **r4 の門を消したから**で `& !1` ではない。
  r5 のコミットメッセージは効いていない行に効果を帰していた
- 「途中で切れた UTF-16LE」の題材は完全な UTF-16 の真部分集合で、
  **構造上どんな変異も殺せない**

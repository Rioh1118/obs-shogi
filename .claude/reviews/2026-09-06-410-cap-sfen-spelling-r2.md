### [MEDIUM] R2-01 「口を1つの規約に揃える」と書いた同じ関数の中に、揃っていない口が残っている（rust / architecture / comment / robustness）

`query_service.rs:112` は刈る側へ移したが、**#410 が実際に通るのは `:191` の

**これは私が入れた退行。** コミット `畳み込み済み` は「検索の失敗をひとつの口から出す」と
名乗り、コメントに「この payload へ載せる文言の口を1つの規約に揃えること」と書いた。

### [MEDIUM] R2-03 `+` が付いた駒の綴りは `+` を落として名指すので、合法な文字を「読めない」と言う（rust）

実測（rust が `partial_position_from_sfen` に直接与えて確認）。

```
"+9ns…" => invalid piece: "9"     ← `9` は段の中では合法。悪いのは `+` のほう
"+Zns…" => invalid piece: "Z"
"+Gns…" => invalid piece: "+G"    ← ここだけ2文字
```

**しかも私が足した doc が、成り立たない不変条件を宣言している**
（「駒として読めなかった1文字（`+` が付いていれば2文字）」）。
`+` を文言へ戻すのは `('G', true) | ('K', true)` の腕だけ。

### [MEDIUM] R2-04 テストの `\0` が刈られる位置にあり、制御文字の assert が常に真（robustness）

### [MEDIUM] R2-05 `\n` を通す理由が、3箇所あるうちの1つしか名乗っていない（comment / rust）

`:\n` を組むのは3箇所（`diagnosis.rs:56` と `encoding.rs:344,363`）。

### [MEDIUM] R2-07 `is_control` は `Cc` だけなので、棋譜由来の双方向制御が素通りする（robustness）

### [BLOCK] R8-1 列で待った保存が、消えた分岐の**番号**で別の変化へ書き込み、その変化の既存のコメントを消す（2体）

- 場所: `KifuCommentNote.tsx` の `save` / `saveOnce`、`entities/kifu/lib/branchEdit.ts` の
  `deleteCandidate`（`forks` を詰める）
- 根拠: `target.cursor` は `forkIndex`（`forks` 配列の位置）を含む。
  `setCommentsByCursor` → `edit` は**走る時点**の `state.jkf` を複製して
  `getMoveByCursor(nextJkf, target.cursor)` を当てるので、待っている間に `forks` が詰められると
  同じ番号が**別の変化**を指す。`deleteBranchInKifu` は**いま画面にいる cursor だけ**を
  詰め直すので、列に積まれた `target.cursor` は誰も直さない。

  **本物の `GameProvider` ＋ 本物の `KifuCommentNote`** で実測。2手目に変化1/2/3を持つ棋譜で、
  変化2にコメントを打つ → 自動保存が撃たれてディスクが返らない → 分岐メニューを開く
  （面の効果が2本目を列へ積む）→ 変化1を削除 → 1本目が返る:

  ```
  writes: 3
  forksOnDisk[1].comments: ["変化2に書いたメモ"]   ← 元の「変化3」のコメントが消えた
  state.error: null                                 ← 失敗していない。保存は success
  ```

- なぜ問題か: 「コメントを打つ → 分岐メニューを開く → いらない変化を消す」という
  **ごく普通の並び**で、打っていない変化に自分のコメントが入り、
  **その変化に元からあったコメントが消える**。書き込みは `success` で返るので
  ノートは「保存済み」を出し、預かりも捨てる。`state.error` は null。
  **取り戻す手段はアプリ内に無い。**
  前提は「1本目のディスク書き込みが、分岐メニューを開いて削除を確定するまでの間、
  まだ返っていない」だけで、これは r7 が上限時間を入れる根拠にした条件そのもの。
  **R7-8 の直し（`dropUnsavedDraftsFor`）は置き場の預かりしか捨てないので、
  列の中にある closure には届かない。**「番号を動かした側が捨てる」は半分しか実現していなかった。
- 直し方: 置き場に**棋譜ごとの世代**を持たせ、`dropUnsavedDraftsFor` が進める。
  `save` は撃った時点で世代を掴み、書く前に突き合わせる。合わなければ書かず、
  預けもしない（本文は失われるが、残すと利用者が打った覚えのない変化へ入る。
  **失うほうを採る**）。
- 導入コミットの sha: 列は `b102ead`（r6）、`commitRef` で「実体だけ」を引き直す形にしたのは
  `749af52`（r7）。`forkIndex` を鍵に使う設計は `41bf046`
- 主張を固定するテスト名: **未検証**（`GameProvider` ＋ `KifuCommentNote` を通した
  組み合わせのテストを書いていない）→ #276

### [HIGH] R8-2 上限時間が直列化を崩し、**古い書き込みが新しい書き込みのあとに着地して**ディスクを巻き戻す（robustness）

- 場所: `provider.tsx` の `withDeadline`
- 根拠: `Promise.race` は**負け側を残したまま** `Err` を返す。`writeOnce` が返れば
  列の次が走るので、**刺さったままの1本目と2本目が並行に走る**。実測:

  ```
  startedBefore: [w1]      ← 2本目は列で待っている
  startedAfter:  [w1, w2]  ← 16秒進めたら w2 が走り出した（w1 はまだ在中）
  landedOrder:   [w2, w1]  ← 古いほうが後に着地
  ```

  1本だけの場合も:

  ```
  returned: Err("書き込みが応答しません")
  memoryAfterDeadline: []   ← jkf_restored が通ってメモリは巻き戻った
  diskNow: [["メモ"]]        ← そのあと本物が着地してディスクには入った
  ```

- なぜ問題か: **R6-2 で BLOCK にした「後に着地したほうが勝つ」がそのまま復活していた。**
  分岐の削除が w2、コメントの自動保存が w1 なら、
  **削除がディスクから消えてメモリだけ削除済み**になる。
  1本だけの場合も、盤で指した手が15秒後に消えたのにディスクには入っており、
  次に開き直すと戻ってくる（利用者から見ると「消えた手が勝手に生き返る」）。
  `persistIfPossible` の doc は「同じファイルへ2本同時に書かない」と宣言しており、
  `withDeadline` の doc は「次の書き込みがディスクをメモリに合わせる」と書いていたが、
  **着地順が逆なら合わせるのは古いほうで、その後に書き込みが無ければ食い違いは永久に残る**。
- 直し方: 上限時間は**呼び出し元へ返すぶんにだけ**掛け、列は本物が settle するまで待たせる。
  応答が無かったときは**巻き戻さない**（書けたかどうかが分からないので、戻すと
  「書けていたのに画面から消える」、戻さないと「書けていないのに残る」。
  後者を採る。残っていれば次の書き込みがディスクを合わせる）。
- 導入コミットの sha: `749af52`（**ラウンド7で私が入れた**）
- 主張を固定するテスト名: **未検証**（`writeQueue.test.tsx` は時間切れを1本も見ていない）

### [HIGH] R8-3 分岐を1つ触るだけで、その棋譜の**全部の**預かりが消える。失敗しても戻らない（2体）

- 場所: `KifuStreamList.tsx` の `onSwapBranch` / `confirmDelete`、`lib/unsavedDrafts.ts`
- 根拠: `dropUnsavedDraftsFor(absPath)` は `${absPath}__` で始まる鍵を**全部**消す。
  鍵は `${absPath}__${tesuu}__${forkPointers}` なので、そのファイルの**全手数・全変化**。
  番号が振り直されるのは触った分岐点だけなのに、無関係な手数の預かりまで落ちる。
  呼ぶ位置も `await` の**前**で、失敗して巻き戻しても預かりは戻さない。
- なぜ問題か: 預かりは**書き込みの失敗が無くても**溜まる（別の棋譜へ切り替えたときの
  `"skipped"`。R5-1 が「元の棋譜へ戻れば出し直せる」と約束した経路）。
  10手目にコメントを打ちかけて別の棋譜へ移り、戻ってきて
  **30手目の変化を1つ「下へ」動かすだけ**で10手目の預かりが消える。
  次に10手目を開くと本文は空で、赤い箱も出ない。
  **「書いた本文はこのまま残っています」という断言が、無関係な操作1回で破れる。**
  削除の書き込みが失敗した場合はさらに悪く、消えたものは何も無いのに預かりだけが消える。
- 直し方: 落とすのは**書き込みが成功したあと**。範囲は `te` 以降に絞る
  （それより前の番号は動かない）。
- 導入コミットの sha: `749af52`（**ラウンド7で私が入れた**）
- 主張を固定するテスト名: **未検証**（`unsavedDrafts` にテストファイルが無い。純関数なので書ける）

### [HIGH] R8-4 自動保存が走っている間に閉じると、**失敗を一度も見せずに**ノートが閉じる（react）

- 場所: `KifuCommentNote.tsx` の `handleRequestClose` の「列が動いているなら待たない」分岐
- 根拠: その `return` は、すぐ下の「**この面で失敗を見せたのが初めてなら閉じない**」を
  丸ごと飛ばす。実測:

  ```
  画面の状態: close保存中          ← 押す前は「保存中」が出ている
  閉じた直後にノートは残っているか: false
  失敗が返ったあとの画面: （空）    ← 2本とも失敗したのに画面には1文字も出ない
  預かり: {"draft":"メモ","error":"書き込みできません","told":false}
  ```

- なぜ問題か: `inFlightRef.current > 0` になるのは「打鍵が止まって 900ms 後に撃った保存が、
  押した時点でまだ返っていない」ときで、**それは書き込みが遅い／失敗する環境そのもの**。
  つまり**失敗する環境ほど確実にこの分岐を通る**。
  本文は預かりに残るが `told:false` のうえ、**同じ面をもう一度開くまで誰も出さない**。
  #227 が塞いだ「書けていないのに成功したように見える」が、
  「成功と出す」ではなく「**何も出さずに閉じる**」という形で戻っていた。
  すぐ上の行のコメントが宣言している規約と、その分岐の挙動が食い違っている。
- 直し方: 待たないのは正しいが、**閉じる判断は結果に委ねる**
  （`void save(...).then((r) => { if (r !== "failed" || told) onClose(); })`）。
  押した瞬間から「保存中」が出ているので押せない見た目にはならない。
- 導入コミットの sha: `749af52`（**ラウンド7で私が入れた** R7-6 の直し）
- 主張を固定するテスト名: **未検証**

## 8ラウンドで繰り返した形

r7 で「撃った時点」と「走る時点」を1つ揃えたが、**揃え損ねたものがまだあった**。

| 何を                                    | r6           | r7                           | r8                     |
| --------------------------------------- | ------------ | ---------------------------- | ---------------------- |
| 書き込みの実体（`setCommentsByCursor`） | 撃った時点 ✗ | **走る時点 ✓**               | ✓                      |
| 宛先（`persistence` / `loadedAbsPath`） | 走る時点 ✗   | **撃った時点＋突き合わせ ✓** | ✓                      |

### [BLOCK] R4-01 rustdoc ラチェットが赤い。`verify:rust` の最終段が落ちる（comment）

`ScreenMessage`（`pub`）の doc から `for_screen`（`pub(crate)`）へ intra-doc link を

### [HIGH] R4-02 索引の警告が二重に刈られ、「失うもの」を言う一文が画面から消える（rust / architecture / robustness）

**3人が独立に発見し、2人が実測で再現した。**

`parse_failed` は上限の**外**で「。このファイルの局面は検索に出ません」を足す。
その `Display` を `file_build` がもう一度刈っていた。

```
組んだ直後: 319 文字 / 末尾 = 「…。このファイルの局面は検索に出ません」
画面に出る値: 301 文字 / 末尾 = 「んんんん…」
```

**`parse_failed` の doc が「消してよい部分ではない」と名指しで禁じた状態。**
`畳み込み済み` で `ScreenMessage` を入れたときに、型を `read/` 段まで下ろさず
`file_build` で `for_screen` を呼んだのが原因。**私が入れた退行。**

既存のテストが緑のままだったのは、観測点が `read_path_inner`（刈り直しの1段手前）
だったため。**この一文が画面まで届くかを見ているテストは1本も無かった。**

### [HIGH] R4-03 型で閉じたはずの門に、回避路が3つ開いていた（rust / architecture / robustness / comment）

1. **モジュールが `pub`**。`ScreenMessage` も `for_screen` も crate の外から辿れた。
   r3 で私が書いた反論（「型が `pub` でないと `private_interfaces` が立つ」）は
   **命題としては正しいが、締める対象を取り違えていた** — architecture が最小 crate で
   `pub(crate) mod` + `pub struct` が `-D warnings` を通ることを示した
2. **`Deserialize`**。`serde_json::from_str::<ScreenMessage>` で綴りから直に作れた
3. **`followed_by` が任意の `&str`**。上限の外に実行時の値を足せた

### [MEDIUM] R4-04 `IndexWarnPayload` の描画の記述が、同じ口の別の doc と逆（comment / robustness）

`types.rs` は「1件が長いと箱が縦に伸びる」、`build_report.rs` は「刈られた側は
読まれない」。`.wsTab__warnMsg` に `overflow-wrap` は無いので、空白を含まない綴りは
折り返さず**横へはみ出す**。`path` と違って `title` も無いので末尾を読む手段が無い。

**Rust の doc が TS / SCSS の現物を主張して腐るのは4ラウンド連続**（R1-10 → R2-08 →
R3-04 → R4-04）。

### [MEDIUM] R4-05 `SearchErrorPayload` の「3箇所とも末尾は読まれない」が無条件の断定（comment）

読まれないのは**器を越えたときだけ**。段落の残りは条件付きで正しく書けているので、
見出しの断定だけが浮いている。

### [MEDIUM] R4-06 `path` の記述が現物と違う（comment / rust）

`text-overflow: ellipsis` + `nowrap` なので1行に固定され、末尾は省略される。
「確実に読める」は成り立たない。**この欄は刈る口を通らない**ことも書かれていなかった。

### [MEDIUM] R4-07 enum の doc が「2通りのどちらかを通す」と書くが、現物は積み重ね（comment）

入力を載せる4バリアントは**すべて `{:?}`**を通り、長さに上限が無い2つは**加えて**刈る。
選択に見せると、片方だけ通す欄を足した人が「何も名指ししない文言」を戻す。
しかも `{:?}` を強制できるのはバリアントではなく `invalid()` に渡す**書式の側**。

### [MEDIUM] R4-08 `capped` の名前が長さしか言わず、doc が段落まるごとで訂正していた（comment）

`CONTRIBUTING.md`「名前で表せるものはコメントにしない」の直接の対象。
受け皿の `Capped` とも大小の違いしか無く、返す型は別物だった。

## 所見

### [HIGH] 1. 席を握り直すと「採らない席」が空になり、盤を1手ずつ動かすだけで古い `info` が通る

reviewer: react / robustness（独立に、同じ再現へ到達）

`hold()` が `ignoredRef` / `returnedRef` を `clear()` していた。**握っている席の照合が
厳密一致だから空にしてよい**という理由だったが、席の欄が空になる窓（返してから
次の席が返るまで）では厳密一致が働かない。再現:

```
P1 開始（session-1）→ P2 再開（session-1 を返し session-2 を握る＝ここで集合が空）
→ P3 再開（session-2 を返し、次の応答は返らない＝席の欄は空）
→ onUpdate("session-1") → candidates 1（期待 0）
```

**P1 の評価値と読み筋が、盤が P3 を映したまま解析結果として出る。**
r10-1 が「1枠では足りない」と言って集合にした、その集合が
**普通の経路（返す→握る→返す）で1枠と同じところまで戻っていた。**

### [HIGH] 2. `matches` が席を先に見るので、捨てた席を握り直すとその `info` が通る

reviewer: react

停止が落ちて席を握り直す枝（`send` の catch）を通ると、
**捨てると決めた席が「自分の席」に昇格**して `matches` が true を返す。
`ignoredRef` を先に見れば落ちる。

### [HIGH] 3. `sweepOnUnmount` が枠を取らずに並ぶ。r10 のコミットメッセージは取ったと書いている

reviewer: robustness

`67c7766c` は「`sweepOnUnmount` が並ぶときに枠を取っていなかったのも直す」と書いているが、
`sweepOnUnmount` の並ぶ枝に `releasingRef.current = queued` は無い（入っているのは
`releaseHeldQuietly` だけ）。**記録が現物と食い違っている。**

### 4. 枠の自己照合と `returnedRef` に、変異で落ちるテストが無い

reviewer: robustness

枠を空ける6箇所を1つずつ無条件の代入へ変異させると、落ちるのは1箇所だけ。
テストで持てないなら、機械で形を固定するか、機構ごと落とすかを決めること。

### 5. `discard` の「開始が飛んでいる間は席の欄が必ず空」が偽

reviewer: comment

返却が落ちた回の書き戻しが席の欄を埋めるので、「必ず空」は成り立たない。

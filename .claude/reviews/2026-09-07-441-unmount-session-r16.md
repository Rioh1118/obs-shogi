## 所見

### [HIGH] 1. 盤を1手進めてすぐ戻すと、解析が別の局面に取り残される

reviewer: react（実測）

「読ませたい局面」の更新が「もう読んでいるから何もしない」の門より後ろにあり、
門が読むのは ref——**ref が動いても effect は再実行されない**。

```
K1 currentSfen=P1 analyzedSfen= P2 analyzing= true startCore= 2
K2 analyzedSfen= P2 error= null startCore= 2     ← さらに 1000ms 待っても変わらない
```

盤は P1、エンジンは P2 を読み続け、**P2 基準の読み筋と評価値が P1 の盤の下に出る**
（表示は「解析中」、断りも無い）。派生して、同じ並びで2秒後に嘘の断りが立つ回
（`J2 error= エンジンが局面を受け取るのに時間が掛かっています…`）と、盤と違う局面へ
`go` を撃ち直す回もある。`main` から在る形だが、**J で出る文言はこの PR が足したもの**で、
押し直す理由が無い回に「押し直せ」と案内していた。

### [HIGH] 2. ■ の失敗だけが断りを立てない

reviewer: robustness（実測）

```
C ■ の後 isAnalyzing= false error= null thrown= Error: ipc gone
C ▶ の後 stopCore= [["session-1","start"]]     ← 席は残ったまま
```

同じ probe で ▶ の6枝はすべて断りが立った。**`state.error` が null のまま終わるのは ■ だけ。**
表示は停止中・タイマーは 0・ペインはキャッシュを出すので**成功と1ドットも違わない**のに、
エンジンは閉じた探索を回し続ける。

### [HIGH] 3. `isReady` の false は3つの状態を潰しているので、断りが「起動中」に嘘をつく

reviewer: react（実測）

```
D1 error= エンジンが起動していません。設定でエンジンを選んでください。
```

▶ は `disabled` にならない（ヘッダはエンジンの状態を1つも読まない）ので、
**起動を待っている人が必ずこの文を見る**。正しい次の一手は「数秒待ってもう一度 ▶」。

### [HIGH] 4. `EngineSeat` の公開契約が、実装が持つ「待ち」と「門」を2箇所で落としている

reviewer: comment

`releaseHeld` は席を握っていなくても飛んでいる返却を待ち切る——それが
`shoot` の catch の「誰も知らない席は作れない」の唯一の根拠。契約どおり
「握っていなければ何もしない」と読んで待ちを外すと、その前提が黙って消える。
`sweepOnUnmount` の「席を握っていない回は撃たない」（#463 の門）も公開面に無い。

### [HIGH] 5. 席を捨てる行の門の理由が、`accepts` の契約に否定されている

reviewer: comment

「握っているなら待っているのはその席のもの」は成り立たない——`accepts` は席の欄が
空の間は**どの席の `info` も通す**（`takeSeatAndGo` のコメントがその窓を前提にしている）。
門そのものは要るが、書いてある理由が実装している条件と違う。

### [HIGH] 6. 画面仕様の失敗の表で、同じ失敗を2行が逆に書いている

reviewer: oss-hygiene / robustness（独立に）

「開始が Rust に弾かれた＝`console.error` だけ」と「開始が断られた＝`state.error` に載る」。
「上限切れ**だけ**が押し直しで直りうる」も、F-2・※15・不変条件3・`RELEASE_FAILED_MESSAGE`
の本文の4箇所と正面から矛盾する。`state.currentPosition` の改名も取り残されていた。

### [HIGH] 7. ※2（▶ の順序の唯一の出典）に、いちばん最近足した段が無い

reviewer: oss-hygiene

表の E1 セルが全部 ※2 を指しているので、ここを読んで ▶ を簡約すると r15-1 の退行が戻る。

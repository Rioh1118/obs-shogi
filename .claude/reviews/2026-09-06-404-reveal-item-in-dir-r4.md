## 対象そのものを疑ったか

**疑った。1つは落とし、1つは残す。**

### `openerCapability` は**模すのをやめる**

r1 から数えて **10件以上**がこの検査から出ている（r1: 6件、r2: 4件、r3: 5件、r4: 4件）。
出てくるのは毎回「Tauri の ACL のもう1つの軸」で、
今回も `windows`/`webviews` が空／`deny-*`／`permissions` の要素の形、と3つ増えた。
**この検査は Tauri の解決規則を TS で再実装しようとしている**が、それは #404 が要求していない。

#404 が要求したのは「capability の scope と `openPath` の呼び出し元を突き合わせる検査」で、
守りたい退行は1つ——**ディレクトリを `open_path` に渡す形が戻ること**。
そこだけを見る形に絞る:

1. `src/` が `@tauri-apps/plugin-opener` から読む口は、**名前付き import だけ**（動的 import・
   名前空間・再エクスポート・IPC の直書きを禁じる）
2. `openPath` は**呼ばない**。呼ぶなら `OPEN_PATH_CALLERS` に「どの `allow` に一致する値を渡すか」を書き、
   同時に capability へ許可を足す
3. `capabilities/**` のどこにも `opener:allow-open-path` が現れない（2 と対にする）

`windows` / `local` / `remote` / `platforms` / glob / ファイルの3形は**落とす**。
ACL の解決を確かめたいなら Tauri のビルド生成物（`gen/schemas/acl-manifests.json` と
`resolved`）を読む形が要るので、それは #404 の外——issue に出す。

### `AiLibraryTab` の `ScanState` は**残して直す**

こちらは #404 が触った失敗経路そのもので、所見も「利用者から見て何が起きるか」で書かれている。
ただし**書く経路を1つに集める**（R4-08 / R4-10 / R4-12 / R4-14 の根）。

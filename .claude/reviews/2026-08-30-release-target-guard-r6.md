  **`on.push.tags` が数字に絞っているなら #285 は存在しない**ので、表と issue の存在も食い違う。

### [MEDIUM] R6-2 空打ちの確認コマンドが 302 を表示する。「200 を返すこと」が満たされない

- 場所: `docs/RELEASE.md:61,64`（reviewer: oss-hygiene）
- 根拠: v0.2.1 の実物の asset に対して**実行して確かめた**。

  ```
  $ curl -sI -H "Accept: application/octet-stream" -L "<asset url>" | grep -i '^HTTP/'
  HTTP/2 302
  HTTP/2 200
  ```

  `curl -I` は `-L` の各ホップのヘッダを順に出すので、`head -1` が拾うのはリダイレクトの側。

- なぜ問題か: この確認は「手動 DL は通るのに自動更新だけ静かに失敗する」を捕まえる唯一の関門なのに、
  **正常なときでも `200` にならない。** 空打ちした人は実在しない故障を追うか、確認を飛ばす。
- 直し方: `curl -s -o /dev/null -w '%{http_code}\n' …`。実行して 200 を確認した。
- 導入コミットの sha: `24a3832`（**ラウンド5で私が入れた。一度も実行せずに書いた**）
- 主張を固定するテスト名: 未検証

## 途中で向きを変えた場所

ここだけは、報告書を開かずに読めるようにしておく。**どれも「直し方を変えた」
のではなく「直す対象が間違っていた」と判断した回。**

### r13 — セルを1つずつ突き合わせる側へ移った

r12 まで「読んで気付いたこと」を積んでいて、件数は 20 → 28 → 33 と増え続けた。
r13 で `docs/state-transitions/game-session.md` の**57セルを全部**現物と突き合わせる形に
変え、12件へ落ちた。**減ったのは直したからではなく、探し方を変えたから。**

### r18 〜 r21 — 自分が作った退行が主成分になった

r17（39件）の修正が r18 の所見のほとんどを作った。r19 で「締切の doc が
足している定数と、実際に足している定数が違う」が出て、r20 では所見の半分が
**振る舞いを変えたのに doc へ届けていないこと**だった。

**機械では防げない形。** `/implement` に「コメントに『〜だから』と書いたら、
その条件式がコードのどの行かを指せるか1件ずつ確認する」を置いたのはこの区間。

### r27 — 機構ごと落とした（最大の転回）

r25 〜 r27 は「所見が減らないラウンドが3回続いた」に該当した。
`/implement` の指示どおり**対象**を疑い、診断の分類機構を測り直した。

**それを正当化していた前提（`emit` は宛先が消えると失敗する）が偽だった。**
`emit` は購読者がゼロでも成功して返る。分類が守っていたものは0件だったので、
分類ごと落とした。→ `failure-surfacing.md` の F-19。

### r32 — 増えたが、出どころが変わった

15件で増加に転じたが、r25 〜 r27 で膨らませた側からではなく
**ラチェット自身の穴**から出た。走査の免除条件・予算の下限・綴りの固定など、
「守り手が守れていない」形。r22 と同じ産地。

### r33 — 回し方そのものを壊した

変異試験を許した rust の1本と、読むだけの2本を**同じワークツリーで同時に**
走らせた。robustness は `MAX_ID_BYTES` が 48 → 51 → 64 と書き換わる最中の
コードを読み、途中で観測を諦めている。

**r34 以降は、変異を当てる1本を単独で先に回し、読むだけの2本をその後で並列**に
している。r34 の報告書に「効果は出た」と測った結果がある。

## この索引の限界

- **主題は各報告書の冒頭から引いた1行**であって、そのラウンドの全部ではない
- 件数の産地が揃っていない（上の注記）
- **「所見が0件のラウンド」は出ていない。** `/implement` はそれを打ち切りの条件に
  しているが、この PR は r35 の修正をもって出している。**打ち切りはユーザーの判断**で、
  機械が緑になったからではない
- **r35 は3人が同じツリーを見ていない。** 1本目（rust）の後に `origin/main` を
  取り込み、その2件を直してから残り2本を回した

### Q2 — 「テストで固定した」は成立していなかった

r4 の P6 で「未作成」検査からリンク名の除外をやめ、「5つの書き方をテストで固定した」と
報告書に書いた。実際には判定ロジックが2箇所に手書きされていて、`test.each` が呼ぶのは
`describe` の中のコピーだけ。**出荷される検査には1本もテストが掛かっていなかった。**

oss-hygiene が変異（`line.split("。")` → `line.split(/[。|]/)`、まさに r4 で
「採らない」と書いた案）を当てて16件すべて green のままになることを実測している。
`headingSlug` / `stripFences` はモジュール直下に切り出して本体を呼んでいるのに、
この1件だけ形が違った。

`staleUncreatedNames` をモジュール直下に出して両方から呼ぶ形にし、
同じ変異で2件落ちることを確認した。

### Q5 — フェンスの閉じ規則を仕様と逆に書いていた

r4 で足したコメントは「CommonMark は開きより深い閉じを認める」だったが、仕様は
**閉じの字下げを開きに一致させることを要求しない**（開きより浅い閉じも有効）。
`closeIndent >= openIndent` を要求すると、開きを字下げして列0で閉じた markdown で
閉じを見つけられず、**そのファイルの残り全部を空行に潰す**。リンクも見出しも見なくなるがテストは緑。
r3 の M7 で塞いだ「未閉じは安全側に倒れる」が、ここでは「検査が黙って盲になる」に
化けていた。字下げ幅を見ない形にし、この形のテストを足した。

**このとき足したテストの入力は、規則の実例になっていなかった**（箇条書きの中で開いて
列0で閉じる形で、CommonMark 参照実装ではリスト項目の終わりでフェンスが終わり、
列0の ``` は新しい開きになる）。あわせて字下げの上限も落としていた。
どちらも r6 の S1 / S2 で直した。

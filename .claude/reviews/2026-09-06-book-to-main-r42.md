### BR-01 (HIGH, 1人が実測): `open_at` のテストが、CI では注記の枝に一度も入らない

一時ディレクトリが symlink かどうかは**環境で違う**
（macOS の `/var` は symlink、Linux の `/tmp` は実ディレクトリ）。

`cargo test` を走らせる CI は **ubuntu-22.04 の1本だけ**なので
`requested == canonical` になり、**注記の枝を1度も通らない。**

| 実行環境               | 注記を後置に戻す変異 |
| ---------------------- | -------------------- |
| 既定 `TMPDIR`（macOS） | **FAILED**           |
| `TMPDIR` が実パス      | **161 passed（緑）** |

**r41 の BO-01 が「テストが本番経路を通らない」ことを所見にした、
その直しが、環境の偶然に依存して枝へ入っていた。**

- 結果: 対応済み `7f6f1ce3`（symlink を自分で張り、
  **枝に入ったこと自体を `starts_with` で固定**。両方の `TMPDIR` で変異が落ちることを確認）

### BR-02 (HIGH, 1人が実測): 本番の復帰文言を誰も見ていない

`unknown_message` の切り出しで守られたのは**テンプレートだけ**で、
`recovery` はテストが自前のリテラルを渡していた。

本番の実引数（`"もう一度開き直すこと"` / `"この定跡を閉じてから開き直すこと"`）を
**両方「リトライ」に変えても全15本のテストバイナリが緑。**

**`Unknown` は blocking プールの panic でしか出ない＝再現の難しい失敗の唯一の案内**

- 結果: 対応済み `7f6f1ce3`（定数へ上げ、テストが**本物を食う**形へ。
  「リトライ」への変異で落ちることを確認）

### BQ-01 (HIGH, 1人が実測): 「読むだけ」の語彙に、書ける動詞が入っていた

`git config -f rust-toolchain.toml a.b c` は**追跡ファイルを書き換える**
（git config として解釈できる形なので成功する）。
使い捨ての repo で10語を1つずつ当てたところ、**変えるのは `config` だけ。**

判定時点のツリーは clean なので種類が空になり、
**`verify:rust` が一度も走らないまま `rust-toolchain.toml` の変更が積まれる** ——
そのファイル自身が「替えると clippy の lint 集合ごと変わる」と書いている。

**r41 の記録にある「`git config -f` は実測で書かない」は誤りだった**
（`Cargo.toml` では失敗するが、`rust-toolchain.toml` では成功する）。

- 結果: 対応済み `7f6f1ce3`（語彙から外し、
  **`expect_readonly` が使い捨ての repo で1語ずつ当てて確かめる**形にした）

### BQ-02 (HIGH, 1人が実測): `--output` の弾きは、alias 1つで丸ごと抜ける

許可の判定は展開先の**先頭の語だけ**だったので、
`d = diff --output=src/app/App.tsx` を置くと `git d && …` が抜ける ——
**打った文字列に `--output` が1文字も出ない**ので、r41 で足した弾きにも当たらない。

**`GATE_EXTRA_READ_ONLY` の seam は解決ロジックを丸ごと差し替えるので、
テストはこの経路を1本も通していなかった** —— r39〜r41 と同じ形。

- 結果: 対応済み `7f6f1ce3`（展開先そのものに書き込む綴りが無いかを見る。
  ケースは **`GIT_CONFIG_GLOBAL` の fixture** を通す）

## このラウンドで分かったこと

r22 で入れた `tidy_csa` が**両方向に外していた**。3枚が別々の入口から同じ場所に
着いたので、まとめて1つの原則に落とした。

> **整形の規則は「tsshogi が受けるものの部分集合」に閉じる。行の型ごとに決まる。**

根拠は `node_modules/tsshogi/dist/esm/csa.mjs:38-118` の行パターンで、
**行を trim せずそのまま当てる**（`parseLine` に正規化が無い）。
だから `$` で閉じたパターンは末尾の空白があるだけで当たらない。

| 行                                   | tsshogi のパターン                   | 末尾の空白       | 整形          |
| ------------------------------------ | ------------------------------------ | ---------------- | ------------- |
| 手番行                               | `^[-+]$`                             | **受けない**     | 触らない      |
| `PI…`                                | `^PI([1-9]{2}[A-Z]{2})*$`            | **受けない**     | 触らない      |
| `P1`〜`P9`                           | `^P[1-9]( \* ?\|[-+][A-Z][A-Z]){9}$` | 最後の升だけ任意 | 升9つに揃える |
| `P+` / `P-`                          | `^P[-+]([0-9]{2}[A-Z]{2})*`          | 受ける           | 落とす        |
| 指し手 / `%` / `T` / `N` / `$` / `'` | いずれも末尾を見ない                 | 受ける           | 落とす        |

前の実装は `starts_with('P')` で一括り＋それ以外は全部 trim だったので、
**手番行と `PI` を削りすぎ**（索引だけが読めて画面で開けない）、
**段は保護しただけで補わず**（tsshogi が読む盤面を索引が読めない）、
**`P+`/`P-` を無駄に保護**していた。

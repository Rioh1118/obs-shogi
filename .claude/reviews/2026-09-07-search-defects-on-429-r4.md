# ラウンド4 — `search` の欠陥（ラウンド3の修正をレビューした）

対象は `review/388-on-429-all`。観点は rust / architecture / robustness / comment。

## このラウンドの共通の原因

**「機械が守る」と書いたが、その機械を迂回してみていなかった。**

R3 はラチェット（`tests/state_is_announced_once.rs`）を足して報告書に
「次に旗を1本足す人は、doc を信じても機械に止められる」と書いた。
R4 のレビュアーは**実際に迂回して緑にしてみせた**——イベント名を文字列で
直に書く形と、`IndexStatePayload` を構造体リテラルで組む形。どちらも
新しい import 無しでコンパイルが通る。

同じ形が3つ重なっていた。

1. `IndexProgress` を新設したのに、**写像を見るテストを1本も書かなかった**
   （`IndexAnnouncement` 側では R3 で塞いだ穴と同じもの）
2. `Updating` の腕が `partially_unreadable` を運ばない。`Building` は運ぶので、
   **同じ旗が経路によって消える**
3. 警告の重複除去が**一度も効いていなかった**。直前の1件としか比べておらず、
   1回の走査が3本出す形では照合が成立しない

## 自分が作った退行

**壊れた振る舞いをテストで固定していた。** R3 で足した
「間に別の警告が挟まれば、同じ文言でも積む」は、重複除去が効かないことを
**仕様として書き留めていた**。直すときにテストのほうが先に赤くなって気付いた。

**`pickWarns` の並びを直そうとして、種類の切れ目を回の切れ目と読む形を書いた。**
同じ種類が続くだけで1つの塊になるので、新しい順が壊れた。既存のテストが
落ちて気付き、確実に言えること（場所を名指しできるか）だけで割り直した。

## レビュー中に起きたこと

R3 で「同じワークツリーで変異検査と編集を並行させない」と書いたのに、
**同じことがまた起きた**。今回はレビュアーの変異が作業ツリーに残った状態で
私が `git status` を見て、それを自分の書き損じと読みかけた。

ただし今回は結果が良かった——残っていた変異
（`unreadable_places(places.len())` → `unreadable.len()`）は**本物の穴**で、
テストが1本も落ちなかった。塞いだ。

**次のラウンドからは、レビュアーに変異を別ワークツリーで当てさせること。**

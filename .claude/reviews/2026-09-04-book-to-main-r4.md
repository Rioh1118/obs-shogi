### U-01 (HIGH, 4人全員): 版の注記が、同じファイルに残る9箇所の誤った行番号を保証した

`yaneuraou_db.rs` のモジュール doc に「このファイルが引くやねうら王の行番号は、
すべて `v9.40` 時点」を足したとき、**同じファイルの他の引用を突き合わせていなかった。**

| 引用          | 主張                       | v9.40 の実際                     | 正しい所在           |
| ------------- | -------------------------- | -------------------------------- | -------------------- |
| `:709-716` ×4 | `#` と `//` を読み飛ばす   | `#if 0` の Apery ponder ブロック | `book.cpp:314-320`   |
| `:118-119` ×4 | `none` / `None` / `resign` | `}` と空行                       | `book.cpp:114-115`   |
| `:705` ×1     | 末尾の改行を要求しない     | Apery の `entries` ループ        | `misc.cpp:1133-1140` |

**注記を足す前は「版が書いていない古い数字」と読めた。付けたことで
「v9.40 を開けば必ずそこにある」という保証になった。** 突き合わせに来た人は
709 行目に死んだコードを見つけ、doc と自分のどちらが間違っているか判定できない。

`:705` は r3 の T-05 が名指した綴りそのもので、**同じ主張が2箇所にあり片方だけ直していた。**

加えて `MemoryBook::insert` と名指して `book.cpp:129-138` を貼っていたが、
`129-138` は `BookMoves::insert`（`120-145`）の中。`MemoryBook::insert`（`166-183`）は委譲するだけ。

- 結果: 対応済み `1c4d6336`（9箇所を貼り直し、委譲の2段を書いた）

### U-02 (HIGH, 4人全員): 書き直した「合わせない理由」も30秒で反証できる

> **どちらでもよいので、畳む側が1パスで済む方を採る** ——
> 後勝ちにすると「先に入れた要素をどこへ上書きするか」を覚える必要が出る。

**走査の枝は `any` を `position` へ替えるだけで、1パスのまま後勝ちになる**
（`moves.swap(j, i)`。追加の確保も「覚える」構造も無い）。`HashSet` の枝も `rev()` で足りる。
4人が独立に同じ反証を出し、うち1人は実際に走らせて出力まで並べた。

さらに「1パスで済む」は、**同じファイルの30行下が「走査が二乗になる。実測で 6.22MB に
16 秒」と書いているのと正面から矛盾する。**

r3 の T-03 が「30秒で反証できる理由は逆に『合わせてよい』の根拠になる」と書いた形が、
差し替えた理由でそのまま再生した。

- 結果: 対応済み `c0c16bf9`（**理由を装うのをやめ、差の記録として置いた。**
  使えない理由（費用・順序依存）を2つとも先に潰し、本当に合わせるなら
  採択回数の合算まで写す必要があることも書いた）

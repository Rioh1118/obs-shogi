対象は `review/388-on-429-all`。観点は rust / architecture / robustness / comment /
react / oss-hygiene の6つ。

## このラウンドの共通の原因

**doc に書いた不変条件を、機械が1つも見ていなかった。**

ラウンド2は `announce_state` を作って「`EVT_INDEX_STATE` を出す口はここだけ」と
doc に書いた。**6人中4人が独立に同じことを指摘した**——閉じたのは終端
（`Ready` / `Empty`）だけで、進行中の段は5箇所が生で出したまま。ファイル数で
数えると、R2 報告書が「3箇所→1つ」と書いた数字は**1つも減っていなかった**。

R1 が嘘を書き、R2 が訂正の節を足し、その同じ PR の中で**同じ型の嘘を1つ増やした**。
違いは、今回は書いた不変条件に対してラチェット（`tests/state_is_announced_once.rs`）を
足したこと。ただし**そのラチェットが見るのは emit の置き場所だけ**で、
段と旗の対応は見ない——それは `announce.rs` の `mod tests` の担当。

## レビュー中に起きたこと

**rust-reviewer が変異を当てている最中の作業ツリーを、私が別の目的で読んだ。**
`announce.rs` に `.scan_failed(true)` が現れ、react-reviewer が「誰が書いたか
分からない変更がある」と報告した。実体はレビュアー自身の変異検査で、
直後に復元されている。

**同じワークツリーで変異検査と編集を並行させない。** 今回は誰も壊さなかったが、
私がその1行を「自分の書き損じ」と読んで消していたら、レビュアーの検査は
偽陰性を報告していた。

なおその変異は**本物の穴を突いていた**——`Built` の腕に旗を1本足しても
テストが1つも落ちなかった。塞いだ。

## 自分が作った退行

**`slice(-PLACE_KEPT)` を書いた。** `PLACE_KEPT` が 0 のとき `slice(-0)` は
`slice(0)`、つまり**1件も残さないつもりが全件残る**。変異検査で
「`PLACE_KEPT = 0` にしてもテストが通る」ことに気付いて見つけた。
`Math.max(0, len - n)` の形に書き直してある。

**変異が通ったときに「テストが弱い」と決めつけない。** 今回は変異のほうが
無効だった。どちらかを確かめるまで、テストを足しにいかないこと。

## この報告書の訂正（R4 で判明）

**「次に旗を1本足す人は、doc を信じても機械に止められる」は誇張だった。**
足したラチェットが見るのは emit の**置き場所**だけで、段と旗の対応は見ない。
R4 のレビュアーが実際に確かめたところ:

- `IndexProgress::into_payload` にはテストが1本も無く、`Restoring` を
  `Ready/999` にする変異も `Updating` の `total`/`dirty` 入れ替えも素通りした
- ラチェット自身も、イベント名を**文字列で直に書く**形と
  `IndexStatePayload` を**構造体リテラル**で組む形の両方で迂回できた
  （どちらも新しい import 無しでコンパイルが通る）

R1・R2 は「直した」の表で嘘を書いた。**R3 は表を正しくしたうえで、
結論の1文だけを誇張した**。同じ型の3回目。

**「機械が守る」と書く前に、その機械を迂回してみること。** R4 で
`IndexProgress` の写像に6本、ラチェットに迂回2つ分の検査を足した。

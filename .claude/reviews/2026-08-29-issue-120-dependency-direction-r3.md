## ラウンド2の修正が入れた不具合

### [BLOCK] 同期待ちの打ち切りがエンジンのセッションを残し、以降解析を再開できなくなる（robustness）

- 場所: `entities/analysis/model/provider.tsx` の打ち切り分岐（`2f45ca4` で新設）
- 中身: `dispatch({ type: "stop_analysis" })` は reducer の action で、React の state を落として
  `sessionId` を null にするだけ。Rust 側には `is_active` なセッションが残る。
- 帰結: `src-tauri/src/engine/bridge.rs` の `ensure_no_active_session` が以降すべての
  `start_infinite_analysis` を `"Analysis already running"` で弾く。`sessionId` も消えているので
  停止対象を指せない。**解析が理由も告げずに止まり、その後 Play を何度押しても無反応。
  Stop はボタンが Play 表示なので押せない。** 復帰はエンジン再起動だけで導線が無い。
  加えて `stop` を送っていないので `go infinite` が回り続ける。
  **打ち切りを入れる前は無限に待つだけで、この行き止まりは無かった。**
- 結果: 対応済み（`1a7f103`）。打ち切りの中で `stopAnalysisCore` を呼んでからリセットする。

### [HIGH] 同期待ちの開始時刻が待ちの対象に紐づいていない（robustness）

- `syncWaitStartedAtRef` をリセットするのは「同期成立」と「打ち切り」の2つだけで、
  `runRestart` の早期 return 5本も `stopAnalysis` も新しい追従の開始もリセットしない。
- 帰結: 待ちの途中で解析を止め、しばらく後に再開して1手進めると、**数分前の開始時刻**が
  使われて同期を1ミリ秒も待たずに打ち切られる。しかも上の BLOCK と重なる。
- 結果: 対応済み（`1a7f103`）。`{ seq, want, startedAt }` として対象ごと持つ。

### [MEDIUM] `NotInitialized` の分岐が到達しない条件を前提にしていた（robustness）

- `failure = isReady ? e : null` の false 側は到達しない。送信ループに入る時点で
  `isReady` は必ず true（false なら送信前に保留して返る）。
- 結果: 対応済み（`1a7f103` と `9f20b1f`）。分岐ごと畳み、`isNotInitializedError` も削除した。

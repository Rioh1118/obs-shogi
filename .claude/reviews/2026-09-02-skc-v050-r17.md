## R17-04 の実測（CSA が黙って捨てる入力）

基準は `V2.2\nPI\n+\n+7776FU\n-3334FU\n%TORYO\n` で `moves=4`。

| 入力                                     | 結果                                                                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1手目の末尾に**半角スペース** `+7776FU ` | `Ok` / `moves=1`（**対局が丸ごと消える**）。対局者名が無ければ `says_nothing` が真になり `NothingToIndex` → **警告も出ない**               |
| 同じものに `N+山田` を足す               | `Ok` / `moves=1` / header あり → **平手の初期局面1件だけ**が索引に入る（`NothingToIndex` の doc が「これを避けるためにある」と言う当の形） |
| 2手目の末尾に半角スペース                | `Ok` / `moves=2`                                                                                                                           |
| 手のあとにタブ                           | `Ok` / `moves=1`                                                                                                                           |
| 最終行に改行が無い                       | `Ok` / `moves=2`（最後の1手が消える）                                                                                                      |
| `%TORYO` のあとに改行が無い              | `Ok` / `moves=3`（終局が消える）                                                                                                           |
| 指し手の途中に `N+late` 行               | `Ok` / `moves=2`                                                                                                                           |

別途こちらでも確認: 途中に棋譜でない行を1本入れた CSA は `Ok` / `moves=3`（健全なら4）。

`csa` の `parser::game` は private mod なので、上流からも残りを受け取れない。

## 確かめて「穴が無かった」もの

所見にはしないが、測って白だったことを残す。**次のラウンドで測り直さないため。**

- **zobrist の差分更新（`advance_key`）は正しい。** 乱数局面 × 乱数の手（成る/成らない・
  `Drop` の全14駒種・持駒0〜30枚）で `advance_key` と `key_from_partial_position` を
  突き合わせ、成立した **19,501組で不一致0**。`make_move` が通るのに `advance_key` が
  `None` を返す組・その逆も0（受け付ける手の集合が `PartialPosition::make_move` と一致）。
  破れるのは R17-33 の1点だけ。**変異（手番反転の削除）は2本のテストが殺した**
- **`AssertUnwindSafe` の根拠は成立している。** `shogi-kifu-converter` v0.5.0 と `csa` 1.0.2 に
  `static mut` / `thread_local` / `OnceCell` は0件。`read_portable` はローカルの `Vec<u8>` と
  戻り値しか持たない。`Cargo.toml` に `[profile]` が無い＝`panic = "unwind"` なので
  リリースでも `catch_unwind` は効く
- **`VERSION = 3` は正しく、二重に上がってもいない。** `decode_all:493-496` が `!=` で弾き、
  `try_restore` は final / bak の両方を `read_decode` 経由で通すので旧版は必ず落ちる
- **`kifu.rs` の #331 コメント3箇所は直す必要が無い。** v0.5.0 で実行して確認 —
  `promote` を `None` にして `normalize()` を掛けると 3手目が `promote=Some(false)` になり、
  綴った KIF から `成` が消える。上流 #9 が変えたのは「記録が `成` と言っているのに
  規則上成れない手」を保つ側（`normalizer.rs` の `decide_promote`）で、**欄が欠けた側は
  変わっていない**。厳密には「復元しない」は言い過ぎで、`piece` が成駒の名前を名乗れば
  `Some(true)` を作る — ただし今回の変更が壊したものではないので所見にしない
- **空綴り番人の撤去は安全。** `initial: None` / `moves: []` / 未知の `手合割` のどれでも
  `kif=59B` / `ki2=19B` / `csa=10B` で、`normalize()` を呼ばない `import_kifu_file` の
  経路でも0バイトにならない

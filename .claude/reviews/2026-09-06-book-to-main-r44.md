## BLOCK の中身

前のラウンド（GT-03）で塞いだのは**手前だけ**だった。
`gate_target_dir` が置換を見ていたのは切り出した呼び出しより手前の部分で、
呼び出し自身の引数の中は見ていない。

```
git status `git rm -f f.ts` && git commit -m x   => deny      （r43 で塞いだ形）
git commit -m `git rm -f f.ts`                   => 素通し
git commit -m "$(git rm -f f.ts)"                => 素通し
git commit -am x `git checkout main -- .`        => 素通し
```

シェルは `git commit` を起動する前に置換を実行するので、後ろに置いても結果は同じ。
しかも prefix が空になるため「手前に何も無い」として通る。
使い捨ての repo で、**検証されていないツリーが実際にコミットされる**ところまで
再現している。

判定の対象をコマンド全体へ移した。**メッセージに置換を使う形は止まる**ので、
コミットメッセージはファイルへ書いて `--file=` で渡すこと。

## 責務の分割

利用者の指示で、`search/` を手本に定跡側を割った。

| 対象           | 前     | 後                                                                       |
| -------------- | ------ | ------------------------------------------------------------------------ |
| `yaneuraou_db` | 1022行 | `mod` 406 + lines 225 + limits 166 + moves 143 + dedup 131 + diagnose 38 |
| `sfen`         | 506行  | `mod` 243 + counts 135 + board 88 + hands 73                             |

どちらも依存は下向きだけで環は無い。

割った結果、**`mod.rs` が `discard_rest_of_line` / `first_token` / `is_note` /
`BOM` / `DECLARED_COUNT_PREFIX` を1つも使っていない**ことが分かった。
どれも `lines` の中だけで閉じている。

**割っても単体テストは増えない。** 74本のうち単体で閉じているのは10本で、
うち5本を持ち主へ移した。残りは `sample` を通して走査全体を回している ——
増やせる場所ができただけで、いま在るものの大半は形式そのものの振る舞いを見ている。

そこから r7・r8・r9・r10 の4ラウンドが全部その機構の穴埋めに費やされ、毎ラウンド BLOCK が出た。

| ラウンド | その機構が生んだ BLOCK                                                     |
| -------- | -------------------------------------------------------------------------- |
| r7       | 列で待った書き込みが別のファイルを前の棋譜で丸ごと上書きする               |

**機構ごと落とした**（`b71a458` / `fe5d689`。551行削除・203行追加）。

## 所見

### [HIGH] R11-1 局面を動かさない書き込みの巻き戻しが、待っている間に進めた手数まで戻す（react）

- 場所: `reducer.ts` の `jkf_restored`、`provider.tsx` の `edit`
- 根拠: compare-and-swap は `jkf` だけを見る。`navigated` は `jkf` を触らないので、
  **移動しても `expectedJkf` は一致したまま**。`edit` は `before = {jkf, cursor, branchPlan}` を
  撃った時点で固定し、失敗したら3つまとめて戻す。
  本物の `GameProvider` を render した実測（`persistence.save` を保留させたまま `nextMove()` を2回）:

  ```
  after fire tesuu: 0 → after navigate tesuu: 2 → after failure tesuu: 0
  error: "Permission denied"
  ```

- なぜ問題か: コメントの自動保存は打鍵が止まった 900ms 後に撃つ。
  書き込みが失敗する棋譜（読み取り専用、他プロセスが掴んでいる）で、返るまでの間に
  → を数回押すと、**盤と棋譜一覧が撃った時点の手数へ黙って戻る**。
  `branchPlan` も同時に戻るので、その間に選び直した変化の選択も消える。
  `state.error` を描く場所は無い（#277）ので理由は出ない。
  手を指す `makeMove` の巻き戻しは「指した手を取り消す」で意図どおりだが、
  **カーソルを動かさない書き込みまで同じ扱いにしていたのが誤り**。
- 直し方: 巻き戻しに `restoreCursor` を持たせ、**局面を動かさなかった書き込みでは
  棋譜だけ戻す**。`edit` は `nextCursor.tesuuPointer !== beforePointer` で判定できる
  （コメントは `forceCommit: true` で通るがポインタは動かない）。
  分岐の入れ替え・削除は自分でカーソルを動かすので従来どおり戻す。
- 導入コミットの sha: `d5ec818`（ラウンド2の巻き戻し）。r3 の「見ていない範囲」に
  **「巻き戻したあとの cursor / branchPlan の整合」として名前だけ残っていた**
- 主張を固定するテスト名: `reducer.test.ts`
  「局面を動かさなかった書き込みでは、カーソルも計画も戻さない」

### [HIGH] R11-2 預かりの掃除が、番号の動いていない面まで落とす（robustness）

- 場所: `lib/unsavedDrafts.ts` の `dropUnsavedDraftsFor`
- 根拠: 判定が `tesuu >= fromTesuu` だけで、鍵に入っている**変化の経路を一切見ていない**。
  実物の鍵生成と同じ式で組んだ probe:
  - 本譜40手目（鍵 `/ws/a.kif__40__`）の預かりが `dropUnsavedDraftsFor("/ws/a.kif", 5)` で消える
  - 20手目の別の変化にぶら下がる30手目（鍵 `/ws/a.kif__30__20:1`）も消える

  どちらも「5手目の変化の入れ替え」で `forkIndex` が1つも動かない面。

- なぜ問題か: 40手目の本譜にコメントを書きかけて別の棋譜へ移り（預かりに入る。
  R5-1 が「元の棋譜へ戻れば出し直せる」と約束した経路）、戻ってきて
  **5手目の無関係な変化を入れ替えるだけ**で、40手目の預かりが赤い箱ごと消える。
  開き直すと本文は空で、**失ったことも画面に出ない**。
  ノートは「保存できませんでした。書いた本文はこのまま残っています」と断言しているので、
  その断言が**本文と何の関係も無い操作1回で、無通知に破れる**。
  これは `dropUnsavedDraftsFor` 自身の doc が「`fromTesuu` より前の手は落とさない」理由として
  挙げているのと**同じ論法**で、実装がそれを `te` の前後にしか適用していなかった。
- 直し方: 当たるのは2つだけ。**その分岐点を通っている面**と、
  **本譜が動いたときの `te` 以降**。鍵の経路を読んで判定する。
  鍵を組む関数を `lib/unsavedDrafts.ts` へ下ろし、**組む側と読む側を同じファイルに置いた**
  （形を2箇所が別々に知っていたのが元凶）。
- 導入コミットの sha: `749af52`（ラウンド7）。`b71a458` の縮小で世代という第2の門番が
  消えたぶん、この掃除の粗さが単独で効くようになっていた
- 主張を固定するテスト名: **未検証**（`lib/` にテストファイルが無い）

### [MEDIUM] R11-3 畳んだあとに遅れて返った失敗が、畳むときに預けたより新しい本文を上書きする（react）

- 場所: `KifuCommentNote.tsx` の unmount の cleanup と `stash` / `showing`
- 根拠: cleanup は「いま画面に出ている本文が必ず新しい」を前提に無条件で預ける。
  しかし走っている保存は自分の `text` で預け直す。実測:

  ```
  saves fired                : [["aaa"]]
  draft right after unmount  : { draft: "aaab", error: "棋譜を閉じたので…", told: false }
  draft after old save failed: { draft: "aaa",  error: "boom", told: true }
  ```

  併せて `faceRef.current` が unmount で消えないため `showing()` が真を返し、
  **一度も描かれていない失敗に `told: true` が立つ**。

- なぜ問題か: 自動保存が飛んだ直後に打ち足してワークスペースを切り替えると、
  打ち足したぶんだけが黙って消え、1つ前の本文が「書いた本文はこのまま残っています」の顔で残る。
  `told: true` の副作用として、開き直したあとの最初の閉じる操作で預かりごと捨てられる。
- 直し方: unmount で `aliveRef` を落とし、`showing()` と `stash` の両方がそれを見る。
- 導入コミットの sha: `b102ead`（ラウンド6）
- 主張を固定するテスト名: **未検証**（`KifuCommentNote.test.tsx` に `unmount()` を踏む本が無い）

## 確認して問題が無かったもの

**落とし残しは1件だけ**（R11-4）。`grep -rn "pendingWrites\|writeChain\|withDeadline\|
NO_RESPONSE\|branchGeneration\|destRef\|WRITE_DEADLINE" src/ docs/` で他に残骸なし。
`branchGeneration.ts` とそのテストはファイルごと消えている。

**落としすぎも無い。** 4件の修正はすべて生きている。

- **保存先の門番**（#245 / #204）: `[persistence, state.loadedAbsPath]` の dep へ戻したが、
  **両方を同じレンダで掴む**ので組が割れない。`persistence.save` は `GamePersistenceGate` が
  `activeKifuPath` を閉じ込めているので、レンダが古くても書き先は `persistence.absPath` そのもの。
  門番を潰す変異で `persistGuard.test.tsx` が落ちることを確認
- **失敗したらメモリを戻す**: reducer 側は `reducer.test.ts` の4本、`edit` 経路は
  `persistGuard.test.tsx` で固定（→ 削除経路も R11-6 で足した）
- **書けなかった本文を面ごとに預かる**（#227）: `KifuCommentNote.test.tsx` の15本が全部生きている。
  `inFlightRef` / `saveRef` と2つの閉じる分岐を落としても緑
- **削除の確認と失敗の箱**（#200）: `b71a458` は一切触っていない
- **`handleRequestClose` の1本化で閉じられなくなる経路は無い。** 落とした分岐は
  `.then(finish)` で結局 settle まで閉じていなかったので、**外から見える挙動が同じ**
  （実物と同じ配線の probe で、成功／失敗2回／速い連打の3通りを確認）
- **`persistIfPossible` を素直な `async` に戻した波及は無い。** `persistence` は
  `useMemo([activeKifuPath, kifuFormat])` 済みなので、identity が動くのは実際に
  ファイルが変わったときだけ。再レンダは増えていない
- **`blocking: false` で同じ参照を返すことで壊れるものは無い。** `blocking` は入口で1回
  計算して `finally` にも同じ値を渡すので、片側だけ数えるずれは作れない
- **残っている ref はどれも要る**（`commitRef` / `chainRef` / `faceRef` / `flashTimerRef` /
  `leavingRef` / `autoSaveTimerRef`）。react 側が1つずつ根拠を挙げて確認した。
  `chainRef` はノート内の保存だけを並べるもので、直列化を落としても
  「置き場にあるのは必ずこれより古い」の前提を支えている
- **`persistGuard.test.tsx` の3本は実物と同じ配線**（`GameProvider` を実 render、
  モックは `save` の中身だけ）。2本目は `rerender` で `persistence` だけを差し替えて
  reducer の state を保つ形になっており、狙った1コミットぶんのずれを正しく再現している
- **この差分に新しいセキュリティの口は無い。** `npm audit` は 0 件

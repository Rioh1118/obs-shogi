### R11-01 [HIGH] プリセット編集ダイアログの描き直しが止まらない（react / robustness の2名、実測）

空欄の自動補完の effect が毎回新しいオブジェクトを返し、その `draft` を自分の依存に
持っている。埋めるものが1つも無い回でも commit → effect → `setDraft` → commit … が閉じ、
ダイアログを開いている間ずっと回る（`Maximum update depth exceeded`、103 回描いても収束せず、
CPU を1コア食う）。配布ビルドでは警告も見えない。

**`origin/main` にも同じ形で在る既存の問題**だが、この枝が触った帯に振る舞いのテストを
1本も書けないのはこれが理由で、直さないと次の所見も固定できない
（`render()` が `act` の中で返らない）。

- 結果: 対応済み。**同じ PR で直した**（`/implement` 手順7 の「変更の前提を壊している」）。
  補完の中身を `autofillPreset` に切り出し、1つも埋めなかったら同じ参照を返すことを
  単体テストで固定した（常に新しい参照を返す形に戻すと3本落ちる）

### R11-02 [HIGH] 帯が、走査中に前のルートの索引で出る（react / robustness の2名、実測。r10 の退行）

R10-02 で門番から `scanReady` を外したのに、索引の側は読み直しに入るとき捨てられない。
ルートを選び直した直後の走査中、帯は**旧ルートの絶対パス**を名指しし、その隣の

ボタンは押せたままになる。

- 結果: 対応済み。索引に読んだルートを添えて持ち、いま指しているルートと一致するときだけ
  分類へ渡す（`AiLibraryTab` の `LoadedIndex` と同じ形）。門番を2つにしないという
  R10-02 の意図はそのまま守れる。読み直し中は帯の2つのボタンを押せなくした。
  ダイアログの振る舞いのテストはこれが1本目で、3本とも変異を当てて落ちることを確かめた

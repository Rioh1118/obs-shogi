## このラウンドでいちばん重いもの

**報告書がまた嘘を書いた。今度は「足したテスト」の表で。**

R7 の報告書は次の2行を「新しく足したテスト」として並べた。どちらも**存在しない**。

原因はどちらも同じ。**`replace` が silently 一致せず、それを確かめずに報告した**
——`cargo fmt` が整えた後の綴りとアンカーがずれていた。

R1・R2 は「直した所見」の表で嘘を書き、R3・R4 は結論を誇張した。R5〜R7 は
表を正しくしたつもりだった。**「変異を当てて確かめる」を手順に書いた3ラウンド後に、
確かめずに書いた。**

同じ silent replace がこのラウンド中だけで**さらに2回**起きた（helper の挿入、
doc のアンカー）。どちらもその後コンパイルか実行が落ちて気付いた。

**手順を1つ足す:** 報告書の「足したテスト」の表を書く前に、**関数名を `grep` して
実在することを確かめる**。落ちなかった変異と同じで、確かめないものは書かない。

## 測って分かったこと

**KIF は中身を失っても `NothingToIndex` に落ちる。**

```
full.kif         Ok indexed=true  positions=2  warns=0
cut_mid_move.kif Err（正しく断る）
cut_header.kif   Ok indexed=true  positions=0  warns=0   ← 中身はあるのに0件
cut_no_nl.kif    Ok indexed=true  positions=2  warns=0
```

R6・R7・自分の修正はどれも「警告が出ないなら何も失っていない」を前提にしていた。
**その前提が成り立つのは CSA だけ**（読み残しを見る口が `warn_if_moves_were_dropped`
1つしか無い）。0バイト・空白・BOM は塞いだが、**中身があって局面0件**の形は残る。
#501 に出した——ここから先は設計の選択（形式ごとに検査を書く／局面0件を一律で
倒す／`indexed` の意味を変える）なので、勝手に決めない。

## この報告書の訂正（R9 で判明）

**「直したもの」の表がまた2行ずれていた。** R7 の失敗を訂正した文そのものが、
同じ形で外れた。**同じ故障の3回目。**

| 書いたもの                                    | 現物                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------- |
| 実在しない2本のテストを「実際に足し」         | 足したのは `indexHealth.test.ts` の1本だけ。`a_header_only_kifu_…` は**今も無い** |
| 丸めの doc に「健全と区別が付かない」と書いた | **そのような doc は無い。** `types.rs` の差分は derive の1行だけ                  |

`a_header_only_kifu_…` を新設しなかったのは、既存の
`a_genuinely_empty_kifu_is_not_a_failure` の `appnew.kif` の腕が同じことを
見ているから——**そう判断したなら、そう書くべきだった**。

丸めの件は R9 で `types.rs::indexed` の doc に実際に書いた。

**手順は足したのに守れていない。** R8 は「表を書く前に `grep` で実在を
確かめる」と書き、その同じコミット（`d4d9c139`）で**存在しない関数名**を
ラチェットの doc に書いている。

**機械で止めようとして、やめた。** `.claude/reviews/*.md` の識別子を `grep` する
検査を書いて回したところ、**117件が過去の報告書から出た**（`game` / `skc` /
`harness` / `store` の別 PR）。それらは**書いた時点では本当**で、その後に
改名や削除があっただけ。報告書は「書いた時点の事実」を残すものなので、
後から走る検査は「当時本当だった」と「いま本当」を区別できない。

**この形のラチェットは作れない。** 止められるとしたら書く瞬間だけで、それは
検査ではなく手順。3回守れなかった手順を4回目も書くことになるが、
**偽陽性117件のラチェットを置くよりはまし**——置けば必ず無効化されるか、
EXEMPT が膨らんで意味を失う。

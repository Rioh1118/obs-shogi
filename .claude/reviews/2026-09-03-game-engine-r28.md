## ラウンド27の置き換えが壊れている

### R28-H1 `finish` の1行が、無検査の `detail` を丸ごと載せる

`src-tauri/src/engine/game/session.rs:1515-1522`（`finish`）と `:995-1009`（`accept_rule_end`）。

rust が実測:

```
PROBE accept_rule_end ok=true
PROBE log line bytes=300057
```

`endGameByRule(id, null, "x".repeat(300_000))` は `Ok` で通り、`finish` の1行が
**300,057 バイト**になる。ログは 200KB ＋ `KeepOne` なので**この1回で診断の履歴が全部飛ぶ**。

**webview から来て何の検査も通らずログへ出る文字列は `detail` だけ。**
`start_sfen` と `setoption` は `MAX_WIRE_FIELD`、指し手は `MAX_USI_MOVE_LEN`、
手数は `MAX_PLIES`、`GameId` は `Display` が48文字で切る。

しかも `finish` は「絞らない」と明記してある唯一の口。
**ラウンド27が塞いだ穴（R27-H3）を、同じラウンドの別のコミットが別の欄で開けている。**

`detail` は `Phase::Over` に保持され、`snapshot` が `get_game_state` のたびに複製する。

### R28-H2 予算を鍵の判定より手前に置いたので、「空いた枠を落とす」が観測できなくなった

`src-tauri/src/engine/commands/game.rs:184-201`。

```rust
if self.spent >= MAX_LINES_PER_INTERVAL {
    return false;          // ← ここで切ると allow_by_key に一度も入らない
}
```

`per_game` に鍵が挿さるのは `allow_by_key` の中だけなので、**1間隔に挿さる鍵は最大8個**。
rust が実測:

```
PROBE per_game.len()=8 spent=8            (quick(), 20ms 枠)
PROBE default per_game.len()=8 spent=8    (既定, 1秒枠)
```

`flood()` は120回回しているのに `per_game` は8件で止まり、
`MAX_TRACKED_GAMES` の枝には**一度も入らない**。

**変異で確認: `retain` を丸ごと削除しても206本すべて green。**
ラウンド26で two-strikes を満たして入れた守りが、翌ラウンドの修正で観測不能になった。
次に「要らないのでは」と消す人を止めるものが1つも無い。

robustness は同じ場所の別の面を挙げている——**予算は鍵より上にあるので、
断られ続けている鍵が8つ揃うと、別の対局の1件目が枠すら作られずに落ちる**。
`per_game` を4ラウンドかけて入れて塞いだ形が、1段上で戻っている。
`MAX_TRACKED_GAMES=120` × 操作6つで鍵は最大720通りありうるのに、1間隔に通せるのは8。

### R28-H3 `emit_warn` の doc が、いま存在しない機構を過去形で説明している

`src-tauri/src/engine/commands/game.rs:73-75`
「分けていたのは『宛先が消えると失敗し続ける』という前提の上で、その前提が偽だった」。

主語（`is_frequent` / `needs_every_line` / `frequent_warn` / `rare_warn`）は
**バリアントごと消えている**。読んだ人は `grep` して0件を得て、
「まだ分かれている枠がどこかにあり、自分が見落としている」と判断するか、
「消し忘れの説明」として doc ごと落とす。

`commentHistory` は「だった」を意図的に外しているので機械は止めない。

### R28-H4 `move is too long` が嘘のバイト数を返す。しかも借りている定数は別の意味のもの

`src-tauri/src/engine/game/session.rs:2012-2016` の `.min(MAX_WIRE_FIELD)`。

300,000 バイトの手を投げると `move is too long: 8192 bytes` が出る。
**8192 は真下の `validate_settings` が `start_sfen` に使っている値そのもの**なので、
読んだ人は「ワイヤのフィールド上限に当たった」と誤読する——当たったのは
`MAX_USI_MOVE_LEN = 8`。

`usize` の10進表記は最大20文字なので、**丸めても守れるバイト数は無く、失うのは診断だけ。**

**変異で確認: `.min(...)` を外しても206本 green。** どちらに倒しても観測されない。

## doc が現物と食い違う

### R28-M2 `MAX_USI_MOVE_LEN` の根拠が、将棋に存在しない指し手を挙げている

`session.rs:2039-2042`「一番長いのは成りを伴う打ち込み（`7g7f+` の5バイト）」。

**打ち込みは成れない。** USI の打ちは `P*7f` の4バイトで、`7g7f+` は成りを伴う**移動**。
値の8は正しいが、この定数を締めてよいか調べる人は存在しない形を探すことになる。

### R28-M3 「`LogThrottle` は枠の先頭を必ず通す」の例外を、`LogThrottle::new` 自身が書いている

主張側が3箇所（`commands/game.rs:143-145` / `:180-181` / `:261`）、現物が `utils.rs:120-130`。

`checked_sub` が失敗した枠（起動直後）は初回 `allow` が `false`、`is_open()` も `false`。
つまり `retain(|_, t| !t.is_open())` はその枠を落とさず、
「静かなときの1件は必ず残る」も成立しない。

併せて `pub struct LogThrottle` と `new` / `allow` / `reset` / `set_interval` に
`///` が1つも無い（`is_open` だけ有る）。**絞りの主張の持ち主なのに、
主張は全部呼び出し側に書かれていて公開面が裸。**

### R28-M4 ログの予算「200KB ＋ `KeepOne`」が7箇所へ数値で複写されている

出どころは `lib.rs:74` の `.max_file_size(200_000)`——**名前も doc も無いリテラル**。
複写先は `commands/game.rs` 4箇所、`session.rs`、`manager.rs`、`types.rs`。

`comment_identifiers` は**識別子しか見ない**ので、数字の綴りは1件も落ちない。
`max_file_size` を上げる人は `lib.rs` の1行だけを触り、
**予算から逆算して決めた4つの定数の根拠がまとめて静かに嘘になる。**

### R28-M5 `Runner.over` は「拍を止める合図」なのに終局そのものを名乗り、真隣に `is_over()` がある

`session.rs:736-741` / `:1550` / `:1607`。

### R28-M6 `game-event` の綴りが Rust と TS で二重に定義され、どちらの doc も相手を指していない

## 修正計画

### 順

1. **R28-H2**——予算と鍵の関係を組み直す。**予算を上限の一次手段にしない**
2. **R28-H1 / H4 / M2**——外来の文字列と、それを説明する定数
3. **R28-M1**——空行を挟む形を拾う
4. **doc の非連動**（H3 / M3 / M4 / M5 / M6 / M7）

### R28-H2 の倒し方

鍵の枠だけで output は既に `枠の数 + 操作の数` に縛られている。
**縛りが緩かったのは枠の数（120）のほう**なので、そちらを実際の対局数に見合う値へ締め、
予算は**背押さえ**として鍵の判定の後ろへ置く。こうすると:

- 実運用（数局 × 6操作）は予算に当たらないので、公平さが戻る
- 連打は枠の数で頭打ちになり、予算がその上をさらに押さえる
- `retain` の枝が**テストから踏める**（枠が数十で満杯になる）

## 結果

**11件すべて着手。**

| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------- |
| R28-H2 / M4           | 一次の上限を**枠の数**に戻し（120→24）、予算は鍵の判定の**後ろ**に置く背押さえ（48）に。2つの数を `LOG_FILE_BUDGET` から式で導く | `fca4272` |
| R28-H1 / H4 / M2      | `detail` に上限を掛けて断る。長さの報告の丸めを外す。`MAX_USI_MOVE_LEN` の根拠を直す                                             | `374424e` |

| R28-M6 / H3 / M3 / M5 | `game-event` の突き合わせを置く。`emit_warn` の過去形／`LogThrottle` の公開面／`over` の改名                                     | `2caa348` |

### R28-H2 の倒し方を変えた

所見は「予算を鍵の後ろへ移す」か「`flood` を窓を跨いで回す」の2択を挙げていた。
**どちらでもなく、一次の上限を枠の数に戻した。**

1間隔に出る行数は「枠の数 ＋ 操作の数」で既に頭打ちになる。緩かったのは
枠の数（120）のほうで、予算はそれを覆い隠していただけ。枠を24へ締めると、
実運用（数局 × 6操作）は予算に当たらないので**公平さが戻り**、
`retain` の枝もテストから踏める。予算は48（＝枠＋余裕）の背押さえに残す。

2つの数の関係は式で持つ（`the_limits_are_derived_from_the_log_budget`）。
片方だけ動かすと落ちる。

### `LOG_FILE_BUDGET` の置き場

`lib.rs` に置いたら `engine_layering` が落とした——`engine/` は crate の
他の枝を `use` できない。**機械が正しい。** 絞りの持ち主の隣（`engine/utils`）へ
置き、`lib.rs` はそこから読む向きにした。

### 変異試験

すべて baseline 差分。

- 空いた枠を落とす枝を消す／予算を8へ戻す／枠を120へ戻す／予算を上げてログを一周させる
- `detail` の検査を外す／長さの報告を丸める
- doc と `use` の間に空行を挟む
- `game-event` を Rust 側だけ改名する

### 残した所見

無し。

## BLOCK の中身

r44 で後置きの置換を塞いだが、**塞ぎ方が綴りの列挙**だった。
拒否リストは必ず次の綴りに置いていかれる —— この関数の頭に書いてあるのと
同じ理由が、直した本人に当たった。

```
git commit -am x > src/app/App.tsx      リダイレクトはコマンド起動前に truncate する
git commit -F =(git rm -f X)            zsh のプロセス置換。実行シェルは zsh 5.9
```

手前と同じ「許す文字だけ」の検査を後ろにも掛けた。引用の中では何も走らないので
先に潰すが、`gate_strip_quotes` は空白を含む引用しか潰さないため、
ここでは空白の無い引用（`-m 'fix(#375)'`）も潰す。
**バッククォートと `$` を含む引用は残す** —— 二重引用符の中では置換が走る。

## HIGH の中身

**床が環境で落ちる。** `GATE_TEST_MIN_RUNS` は現在値ちょうどで、
その1本が「別ワークツリーが在るか」に懸かっていた。
`git clone` しただけの環境では `npm run verify` ごと落ちるので、
**`.ts` を1文字触るコミットが全部 deny される。** クローンを作って再現した。

案内は「本数が減ったなら床を下げること」なので、従うと床が下がり、
r44 で入れた保護がそこで無効になる。

**ログ走査の窓が3行固定。** rustfmt が引数を折り返すと `input.path` が
窓の外へ落ちる。`log::` の行数は変わらないので等値の assert も発火しない。
マクロ呼び出しの閉じ括弧までを見る形に変えた。

このラウンドの所見のうち **8件が r44 の自分の変更が作ったもの**。

## 判断

**`search` と `book` の SFEN 読み取りは統合しない。**
出す物が別（Zobrist の鍵 / 定跡ファイルの綴りと突き合わせる正規化済み文字列）で、
失敗の型も別（内部語 / 利用者に届く復帰操作つき）。受理集合も実際に食い違う。
どちらへ寄せるかは #236 のまま。理由を `sfen_position.rs` の doc に書いた。

**`ratchet:rustdoc` の基準を 34 にした。** 30 件は #429 側の既存の警告で、
この PR が引き受ける形になる。ラチェットの基準はそのためにある。

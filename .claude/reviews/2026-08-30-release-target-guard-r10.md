## 確認して問題が無かったもの

**4セル表 × `create-release` の分岐**（1セルずつ突き合わせた）:

| セル      | コードの経路                                                               | 配る `sha`    | 一致 |
| --------- | -------------------------------------------------------------------------- | ------------- | ---- |
| あり/あり | `hadRelease=true` → `createRelease` を通らない → ガード不成立              | `tagSha`      | ○    |
| あり/なし | `hadRelease=false` → `createRelease`（`target_commitish` は API 側で無視） | `tagSha`      | ○    |
| なし/あり | `hadRelease=true` かつ `tagSha===null` → `throw`                           | 配らない      | ○    |

## このラウンドで分かったこと

r5〜r9 の所見は4件とも「タグ × リリースの掛け合わせのうち1セルを外している」だった。
r9 で表を文書に置いたら、r10 では**そのセルからは1件も出なかった**。

代わりに出たのは、**文書が「毎回やっていること」を書いていない**という別の穴
（R10-1 / R10-2）。どちらも「yml が何をするか」は正しく書いてあり、
**yml がやらないこと（ノートを人が書く）を書いていない**ために起きている。
運用の文書は、自動化されている部分よりも**自動化されていない部分**を書き落としやすい。

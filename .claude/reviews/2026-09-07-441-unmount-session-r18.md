## 所見

### [BLOCK] 1. 解析中にエンジンを起こし直すと「解析中」の表示のまま二度と戻らない。その入口だと doc に書いた effect は1度も発火しない

reviewer: react / robustness / comment（3人が独立に。うち1人は発火数を計器で測った）

```
F analyzing= true startCore= 1 stopCore= [] error= null analyzedSfen= sfen-1   ← 500ms 待っても不変
G after unmount stopCore= [[null,"unmount"]]                                   ← 席は握ったまま残っていた
R18 effect525 reached= 25 fired= 0 blocked= {"live-timer":25}                  ← 53本を通して0回
```

引き金は**この画面の断り6本が案内している操作**（設定でオプションを変えて保存する）。
Rust は畳む前に席を全部空けるので、フロントは死んだ席を握ったままタイマーだけが回り、
候補手は前のエンジンのものが残り、断りも出ない。原因は「投げ済み」の印が落ちている間も
残ることで、戻った回に「その局面は投げ済み」と読んで降りていた。

### [HIGH] 2. 購読が落ちた回の断りが、▶ を1回押すだけで消える

reviewer: robustness（実測）

```
P1a error= LISTENERS_FAILED       listeners registered= false
P1b error= null  isAnalyzing= true  candidates= 0  startCore calls= 1  listeners= false
```

他の断りは押し直すと同じ条件を踏んで立て直るが、**この枝だけは条件が再検査されない**。
`clear_results` が `error` を消し、Rust には本物の `go` が出る——以後は
「解析中・候補手0・断りも無し」で、唯一の案内（起動し直し）が画面から消える。

### 3. `isReady === false` なら理由が在る、が型に無いので呼び手が既定値を書いている

reviewer: architecture

`notReadyReason ?? "no-engine"` の既定値は、**前のラウンドが「起こし直しの最中に
出してはいけない」と結論した断りそのもの**。踏めないことを固定したテストも無い。

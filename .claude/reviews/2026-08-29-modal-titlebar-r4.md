## 対応した所見

### [HIGH] 基底の `max-height` の説明が、同じファイルの注記と正面から矛盾していた

- reviewer: `comment`
- 対応: `cc80c16`

`.modal__card` に付けた「上限は size ごとの規則ではなく**ここで一度だけ決める**」は偽。
`.modal--size-sm .modal__card`（詳細度 0,2,0）は `.modal__card`（0,1,0）に勝つので、
size が高さを書いていればそちらが実効の上限になる。基底が効くのは高さを書かない size だけ。

150行下の sizes の注記は「size でも必ず `100%` で挟め」と言っており、両立しない。
読み手は基底を信じて size 側の `, 100%` を冗長と見なす。
役割の切り分けとして書き直し、検査の `it` 名も実際に見ている性質に合わせた。

`cdffd22` のコミット本文の「size 側の指定はその内側の意匠に限る」も同じ理由で
現状と一致しない。コミットメッセージは書き換えられないのでここに記録する。

### [MEDIUM] 疑似要素を本体の宣言として数え、正しい変更を落としていた

- reviewer: `robustness`（変異を実測）
- 対応: `b284e12`

`\b` は `::` の前でも成立するので、`.modal__overlay::after` と
`.modal__card--scroll-card::-webkit-scrollbar` が本体の規則として拾われていた。

| 落ちていた正しい変更                                   | 何が起きるか                                                                                                                     |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| overlay の `&::after` に飾りの `top: 0`                | 失敗文言に従うと `::after` に `top: 2.6rem` を書く。疑似要素はパディングボックス基準なので飾りが 26px ずれるだけで、帯とは無関係 |
| `::-webkit-scrollbar` に横スクロール用の `height: 8px` | スクロールバーの太さをカードの高さとして数えていた                                                                               |

### [MEDIUM] `min-height` を viewport で書くと素通りした — r2 の退行と同じ形

- reviewer: `robustness`（変異を実測）
- 対応: `b284e12`

解決順は `max(min-height, min(max-height, height))` なので、`min-height` が器を超える値なら
`max-height: 100%` では止まらない。`.presetDialog` の `min-height: 0` を `60vh` に変えるだけで
**7 passed のまま通っていた**。ウィンドウ高 400px（内容ボックス 310px）でパネルが 360px になり、
カードの `overflow: hidden` ではみ出したフッタと保存ボタンがスクロールでも届かない。

**r2 で見つけた退行とまったく同じ形の故障が、その退行を守るはずの検査を素通りしていた。**
`height: auto` を上限として数えていた点も同時に直した。

### [MEDIUM] `clamp()` の第1引数（下限）を見ていなかった

- reviewer: `robustness`（変異を実測）
- 対応: `b284e12`

`clamp(a, b, c)` は `max(a, min(b, c))` なので、`a` が `100%` を超えうるなら上限は効かない。
`clamp(32rem, 78vh, 100%)`（「最低でも 320px は欲しい」という自然な書き方）で
ウィンドウ高 400px のときパネルが 320px になり器を超えるのに、上限ありと判定していた。

### [MEDIUM] 「カード自身が上限を持つ」を at-rule の内側でも満たせた

- reviewer: `robustness`（変異を実測）
- 対応: `b284e12`

規則がどの at-rule の下にあるかを見ていなかった。基底の `max-height: 100%` を消して
既存の `@media` の中へ移し、上限を書かない size を1つ足すと素通りする。
1280×900（対象画面サイズ）では上限が一切効かず、`cdffd22` が構造で塞いだ故障が戻る。

### [MEDIUM] 検査の判定を固定するテストが1本も無かった

- reviewer: `robustness`
- 対応: `48cef2f`

r3 と r4 で**この検査自身に9個の判定バグ**が見つかったのに、判定が正しいことを
確かめるテストが無かった。上の検査は SCSS の現状に依存するので、判定を緩めても
現状が通れば緑のままになる。

`isBounded` と違反の拾い方に表で当てるテストを足した。判定を緩める3通りの変異
（clamp の下限チェックを外す / `min-height` の強制判定を外す / viewport 単位を `vh` だけに戻す）が
いずれも落ちることを確認した。

### [MEDIUM] `VIEWPORT_UNIT` が名前とコメントの主張ほど広くなかった

- reviewer: `comment`
- 対応: `97466c4`

名前とコメントは「ビューポート基準の高さ」全般を約束していたが、実体は `vh` 系4つだけ。
`height: 80vmin` / `60vmax` / `50vw` も同じく器と無関係に決まるのに素通りしていた。
`vw` / `vi` / `vb` / `vmin` / `vmax` と `dv` / `sv` / `lv` の変種を含め、5通りで落ちることを確認した。

### [MEDIUM] カード上端 20px が反実仮想の値であることが書かれていなかった

- reviewer: `comment`

overlay が `inset: 0` だった場合の値。現行は `top` が 26px あるので同じ構成でも 46px になる。

| 素通りする形                             | 実在するか                                                                                                                           |

範囲を広げると、全画面の根（`App.scss` / `FolderSelect.scss` / `BootSplash.scss` /
`WelcomeScreen.scss` の `100vh`）を除外する許可リストが要る。また
`grid-template-rows` を入れると `StudyPositionSaveModal` が引っかかり、
**#53 とは無関係のファイルを直すか、既知の懸念を許可リストに書き込む**ことになる。

代わりに、ファイル冒頭の「知らない書き方に当たったら通さずに落とす」が
**辺の検査にしか当てはまらない**ことを明記した（`48cef2f`）。

lint ルール」は、走査範囲と実際の配置が乖離しないことを機械で保証できる。
検査の範囲を広げるかどうかと一緒に別 PR で扱うのが妥当。

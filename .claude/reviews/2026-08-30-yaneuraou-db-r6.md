対象: `feat/91-yaneuraou-db-reader`（issue #91）
観点: rust / robustness / comment / architecture
基点: `a68a88f`（R5 の報告書）

所見15件（BLOCK 0 / HIGH 3 / MEDIUM 10 / LOW 2）。**このラウンドは外部の一次資料に

## H-01 (HIGH, robustness): 見出しの無い定跡を拒否していた → 修正済み `77c5314`

**ShogiHome は `yaneuraou-no-header.db` を「開ける」側の回帰 fixture に持っている**
（`index.spec.ts` の `sources`）。本家も見出しを検査しない。

    やねうら王テキスト定跡の見出しが無い（1行目: sfen lnsgkgsnl/... w - 1）。
    別の形式のファイルかもしれない。取得し直すか、別の定跡を開くこと

引用している行は誰が見てもやねうら王の局面行なので自己矛盾している。案内する
復帰操作2つはどちらも効かず、実際に効く操作（見出しの行を足す）は書かれていない。

この検査を置いた理由（別形式を「0局面の定跡」として開かない）は他の枝が既に
満たしている。実測で `html.db` は E8、`archive.db` は H1、`sqlite.db` は H8、
注記だけのファイルは H5 で落ちる。

局面行を暗黙の見出しとして扱う。**読んだ行は捨てない**（捨てると見出しの無い
定跡だけ先頭の1局面が消える）。

## G-02 (HIGH, comment): 引用のガードが引用の経路を通っていなかった → 修正済み `7b7eac8`

`a_long_first_line_is_cut_to_the_excerpt_budget` が 10,000 バイトの1行を渡していた。
**行長の上限（4 KiB）を超えるので `read_line` の側で落ち、`excerpt` を1バイトも
通らない。** `excerpt`（120字）をパス用の `truncate_path`（4096字）へ差し替える
変異が `cargo test --lib book::` 全緑で通った。R1 A-09 のガードは無防備だった。

`text_that_is_not_a_move_is_rejected` の 5,000 バイトも同じ。

## G-03 / G-04 / G-05 (HIGH / MEDIUM, comment): 表の ✓ が嘘 → 修正済み `0531753`

表は「`✓` はそのセルを踏むテストがある」と自分で定義しているのに、S0 の
E5 / E6 / E7 に ✓ が付いていた。**見出しより前に局面行・指し手を置いたテストは
1本も無い。** (S0, E2) も「値を覚える」の側を見ていなかった。

## R-01 (MEDIUM, rust): キーが常に長さの 1.85 倍を確保していた → 修正済み `1c6ceb0`

`format!` は途中で `reserve` を呼ぶので容量が倍化する。76 字のキーが 138 バイト。
`BookKey` は定跡を開いている間ずっと保持されるので、**実物の定跡で 144 MB が
無駄に居座る。**

あわせて単価を測り直した。**どちらも上界になっていなかった。** 較正が1点だけで
取られていて、確保のピークが `HashMap` / `Vec` の拡張で鋸歯を描くことを吸収して
いなかった。拡張の直後で測ると 199.3 → 311.0 B/局面と倍近く違う。
280 → 330、150 → 160、展開の上限 6 GiB → 7 GiB（実メモリで見た閾値はほぼ不変）。

## R-02 (MEDIUM, rust): 不変条件2が偽 → 修正済み `52f78cf`

`+` / `*` / `0` / `win` が候補手の先頭＝best move に座る。3行の `.db` で再現。
`looks_like_a_move` の doc は正しく「形だけ」と書いていて、嘘なのは表の側。

**狭める方向では直さない。** 綴りの文法まで狭めると、こちらが知らない綴りを
使った定跡をファイルごと拒否することになり不変条件1と衝突する。本家が `win` を
書くかは未確認。通る側をテストで固定し、盤へ渡す側の検査は **#311** に出した。

## H-02 / H-03 (MEDIUM, robustness): `none` を「読めない欄」に数えていた → 修正済み `d8d153e`

**現行の ShogiHome は評価値・深さを省くとき `none` を書く**（空文字は v1.20.0 まで）。
実物 fixture `yaneuraou.db`（指し手19行）で「読めない欄 20件」。指し手より多い。
値は `None` になるので誤読みは起きず、壊れるのは診断の信号だけ。

一次資料の表も直した。あわせて **本家が連続空白を畳むこと**（`misc.cpp`）を足した。
こちらは畳まないので本家と一致しない。その事実が無いと、次に突き合わせた人が
`split_whitespace` へ戻せてしまう（R1 A-05 の退行）。

## H-04 (MEDIUM, robustness): 不変条件1の例外が7つ抜けていた → 修正済み `77c5314`

**本家は中身では一度も失敗しない**ので、「例外は見出しの検査だけ」は成り立って
いなかった。中身由来の拒否7つを、それぞれなぜ拒否側に倒すかと共に列挙した。

## A-02 (MEDIUM, architecture): 開く手順の後半が宣言に反して reader 側にあった → 修正済み `3a686b7`

`apery_bin.rs` を書く人が `reader.rs` の「枝を足す」だけに従うと、**前段の
大きさの検査を書き忘れても何も落ちない。** 上限を `match` で形式ごとに決めさせ、
検査は分岐より前に1回。reader がまだ無い形式は上限を持たない（大きさより先に
「対応していない」と言うのが正しい）。

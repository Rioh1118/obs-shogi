  掃除へ渡るのは `te` と真偽値1つだけだった。実物の分岐編集と実物の掃除を組んだ probe:

  赤い箱ごと消える。開き直すと空で、失ったことも画面に出ない。

  「その分岐点で本譜を辿っていて、本譜が差し替わった場合の `te` 以降」の2つだけ。

### [HIGH] R12-2 打ち直して元へ戻した本文が預かりに残り、開き直すと**利用者が消した本文がファイルへ書かれて「保存済み」と出る**（robustness）

- 場所: `KifuCommentNote.tsx` の `stash` と、開き直しで `kept.draft` を採る箇所
- 根拠: `stash` は「いま書こうとした本文」を無条件に預けるが、`save` は 900ms 前に
  固定した `text` を持っており、返ってくる頃に画面の本文は別物になりうる。
  **unmount は要らない。** 実物の `KifuCommentNote` と実物の預かりを使った probe:

  ```
  コメント欄が空の手に「打ち間違い」と打つ → 900ms → 保存が走る（返らない）
  気づいて全部消す（= baseText と同じ。dirty が落ちるので再保存は撃たれない）
  → 保存が Err で返る

  画面の本文 = 元の本文
  画面       = …保存できませんでした。書いた本文はこのまま残っています…
  預かり     = { draft: '打ち間違い', error: '…', told: true }

  閉じる（dirty が偽なので "failed" の枝を通らず、預かりは捨てられない）
  開き直す → エディタは「打ち間違い」で mount
  → 900ms → 書いた内容 = [["打ち間違い"]]
  ```

- なぜ問題か: 3つが同時に壊れる。
  1. **失敗を伝える箱が、画面に無い本文について語る。** 画面には元の本文が出ているのに
     「書いた本文はこのまま残っています」と出る
  2. **消したはずの本文が復活する。** 書き込めない棋譜で一度でも失敗すれば、閉じただけで残る
  3. **その本文が自動でファイルへ入る。** 開き直した 900ms 後に書き込まれ「保存済み」が出る

  「書いたけどやっぱり全部消す」は、コメントの無い手では `draft === baseText === ""` に
  なるので、**特別な操作ではなく普通の使い方で踏む**。

- 直し方: 預けるのは常に**いま画面にある本文**。元へ戻していたら預からない。
  R11-3 が unmount 側にだけ入れた「置き場にあるより新しい本文を残す」を、
  生きている側にも同じ形で適用する。
- 導入コミットの sha: 失敗した本文を預ける形は `18be853`、開き直しで出す形にしたのは `40424f4`。
  `94cc2f1` は unmount 側（`aliveRef`）だけを塞いだ
- 主張を固定するテスト名: `KifuCommentNote.test.tsx`
  「打ち直して元へ戻したら、消した本文を預からない」（変異で確認）

## 確認して問題が無かったもの

- **`restoreCursor` の判定は、`edit` の2つの呼び出し元に対して正しい。**
  `makeMove` は必ずポインタが動き `true`、コメントは `forceCommit` で通るが動かないので `false`。
  `grep` で `edit(` の呼び出しは2つだけ。**「戻すべきなのに戻さない」経路は無い**
- **`restoreCursor: false` で `cursor` が無効にならない。** コメントの書き込みは
  木の形を変えない（`comments` しか触らない）ので、戻した棋譜の中でも同じ経路が解決できる。
  ただし**その前提はコードにも型にも書かれていなかった**ので、`types.ts` に書き足した
- **分岐を触っている間、ノートは必ず閉じている**（3つの入口が `setOpenComment(null)` を撃つ）。
  掃除が「いま開いている面の下書き」を画面の下で消す形にはならない
- **鍵に「計画」が混じることは無い**（`normalizeForkPointers(picked, te)` を通るので
  `te <= tesuu` しか入らない）
- **`aliveRef` の「落としすぎ」は StrictMode 以外に無い**（`open=false` や
  `editing = null` では触らない）
- **`dropUnsavedDraftsFor` の `res.success` の門番は空振りしない**
  （`swapBranchesInKifu` が `changed: false` を返すのは `a === b` のときだけで、
  UI は `neighborBranchIndex` で ±1 しか作らない）
- **`makeMove` が掃除を呼ばないのは正しい**（`applyMoveWithBranch` は末尾に足すだけ）
- **`main.tsx` に `StrictMode` は無い**ので、R12-5 は製品では踏まない
- **新しい2本のテスト（r11 で足したもの）はどちらも効いている**（変異で確認）
- **この差分に新しいセキュリティの口は無い。** `npm audit` は 0 件

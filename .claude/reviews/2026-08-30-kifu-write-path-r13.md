## 確認して問題が無かったもの

- **`aliveRef` と同じ形の ref は他に残っていない。** `KifuCommentNote.tsx` の ref は7つ。
  cleanup で落として setup で戻さない旗は `aliveRef` だけで `e430b8b` で直っている。
  `faceRef` / `leavingRef` は毎レンダ走る効果の**本体**で書くので StrictMode でも戻る。
  `grep -rn "\.current = false" src/` でも同型は無い
- **StrictMode を通しても壊れない**（実測）。二重保存・二重預けは起きず、
  R12-5 の「赤い箱が空・保存済みが出ない」は再現しない
- **Lexical は mount 時に `onMarkdownChange` を撃たない。** 本物の `LiveMarkdownNote` を
  happy-dom で mount して6通り実測、すべて `calls: 0`。`OnChangePlugin` が
  初期投入の `history-merge` を落としている。**「開いただけで markdown が正規化されて
  900ms 後に書き込まれる」形は無い** — r11 / r12 が保留した Lexical の1点を潰した
- **`key` と `initialMarkdown` は同じコミットで揃っている**（1つの state から出ている）
- **レンダ中の `setEditing` に副作用は無い**（`getUnsavedDraft` は読むだけ、
  `face` は `useMemo` で同一参照なので1回で収束）
- **`makeMove` が掃除を呼ばないのは正しい**（`applyMoveWithBranch` は末尾に足すだけ）。
  番号を振り直す経路は入れ替えと削除の2つだけで、両方とも掃除を呼んでいる
- **掃除へ渡す `state.loadedAbsPath` は `await` を越えて古くてよい。**
  消すべき預かりは「編集したファイルのもの」なので、`loadedAbsPathRef.current` を
  渡すほうが誤り。同じ関数の中で使い分けているのは意図どおり
- **index を `key` にしている箇所はこの差分に無い**（行は `key={r.te}`）
- **`write_started` / `write_ended` の `blocking: false` が同一参照を返す**ので、
  コメントの自動保存で `useGame()` の消費者が余分に描き直されることはない
- **`edit` の3つの早期 return はすべて `try` の中**にあるので、
  `write_started` と `write_ended` の対が割れる経路は無い
- **`npm audit` は 0 件。** この差分に `dangerouslySetInnerHTML` /
  `shell.open` 相当 / 新しい `as` キャスト（テスト以外）は無い

## 検証の道具についての注意

`vp test` は**ソースを書き換えた直後の1回目に古い transform を使うことがある**。
変異を当てて「緑のまま」に見えたら `node_modules/.vite/vitest` を消してから再実行して
確定させること。r12 に続いてこのラウンドでも踏んだ。

`npm run test -- run <path>` を使う（`npx vitest` は別の vitest を拾って落ちる）。
パスを付けずに `-- run` だけ渡すと「run」が filter として扱われ、1本も走らずに
成功したように見える。**全部走らせるなら `npm run test` を引数無しで。**

## 実害

### R14-H1 喋り続けるエンジンに上限が1つも残っていない（rust HIGH / **自分が作った退行**）

r13 で沈通条件を **and** で足したので、`info` を出し続けながら `bestmove` を
返さないエンジンに上限が無くなった。`Phase::Thinking` を終わらせる口は
`on_tick` の2つだけで、片方は `enforce_engine_timeout`（既定 false）で塞がり、
もう片方が沈黙を要求する。`run_search` にも締切は無い。

詰み探索のループ、`btime 0` で終わらない実装、`info string` を出しながら
固まった実装——どれでも踏む。フロントには読み筋だけが流れ続け、
`over` も `moveDecided` も来ず、ログにも1行も出ない。
**利用者が中断を押すまで対局が終わらない。**

「持ち時間切れの30秒後に必ず負ける」を、**上限を消して**直していた。
この repo で6回出ている「片方を塞いで反対側を開ける」形。

### R14-H2 表の E18 が r13 以前の条件のまま（両 reviewer が指摘）

`stalled_turn` に条件が増えたのに、表の3箇所（`:89` の定義 / `:122` のセル /
※12）とも「持ち時間＋`SEARCH_GRACE`」だけを書いている。
`(G0, E18)` は「→ G2」と**無条件の遷移**として書かれているが、
喋り続けるエンジンでは発火しない。

**表がいま、R14-H1 の退行を正しい姿として記述している。**

### R14-H3 ※8 が「`info` は2箇所で落ちる」と書くが、片方は r13 で消えている（state-table HIGH）

落とす場所は `on_search_info` の `is_to_move` **1本しかない**。
この注を信じて `search.rs` に間引きを書き戻すと R13-H2 がそのまま再発し、
逆に「`search.rs` が落としているのだから」と `is_to_move` を冗長と読んで消すと、
相手の手番中の先読みが画面に出る。**いま現物を守っているのはその1行だけ。**

### R14-H4 `last_progress` の doc が「動かす口は `begin_turn` の1つ」と断言（rust HIGH / 自分が書いた）

`on_search_info` も動かす。**しかもそれが R13-H1 の修正の本体。**
消すと沈黙条件が意味を失い、r13 が直した症状に戻る。

### R14-H5 「`TurnChanged` は `running: null` で飛ぶ／3 は毎手通る」が偽（state-table HIGH）

`Handover::StartNow` と `PonderHit` は emit より**前に** `begin_turn()` を通るので
`running: Some(...)` が載る。`null` になるのは先読みが外れたときだけで、
`ponder` の既定は false なので**既定設定では一度も起きない**。

境界の型（`rust-types.ts`）はさらに強く「3 は毎手通る」と書いている。
この記述に従って受け手を作ると、毎手 `running` を捨てて次の `ClockUpdated`
（最短500ms）まで期限を持たないコードになる——doc が避けようとした
「相手の手番の頭で毎回止まって見える」を、doc のとおりに作ると起こす。

  `Runner` を直に組んで `req` をずらせば1関数呼び出しで踏める。
  同じ表の2行上が同じ手法を「踏める」と書いている

  人対人の対局でエンジンに `gameover` が永久に届かない

  解析側（エンジン→GUI）で向きも形も違う。r13 が「同じ綴りのバリアントを止める検査」を

  スライスの公開 API を素通りするしかない

  `protocol.rs` は**まさにこの理由で** `kill` と書き込みを `spawn_blocking` に
  逃がしてあるのに、同じ根拠がここには適用されていない。
  `canonicalize` と `UsiEngineHandler::spawn` には上限も無い

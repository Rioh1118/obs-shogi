平均91.5個）と矛盾する数を、その報告書を書いた直後に推論で書いた**。
規律を「気をつける」の形で書いたのが誤りで、気をつけることでは直らない。

**機構を変える。r3 以降、doc について次を守る。**

1. **他のモジュールの振る舞いを断定する散文を新しく書かない。**
   代わりに**そこを指す**（`実装は X を見ること`）。指せば、腐っても指し先を読めば分かる。
   断定すると、腐ったときに読み手が2つの主張のどちらが正しいかを判断できない
2. **数を書くなら、式か実測値の出典を併記する。** `2,536` は式で書いてあるので生き残った。
   `1/256` は根拠が無かったので死んだ
3. **「〜だけ」「必ず」「常に」を書くときは、反例を1つ探してから書く。**
   R2-5 は「だけ」を2回間違えた
4. **修正で doc を書き足すより、間違っている文を削る方を先に選ぶ。**
   情報量は減るが、嘘は増えない

**この4つは r3 の焦点であり、私自身への焦点。**

なお**所見の質そのものは高い**（4人が独立に同じ4件へ収束し、うち3件は実測付き）。
reviewer 側を疑う理由は無い。

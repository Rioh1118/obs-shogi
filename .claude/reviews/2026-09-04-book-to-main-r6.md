## 所見

### W-01 (HIGH, 2人が独立に再現): 新規ファイルだけのコミットが、検証0本で通る

ゲートが見るのは追跡済みの変更だけ（`git status --porcelain -z --untracked-files=no`）。
**PreToolUse は `git add` が走る前に判定する**ので、`git add -A && git commit` を
1呼び出しで打つと、追加するファイルがすべて新規なら**ツリーは空に見える。**

こちらでも再現した。

```
$ echo x > new.rs
$ git status --porcelain -z --untracked-files=no | wc -c
0
```

reviewer の実測: untracked の `.ts` ＋ `git add -A && git commit` → **exit 0、1秒**。
同じファイルを `git add` 済みにすると 15秒（`npm run verify` が走る）。

**当たり方が最悪。** 表の登録漏れを見る検査が落ちうる唯一の場面は表を新規追加したときで、
それはまさに untracked。`docs/state-transitions/*.md` を `rust` に分類する根拠にした検査が、
その根拠が要る場面で走らない。

- 結果: **ゲート自身は触らず、#342 へ送った**（検査の強化はこの PR から降ろす方針）。
  `CLAUDE.md` が「素通しするのは A か B」と**網羅を名乗っていた**方は直した（W-02 と同じコミット）

### W-02 (MEDIUM, 2人): 素通しの動詞を3つしか挙げていない

`git merge` / `git rebase` / `git cherry-pick` の3つだけを挙げたが、ゲートの語彙
（`GATE_COMMIT_VERB_BASE`）は `revert` / `am` / `pull` も含む。**`git revert` は `.rs` を
丸ごと巻き戻すコミットを作る**のに、指示が「**合流の**後は手で通すこと」なので発火しない。

同じ節の3行下で「対応は `gate_kinds_for_path` が唯一の出典。ここに写さない」と決めているのに、
動詞の一覧だけは（しかも部分的に）写していた。

- 結果: 対応済み `4b29d70c`（経路を書き足し、指示を「それらの後は」へ）

### W-03 (MEDIUM, 3人): hook が走らせるものを「整形」とだけ書き、止まった人の行き先が無い

3件が1文に入っていた。

- **`vp check` は整形だけではない**（help は "Run format, lint, and type checks"）。
  `--fix` は直せるものを書き換えるので、「整形だけ」と読んだ人は自分のコードが
  書き換わることを想定しない
- **lint で落ちるとコミットは作られない。** 上向き import や JSX 内の全角スペースで
  止まった人は「整形が壊れた」と読み、再現手段も規則の置き場も書いていないので**行き止まる**
- **「自動的に走るのは…だけ」に主語が無い。** Claude Code で作業する人にはゲートが走るので、
  `CLAUDE.md` と正面から食い違う（r5 の V-02 が直した向きに、今度は振り切れていた）

- 結果: 対応済み `1810894e`

### W-04 (MEDIUM, 3人): 「替えるなら」の列挙が、行き先も借用の壁もテストの実態も落としている

1つの段落に6件。

- **どちらへ揃えるかが書いていない。** 2つの枝を対等に並べたので、実装が楽な側
  （どちらも最後の出現位置）へ揃えられる。それは2枝としては一致するが**本家とは一致しない**
- **`HashSet` の枝を要求どおりにする道が無い。** 自然な実装は `seen` が `moves` を
  借りているので **E0502** で止まる（reviewer が再現）。途中で止まると走査の枝だけ後勝ちになり、
  同じ箇条書きが警告している境界の不一致そのものになる
- **「いまその形のテストは無く」が偽。** `a_position_with_very_many_moves_is_still_deduped` が
  その形。無いのは「どちらの重複が残ったか」を見るテスト
- **「2本」「3つ」の件数**（`CLAUDE.md` が「件数をここに書かない」と決めている形）
- **「順位付けに載る」の順位付けが、このリポジトリのどこにも無い。**
  `count` で並べ替える箇所は1つも無い
- **一次資料の表の2行が列挙から落ちている。** 従った人は表の「こちらは先勝ち」を残す

加えて `[`SCAN_LIMIT`]` は関数本体の中の `const` なので **rustdoc が解決できない**
（`cargo doc` で確認。`verify:rust` は rustdoc の lint を走らせないので緑のまま通る）。

- 結果: 対応済み `a576dabf`

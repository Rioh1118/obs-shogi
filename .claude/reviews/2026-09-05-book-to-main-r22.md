## 所見

### AN-04 (HIGH, 1人が実測): 下限が `#[test]` だけを数えていて、非同期のテストが外にある

合流前は綴りが1つだったので手書きで足りていた。**合流でそれが偽になった。**
`#[tokio::test]` が 60 本入り（`session.rs` に 49）、`EXPECTED_MIN` を 393 へ上げたときも
その 60 本は数えていなかった —— **消してもラチェットが緑のまま通る状態。**

しかも同じ `tests/` の中の `scanning/mod.rs` が、この穴をそのまま文章にしている ——
「**属性の綴りで絞ると片方が丸ごと死角になる。** …`#[test]` だけを見る走査は
`session.rs` を1本も読まないまま緑になる」。

- 結果: 対応済み `017bcec9`（`scanning::is_test_attribute` に一本化、下限を実測の 453 へ。
  **変異を当てて落ちることを確認した**）

### AN-01 (HIGH, 2人): 門番自身を触ったコミットで、判定表の識別子の検査が走らない

向こうは `.claude/hooks/*` を `needs_ts=1` にし、理由も書いていた。**合流でこちらの `gate`
だけを採り、`ts` を落とした。** しかも同じ合流で `docsIdentifiers` が
`.claude/hooks/*.sh` を走査対象へ足しているので、シェルは今や `npm run verify` の入力。

門番だけを触るコミットで関数を改名し、検査側も同じコミットで直すと、**`gate` しか
選ばれないので緑で通り、判定表が実在しない関数名を指したまま入る。**
`gate_flatten` / `gate_strip_quotes` / `run_gate` は検査側に一度も現れないので、経路は実際に開いている。

- 結果: 対応済み `5596cf14`

### AN-02 (HIGH, 1人が実測): 版を固定した文書での免除が、綴りの形で判定していて自リポジトリまで通す

判定に `tracked` を流用していた。あれは「実在を要求してよい**形**か」を見る別の関門で、
`existsSync` を1度も引かない。実測 —— 版宣言のある文書では
`AnalysisPaneHeader:84` / `optional_number:42` / `README.md#L10` / `vite.config.ts:88` が
全て素通しになっていた。

**`AnalysisPaneHeader:84` は `docsSourcePaths.test.ts` が「拾う」と名指しで固定している形**で、
向こうが止めたかったものの中心。免除は文書全体に掛かるので、上流の版を書いた1行があるだけで
自リポジトリの参照まで入る。

- 結果: 対応済み `5d6b2ca0`（実在で決める形へ。裸の識別子は上流でも免除しない ——
  そちらは `docsIdentifiers` が追える側で、逃げ道が実在する）

### AN-03 (MEDIUM, 1人): シェルを走査に足したのに、コメントの落とし方が言語に追随していない

`codeOf` が落とすのは `//` だけで、**シェルの `#` は1つも落ちない。**
検査が自分で書いている「コメントを落としてから数える」の保証が、シェルに対してだけ空文だった。
`verify-gate.test.sh` が**検査したい名前を文字列リテラルで持つ**問題も同じ根。

**シェルの枝を固定するテストが1本も無かった**（2通りの変異を当てて両方緑だった）。

- 結果: 対応済み `c3555a9b`（`codeOf` に言語の枝。`#` を落とし `//` は落とさない。
  引用符の中も落とすが**定義は残る**。テストを4本足し、両方の変異で落ちることを確認）

### AN-05 / AN-06 (MEDIUM, 1人): 表の登録が2ファイルを落とし、規則が禁じている選び方になっている

合流で `game-session.md` を登録したとき、**いまの定数がどのファイルにあるかで選んだ。**
このファイル自身がそれを禁じている。落ちていた `clock.rs` / `events.rs` には
`GameClocks` / `has_expired` / `RecordedEvents` / `GameEventSink` しか無い。
**`CLOCK_EMIT_INTERVAL` を本来の置き場へ移した瞬間に落ち、読んだ人は正しい表の行を消す。**

併せて `RESULT_FLUSH_MS` の挿入位置が `DEPTH_NONE` を巻き込み、
ShogiHome の識別子が「このリポジトリの TS 側」の説明の下に来ていた（AN-06）。

- 結果: 対応済み `da55f87c`（セル記号の規則にテストも足し、**2通りの変異で落ちることを確認**）

### AN-07 (MEDIUM, 1人): 合流で `G` の記号が2つの表で衝突した

`book-key-failures.md` の `G0`（入力の長さ超過）と、合流で入った `game-session.md` の
`G0`（`Phase::Thinking`）。**これは `failure-surfacing.md` の採番の宣言が `F` について

- 結果: 対応済み `7b3e7271`（記号を振り直すと既存の参照が全部動くので、採番の出典に事実を書く方を採った）

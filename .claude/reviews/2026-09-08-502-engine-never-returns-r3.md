## 所見

### HIGH-1 `deletePreset` の畳み込みで、保存が落ちた回が「完全な成功」と見分けが付かなくなった（robustness）

**r2 の修正が作った退行。** `persist` は再 throw するが、呼び手（`EngineTab` の `onDelete`）は
catch していない。畳んだことで、`save_presets` が `Err` を返した回でも画面は

1. 消したカードが一覧から消え
2. 代わりのカードに「適用中」が付き
3. エンジンが起こし直されて解析が読み直される

——**成功と1ドットも違わない。** ディスクは元のまま、`last_preset_id` も元のまま
（`setLastPresetId` は `await persist` の後ろなので走らない）。次回起動で
`chooseInitialSelectedId` が消したはずのプリセットを選び直すので、**削除も切り替えも
無かったことになる。**

**畳む前は壊れたことが画面に出ていた**（選択が消した id を指したままなので
「適用中」がどのカードにも付かず、解析も断たれた）。畳んだぶんだけ失敗が静かになった。

決定的に踏める形も在る——`engine_presets.json` の1件でも `id` が空文字なら、
`createDefaultPreset` の `partial.id ?? genPresetId()` が空を拾わないまま通し、
Rust 側の `ensure_non_empty("id")` で**以後すべての保存が永久に `Err`**。
追加・複製・編集・削除の全部が「画面上は成功、ディスクは不変」になる。

### HIGH-2 `no-engine` の断りが、▶ 側だけ古い広さのまま（architecture / react / robustness / comment の4本）

r2 の MEDIUM-6 は `WHILE_ANALYZING` 側だけを広げ、`ON_START_REFUSALS["no-engine"]` は
「エンジンをまだ選んでいない」のまま残った。**踏むのはこちらの方が多い**——
`provider.tsx` 自身が「ここはいちばん踏まれる枝」と書いている ▶ の前置きの門。

踏む筋: 設定 → 追加（`createDefaultPreset` は必須欄が空）→ そのカードを押す →
▶ を押す → 「設定でエンジンを選んでください」。**利用者はいま選んだ直後**なので、
指示どおり選び直しても何度でも同じ文が返る。行き止まり。

さらに TSDoc「エンジンをまだ選んでいない」は、同じ PR が `types.ts` に書いた
「**選んでいないとは限らない**」と正面から食い違う（腐ったコメント）。

### MEDIUM-3 `no-engine` の入口は3つなのに、doc 3箇所が2つしか挙げていない（robustness）

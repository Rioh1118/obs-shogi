# ラウンド5 — `search` の欠陥（ラウンド4の修正をレビューした）

対象は `review/388-on-429-all`。観点は rust / robustness / comment。
**レビュアーは各自の worktree で走らせた**（R3・R4 で変異が私の作業ツリーに
残る事故が2回続いたため）。

## このラウンドの共通の原因

**「運ぶ」ところで止まって、「覚える」まで行っていなかった。**

R4 は `indexed_ok` を `IndexAnnouncement::Built` で運ぶようにした。だが運ぶのは
**その回に数えた値**なので、差分適用の経路は自分が触れた分しか知らない。
結果 `Rescanned` の腕は `live_len` で埋めるしかなく、**再走査1回で
「一部を索引に入れられていません」が緑の「準備完了」に戻る**。

しかも復元経路は必ず再走査を通るので、**開き直すと以後一度も出ない**。
R4 が「直した」と書いた状態が、いちばん普通の経路で復活していた。

同じ形が3人から別々に出た。robustness は画面の組み合わせ表から、
rust は変異から、comment は doc の裏取りから、同じ1点に着いた。

## 自分が作った退行

**`git checkout -- <file>` でまた作業を消した。** R3 で1度やって報告書に
書いたのに、変異を戻すときに同じことをした。今回は `build.rs` の
`indexed: ok` と `Built` の変更が丸ごと HEAD へ戻り、次のビルドで
コンパイルが落ちて気付いた。

**変異の復元は必ずコピーから。** `git checkout` は「変異だけ」を戻す道具ではない。
2回同じ失敗をしたので、これは**ルールではなく手順**として書く——
変異を当てる前に `cp <file> /tmp/x.bak`、戻すときは `cp /tmp/x.bak <file>`。

### 3人が独立に同じ結論へ着いた

**ラウンド28で入れた「1間隔の予算」は死んでいる。**

- rust が実測: 6操作 × 未知ID 200個を4秒回して `spent` の最大は **30**。上限は48で、
  **近づきもしない**。枝を丸ごと削除しても全13スイート green
- しかも `the_limits_are_derived_from_the_log_budget` の表明2（`48 >= 24 + 8`）が
  **到達不能を能動的に強制している**
- 台帳 F-28 と doc 3箇所が、その予算を「連打を止めている側」として説明している

さらに、**予算と枠の順序を入れ替えた変更も、現在の定数の下では実行時に何も変えない**
（rust が変異で確認: 順序を戻しても全13スイート green）。ラウンド28は2つの変更を
1本のコミットで入れたが、効いていたのは定数だけだった。

**予算の一段を落とす。** 一次の上限は枠の数で、予算はそれを覆い隠していただけ。

## 予算の機構が死んでいる

### R29-H1 `MAX_LINES_PER_INTERVAL` の枝は構造上到達できず、`window` / `spent` の一段が丸ごと死んでいる

`src-tauri/src/engine/commands/game.rs:171-174` / `:193-214` / `:276-279`。

rust の実測:

```
PROBE max_spent=30 calls=1274018 limit=48
```

構造で決まる。1つの窓の中で、既存の枠は1つあたり1回しか通せず、
枠を落とせるのは「最後に通したのがその窓より前」の枠だけなので、
**落として作り直した枠の通過は、落とされた枠の通過と排他**。
したがって通過は最大 `MAX_TRACKED_GAMES + 操作の数` = 30。

`log_rejection` の「拾えないもの」に挙がっている「予算を使い切った後に来た断り」は
**起こりえない事象**。読んだ人は存在しない死角を警戒する。

### R29-H2 逆算のテストが、実際に出る行数に一度も掛かっていない

`src-tauri/src/engine/commands/game.rs:448-472`。

2つの表明が縛るのは `MAX_LINES_PER_INTERVAL <= 100` と
`MAX_TRACKED_GAMES <= MAX_LINES_PER_INTERVAL - 8` だけ。
**一次の上限は 92 まで通る。**

rust の変異: `MAX_TRACKED_GAMES = 90` / `MAX_LINES_PER_INTERVAL = 98` で**全13スイート green**。
実際の流量は 96 行/秒、1行170バイトで 16KB/秒——`LOG_FILE_BUDGET` は**12秒で一周**する。
R27-H2 が「121行/秒で10秒前後」と書いて塞いだ形と同じ桁。

doc は「片方だけ動かすと逆算の根拠が静かに崩れる。式で持って、動かした人に
数え直させる」と書いているが、**数え直させる相手が一次の上限ではない**。

### R29-H5 `the_frames_actually_fill_up` が、名指ししている当の回帰を検出しない

`src-tauri/src/engine/commands/game.rs:474-489`。

テストの doc は「予算を鍵の判定より手前に置いていたとき…」と書いていて、
**その順序を戻す変更を落とすため**に置かれている。落とせない。

rust の変異（順序をラウンド28以前へ戻す）で**全13スイート green**。
`flood` は24回しか回さず予算は48なので、順序を戻しても24枠すべてが挿さる。

### R29-M7 同じ量に2つの数字が、同じモジュールの中で並んでいる

- 1行のバイト数: 式は `APPROX_LINE = 200`、散文は「約170バイト」
- 操作の数: 定数の doc は「操作は6つ」、テストは `OPS_HEADROOM = 8`
  （doc は「`per_op` の枠がこれだけ上乗せされる」だが、上乗せされるのは6）

### R29-M8 `MAX_TRACKED_GAMES` の 24 が、2通りの出どころで書かれている

定数の doc は「実際に同時に見たい対局の数に見合うところで止める」＝運用で決めた数。
テストと `LOG_FILE_BUDGET` の doc は「どちらも `LOG_FILE_BUDGET` から逆算した値」。

24 を上げたい人は、上げてよい数なのか予算から決まる数なのかを判断できない。

### R29-M5 doc 3箇所が、過去の構成とそのときの実測を語っている

- `allow` の doc「枠が120**あった時点**の実測で121行/秒」
- `a_sustained_flood_stays_within_the_log_budget` の doc「この上限を外した実測で121行/秒。
  …`LOG_FILE_BUDGET` の `KeepOne` は10秒前後で一周する」
- `the_frames_actually_fill_up` の doc「置いていたときは…全部緑で通った」

いまの定数では上限を外しても25行/秒で、一周は47秒前後。
**数字が古いだけでなく、因果そのものが現在の構成で成り立たない。**

### R29-H4（台帳） F-28 が `MAX_LINES_PER_INTERVAL` を「連打を止める側」として説明している

`docs/state-transitions/failure-surfacing.md:100`。`MAX_TRACKED_GAMES` の名を1度も出さない。

読んだ人は「ログが多いのは予算が緩いから」と判断して予算を締める——それは
現物の doc が名指しで禁じている改変で、ラウンド26〜28が4回かけて塞いだ形へ戻る。

## `detail` の扱い

### R29-H3 `MAX_DETAIL_LEN` は裁定そのものを断るので、`MAX_PLIES` が名指しで避けた形を作る

`src-tauri/src/engine/game/session.rs:997-1020`。

同じファイルの `MAX_PLIES` の doc:

> 裁定で超えたら**終局にする**。断ると、フロントは一意に固定された列しか返せないので
> やり直しても同じ `Err` になり、`RULING_TIMEOUT` 後に「アプリが裁定を返さなかった」で
> 畳まれる——**返しているのに「返さなかった」と棋譜に残る。**

`end_by_rule` は詰み・千日手・持将棋・反則の結末を記録できる**唯一の口**。
`detail` が上限を超えると裁定は丸ごと拒否され、呼び直さなければ30秒後に
`Aborted { winner: None }` で畳まれる——**「先手の勝ち・詰み」が「中断・勝者なし」に化ける。**

`MAX_DETAIL_LEN` は `pub` ですらないので TS 側は上限を知りようがない。

**入口で切り詰めれば、3つの吸い口（ログ・`Over`・`snapshot`）が同時に収まる。**
裁定を拒否する必要はどこにもない。

### R29-H4 `MAX_DETAIL_LEN` に式が1本も無い。190,000 に戻しても全部緑

rust の変異: `const MAX_DETAIL_LEN: usize = 190_000;` で**全13スイート green**。
`endGameByRule(id, null, "x".repeat(189_999))` の1回で `finish` の1行が約190KB になり、
R28-H1 の失敗がそのまま戻る。

隣の2つには（不十分ながら）式があるのに、**同じ根拠から出たこれには1本も無い。**

### R29-M6 doc の「1行が予算の1/100を超えない」が、この定数が想定している入力で3倍外れる

`finish` は `detail={:?}` で出す。`Debug` は制御文字を `\u{7f}` の形（1バイト→6バイト）へ
展開する。rust の実測:

```
detail_len=1024  →  1行 6,209 バイト
```

`LOG_FILE_BUDGET / 100 = 2,000` に対して**約3.1倍**。`"` だけの1024バイトでも超える。

`shown()`（制御文字を `\u{fffd}` へ潰す既存の関数）を通せば1バイト→3バイトに収まる。

`src-tauri/tests/comment_identifiers.rs:264-285`。次の非空行が `///` なら読み飛ばすが、

### R29-M3 `obs-shogi-spec.md` に「200KB」の写しが残っている

### R29-M4 `abort` だけが、終局済みの対局に対して何もせず `Ok` を返す

`src-tauri/src/engine/game/session.rs:847-857`。`accept_rule_end` / `accept_resign` は
`Err("game is already over")` を返す。

利用者が「中断」を押したのと `on_tick` の `over { timeout }` が同じ拍に入ると、
`abort_game` は何もせず `Ok`。呼び出し側が「中断が成立した」と読んで棋譜へ書けば、
Rust 側の結末と食い違う。`Err` を返していないので `log_rejection` も1行も残さない。

`abort_within_budget` は結果を捨てるので、コマンド側だけ揃えても壊れない。

### R29-M9 `finish` に、`detail` の長さを呼び出し側が保証していることと、`{:?}` の理由が無い

`self.finish(` の呼び出しは14箇所あるのに、検査は `accept_rule_end` にしかない。

### 落としたもの

**`MAX_LINES_PER_INTERVAL` / `window` / `spent`。** 一次の上限は枠の数で、
予算はそれを覆い隠していただけ。到達しない枝と、その到達不能を強制する表明と、
役割を逆に説明した doc 3箇所が同時に消えた。

ラウンド28で入れた「予算と枠の順序」も、現在の定数の下では実行時に何も
変えなかった（rust が変異で確認）。順序の議論ごと無くなった。

### 基準を言い直した

「1間隔で予算の1/10」だと**10間隔で一周してよい**ことになる。
守れるのは履歴ではなく**時間**なので、「断りが出続けても30間隔ぶんは残る」を
式にした。これで枠90（12秒で一周）は落ちる。

### 操作の数の数え方

手で書くと口を1つ足したときに数え直されないので、**`include_str!` で
このファイルから数える**。引数を折り返した口が3つあるので、`(` の直後だけを
見ると落ちる——そこも変異で確認した。

### 変異試験

すべて baseline 差分。

- 枠を90／120へ戻す、改行を跨ぐ呼び出しを数えない
- `MAX_DETAIL_LEN` を 190,000 へ戻す、切り詰めをやめて素通しにする
- doc と `use` の間に属性／空行を挟む
- `abort` を `Ok` に戻す

改名（`the_lines_per_interval_fit_the_log_budget` → …）は
`comment_identifiers` が拾った。

無し。

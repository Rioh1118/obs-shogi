# ラウンド6 — `search` の欠陥（ラウンド5の修正をレビューした）

対象は `review/388-on-429-all`。観点は rust / robustness / comment。
3人とも各自の worktree で走らせた。

## このラウンドの共通の原因

**`Ok` を「成功した」と読んでいた。**

R5 は「組めた数」を索引に覚えさせた。だが覚える値の元が
**`build_file_index` が `Ok` を返したか**で、`NothingToIndex` も
`Ok(FileBuild::empty(..))` で返る——**局面を1つも持たない棋譜が
「索引済み」に数えられる**。R5 が直したはずの症状が、この族については
そのまま残っていた。

rust-reviewer は実際の CSA（`V2.2\nPI\n+\nZZZZ not a kifu line\n...`）を
組んで測り、「`Ok` で返って局面0件」を出してみせた。

## レビュアーが確かめてくれたこと

- **`indexed_len` の全走査は問題にならない。** 実測で5万件 32.7µs/call、
  `EMIT_INTERVAL`（100ms）に2本で**1コアの 0.06%**。ロックの外で回る
- **`CACHE_VERSION` 4 は意図どおり。** `min_bytes::FILE_ENTRY` 13→14 は
  `encode_all` が書く最小とちょうど一致し、正当な blob を弾かない
- **`indexed` の載せ忘れは無い。** `FileEntry` に `Default` が無いので
  コンパイラが全構築サイトを止める。墓標の後も畳んだ後も正しい
- **R5 の表8行のうち7行は本当に落ちた。** 落ちなかったのは別名の1行だけ

## 自分が作った退行

**doc の直下に関数を挿し込んで doc を剥がした。** `///` は次の item に黙って
付くので、rustdoc も `cargo fmt` も何も言わない。しかも剥がれた先の doc は
**その helper の作り方を禁じる内容**だった。

**同じ形の間違いを2つ重ねた。** doc に「ここで見ない」と書いた後に、
そこへ assert を足した。書いた本人が忘れる。

## ラチェットが空振りする

### R25-H1 テスト列を**位置**で採っているので、表に列を1本足すと突き合わせ3本が黙って空振りする

`src-tauri/tests/state_transition_cells.rs:195`。`cells[cells.len() - 1]` を読み、

| ----------------------------------------- | ----------------------------------------------------------- |

| 上に加えて、表の全行に「備考」列を1本足す | **11 passed で緑**                                          |

## 絞りが、絞ると宣言した相手に効いていない

### R25-H2 溢れが続くと、絞りは1行も落とさない

`src-tauri/src/engine/commands/game.rs:132-137`（doc）と `:177-189`（実装）。

`LogThrottle::new` は `last = now - interval` を置くので、**新しく作った枠の
最初の `allow()` は必ず `true`**。溢れたときの `clear()` は、次の呼び出しをまた
「新しい鍵」に戻すだけ。

筋道: `game_id` を毎回変えて `submit_game_move` を撃つ → 枠が埋まった後は
呼び出しのたびに `clear()` → 1件挿す → `allow()` は必ず真 → `warn` が1行。
**絞りが1件も掛からない状態で、呼び出しと同じ頻度でログが書かれる。**
`Display` が48文字に切るので1行は約130バイト、200KB は1600回ほどで一周する。

doc は「捨てた直後は各枠の先頭が1行余分に出るだけで、絞りの目的
（ログの予算を守る）は崩れない」と書いている。**溢れが1回きりならそのとおりだが、
継続する場合は成り立たない。** しかも `clear()` はその瞬間に**実際に走っている対局**の
枠も巻き添えにする。

`MAX_TRACKED_GAMES` の doc は「枠を持てる**対局**の数」と書いているが、鍵は
`(op, GameId)` で `op` は6つ。実際に枠を持てるのは最悪で10局。

さらに鍵に入るのは `GameId` の**生の値**で、長さは `GameId::new` でも入口でも見ていない。
R24-M7 が抑えたのは `Display` だけなので、**静的な写像が無検証の文字列を保持する経路が
同じラウンドの別コミットで新設された**形。`GameId` は webview から来る値のうち
**唯一長さを見ていないもの**でもある（`start_sfen` と `setoption` は `MAX_WIRE_FIELD`、
指し手は8バイト、手数は `MAX_PLIES`、option 件数は `MAX_OPTIONS`）。

### R25-H3 `close_game` はログ行を2本書き、絞りが掛かるのは片方だけ

`src-tauri/src/engine/game/manager.rs:159-163` の
`close: session still borrowed, kept in the ledger` が無条件。

筋道: `ponderhit` の書き込みが詰まって `continue_game` が `Arc<GameSession>` を
握ったままになる → 利用者が閉じる → `Busy` → 案内どおり呼び直す →
2回目以降は対局が既に `Phase::Over` なので `abort_within_budget` が即返り、
1反復がミリ秒で回る → **F-26 の `error` も F-19 の `error` も数秒で消える。**

`closeGame` の doc の「Rust 側は `(操作, 対局)` ごとに1秒で絞って**ログを守っている**」も
現物と食い違う。

## ラウンド24で直した先が、doc と連動していない

### R25-H4 `engine_layering.rs` の中で、機構の説明が2箇所で正反対

モジュール doc（`:15-18`「## 走査の限界」）は「拾うのは `use` の行だけ。関数の中で
完全修飾に書けば素通りするが、**それは `use` を書くより目立つ**ので走査を厚くするより
読み手に任せる」。`Layer::forbids` の欄 doc（`:52`）は「**`use` してはいけない**外部クレート」。

実装（`:596-599`）は本文の綴りを見る。同じ関数の doc（`:575-578`）と ADR-0008（`:64-66`）は
「`use` の行だけでは足りない…だから本文も見る」。

**赤を見た人が最初に開くのが「## 走査の限界」。** そこに「完全修飾は素通りするはず」と
書いてあるので**走査の誤検出だと診断**し、`code.contains` を `use_statements` を回す形へ
戻す。R24-H3 で塞いだ穴に、doc が戻し方の根拠を提供している。

「ここで見るのは2つ」も現物は3種類（環／段の辺／`forbids`）＋`the_engine_does_not_reach_out_of_itself`。

### R25-H5 `CLAUDE.md` の「docs や `.claude/` だけの変更は素通しする」が門番の現物と逆

`CLAUDE.md:12-14` と `.claude/hooks/verify-gate.sh:47-59`、`CONTRIBUTING.md:383`。

門番は `docs/state-transitions/*` を `needs_rust`、`docs/*` を `needs_ts` に入れる。
**docs だけのコミットは素通しどころか、状態遷移表なら 2m15s の `verify:rust` まで走る。**

「変更ファイルの**種類**に応じて」も、`verify-gate.sh:4` の「選ぶ基準は**ファイルの種類では
なく、検査が何を見ているか**」と `:13`「**種類で二分しない。**」に正面から反する。
`CONTRIBUTING.md:383` は正しく書いているので、**規約文書2つが反対のことを言っている。**

読んだ人は「docs は素通しだから検証は要らない」と判断してそのまま「完了」と報告する
（`CLAUDE.md` は「通していないなら『未検証』と明示すること」と要求しているので、
素通しだと信じた人は明示しない）。

### R25-M5 `verify-gate.sh` の doc とテストのラベルが、`.claude/` を一括で「どの検査にも当たらない」と言っている

`.claude/hooks/verify-gate.sh:17`、`verify-gate.test.sh:94-95`、`package.json`。

`npm run verify` は `test:hooks`（＝`verify-gate.test.sh`）を含むので、
**`.claude/hooks/` は専用の検査を持つ唯一の `.claude/` 配下**。
そして門番のパターンに `*.sh` も `.claude/hooks/*` も無いので、
**門番自身とその検査を書き換えるコミットでは、その検査が1度も走らない。**
実測で R24-H4 の `dd7ef1b` がその形（2ファイルとも `.claude/hooks/`）。

`verify-gate.test.sh` 自身が「選び損ねても何も落ちないのが、この門番の一番危ない壊れ方」と
書いている状態が、**門番自身の変更に対してだけ成立し続ける。**

## 失敗経路

### R25-M6 `startGame` の失敗から「再試行すべき時間切れ」と「設定の誤り」を区別する手段が無い

`docs/state-transitions/failure-surfacing.md:99`（F-27）の復帰導線は
「設定タブでエンジンや持ち時間を直す。**時間切れのときは再試行**（設定は誤っていない）」。

現物が返すのは全部フラットな `String` で、しかも綴りが揃っていない:

- `Operation timeout: the engine did not start in time; check the path and the volume`
- `timed out before the engine said usiok`（`EngineError` を通らない素の `String`）
- `Operation timeout: timed out before waiting for readyok`
- `timed out before the engine said readyok` / `timed out before the options were sent`
- `Engine startup failed: engine_path is not a valid existing path: …`（設定の誤り）

`closeGame` は3つの文言を TSDoc に**契約として写して**分類を渡しているのに、
`startGame` の TSDoc には文言が1つも無い。**再試行で通る失敗が、直しようのない
設定の誤りとして案内される。**

### R25-M7 `starting` の doc が閉じたと書いている窓は、実際には開いたまま

`src-tauri/src/engine/registry.rs:77-83`。doc は「`spawn` から `processes` への登録まで
`USI_OK_TIMEOUT` の窓があり、その間ここに居ないと終了時の掃除から見えない」と書くが、
`starting.push` が走るのは `spawn_blocking` が解けた**後**。

- 正常系: 子が起きてから `push` までの区間はどちらの台帳にも居ない（通常マイクロ秒）
- `SPAWN_TIMEOUT` 超過: `tokio::spawn(dispose_late_spawn(started))` が**唯一の参照**になる。
  このタスクはどの台帳にも載らないので `shutdown_all` は見つけられない。
  ブロッキングワーカが埋まっていれば分単位で続きうる

`SPAWN_TIMEOUT` の doc も「ワーカが1本減る」しか書いておらず、
**子プロセスがどこにも居なくなる**ことを書いていない。

### issue へ送った理由

**R25-M7。** `SPAWN_TIMEOUT` を超えた子プロセスがどの台帳にも載らない件は、
直し方に設計の選択が要る（終了時に起き上がりをどこまで待つか）。
`/implement` の「直し方に判断が要る → issue を立て、ユーザーに選ばせる」に当たる。
窓の範囲についての**嘘だけ**はこの回で直した。

### 変異試験

すべて baseline 差分。

- 表に列を1本足す（末尾を採る版では緑、見出しから引く版では赤。
  さらに空振り検出が「印以外の値がある」で拾う）
- `game/` に `mod not_tauri` を置く（部分一致の版では**誤検出**、語の境目を見る版では通る）
  ／本物の `tauri::AppHandle` を置くと落ちる
- 絞りを写像を捨てる形へ戻す（連打1000回が1000行通る）／鍵から対局を落とす／長さを見ない
- 門番から `.claude/hooks/*` の行を落とす

### 未検証で入れたもの

**R25-M6 の一部。** `registry::spawn` / `ensure_ready` / 書き込みの時間切れは
実プロセスを要するので踏めない。踏める `remaining` だけテストで固定した。
**目印を機械は見ていない**——2回目が出たらラチェットにする
（`CLAUDE.md` の「同じ失敗を2回するまでルールを足さない」）。

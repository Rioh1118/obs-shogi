### HIGH

#### R7-A 節表の `file_id` が重複すると、別のファイルの索引が黙って差し替わる

rust。`index_cache.rs:604,639` / `store/index_store.rs:39-45`。

`decode_all` の節表ループは `file_id` の**一意性も並びも見ていない**。
`NodeTables::upsert` は `self.by_id[idx] = Some(nt)` で黙って上書きする。

`encode_all:404-409` は `by_id_iter().enumerate()` で書くので `file_id` は
**昇順かつ一意**。読む側がそれを検査しないので、**後に書かれた節表の `file_id` が
1ビット化けて前の `file_id` に一致すると、前のファイルの節表が差し替わる**
（`7 → 5` は1ビット）。

差し替えられた側（file 5）の出現は file 7 の節表に対して `node_id` を検査されるので、
**節数が足りていれば全部通る。** 結果、file 5 の全ヒットが file 7 の
`tesuu` / `fork_path` を持ち、押すと**別の手数の局面へ跳ぶ。**

`node_id` の化け（0手目に並ぶ）より悪い。**開始局面なら誤りに気付けるが、
それらしい局面が出ると気付けない。**

**この経路の前提を作っているのは r6 で書き足した段落そのもの**（`search.md:268-271`）——
「出現ゼロの節表は普通に在る」ので、化けた側に出現が無く `B` にならない形が実在する。

- **`err!` は `trace!` と同型。** 接頭辞・`format_args!` の渡し方・引数の評価回数（1回）・

  `decode_all` は `gen` を検査しないので意味も変わらない。
  **blob の並びを再現して数えると `gen=1` で3件、`gen=7` で1件**
- **`realistic_size` の題材は痩せていない。** 分岐の表は 3件/ファイル → 39件/ファイルに増えた
- **`node_table.rs` の2本を抜ける変異は無い**（`fork_off` を `+1`/`0`/`nodes.len()`、
  `fork_len` を `0`、`node_id` を `0`/`forks.len()`、`finish()` を `Default::default()`）
- **`read_decode` を `trace!` に戻して見えなくなる失敗は無い。** `try_restore` の `Err` は
  必ず `commands.rs:171` の `log::warn!` に載り、`e` は `read_decode` の3経路の文言を全部含む

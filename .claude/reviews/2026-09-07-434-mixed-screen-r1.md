#### r1-01 盤に載っている棋譜を押し直せなくなり、以降の保存が全て黙って落ちる（robustness）

`FileNode.tsx:34` の関門を `loadedAbsPath` **だけ**に寄せたのが原因。**C が作った退行。**

1. `a.kif` を開く（`activeKifuPath = a` / `loadedAbsPath = a`）
2. 壊れた `b.kif` を開く → `activeKifuPath = b`、`loadedAbsPath` は `a` のまま
3. `a.kif` を押して戻ろうとする → `isActive = (loadedAbsPath a === a)` が**真**なので `openKifuNode` を呼ばない。盤は既に `a` なので利用者は戻れたと読む
4. `activeKifuPath` は `b` のままなので `persistence.absPath(b) !== loadedAbsPath(a)`。以降 `a` への1手・分岐編集・コメント保存は全て `persistIfPossible`（`provider.tsx:72`）で `Err`。`edit` が `jkf_restored` を撃つので**指した手が一瞬出てから黙って戻る**
5. 抜けるには「`a` でも `b` でもない第3のファイル」を押すしかない。**2ファイルしか無いワークスペースでは復帰手段が無い**

`main` は `isActive = activeKifuPath === node.path` だったので、手順3で `openKifuNode(a)` が走って整合が回復していた。**この PR がその復帰路を消している。**

直し方: 両方を見る。`loadedAbsPath === node.path && activeKifuPath === node.path`。
載せられなかった `b` も押し直せ（`loadedAbsPath ≠ b`）、盤に載っている `a` も押し直せる（`activeKifuPath ≠ a`）。

- 結果: 対応済み（`997c0064` 関門を「ツリーと盤の両方が指しているとき」に変えた。落ちる test を先に書いて確認）

#### r1-04 ツリーの全行が game context を購読し、盤の操作1回ごとに再レンダする（perf / react / architecture / robustness の4人が独立に指摘）

perf reviewer が実測した。**「AppLayout が既に `useGame()` を読んでいるので描画量は変わらない」という前提は成り立たない。**
ツリーは `<Outlet />` の先に居て、`Outlet` が返す要素の identity は `AppLayout` の再レンダで変わらないため React が bailout する。

```
NO-useGame: layout 2->3  panel 1->1  row 2->2
useGame   : layout 2->3  panel 1->1  row 4->6
```

従来 **0回**だったツリーの再レンダを、盤の操作という最も頻度の高い経路に対して新設した。
ツリーは仮想化されていない（`widgets/kifu-stream` と違う）ので n = 展開済みの行数そのまま。
`FileNode` は1行ごとに `useDraggable` + `useDroppable` を張る。

```
n=0    median 4.86ms   ← game 側の再計算だけ
n=200  median 16.35ms  (+11.5ms)
n=1000 median 60.16ms  (+55.3ms)
```

行あたり約 55µs の線形。発火回数は `navigated` で1回、盤で1手指すと2回、コメント自動保存で 900ms ごとに1回。
`React.memo` では消えない（context 消費者は memo を貫く）。
`FileTree` で1回読んで prop で配るのは**逆効果**（`FileTree` の再レンダで子要素が全部作り直される）。

直し方（perf の推し順）: `entities/game` に値がプリミティブな細い context を足す。
`loadedAbsPath` は `game_loaded` / `reset_state` でしか変わらないので、移動・選択・編集ではツリーは1行も再レンダしない。
`shared/lib/notification` が同じ理由で context を2本に割っている先例がある。

- 結果: 対応済み（`d4f91026` `LoadedKifuPathContext` を分け、`FileNode` は `useLoadedKifuPath()` を読む。
  「カーソルが動いても細いほうは描き直さない」を test で固定した。広いほうが動くことも同じ test で見ている）

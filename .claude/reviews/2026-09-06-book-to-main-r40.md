## 所見

### BN-01 (HIGH, 1人が実測): ツリーを変える git を手前に置くと、検証も deny もされずに素通しする

手前に置いてよいものを「ディレクトリ指定の無い git 呼び出し」で見ていた。

**PreToolUse はコマンドが走る前に判定する。** `git rm src/app/App.tsx` を手前に置くと、
**判定した時点では対象がまだ在る**ので `git status` は1行も返さず、種類が空のまま `exit 0`。
`src/main.tsx` がその綴りを import しているので、
**tsc が必ず落ちるコミットが、検証も deny もされずに積まれる。**
**利用者にはゲートが働かなかったことすら見えない。**

同じ形が `git mv` / `git stash pop` / `git checkout --` / `git restore` / `git reset` にもある
（この repo には stash が8本あり、実際に打つ筋道がある）。

**走査の仕方を変えても閉じない** —— 消される側もこれから現れる側も、
コマンドの前には原理的に見えない。判定表は (B, S4) を
「分類の問題なので塞げる」と書いていたが、**これは構造の問題。**

- 結果: 対応済み `ce9862fa`（手前に置ける動詞を列挙する側で塞ぐ。
  ケースを10本固定 —— **塞ぎすぎの側も見る**）

### BN-02 (HIGH, 1人が実測): alias 名が最後の網に入り、読み取りコマンドが軒並み止まる

このマシンには `alias.ci commit` があり、網の語彙が
`(commit|…|ci)` に広がる。網は引用も潰さず語として当たれば deny する。

```
git diff .github/workflows/ci.yml   → deny
git log -- .github/workflows/ci.yml → deny
```

`.github/workflows/ci.yml` はこの repo に実在する。CI を直そうとしただけで、
**コミットを1つも作らないのに「コミットの打ち方」を指示されて止まる** ——
**従える操作が1つも無い。** alias 名は利用者が短く付けるので、
`c` / `p` を持つ環境では網はさらに広がる。

- 結果: 対応済み `c786fd80`（網から alias 由来の名前を外す。
  `git ci -m x` は `gate_commit_call` が構造として切り出す。
  **併せて BN-01 が持ち込んだ誤発火も潰した** —— `git st &&` が止まっていた）

### BM-01 (HIGH, 1人が実測): 網羅テストが12種のうち2種しか見ておらず、`/tmp` に依存していた

r39 で足したテストは**3つ壊れていた。**

**実物を手で並べていた。** `covered()` の `match` はコンパイルを止めるが、
`seen` に積む実物とは何の関係も無い。**種別を足しても腕に綴りを足せば緑。**

**`/tmp/x.bin` の有無で結果が変わる。** そのファイルが無い環境では
`UnsupportedFormat` ではなく **`NotFound` が入る。** `touch /tmp/x.bin` すると落ちる ——
`temp_dir_names` が塞ごうとしている非決定の同型を持ち込んでいた。

**4枝が不変条件3を満たしていなかった。**「満たさないのは2枝だけ」も偽:
`UnsupportedFormat` / `InvalidSfen` / `InvalidHandle` / `Unknown`。
**`InvalidSfen` は引用で終わる** —— 同じファイルの `to_book_key_in_file` が
「引用で終わると復帰操作を読み飛ばす」と書いて避けている形そのもの。

- 結果: 対応済み `3d7228da`（種別ごとに実物を作る `match` へ。
  求めた種別と一致することも見る。4枝の文面を直し、戻すと落ちることを確認）

### BN-03 / BN-04 / BN-05 (MEDIUM, 1人が実測): 入口が読めないと無音で全て素通しする

**jq が無いと1度も走らない。** `set -e` が無いので失敗は握り潰され `rc=0`。
**macOS に jq は標準で入っていない**ので、新しいマシンで clone した人は
「コミットが通ったから検証も通った」と読む。
payload が空のときも、`cd` できないときも同じ。

**失敗の案内が、どのツリーを検証したのかを言わない。** このゲートは設計上
`project_dir` を検証するので、**触ってもいないファイルのエラーが返ることがある**
（このレビュー中に実際に起きた）。「上を直してから」に従うと
**別ブランチの WIP を直しにいく。**

**判定表の I 行が「素通し（正しい）」と書いているが、`git` と動詞が同じコマンドに
並ぶだけで deny になる。** 不変条件3の「誤発火は余分な検証が走るだけ」も
S2 では成り立たない（無条件の deny で、案内に従える操作が無い）。

- 結果: 対応済み `692aeed1`（**入口を通すケースを2本足した** ——
  ここまでのケースは全て関数呼び出しで、**入口を1つも通っていなかった**）

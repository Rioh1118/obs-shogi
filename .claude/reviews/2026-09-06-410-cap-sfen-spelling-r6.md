## 所見

### [MEDIUM] R6-01 `describe` の最後の腕だけ、案内が引用の後ろにある（rust / comment / robustness）

**3人が独立に指摘。** r5 で語順を規約にしたのに、同じ規約の適用先として doc が
名指ししている `describe` の1腕が外れていた。

利用者が最初に読む語が `Decode Error:` になる。`unreadable_record` の doc が
「`nom` の語彙で、利用者の言葉ではない」と名指しで禁じている形。

いま壊れていないのは引用が短いからで、**それは規約が名指しで禁じた
「腕ごとに、いまは短いから大丈夫」の論証そのもの。**

### [MEDIUM] R6-02 もう存在しない文言（`scan failed`）を「いまも出る」と書く doc が2つ（rust）

`docs/state-transitions/search.md` と `types.rs`。**`畳み込み済み` が直した当の欠陥を
「未着手」と書いていた。** `types.rs` の側は「クレートの理由に」も違う
（埋まるのはこのリポジトリ自身の `ScanError::RootNotFound`）。

### [HIGH] R6-03 `KifuReadError::NothingToIndex` が2箇所に残っていた（comment）

r5 で直したのは3箇所のうち1つだった。実在しないバリアントなので、読み手は
`KifuReadError` を見に行って「`Err` なのだから失敗なのだろう」と読む——
`outcome.rs` が節を割いて**名指しで禁じている読み方**。

### [MEDIUM] R6-04 「組みながら刈る」がこの crate の用語と食い違う（comment）

read 側は `warn_if_moves_were_dropped` が `String` を組み終えてから刈る。
`for_screen` の doc が「組みながら」を「刈るのを組み上げた後まで遅らせない」と
定義しているので、この語を使うと**確保が頭打ちだと誤解させる**。

### [HIGH][差分外: `src/`] R6-05 後から出た索引の警告は、一度も画面に出ない（robustness）

`reducer.ts` は新しいものを**末尾**に積み、`WorkspaceTab` は `slice(0, 5)` で
**先頭＝いちばん古い5件**を描く。5件溜まった後の警告はどれも描かれない。

**`畳み込み済み` で足した文言（走査失敗）は、この画面の描き方のせいで利用者に届かない。**
数字が1増えるだけで、索引は `Ready` のまま（#472）検索は成功する。

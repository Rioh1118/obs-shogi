## 入れた機械

### Rust の doc が名指す TS の綴りの実在検査（`comment_identifiers.rs`）

バックログで**7回**再提案されていた項目（`.claude/knowledge/mechanization-backlog.md`）。
候補が「下線を含む綴り」だけだったので、境界を説明する doc が名指す camelCase
（受け手の関数名と、`serde(rename_all = "camelCase")` で wire に出る欄名）は
**1つも見られていなかった**。

- 候補に camelCase（小文字始まり＋大文字を1つ以上）を足し、干し草にフロントの `src/**` を足した
- 実測: 候補は **27件**。うち **26件**が解け、残り1つは外部アプリ（ShogiHome）の綴り
- **入れた回に腐りを1件拾った**（`enableEngineTimeout`。ShogiHome 側の設定名で、
  こちらの欄は `enforce_engine_timeout`）。2件とも `EXEMPT` へ
- 大文字始まりは入れない —— 文頭の英単語と外部クレートの型名（`JoinError` / `TryFrom` /
  `OsString`）が雪崩れた（実測で30件超）
- **変異**: `clock.rs` の doc の `useNow` だけを改名 → 落ちる。確認済み
- 候補の形そのものを `the_candidate_shapes_cover_both_sides_of_the_boundary` が固定する
  （件数だけを見ていると、camelCase を落とす変異が素通りする）

**残っているのは SCSS の綴り**（`&__seat--turn` のような入れ子の途中形）。
入れ子を展開したセレクタ集合が要るので入れていない。バックログの回数を8へ更新した。

### 時計の欄の幅と持ち時間の上限の突き合わせ（`clockColumnWidth.ratchet.test.ts`）

出典が3つ別々に動く —— SCSS の `min-width: Nch`・`formatClock` の桁の増やし方・
`MAX_TIME_MS`。**どれを動かしてもコンパイラは緑**で、症状は
「長い持ち時間の対局でだけヘッダが横に揺れる」という当たらないと出ない形。

入れた回に**現物の不足を拾った**（`7ch` では上限の `24:00:00` が入らない）。

- **変異**: `7ch` に戻す → 落ちる。確認済み
- 走査が空振りしたときは「幅を読めていない」で落ちる（0 と 0 の一致を緑にしない）

### `useNow` のテスト（`useNow.test.tsx`。これまで1本も無かった）

**commit ごとに積む probe** で見る。描画の回数で見ると差が出ない ——
描画中に入れ直す形は捨てられる描画を1回挟むので、返り値の列は `useEffect` 版と同じになる。
違うのは**その古い値が画面に出たかどうか**で、それは commit の有無。

- **変異**: `useEffect` で入れ直す元の形に戻す → 落ちる。確認済み

### Rust の境界のテスト（`a_deadline_that_has_just_run_out_points_at_now`）

`main_left` と `into_byoyomi` が**両方 0 になる唯一の入力**（ちょうど尽きた瞬間）。
既存の4本はこの境界を1度も踏んでいなかった。

## lint / hook で強制できるもの

- **R14-1 は静的に数えられる。**「ある state を `null` にする（＝子を画面から外す）呼び出しが、
  その子の閉じる手続きを通っているか」。`setOpenComment(null)` は4箇所で、
  手続きを通るのは1つ。**「同じ state を落とす呼び出しが N 箇所あるとき、
  うち何箇所が同じ手続きを通るか」を数える検査が、このブランチで7回出た
  「片方だけ塞ぐ」の全部に当たる**
- **R14-3 は hook で拾える。** 「機構を削除するコミットで、その機構を説明している doc の行が
  同じコミットで変わっているか」。`eb8a4c1` は doc を3行書き換えたが、
  主張の中身（「画面にもそう出している」）を検証せずに足した
- **R14-C7 のような死んだ識別子**は検査できる。`docs/state-transitions/*.md` の
  バッククォート囲みのうち、`[A-Za-z][A-Za-z0-9_]{4,}` に合致するものが `src/` に
  1件も無ければ落とす（除外リストは要る）
- **R14-C6 の「N経路」型の見出し**は、見出しの数と表の行数の一致を機械で見られる。
  ただし**見出しから数を外す運用のほうが安い**
- **R14-C1 〜 C5 は機械では止まらない。** どれも「コメントが主張する条件式が、
  同じファイルの別の行で否定されている」形で、`commentHistory` の対象外（経緯ではなく理由の嘘）。
  レビュー時に「『〜だから』と書いてあったら、その条件がどの行かを指せるか」を
  1件ずつ潰す以外の手当ては無い

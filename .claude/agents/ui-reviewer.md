見た目とレイアウトだけを見る。フックや state は react-reviewer の担当。

## 前提

- 対象は **MacBook 相当以上（幅 1280px 以上）**。それ未満で崩れることは所見にしない
- ただし「ウィンドウを縮めたら**操作不能になる**」（ボタンが押せない、盤が消える、モーダルが画面外に出る）は幅に関係なく BLOCK
- SCSS トークンは `@use "@/index.scss" as index;` で読み込む規約

## 見るもの

### 1. レイアウトの土台

- 画面を構成しているのは何か（flex / grid / 絶対配置）を特定し、**同じ役割の領域が違う方式で組まれていないか**を指摘する
- 固定 px の高さ・幅を持つ領域を列挙する。中身が増えたときに何が起きるか
- ペイン分割（盤 / 棋譜 / 解析 / サイドバー）の伸縮の主従関係が定義されているか。全部が `flex: 1` になっていないか

### 2. オーバーフロー

- スクロールできる領域とできない領域を列挙する。**どのレベルでスクロールを受け持つかの方針が一貫しているか**が最重要
- 長い文字列（棋譜のコメント、ファイル名、エンジン名、エラーメッセージ）が入ったとき何が起きるか。省略なのか折り返しなのか、方針が場所ごとにバラバラでないか
- `overflow: hidden` で隠しているだけで、中身に到達できなくなる箇所がないか
- ネストしたスクロール領域があれば、内側と外側のどちらが動くかが予測可能か

### 3. レスポンシブ

- メディアクエリの breakpoint を全て列挙し、値が散っていないか（トークン化されているか）を見る
- 1280px 幅で実際に成立するか。特に横並びの要素の合計最小幅が 1280px を超えていないか
- ウィンドウの高さが低いとき（例: 800px）に、縦方向で操作不能になる箇所がないか

### 4. ビューの一貫性

同種の UI が場所によって違う実装・違う見た目になっていないかを、**横断的に**確認する:

- モーダル / ダイアログ: 閉じ方（Esc・背景クリック・×ボタン）、フォーカスの扱い、重なり順が揃っているか
- ボタン: 主/副/破壊的 の区別が一貫しているか
- 空状態・読み込み中・エラー表示: 同じ扱いになっているか、それとも場所ごとに独自実装か
- フォーム項目のラベル位置・バリデーション表示
- 余白と角丸と影: トークンを使っているか、直値が混じっていないか

### 5. SCSS の構造

- トークンを使わず直値（色・余白・フォントサイズ）を書いている箇所
- セレクタのネストが深い（4段以上）箇所
- コンポーネントのスタイルが他コンポーネントの内部要素を指定していないか（カプセル化の破れ）
- z-index の値が直値で散っていないか。重なり順は一元管理すべきもの

## 出さない所見

- スマホ・タブレット幅での崩れ
- 色使いやデザインの好み。**一貫していないこと**を指摘するのであって、どちらが良いかは決めない
- **既存の余白・大きさ・要素間の関係は、意図して決められたものとして扱う。**
  「この padding は大きい / 小さい」「余白を揃えるべき」といった値そのものへの意見は出さない。
  指摘してよいのは次の場合だけ:
  - 同じ役割の部品が**別々のトークン・別々の直値**で書かれている（＝一貫性の破れ、または将来変えるときに漏れる）
  - その値が原因で**中身が入りきらない / 操作できない**（＝機能的な問題）

`references/preferences.md` を先に読む。本文と食い違ったら preferences を優先する。

形式は固定しない。読み手は依頼元の会話を見ていない。

## 手順1: 高さを決める

依頼の語に合わせる。

| 依頼の語            | 書くもの                                                         |
| ------------------- | ---------------------------------------------------------------- |
| ふわっと / 軽く     | 目的を数行。前提は欠けると誤る分だけ                             |
| 指定なし            | 目的（なぜ）・相手が知らない前提・完了の形。やり方は相手に任せる |
| 具体的に / 手順まで | 上に加えて、触る場所・手順・止まる条件                           |

細かすぎると相手の判断を縛り、粗すぎると判断の材料が足りない。

完了: どの高さで書くかが決まっている。

## 手順2: 材料を分ける

会話を見返し、3つに分ける。

- **書く**: 会話の中にしかないもの。決定、却下した案とその理由、実測、利用者の発言
- **パスで指す**: ファイル・PR・Issue にあるもの。書き写さない
- **捨てる**: 相手の仕事に効かないもの

指す先は相手が読めること。別環境の相手には、未 push の変更と `.gitignore` 配下は見えない。
ブランチやコミットに依存するなら、それも書く。相手が使うとよい skill があれば名前で挙げる。

事実は確かめたものだけを書く。未確認の事実は未確認と書く。

完了: 書くものが、パスで置き換えられないものだけになっている。

## 手順3: 書く

- 完了の形は、終わったと判定できる形で書く
- 止まる条件は、取り返しのつかない操作があるときと指定されたときに書く。
  それ以外は、迷ったら相手の判断で進めてよいと分かる形にする
- 調べるだけか、変更までするかを明示する
- 理由は相手の判断に効くときだけ、1文添える
- 欲しい動きを肯定形で書く
- 例は、形が言葉で伝わらないときだけ入れる

完了: 消しても相手の動きが変わらない文が残っていない。

## 手順4: 確かめる

1. **文脈ゼロ。** この会話を読んでいない同僚が、質問せずに動けるかを読み直す。
   「さっきの」「例の」、内輪の略称、説明の無い識別子を置き換える
2. **秘密。** API キー、トークン、パスワード、接続文字列、個人情報を入れない。
   必要なものは、置き場所か環境変数の名前で指す

完了: 2点とも通っている。

## 手順5: 出す

1. 本文だけを scratchpad のファイルに書く
2. この skill のディレクトリの `scripts/copy.sh <そのファイル>` を走らせる
3. 本文をコードブロックで表示する。本文にバッククォート3つが含まれるなら、外側のフェンスを長くする

`copy.sh` が失敗したら表示だけにして、コピーできなかったと書く。

完了: 本文が表示され、コピーの成否が書いてある。

## 手順6: 書き直しを受ける

| 言われたこと            | 対処                                     |
| ----------------------- | ---------------------------------------- |
| もっとふわっと / 長い   | 手順と観点の列挙を消す。目的は残す       |
| もっと具体的に          | 欠けている場所・手順・完了の形を足す     |
| 相手が迷った / 誤解した | 迷った箇所の前提を足す。文章は増やさない |
| 相手が縛られた          | やり方の指定を消し、目的と完了の形に戻す |
| 口調が違う              | 本文の情報を変えず、言い回しだけ直す     |
| 何が違うか分からない    | どの文が違うかを1問だけ聞く              |

直したら手順5をやり直す。

次回以降も効く好みなら `references/preferences.md` に1行で足す。同じ話題の行があれば書き換え、
矛盾する古い行は消す。今回の題材にしか効かない事実の修正は書かない。
追記はコミットせず、追記したことを返答に書く。

完了: 直した版が出ていて、効く好みが preferences にある。

## 出どころ

作法を足すときは、次の文書に書いてあるものに限る。一般論から足さない。

- Anthropic, Prompting best practices: 文脈の無い同僚に見せて確かめる、理由を添える
- Anthropic, Effective context engineering for AI agents: 高さ、期待する動きを尽くす最小限の情報
- OpenAI, GPT-5 prompting guide: 止まる条件と手放してよい場合の明示（GPT-5 向けで、記事は保管扱い）
- mattpocock/skills の handoff: 既存の成果物は参照で渡す、秘匿情報を除く、使う skill を挙げる
- improving-prompts: 文書化された作法だけを使う、具体的な不具合を聞いてから変える

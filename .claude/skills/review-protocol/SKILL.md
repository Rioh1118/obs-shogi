# レビュー共通プロトコル

あなたはレビュアーである。**ファイルを書き換えない。** 所見を返すのが仕事。

## 事実確認の義務

- 所見は必ず**実際に読んだコード**に紐づける。`path:line` を必ず書く
- 読んでいないファイルについて書かない。「おそらく」「〜と思われる」で始まる所見は出さない
- 確信が持てないものは**出さない**。数を稼がない。1件の確実な指摘は10件の推測に勝る
- 一般論（「DRY を守るべき」「テストを書くべき」）だけの所見は出さない。この repo のこの行に紐づかない指摘は雑音

## このプロジェクトの実態（前提を間違えないこと）

- テストは TS 側が片手で数えられる本数 / Rust 側 `#[test]` 0個（現在値は `npm run test` で確認）。**`cargo test` の green は何も保証しない**。「テストが通るので安全」と書かない
- 検証は `npm run verify`（tsc + oxlint + vitest、約8秒）と `npm run verify:rust`（fmt + clippy + test、約2分15秒）
- E2E は無い。今後も作らない（`tauri-driver` が macOS 非対応のため）
- 対象画面サイズは **MacBook 相当以上**（幅 1280px 以上）。スマホ・タブレット対応は要求しない
- Lint は oxlint（`vite.config.ts` の `lint` に設定がインラインで書かれている）

## 深刻度

| 深刻度 | 意味                                   | 扱い                         |
| ------ | -------------------------------------- | ---------------------------- |
| BLOCK  | 壊れている / データ喪失 / セキュリティ | マージ前に必ず直す           |
| HIGH   | バグまたは明確な設計上の誤り           | このループ内で直す           |
| MEDIUM | 変更しやすさを確実に損なう             | issue 化するか、まとめて直す |
| LOW    | 好みの範囲                             | 記録だけ                     |

**LOW を並べない。** MEDIUM 以上に絞る。LOW は「同種が5箇所以上ある」場合だけ1件にまとめて出す。

## 出力形式

所見ごとに、この形だけで書く。前置き・要約・励ましは書かない。

```
### [深刻度] 一行要約
- 場所: `path:line`（複数なら列挙）
- 根拠: 実際のコードの引用（2〜6行）
- なぜ問題か: 具体的な失敗の筋道。「〜という入力で〜になる」まで書く
- 直し方: 具体的な変更。方針だけで終わらせない
```

最後に必ずこの2つを付ける。

```
## 見ていない範囲
（時間・権限・文脈で確認できなかった箇所を正直に列挙。「全部見た」と書かない）

## lint / hook で強制できるもの
（今回の所見のうち、人の注意ではなく機械で防げるものを挙げる。無ければ「なし」）
```

所見が無ければ `所見なし` とだけ書き、上記2セクションを付ける。

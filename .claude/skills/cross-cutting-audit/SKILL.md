読むもの: `docs/rules/`、`CONTEXT.md`、`.claude/rules/agents.md`。
成果物は全部 `.claude/plans/audit-<日付>/` に置く。**この skill はコードを変えない。**

## 段階1: 棚卸し

機械で作る。読んで作らない。

```bash
node .claude/skills/cross-cutting-audit/scripts/inventory.mjs .claude/plans/audit-<日付>/inventory [範囲]
```

| ファイル         | 中身                                           |
| ---------------- | ---------------------------------------------- |
| `functions.tsv`  | 公開関数                                       |
| `types.tsv`      | 公開の型                                       |
| `api.tsv`        | Tauri コマンドと、フロントの呼び出し           |
| `errors.tsv`     | エラー型、エラー文                             |
| `messages.tsv`   | 画面に出る文言の候補                           |
| `collisions.tsv` | 同じ名前（綴りを揃えて）が複数の場所にあるもの |

完了: 件数が0のファイルが無い。0なら走査の失敗として止める。

## 段階2: 判定

### 範囲の中はサブエージェント

ディレクトリか crate で最大3本に割る。各プロンプトに、範囲のファイル一覧、該当の棚卸しの行、
`docs/rules/` を渡す。**範囲の外を見させない。**

見るのはルール違反だけ。形式は `.claude/skills/review-protocol/SKILL.md`。範囲が小さければメインが見る。

### 範囲をまたぐ問題はメインが判断する

サブエージェントに渡さない。全体を見ないと判定できないため。

| 問題       | 探し方                                                 | 判定                                                  |
| ---------- | ------------------------------------------------------ | ----------------------------------------------------- |
| 同名異処理 | `collisions.tsv` の本体を読み比べる                    | 意味が違うなら改名の案。Rust と TS の写しなら対応表へ |
| 異名同処理 | `functions.tsv` の動詞と目的語で寄せ、本体を読み比べる | `R-DUP-*` で判定する。**形が同じだけならまとめない**  |
| 用語揺れ   | `messages.tsv` と型の名前を `CONTEXT.md` に当てる      | 正の語を決める案。語が未定なら `/decide`              |

**上の3つには全件の本体を開いて確かめる。** 名前だけで判定しない。

## 段階3: 出力する

1. **`violations.md`** — ルール違反の一覧。確信度80未満を落とし、ルール ID ごとに件数を出す
2. **`rule-proposals.md`** — ルール追加案。違反が3件以上あるのに当たるルールが無いもの。
   消す案も出す（違反0で、機械も理由も無いルール）。機械にできるなら検査の案を先に書く
3. **`plan.md`** — 修正計画。次の形で、効果の大きい順に並べる

| 順  | 問題 | 対象 | ルール ID | 確信度 | 修正案 | 壊しうるもの | 大きさ |
| --- | ---- | ---- | --------- | ------ | ------ | ------------ | ------ |

- `CONTEXT.md` に足す語の案も `plan.md` に書く
- 大きさは PR の本数で書く

人には件数の要約と `plan.md` の上位を見せる。実行するかは人が選ぶ。実行は `/implement` に渡し、
Issue にするなら `/write-issue` を使う。

完了:

- 段階1の全ファイルが段階2の判定を通った
- 同名の全組に判定か「対応表」の印がある
- 3つの成果物がある

skill は**回す・振り返る・整える**の繰り返しで育てる。記録と振り分けの規則は
`.claude/rules/skill-care.md`、記録は `.claude/knowledge/correction-log.md`。

## 書き足す

未反映の記録を読み、**同じ原因をまとめてから**足す。

- 足す先は1か所。工程の手順のどこで防げたかを探し、その手順の文を**書き換える**。末尾に積まない
- 足すのは「やること」を先に。「やめること」は肯定形で書けないときだけ添える
- その手順の完了条件で落とせるなら、完了条件に足す
- 機械で落とせるなら、skill に書かず検査にする（`.claude/knowledge/mechanization-backlog.md`）
- 反映したら記録の `反映先` を埋める

## 圧縮する

上限は `src/__tests__/skillCompact.test.ts` が持つ。上限に当たる前でも、指示がぶつかったら整える。

全文を読み、1文ずつ問う。

| 問い                                     | 当たったら                 |
| ---------------------------------------- | -------------------------- |
| 消しても動きが変わらないか（既定の動作） | 文ごと消す                 |
| 同じ意味が別の場所にあるか               | 1か所に寄せて他は指し先に  |
| 他の指示とぶつかるか                     | 人に聞いて片方を消す       |
| 現物を見れば分かるか                     | 消す。現物へ向ける         |
| いまも正しいか                           | 開いて確かめる             |
| 経緯や実例の語りか                       | 判断に効く1行だけ残す      |
| 一部の場合にしか使わないか               | `references/` へ。1段まで  |

**実測とやらかしの記録は残す。** 理由の無い手順は次の圧縮で消され、同じ失敗が戻る。

- `description` は**いつ使うか**だけを書く。手順を要約すると本文が読まれなくなる
- 各手順に、終わったと判定できる完了条件を置く
- 同じことを3行で言っている所は、語を1つ決めて置き換える

## 確かめる

1. 消した文を一覧にし、落とした意味が無いかを見る
2. 動きが変わる圧縮なら、fresh な agent 1本に圧縮後の skill で同じ題材を走らせ、
   迷った箇所を挙げさせる
3. 差分を人に見せる

## 新しく作る

**手直しを重ねた実際の作業から作る。** 何をやり、何を確かめ、どこで手戻りしたかを洗い出し、
手戻りが無くなる順に並べる。公開の skill は読んで考え方を借りる。そのまま入れない。

1工程1本。前の工程の成果物を読んで始め、次の工程へ渡すものを書く。

# 候補の切り方と本文

書く中身の規則は `docs/issue-guidelines.md`。ここには切り方だけを置く。

## 切り方

**1 Issue は、それだけで完了を確かめられる細い縦の一本。** 層ごとに割らない。

- 良い: 「`spin` の欄で範囲の外を入れると端へ丸まり、保存される」（Rust から画面まで通る）
- 悪い: 「Rust の型を足す」「画面の部品を作る」（それぞれ単独で確かめられない）

- 大きさは PR 1本。1回の作業で終わらないなら、さらに切る
- 下準備のリファクタは先に切り、後の Issue を `Blocked by` にする
- 全域の機械的な変更は縦に切れない。新しい形を足す、呼び手を束ごとに移す、古い形を消す、の順に切る
- 依存は本当に先に要るものだけ。依存が2件以上で順番があれば親 Issue を立てる
- 受入条件と Issue は1対1でなくてよい。AC の ID を本文に並べ、追跡できる形にする

## 本文

節の並びは `.github/ISSUE_TEMPLATE/task.yml` と同じにする。

```markdown
## 何をやるか

<1〜3行。利用者から見た変化>

## 完了条件

- [ ] AC-3: <観測できる結果>

## 正本

docs/spec/features/<slug>.md の AC-3

## ブロック

Blocked by #N
```

親は `.github/ISSUE_TEMPLATE/tracking.yml` の並びにする。

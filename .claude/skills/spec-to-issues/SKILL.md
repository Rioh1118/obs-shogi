**規則の正本は `docs/issue-guidelines.md`。先に読む。ここに写さない。**
`gh` の書き込みは外部への変更なので止まる（`docs/rules/decisions.md` R-DEC-9）。人の判断は**手順4の1回だけ**で、他の判断は `/decide` が決める。

## 手順1: 材料を揃える

`git fetch` して `origin/main` を基準にし、コミットハッシュを控える。

```bash
gh label list --limit 100 --json name
gh issue list --state all --limit 1000 --json number,title,state,body,labels
```

対象の仕様と、そこからリンクされた状態遷移表を読む。**基準で読めない仕様は対象にしない。**

## 手順2: 候補を洗い出す

作業の種は、仕様の受入条件、「いま満たしていないこと」、「これからの要件」。
受入条件の節が無い `features/` は「要件」の節を種にする。AC の ID が無ければ節の名前で正本を指す。
[references/drafting.md](references/drafting.md) に従って、完了を確かめられる単位に切る。

完了: 種の全行が、候補か手順3の除外のどちらかに対応している。

## 手順3: 自動で除外する

候補を上から確かめ、当たったものを除く。**除外にも根拠を付ける。**

| 除外     | 確かめ方                                                                                                                | 根拠に書くもの        |
| -------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 起票済み | 仕様の行に open の `#N` がある。本文の正本リンクが同じ節を指す open の Issue がある。閉じた番号は実装済みの行で確かめる | Issue 番号            |
| 未決     | 「決まっていないこと」に紐づく。`docs/OPEN-QUESTIONS.md` の未決に依存する                                               | Q 番号か仕様の行      |
| いつか   | `docs/IDEAS.md` にある。**着手の時期が読めないだけなら除外せず、一覧で人が外す**                                        | IDEAS の行            |
| 重複     | open の Issue を**語でなく振る舞いで**照合する。閉じた Issue も同じ作業の再発でないかを見る                             | Issue 番号            |
| 実装済み | 概念で実装を探し、完了条件を現物に当てる。**当てられないものは除外しない**                                              | 関数名か PR、見た場所 |

未決が混ざった候補は、決まった部分だけを切り出せるなら残す。切り出せなければ除外する。

## 手順4: 一覧を出して1回だけ承認を取る

次の形で全件を出す。起票の本文は `<scratchpad>/issues/<NN>.md` に書いておく。

```markdown
対象: docs/spec/features/<slug>.md（基準 <hash>）

## 起票する N件

| # | タイトル | ラベル | Blocked by | 完了条件 | 正本 |

親 Issue: 立てる / 既存の #N に足す / 立てない（理由）

## 除外した M件

| 候補 | 理由 | 根拠 |
```

`AskUserQuestion` で1問だけ聞く。「全部起票する（推奨）」と「起票しない」の2択。
番号を指定して外す指示は Other で受ける。**指示どおりに一覧を確定し、聞き直さない。**

承認されるまで次へ進まない。承認された一覧に足さない。

## 手順5: 起票する

依存の先から順に、1件ずつ立てる。後の Issue の `Blocked by` には実際の番号を入れる。

```bash
gh issue create --title "<タイトル>" --body-file <本文> --label <種別> --label <エリア> --label <優先度>
```

- 本文が `docs/issue-guidelines.md` の上限に収まることを、立てる前に確かめる
- 親は子を全部立ててから、子の番号を並べて立てる。既存の親にはチェックリストの行を足す（`gh issue edit`）
- **1件立てるごとに手順6の書き戻しをする。** 途中で落ちても、再実行で手順3が起票済みとして除く
- 失敗したら止める。残りを立てず、立てた番号と止まった理由を報告する

## 手順6: 仕様へ番号を書き戻す

- `features/` は冒頭の `追跡:` に足し、受入条件の行末に `#N` を付ける
- `screens/` は「いま満たしていないこと」の行に `→ #N` を付ける
- 親があれば `追跡:` の先頭に置く

書き戻しはファイルの変更だけ。コミットは `/implement` の規則に従う。

## 報告

起票した番号、除外の件数と内訳、書き戻したファイル、検証の結果。

完了:

- 手順2の全行に行き先がある
- 承認した全件に番号があり、仕様に書き戻してある
- `npm run verify` が通っている

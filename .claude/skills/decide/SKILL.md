規則の正本は `docs/rules/decisions.md`（基準の優先順位、ドア、止まる条件、記録）。先に読む。ここに写さない。
エージェントの使い方は `.claude/rules/agents.md`。

## 手順1: 問いを立て、ドアに分ける

- 判断を**1文の問い**にする。答えで作るものが変わらないなら、判断ではない。決めずに進む
- 先に決まる別の判断に依存するなら、そちらから決める
- 依頼の文、ADR、ルール、`CONTEXT.md`、利用者が却下した案に答えがあれば、それに従って終わる
- 戻す手間、戻す速さ、影響の広さでドアに分ける。**迷ったら一方通行**
- 一方通行なら、双方向に変える手を全部当てる
- 止まる条件に当たるなら手順5へ

| 重さ | 条件                                 |
| ---- | ------------------------------------ |
| 軽い | 双方向で、影響が1スライスに閉じる    |
| 中   | 双方向で、複数のスライスか画面に効く |
| 重い | 一方通行、または変換して双方向にした |

完了: 問い、ドア、重さが1行ずつある。

## 手順2: 調べる

足りない事実は自分で調べる。深さは重さで決める。

| 重さ | 見るもの                                                                    |
| ---- | --------------------------------------------------------------------------- |
| 軽い | リポジトリ内の前例、`docs/rules/`、`CONTEXT.md`                             |
| 中   | 上に加えて、言語とフレームワークの公式の慣例、似た製品2〜3個（`research/`） |
| 重い | 上に加えて、双方向に変える手を選択肢として比べる                            |

残りの情報で結論が変わらないなら、そこで止めて決める。

## 手順3: 決める

選択肢を最低2つ出し、基準を上から当てる。**最初に差がついた基準で決める。** 点数を付けて足さない。

決めた案に、自分で問う。

- それが成り立たないのはどういう場合か
- 根拠は測ったものか、感触か
- 何を諦めたか
- 6週間後に失敗していたら、原因は何か

壊れる筋道が見つかったら、案を変えるか、撤退口を足す。足りない前提は置いて、判断ログに書く。
**人には聞かない。**

## 手順4: 記録する

成果物の末尾の `## 判断ログ` に1行足す。成果物が無ければ最後の報告に書く。

| 判断 | 選択 | 理由と基準 | 戻し方 |
| ---- | ---- | ---------- | ------ |

- 理由にはルール ID を入れる。選ばなかった案も短く書く
- 置いた前提は理由に書く
- 戻し方は具体的に書く。書けないなら、ドアの分類を見直す

`docs/rules/decisions.md` の R-DEC-14 に当たるなら、`docs/decisions/` に
[references/adr-template.md](references/adr-template.md) の形で残し、`docs/decisions/LOG.md` に1行足す。
**覆す決定は新しい ADR で supersede する。** 未決が解けたら `docs/OPEN-QUESTIONS.md` から消す。

## 手順5: 止まるとき

止まる条件に当たるものだけ、`AskUserQuestion` で1問聞く。選択肢と推奨、当たった条件の ID を添える。
止まる前に、戻せる部分は進めておく。答えも判断ログに書く。

## 手順6: 覆されたとき

人が判断を覆したら、覆された通りに直す。理由を聞き取れる形で読み、`docs/rules/` か `CONTEXT.md` への
追記案を出す。記録は `.claude/rules/skill-care.md` に従う。

完了:

- 選択肢が2つ以上あり、基準で決めた
- 判断ログに1行ある
- 止まる条件に当たらない判断で、人に聞いていない

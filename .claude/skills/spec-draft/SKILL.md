入力は `.claude/plans/<slug>/ledger.md` と、あれば `survey.md`。
節の順は `docs/spec/README.md`、見た目は `docs/spec/design-language.md` が持つ。

## 手順1: 骨格を見せる

文章の前に、利用者の操作の骨格を2〜3案、見比べられる形で出す。
**利用者が何を選び、何を設定するか**だけを書く。内部の段（取得・当て・確かめ）は骨格に入れない。
失敗して利用者が手を打てるときだけ画面に出す。

案ごとに、諦めるものを1行書く。`/decide` で選ぶ。見本は成果物として残す。

**骨格の見本と判断ログが無いまま画面を実装しない。** 大きな画面は、骨格が動く最小の一本を先に入れて段階化する。
所見への対処で積んだプリセット編集は人が不可と判定し、対局画面と合わせて6,378行を消した。
後から欄や文言を足すときも、骨格のどこに置くかを先に答える。

## 手順2: 見本で問いに答える

見本は**問いに答える使い捨て**。先に問いを1文で書く。

| 問い                 | 作るもの                                          |
| -------------------- | ------------------------------------------------- |
| どう見えるか         | 実物の値を使った HTML（Artifact）                 |
| 状態の持ち方でよいか | ボタンで状態を動かせる HTML。状態を画面に全部出す |
| 実データで成り立つか | 実エンジンの申告など実物の入力を流した見本        |

**部品の見本は状態を全部並べる。** 既定 / 値を変えた / 範囲の端 / 不正な値 / 無効 / 読み込み中 / 失敗。
入力の種類ごとに1部品。同じ種類を別の部品にしない。
見本のうち、並べてみて足りなかった状態は台帳の問いにする。

## 手順3: 仕様を書く

- `main` に無いものは `docs/spec/features/<slug>.md`、あるものは `docs/spec/screens/` を直す
- 語は既存の語彙に揃える。新しい語は仕様の `語彙` 節に定義し、同じ意味の別の語を持たない。
  **1語が2つの動作を指さない**（「閉じる」が3動作を指し、`Aborted` の直しが12箇所に及んだ）
- 決定は ADR、未決は `docs/OPEN-QUESTIONS.md` へ。仕様の中で未決を決めたことにしない

**受入条件は1行1件、ID つき。** 型は1つだけ。

```text
AC-1: 〈状況〉で〈操作・事象〉すると、〈利用者が観測できる結果〉になる。
```

観測できる結果で書く。実装の手段を書かない。

## 手順4: 仕様の単体テスト

実装を見る検査ではなく、**文章の検査**。全部を確かめ、落ちた行を直す。

- 測れない語が残っていないか（速い / 分かりやすい / 適切に / 必要に応じて）
- 同じものを2つの語で呼んでいないか
- 空・読み込み中・失敗・取り消しを全画面で書いたか
- 同じ操作が別の画面で別の結果にならないか
- 非ゴールを破る受入条件が混ざっていないか
- 画面の文言が全部決まっているか（ボタンは動詞、失敗は「何が起きたか」と「次にすること」）
- 既存データ・既存の操作の互換を書いたか

## 手順5: 状態遷移で穴を探す

状態・非同期・外部プロセスがあるなら `/state-transition-table` を使う。
埋められないセルは2つに分ける。

- 仕様に書けば済む → 仕様へ
- **与件に無い判断が要る → 台帳に足し、`/intake` の手順4へ戻る**

## 手順6: 追跡表を作る

仕様の末尾に置く。**空の欄が漏れ。** 空のまま隠さない。

| 与件 ID | AC  | 状態のセル | テスト |
| ------- | --- | ---------- | ------ |

- 与件が AC に届いていない → 仕様の漏れ
- AC に与件が無い → 頼まれていない機能。消すか台帳に足す
- テストはどの継ぎ目で掛けるかを書く。既存の継ぎ目を優先し、できるだけ高い層で1つにする
- テスト欄は実装の時に埋める。書けない理由があるなら書く

## 手順7: 文脈の無い読み手で試す

fresh な agent 1本に**仕様書と見本だけ**を渡し、「これで実装するなら何を質問するか」を列挙させる。
会話も台帳も渡さない。出た質問は仕様に答えを書く。与件に無ければ `/intake` へ戻る。

## 手順8: 渡す

見本、受入条件、判断ログを仕様の末尾に揃えて渡す。**検査を全部通っても良いとは限らない。** 人が見て直したら従う。
直されたら `.claude/rules/skill-care.md` に従って理由を残す。

完了:

- 手順4の全項目を確かめた
- 追跡表の与件・AC に空が無い
- 文脈の無い読み手の質問に全部答えた
- 判断ログが仕様の末尾にある
- この仕様が古くした文書を、台帳の `文書の状態` に足した
- 次は `/spec-to-issues` で作業に割り、`/implement` へ渡す

# コメントの判定

規則の正本は `CONTRIBUTING.md`「コメントの書き方」。ここには判定の順と実例を置く。
実例は全て実在のコードから取った。

## 判定の順

**1文ごとに**上から問う。最初に当たったところで止める。

1. **消す**: 消しても第三者が誤解しない。名前や型の言い換えである
2. **移す**: 名前か型で言える。名前を変えるか、型にする
3. **割る**: 関数の本文の説明が3行を超える。塊を名前のある関数にする
4. **直す**: コードと食い違う。腐ったコメントは無いより悪い
5. **書き換える**: 正しいが読めない。下の型へ入れ直す

## 種類ごとの型

| 種類             | 1文目                                     | 続けて書くこと                                 | 書かないこと                 |
| ---------------- | ----------------------------------------- | ---------------------------------------------- | ---------------------------- |
| ファイルの冒頭   | 何を決める場所か                          | 責任の切れ目                                   | 中の関数の一覧               |
| 関数の doc       | 何を返すか、何を起こすか（文で句点）      | 呼び手が守ること、失敗の意味、順序、理由       | 手順の説明、引数の型         |
| 型、trait の doc | 1つの値が何を表すか、実装が何を約束するか（名詞句で句点なし） | 欄の組み合わせの制約、取りえない状態           | 欄の名前の言い換え           |
| 定数、enum の変種 | 何の値か                                  | なぜこの値か、変えると何が起きるか             | 値そのもの                   |
| 本文のコメント   | 特定の行にだけ関わる理由。なぜこの順序か  | 成り立つ条件                                   | 次の行が何をするか           |
| テストの doc     | 守っている不変条件                        | 壊れたときに利用者に起きること                 | テスト名の言い換え           |

### Rust の構文

上の表に足す。正本は `docs/rules/rust.md` の各ルールで、ここには doc に何を書くかだけを置く。

| 構文                         | 書くこと                                                         | 書かないこと           |
| ---------------------------- | ---------------------------------------------------------------- | ---------------------- |
| `//!`（モジュールの冒頭）    | 何を隠すか（R-RES-6）                                            | 中の項目の一覧         |
| trait                        | 実装する側が守る契約。呼ばれる順、スレッド、不変条件             | メソッドの一覧         |
| impl の中のメソッド          | trait の契約から外れる点だけ                                     | trait の doc の写し    |
| 型引数の境界                 | 境界の名前で言えない目的                                         | 境界の言い換え         |
| lifetime                     | 省略できないときだけ、返す参照が何に縛られるかを1文              | `'a` の説明            |
| `macro_rules!`               | 展開した後の形と、関数にしなかった理由（R-RSX-1）                | 展開の手順             |
| `Mutex` を持つ欄             | 何を守るロックか。2つ以上あるなら取る順序（R-RSC-2）             | 型の言い換え           |
| async fn                     | 途中で取り消されたとき何が残るか                                 | 中の `await` の説明    |
| `clone` `spawn_blocking`     | その行の前に理由を1行（R-RSM-2、R-RSP-2）                        | 何をしているか         |
| `expect`                     | 成功するはずの理由を、コメントでなく `expect` の文に書く（R-RSM-5） | 失敗したときの状況だけ |

失敗、panic、安全条件は見出しを立てて書く。**見出しは日本語の `# エラー` `# パニック` `# 安全性` に揃える**（R-RSA-12、R-RSM-6）。

## 実例

**消す。** 名前の言い換えは情報が無い。続きの契約がある doc では、言い換えの1文だけを消し、契約を1文目にする。

```rust
/// リスナー削除
fn remove_listener(/* … */)
```

**書き換える。** 1文目を要約にし、続きに契約を置く。

```rust
/// 局面の候補手を、定跡に書かれている順で返す。
/// 未収録の局面は空の `Vec` であって、エラーではない。
```

`book/reader.rs` の `lookup`。要約 → 呼び手が間違えやすい点の順で、この形が見本になる。

**直す。** 下の doc は添字1からと名乗るが、`applyMoveWithBranch` の本体は `forks` を添字0から見ている。

```ts
/**
 * 2. 同じ手が forks[1..] にあれば forkAndForward()
 */
```

**食い違いと書く前に、関数を最初の行から最後の行まで読み、テストの期待値に当てる。**
部分だけ読んで「比べていない」と判定すると、コメントの正しい行を壊す。

**理由を書く。** 値を変えた人が何を壊すかが読める。

```ts
/**
 * 確認を諦めるまでの時間。渡さないと待ち続ける。
 * plugin は上限を省くと reqwest の既定（無期限）になり、応答を返さない経路で確認が終わらない。
 */
```

`entities/updater/model/provider.tsx` の `CHECK_TIMEOUT_MS` を短くしたもの。

**要約を置く。** 下の doc は要約が無く、何の値かが読めない。

```ts
/** （applyMoveWithBranchが合流判定に使うのは Minimal が安全） */
export const eqMove = eqMoveMinimal;
```

## 日本語の型

- 1文は50〜60字を目安に、論点を1つにする。超えたら文を分ける
- 主語を省くなら、前の文の主語と同じときだけ
- 結論を先に書き、続けて理由を書く
- 「これ」「その回」「ここ」は同じ塊の中で指す先が言えるときだけ使う
- 否定の連続を避ける。「〜しないわけではない」より「〜することもある」
- 3つ以上を並べるなら箇条書きにする

## 語

**コードの語、`CONTEXT.md` の語、一般の語の順に選ぶ。** 比喩を増やさない。

| 書いてある語     | 問題                                      | 替え方                                        |
| ---------------- | ----------------------------------------- | --------------------------------------------- |
| `口`             | 関数、Tauri コマンド、引数、経路が1語に潰れる | 指しているものの語で書く                  |
| `門`             | 条件の判定のことだが第三者には読めない    | 判定を担う関数の名前か、条件式を書く。無ければ `検査` か `判定`。`関門` `門番` も同じ |
| `回`（「〜の回」） | 場合、呼び出し、局のどれかが読めない      | 「〜のとき」「〜の呼び出しで」                |
| `席`             | 解析と対局で別の意味を持つ                | `CONTEXT.md` の定義のどちらかを文脈で明らかにする |

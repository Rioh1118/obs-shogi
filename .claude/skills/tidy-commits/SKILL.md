レビューの往復で埋まった履歴を、**読み手が知りたい単位**へ並べ直す。

`/implement` 手順3 は「1コミット = 1つの変更」で刻ませ、`/review` は「1所見 = 1コミット」で直させる。
どちらも正しいが、残るのは**レビューの往復の履歴**であって変更の履歴ではない。
PR のレビュアーも半年後の読み手も「どの指摘で何を直したか」ではなく「何をどう変えたか」を知りたい。

## まず「触らない」かを判定する

**既定は触らない。** 1つでも当たれば中止。

- **作業ツリーが汚れている**（`git status --porcelain -uall` が非空）
- **push 済み**（`git log --oneline @{u}..HEAD` の範囲に出ている）
- コミットが3つ以下、またはレビュー由来が半分未満
- **畳まないと決めたコミットが、本体と同じファイルを触る**（下の理由で境界を復元できない）

並べ直すのは「6つ以上あり半分以上がレビュー由来」「『ついで』が混ざった」場合。

## 目標の形

**1コミット = 元に戻すときに一緒に戻したい塊。** レビューで直した分を、それが直した本体へ畳む。

**畳まないもの**は別コミットのまま残す。

- 本体と独立して意味を持つ修正（`/implement` 手順7）
- 退行の修正が、退行を入れたコミットと別の関心事に属する場合
- docs だけの変更と、コードの変更

## 手順1: 範囲を記録する

**シェル変数を使わない。** Bash ツールの状態は呼び出しを跨いで持続しない。
`BASE=...` は次の呼び出しで空になり、**`git reset --soft`（引数なし）は
HEAD へのリセット＝成功する no-op** になる。積み直しが起きていないのに手順4 が必ず一致する。

作業用ファイルに落として `$(cat ...)` で引く。置き場はセッションの scratchpad
（`/tmp` 直下はワークツリーが2つ動いていると衝突する）。**絶対パスを毎回そのまま書く。**
以下の `<W>` は展開済みの絶対パスに置き換えること。

```bash
git merge-base HEAD main > <W>/tidy-base.txt
git rev-parse HEAD > <W>/tidy-head.txt
git diff $(cat <W>/tidy-base.txt)..HEAD > <W>/tidy-before.diff
test -s <W>/tidy-before.diff            # 非空であること。空なら基点の取り違え
```

**作業ツリーが汚れたまま進めない。** 手順3 の `git add -A` が未コミットの変更を群へ巻き込み、
手順4 の比較が必ず不一致になる。指示どおり `git reset --hard` を打つと**それごと消える**。

## 手順2: 群に割る

`git show --stat <sha>` で各コミットを読む。**推測で割らない。**
レビュー由来のものは、どのファイルのどの行を直したかで本体の群を決める。

**先に「畳まない」と決めたコミットを見る。** それが他の群と同じファイルを触っていたら中止する。

## 手順3: 積み直す

**`git rebase -i` はこの環境で使えない**（対話フラグが通らない）。
`GIT_SEQUENCE_EDITOR=` や `GIT_EDITOR=true` の前置も通らない。**選択肢として数えない。**

soft reset で作り直す。

```bash
git reset --soft $(cat <W>/tidy-base.txt)
git rev-parse HEAD                       # ← tidy-base.txt の中身と一致すること
git diff --cached --stat                 # ← 非空であること
```

**この2つの確認を飛ばさない。** `<W>` の展開を忘れると `$(cat ...)` が空になり、
`git reset --soft` は**成功したまま何もしない**。ここで気づかないと最後まで気づけない。

群ごとに add して commit する。**`git commit` は必ず `-m` を付ける**（無いと `$EDITOR` が開いて
戻ってこない）。**1呼び出しにつき1つだけ**（ゲートが2つ以上を deny する）。

```bash
git restore --staged .
git add <群1 のパス...>
git commit -m "<type>: <群1 の要約>"     # ← 別の呼び出しで。ゲートが走る
```

**群がファイル単位で割れないなら中止する。** soft reset は全コミットを1つの状態に潰すので、
**同じファイルの中の境界は復元できない**（`git add -p` も対話なので使えない）。
無理に進めると「畳まないもの」を本体へ畳むことになる。

### 検証のコスト

**`git commit` ごとにゲートが走る。** 見積り = 群の数 × そのブランチで走る検証の時間。
所要時間は `CLAUDE.md` の検証節。

**どの検証が走るかを机上で決めない。1群目を積んで測る。** 判定の唯一の出典は
`.claude/hooks/verify-gate.sh` で、**走るのは `.claude/settings.json` が指す版**
（`${CLAUDE_PROJECT_DIR}` 側）であってチェックアウト中の版とは限らない。
ワークツリーで回すと、手元が `.rs` を含まなくても Rust の検証が走りうる。

Rust の検証が走るブランチを10群に割ると20分を超える。**群の数はここを見て決める。**

## 手順4: 差分が変わっていないことを確かめる

**これを飛ばさない。並べ直しの唯一の安全網。**

```bash
git diff $(cat <W>/tidy-base.txt)..HEAD > <W>/tidy-after.diff
test -s <W>/tidy-after.diff             # 空同士の一致を「OK」と読まない
diff <W>/tidy-before.diff <W>/tidy-after.diff && echo "OK: 差分の合計は同じ"
```

一致しなければ `git reset --hard $(cat <W>/tidy-head.txt)` で戻す。

## 手順5: 報告書の sha を書き戻す

**`/review` は所見ごとに短ハッシュを報告書へ書いている。** 積み直すとその sha は
1つ残らず到達不能になる。1対1で畳んだなら新 sha へ、そうでなければ `畳み込み済み` へ置換する。
**到達できない sha を残さない。** 報告書そのものは消さない——
どの所見をどう直したかを持っているのはそこで、git log ではない。

## 手順6: 報告

何コミットから何コミットになったか / 畳まずに残したものとその理由 /
差分の合計が一致したこと / 検証を通したか（通していないなら「未検証」と明示）。

## 禁止事項

- **push 済みのコミットを書き換える**
- **差分の合計を変える。** ついでに直さない。直したいものは並べ直しを終えてから別コミットで
- **手順4 の確認を飛ばす**
- **到達できなくなった sha を報告書に残す**
- 独立して意味を持つ修正を本体へ畳む
- 検証を飛ばして「整理した」と報告する
- レビューで直した事実を隠すために報告書を消す

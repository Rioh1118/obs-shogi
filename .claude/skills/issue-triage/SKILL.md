**規則の正本は `docs/issue-guidelines.md`。先に読む。ここに写さない。**
人の判断は**手順4の1回だけ**。**承認の前に `gh issue` の書き込みをしない**
（作成、編集、クローズ、コメント、ラベルの全部）。使ってよいのは読み取りだけ。

## 手順1: 全件を読む

`git fetch` して `origin/main` を基準にする。open の全件を本文、コメント、ラベル、`updatedAt` つきで取り、
`.claude/plans/issue-triage/<日付>/snapshot.json` に保存する。件数の上限に当たっていないことを、
`gh api` の総数と突き合わせて確かめる。

読む量が多ければ agent に割る。**エリアで割る。** 本数は `.claude/rules/agents.md` に従う。番号の一覧を重ねない。

完了: 取得した全件が手順2の判定を持つ。

## 手順2: 現物に当てる

推測で判定しない。1件ごとに確かめる。

- 実装済みか: 語でなく振る舞いで探し、完了条件か症状を現物に当てる
- 重複か: open どうしを振る舞いで照合する
- 本文のパスと識別子が今もあるか
- 未決か: 判断待ち、相談、案の比較になっていないか
- 親か子か: 親の中で議論していないか、子が全部閉じていないか
- 受理から60日動いていないか（起点は `docs/issue-guidelines.md`「ライフサイクル」）
- 一度閉じて開き直した Issue か。timeline を見る。**開き直した理由があれば、その理由を覆す根拠なしに閉じない**
- 別の Issue に塞がれて踏めないだけか。踏めないことを「再現しない」と読まず、`Blocked by` にする

**判定できないものは「残す」にして、理由に「判定不能」と書く。** 閉じる側に倒さない。

## 手順3: 案を決める

上から順に当て、最初に当たったものにする。

| 案         | 条件                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 閉じる     | 作業が要らない。**全部の完了条件を**満たした、実装済み、範囲外、重複、再現しない |
| 仕様へ移す | やると決まっていない。未決、相談、いつかやる。移した後で閉じる                   |
| 書き直す   | 作業は生きているが、参照が死んでいる、本文が現物と違う、上限を超える             |
| 残す       | どれにも当たらない。正本が無いだけなら残す                                       |

- 一部だけ終わった Issue は閉じない。残りを本文にして書き直す
- 正本の無いバグは、`.github/ISSUE_TEMPLATE/bug_report.yml` の並びで書き直す
- ラベルだけが足りないなら「残す」にして、付けるラベルを一覧に書く
- 書き直すときも**本文の事実を消す前に行き先を決める。** 正本に無い実測は、仕様か `.claude/reviews/` へ移す
- 新しい本文は全部書いて、`.claude/plans/issue-triage/<日付>/bodies/<番号>.md` に置く
- 優先度の無い Issue には、残すか書き直すなら優先度の案も付ける

## 手順4: 一覧を出して1回だけ承認を取る

全件の一覧を `.claude/plans/issue-triage/<日付>/plan.md` に書く。

```markdown
基準 <hash> / open N件 / スナップショット <日時>

| # | タイトル | 案 | 理由 | 行き先または新しいラベル | 確度 |
```

- 確度は「実機」（動かした）か「コード」（読んで当てた）か「推定」。**推定の「閉じる」は案に出さず「残す」へ落とす**
- 理由は1件1行。「古い」で済ませず、何が古いかを書く
- 会話には案ごとの件数と、閉じる全件、仕様へ移す全件を出す。書き直すと残すは `plan.md` を指す

`AskUserQuestion` で1問だけ聞く。「全部適用する（推奨）」と「適用しない」の2択。
番号と案の変更は Other で受ける。**指示どおりに一覧を確定し、聞き直さない。**

承認されるまで次へ進まない。

## 手順5: 適用する

[references/apply.md](references/apply.md) の順に従う。承認された一覧に足さない。

## 報告

案ごとの適用件数、適用しなかった件とその理由、移した先のファイル、閉じる基準で多かった理由。
同じ理由が多いなら、その原因を `.claude/rules/skill-care.md` に従って記録する。

完了:

- 手順1の全件が `plan.md` にある
- 承認した全件が適用済みか、理由つきで未適用
- 閉じた全件に、理由と行き先のコメントがある

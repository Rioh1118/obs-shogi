# research — 他実装の実地調査

**目的は1つ。他の将棋 UI が実際にどう作っているかを、推測でなくソースで記録すること。**

ここは方針を書く場所ではない。方針は `docs/PREMISES.md` / `docs/OPEN-QUESTIONS.md` /
`docs/decisions/` が持つ。ここが持つのは**事実**だけで、そこから何を決めるかは持たない。

## 規律

1. **出典はファイルパスを書く。** 「ShogiHome はこうしている」と書くなら
   `src/common/settings/game.ts` のように、開けば確かめられる形で書く。
   リポジトリの版（コミット SHA）も添える。
2. **要約器を信じない。** 検索結果の要約や AI の要約を事実として書かない。ファイルを開く。
3. **無いことを書くときは、探した場所を書く。** 「対局タブは無い」なら、
   どのファイルの何を見て無いと判断したかを書く。
4. **感想と事実を混ぜない。** 「うまい」「微妙」は `所感` の見出しの下に隔離する。
   本文は「何がどうなっているか」だけにする。
5. **受動的な閲覧のみ。** 公開されたソースとドキュメントを読む。
   issue へのコメント・DM・問い合わせ・アカウント作成はしない。
   - これは `docs/PREMISES.md` P-004 の「#236 のコメント主に直接あたる」を**明示的に取り消す**。
     代わりに公開された発言の集計で測る。**前提の運用を持つのは `PREMISES.md` なので、
     あちらの `次回確認` を直すまでこの取り消しは片方にしか書かれていない** → issue
6. **引用元のライセンスと著作権者を、各ディレクトリの README に書く。**
   他プロジェクトのコードを逐語で載せる場所なので、判断した形跡を残す。
7. **obs-shogi 側の要望や論点を鉤括弧で引くなら、出典を書く。**
   書けないなら鉤括弧を外し、**（出典なし）**と明示する。
   口頭の発言をそのまま引くと、次に読む人が確かめられない。
8. **語を ShogiHome の機能名と一般語で二重に使わない。**
   とくに **`検討`** は ShogiHome の `ResearchState`（エンジンに読ませ続ける機能）を指す。
   設計の議論の意味では使わず、`案` / `検討中の設計` と書く。

## 証拠の等級（例外なし）

`findings/` はこの語彙で書かれている。**`shogihome/` にも同じ規律を当てる。**

| 等級         | 意味                                                       |
| ------------ | ---------------------------------------------------------- |
| `[確定]`     | 一次情報で裏取り済み。ソース・公式リリース・公表資料の原典 |
| `[推定]`     | 状況証拠のみ。**何をもって推定したかを併記する**           |
| `[未確認]`   | 未検証の仮説                                               |
| `[反証]`     | 主張が誤りであることを一次情報で示せたもの                 |
| `[判定不能]` | 探したが決着しなかった。**試した検索語を必ず併記する**     |

## 「結論」を書く前の要件

次を全部満たさない限り、`docs/PREMISES.md` の状態を ✅ にも ❌ にもしない。

- [ ] 結論に使った出典を**自分で開いた**
- [ ] 「無い / 存在しない」と言うなら、**試した検索語を全部列挙した**
      （検出力の記録が無い不在証明は採用しない）
- [ ] 反証側の証拠を探した
- [ ] **失効条件**を書いた（何が起きたらこの結論は覆るか）

## 再取得

ソースは `gh` で取る。クローンしない（更新の追従が要るのは調査のときだけ）。

**版を必ず固定する。** `?ref=` を付けないと既定ブランチが返り、
記録した版と違うものを開いて「合っている／合っていない」を判定してしまう。
版の出典は各ディレクトリの `README.md` 冒頭。

```bash
REF=de27f0c1c352   # shogihome/ 用。版はディレクトリごとに違う
#                    findings/ の版は各ファイルの冒頭（書いていないものもある）

# ファイル一覧
gh api "repos/sunfish-shogi/shogihome/git/trees/$REF?recursive=1" \
  --jq '.tree[] | select(.type=="blob") | .path'

# 単一ファイル
gh api "repos/sunfish-shogi/shogihome/contents/<path>?ref=$REF" --jq '.content' | base64 -d
```

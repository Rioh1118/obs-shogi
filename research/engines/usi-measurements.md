# USI の実測（2026-10-31）

生の結果は `raw/`。値はミリ秒。等級はすべて `[確定]`（この3本のエンジン、この版、1スレッドの範囲で）。
**スレッド数を増やした回、DL 系、評価関数の読み込みが重い組は測っていない。**

`usi` → `usiok`、`isready` → `readyok`。各1回（`raw/boot.json`）。

| -------------- | ------- | --------- | ------------------------------------------------------------------------- |
| やねうら王 V8.30 | 35    | 1,365     | 評価関数・定跡・ハッシュの読み込みを `info string` で言う                 |

## `go` の形

`position startpos moves 7g7f` の後に送り、`bestmove` までの経過。上限 6 秒。

| 送った行                         | やねうら王 V8.30 | やねうら王 V9.00 | zermelo  |
| -------------------------------- | ---------------- | ---------------- | -------- |
| `go movetime 1000`               | 999.7            | 999.5            | 971.4    |
| `go depth 5`                     | 0.7（depth 5）   | 2.9（depth 5）   | 2.3      |
| `go nodes 20000`                 | 34.7（20,028）   | 27.0（20,010）   | 21.9     |
| `go byoyomi 1000`                | **101.5**        | **101.6**        | 971.3    |
| `go btime 0 wtime 0 byoyomi 1000`| **101.5**        | **101.7**        | 970.9    |

- **3本とも `movetime` / `depth` / `nodes` に従う。** `nodes` の括弧は最後の `info` の `nodes`
- **`byoyomi` はやねうら王では 1 秒にならない。** 同じ 1000 でエンジンによって約 10 倍違う。
  原因は調べていない（`[未確認]`。`MinimumThinkingTime` など時間の設定が関わる可能性はある）
- `go mate 2000`（1手詰の局面）: やねうら王は **`checkmate` でなく `bestmove G*1b`** を返す（3.2〜5.3）。
  zermelo は `checkmate notimplemented`（1.0）。この NNUE のビルドの範囲の結果で、
  詰将棋エンジンのビルドは測っていない

## `go` に制限を並べる

同じ行に2つ以上の制限を書く。上限 4 秒（`raw/combined.json`）。

| 送った行                                | やねうら王 V8.30 | やねうら王 V9.00 | zermelo |
| --------------------------------------- | ---------------- | ---------------- | ------- |
| `go movetime 2000 depth 5`              | 1.3              | 2.4              | 2.8     |
| `go depth 40 movetime 500`              | 499.9            | 499.9            | 471.6   |
| `go nodes 20000 movetime 2000`          | 36.5             | 24.1             | 21.6    |
| `go nodes 20000 depth 40 movetime 2000` | 32.5             | 24.3             | 22.2    |
| `go infinite depth 5`                   | **返らない**     | **返らない**     | **返らない** |

**3本とも、先に届いた制限で止まる。** `infinite` と並べると制限は効かず、`stop` まで返らない
（`depth 5` までの `info` は出る）。

| -------------- | ------------------- | ---------------- | ------------------ | --------------------------- |
| やねうら王 V8.30 | 0.1 / 0.1 / 0.1   | 10.6（終了 0）   | 10.6 で終了        | `bestmove` を返さない       |
| やねうら王 V9.00 | 0.1 / 0.1 / 0.1   | 4.6（終了 0）    | 4.6 で終了         | `bestmove` を返さない       |
| zermelo        | 1.0 / 1.1 / 1.1     | 4.6（終了 0）    | 4.5 で終了         | `bestmove` を返さない       |

## 探索中に `stop` を挟まず `go` を重ねる

`go infinite` の 0.5 秒後に `position` と `go infinite` を重ねて送る。

| エンジン       | 重ねた時点の `bestmove` | 続く `stop` | 続く `isready` | 続く `quit` |
| -------------- | ----------------------- | ----------- | -------------- | ----------- |
| やねうら王 V8.30 | 出ない                | **5 秒応答なし** | **3 秒応答なし** | **5 秒終わらない** |
| やねうら王 V9.00 | 出ない                | **5 秒応答なし** | **3 秒応答なし** | **5 秒終わらない** |
| zermelo        | 前の探索の `bestmove` を出す | 1.2  | 0.0            | 4.6         |

**やねうら王はこの形に入ると、プロセスを殺す以外に抜ける口が無かった**（測った上限の中で）。

## 測り直し

1回目は1本のプロセスに全項目を順に流した。やねうら王は上の「重ねる」の後で応答しなくなり、
以降の項目が全部壊れた値になったので捨て、1件ごとに起動し直した。`raw/` にあるのは2回目。

## 走行中のオプション

`go infinite` の 0.8 秒後に `setoption name MultiPV value 3`、続く 2 秒の `multipv` の値。

| エンジン       | 同じ探索の中     | 次の `go`（`isready` なし） | `isready` を挟んだ次の `go` |
| -------------- | ---------------- | --------------------------- | --------------------------- |
| やねうら王 V8.30 | 1, 2, 3        | 1, 2, 3                     | 1, 2, 3                     |
| やねうら王 V9.00 | 1 だけ         | 1 だけ                      | 1, 2, 3                     |
| zermelo        | `MultiPV` を申告しない | —                     | —                           |

**同じ `setoption` が版で違う効き方をする。** V9.00 は `isready` を挟むまで効かなかった。
zermelo には候補手の数という概念自体が無い。

| `USI_Hash` を範囲の外に          | 何も言わず丸める                                             | `info string setoption: 受理できない…`                     |
| 評価関数のパスが無い             | `readyok` を返さず**終了コード 1**。`Error! : failed to read nn.bin` | `readyok` を返さず**終了コード 0**。`info string …起動を中止する` |

**失敗の綴りは揃っていない。** 終了コードも揃っていない。揃っているのは「`readyok` が来ないまま出力が終わる」だけ。

## 申告の幅

`spin` の幅（`max - min`）。申告の写しから数えた。

| エンジン   | `spin` | 幅 1,000 以下                                                                                                                       | 幅 1,000 超 |
| ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| V8.30      | 22     | 5（`MultiPV` `SlowMover` `BookIgnoreRate` `BookPvMoves` `FV_SCALE`）                                                                | 17          |
| V9.00      | 22     | 5（同上）                                                                                                                           | 17          |
| zermelo    | 10     | 7（`FV_SCALE` `EvalPawnValue` `DeclarationPointBlack` `DeclarationPointWhite` `DeclarationPiecesInZone` `DeclarationBigPiecePoints` `DeclarationSmallPiecePoints`） | 3           |

**幅が狭くても段が意味を持つとは限らない。** `DeclarationBigPiecePoints` の範囲 0〜1000 に対して既定は 5、
`SlowMover` は 1〜1000 に対して 100。線形のつまみでは既定の近くを刻めない。
`BookIgnoreRate`（0〜100、百分率）だけが線形の範囲を丸ごと使う形。

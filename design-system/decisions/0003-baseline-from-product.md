# 0003. 値を製品の今の画面から写し、固定値を製品に合わせる

- 状態：承認済み（固定値の変更はユーザーが明示的に承認した。2026-11-08）
- 日付：2026-11-08
- 対象版：0.1.0
- 根拠資料：製品の `src/index.scss`（origin/main 0be56281）、`references/current-screens-2026-11-08/`、製品の `docs/proposals/design-system-migration.md` の工程2

## 背景

このデザインシステムは、すでに一貫した見た目を持つ1つの製品のために複製した。利用者の決定は「リブランディングではない。今のイメージを保ったまま洗練させる」。
そのため最初の値は、モード B の案から選ぶのではなく、**製品の今の値をそのまま写した基準線**にする。洗練はこの基準線からの差分として、モード B で扱う。

雛形の固定値（0001）は、製品の今の値と3点で合わなかった。

| 固定値 | 雛形 | 製品の今 |
| --- | --- | --- |
| 文字の下限 | 本文 16px、全体 14px | 本文 13px、注記 11px、説明 12px |
| 行間の下限 | 本文 1.5 以上 | 指定していない（ブラウザの既定） |
| フォーカス | 白黒の二重リング、2px、離し 2px | 銅（`#a27b5c` の 85%）の 2px |

## 決定

### 1. 値は製品の `index.scss` から写す

- 色・文字・太さ・間隔・角丸・動き・重なり・影を、名前を役割に合わせて写した。`color-mix()` は16進に計算して固定し、半透明は alpha を持たせた
- 盤・駒台・駒は実物の画像で、トークンの対象外
- **テーマは1つ。** 製品に明るいテーマは無い。雛形の dark テーマのファイルは消し、既定の組を製品の暗い枠にした
- 製品にだけ意味があるもの（ウィンドウ操作の3色、タイトルバーの高さ、サイドバーの幅など）は写さない。製品の画面の寸法として製品に残す

### 2. 文字の下限を 本文 13px・全体 11px にする（ユーザーの承認）

密度の高いデスクトップの研究アプリで、利用者が「理想的でモダン」と言った検討のドックと候補手のパネルがこの大きさで組まれている。
16px に上げると全画面の密度が変わり、理想とした見本そのものが崩れる。

### 3. 行間の下限を外す（ユーザーの承認）

製品は表と一覧を詰めて並べており、行間を広げると検討のドックも間延びする。
`font.lineHeight.body`（1.5）は長い文（説明文、ノート）にだけ当てるトークンとして残す。

### 4. フォーカスは銅の1本のリングにする（ユーザーの承認）

今の見た目（銅）を保つ。ただし今の値（`#a27b5c` の 85%）は、本文の背景で 2.76:1、盤を置く面で 2.03:1 しか無く、UI 部品の 3:1 を割っていた。
既存の銅の文字の色（`#c29a78`）に寄せると、全ての面で 3:1 以上になる（本文の背景 4.83:1、深い面 6.22:1、盤を置く面 3.39:1、撮影の盤の周り 3.03:1）。
これは移行で見た目が動く唯一の点で、製品側の工程3で取り込む。

コントラストの固定値（文字 4.5:1、UI 部品 3:1）は変えない。製品の値はすでに満たしていて、`contrast-pairs.json` の21組で照合している。

## 採らなかったもの

| 案 | 採らなかった理由 |
| --- | --- |
| 製品の文字を 16px に上げる | 全画面の密度が変わる。利用者が理想とした検討のドックが崩れる |
| 白黒の二重リングにする | 銅のアクセントから外れ、今の見た目から離れる |
| 雛形の dark テーマの枠を残し、light を空にする | テーマが1つなのに2つあるように見え、ds:check のテーマの完全性が無意味な値を要求する |

## 戻し方

- 固定値: `locked.json` の値と rules を 0001 の値へ戻し、`npm run ds:check` が指す不合格を製品の値ごと直す
- テーマ: `tokens/themes/<名前>.tokens.json` を足せば、ビルドと検査は元の仕組みのまま動く

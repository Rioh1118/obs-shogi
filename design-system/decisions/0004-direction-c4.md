# 0004. 洗練の方向を C4（計器に寄せ、盤の周りを半段沈める）にする

- 状態：承認済み（ユーザーが選んだ。2026-11-08）
- 日付：2026-11-08
- 対象版：0.2.1
- 根拠資料：`explorations/2026-11-08-comparison.md`（A〜D、C2〜C5 の案と比較）、brief.md v0.2

## 背景

0003 で値を製品の今の画面から写した（基準線）。そこから洗練の方向をモード B で探った。
brief の言葉は「開発者の道具（IDE・計器）」と「タイトル戦で使われるような本物の盤と駒台（木）」、洗練を判定するのは棋譜を研究する人。

## 経緯（ユーザーの判定）

| 段 | 出した案 | ユーザーの判定 |
| --- | --- | --- |
| 1 | A 整える / B 木に寄せる / C 計器に寄せる | 「好みは B か C」 |
| 2 | D（C の枠 ＋ B の焦げ茶の盤の面） | 「ダメだな。C かな」。ただし「サイドバーと棋譜（手順）のビューの色を分けているのは、今のデザインもダサい」 |
| 3 | C2（ペインを1色に、盤だけ沈める）/ C3（全部1色） | 「サイドバーとファイルツリーの関係性（配置）は今のまま」「C2 と C3 かな」 |
| 4 | C4（半段だけ沈める）/ C5（盤の下敷き） | **C4** |

## 決定

### 1. 値は C の計器の配色にする

枠は一段深く冷たい緑黒（深い面 `#121819`、本文の背景 `#1b2325`、持ち上げた面 `#253033`）、文字は冷たい砂（`#d8dbd3`）、銅は `#a8805f`（文字は `#c8a07c`）。
見出しと注記の書体（`font.family.label`）は等幅、題（`font.family.heading`）は本文と同じゴシック。角丸の役割は一段絞り（行 2px、押すもの 4px、面 4px、モーダル 6px）、面は影で浮かせず線で区切る。

### 2. ペインを色で塗り分けない

サイドバー・棋譜・ヘッダ・ドックは同じ1色（`color.background.default`）の面にし、境目は線（`color.border.weak`）で引く。選ばれた行の濃淡と左の銅の棒は、どのペインでも同じに見せる。

### 3. 盤の周りだけを半段沈める

`color.background.stage` を足す。値は `#161d1f`（本文の背景 `#1b2325` と、いちばん深い C2 の `#0f1415` の中間）。
C3（全部1色）は「一色すぎる」、C2（いちばん深く沈める）は窪みが強すぎる、の間を取った。

### 4. 配置は今のまま

サイドバーは縦いっぱい、ドックは盤と棋譜の列の下だけ。

### 5. 製品への入れ方

**色・角・影はトークンで一斉に変える。形（ペインを1色にする、盤の周りに `color.background.stage` を当てる、見出しを等幅にする）は、製品の工程5で画面ごとに入れる**（ユーザーの判断、2026-11-08）。途中の画面は「新しい色 ＋ 古い塗り分け」になる。

### 6. 今の値の不足を同時に直す

案の見本の axe で、基準線の値に 4.5:1 を割る組が2つあると分かった（説明文 × 持ち上げた面 4.32:1、失敗の文字 × 本文の背景 4.39:1）。C4 の値ではどちらも満たす。`contrast-pairs.json` にこの2組と、盤の面の組を足す。

## 採らなかったもの

| 案 | 理由 |
| --- | --- |
| A 整える | 「洗練された」と感じる差が小さい（ユーザーの好みに入らなかった） |
| B 木に寄せる、D | 枠を温める方向をユーザーが採らなかった |
| C（ペインを塗り分け） | 「サイドバーと棋譜の色を分けているのはダサい」 |
| C2、C3、C5 | C4 を選んだ。C3 は一色すぎ、C5 の下敷きは選ばれなかった |
| 雛形の「2案以上で主色の色相を変える」 | brief §0「今のイメージを保ったまま洗練させる」が優先 |

# 3案を出させるときのプロンプト

SKILL.md のモード B で使う。下の「プロンプト」をそのまま渡す。案は `explorations/<YYYY-MM-DD>-a/`、`-b/`、`-c/` に置き、採らなかった案も消さない。

## プロンプト

```markdown
design_system/brief.md を読んで、デザインシステムの方向性を3案作ってください。

進め方
1. まず brief の空欄や曖昧な点を最大5つまで質問してください。私の回答を待ってから次に進んでください。
2. 3案は「軸」をずらして作ってください。以下を一例として、brief の「4. 性格」のうち別々の軸を強調してください。
   - A：brief にいちばん忠実な王道案
   - B：「音量」と「古さ」を一段大胆に振った案
   - C：「密度」と「形」を逆側に振った案
   3案のうち2案以上で、同じ書体や同じ主色の色相を使わないでください。
3. brief の「7. 避けたいもの」に加えて、AI が既定で選びがちな表現も避けてください。たとえば紫のグラデーション、Inter 単体、どこにでもあるカードの並び。避けるだけでなく、代わりに何を選んだかも書いてください。
4. 各案を explorations/<今日の日付>-a, -b, -c/ に保存し、下の「各案に必ず含める項目」をすべて作ってください。
5. 各案に npm run ds:check -- --dir explorations/<今日の日付>-a のようにかけ、不合格は直してください。直せないものは、その旨を書いてください。
6. 最後に比較表を出してください。列は「案 / 一言 / brief との対応 / 強み / リスク / コントラスト検査の結果」です。おすすめは書いてかまいませんが、確定はせず、私が選ぶまで待ってください。
```

## 各案に必ず含める項目

1. 名前と一文のコンセプト。brief のどのキーワードをどう解釈したかを書く。
2. 具体的な参照。1〜2文で、形容詞ではなく「何のような」で書く。
3. カラー：名前つきの色 5〜7 色とその役割（背景、本文、主色、強調、境界線、危険）。主要な組み合わせのコントラスト比も付ける。
4. タイポグラフィ：和文・欧文の書体とフォールバック。文字サイズの段階（6 段階程度）とそれぞれの行間・太さ。本文は 13px 以上、全体は 11px 以上（locked.json）。
5. 密度と形：余白の基数、コントロールの高さ、角丸の段階、影または境界線の方針。
6. 文言の声：ボタン・エラー・空状態の文言例を各 1 つ。
7. 同じ 3 画面の見本：brief の「主な画面」を HTML で作る。比較できるよう、全案で同じ画面と同じ内容にする。
8. トークン案：DTCG 形式の小さな JSON（base と semantic。dark を作るなら themes/dark.tokens.json）。
9. Do's and Don'ts：各 3 つずつ。
10. リスクと弱点：この案を選んだ場合に作りにくくなる画面や、アクセシビリティ上の懸念。

## ds:check --dir が案に対して検査すること

| 対象 | 検査 |
| --- | --- |
| `**/*.tokens.json` | DTCG の構文、固定値（locked.json：フォーカス表示は案でも変えない）、文字サイズと行間の下限、テーマの完全性 |
| 同上 | contrast-pairs.json の全ペア（案に contrast-pairs.json があればそれを使う） |
| `**/*.css`（`tokens.css` と `dist/` は除く） | 色の直書き、トークン外の余白・角丸・文字サイズ（`var(--lm-*)` だけ） |
| `**/*.jsx`、`**/*.tsx` | Tailwind、style 属性の直書き、CSS-in-JS |
| `**/*.html` | axe（WCAG 2.2 AA） |

トークン名は本体と同じ体系（`base.*`、`color.text.*`、`focus.ring.*` など）にする。本体と名前がそろっていれば、選ばれた案をそのまま本体へ移せる。

## 案

1周目（4案。メインとエンジン管理）。利用者は D を選び、A（今のドック）を混ぜ、B と C を外した（2026-11-23）。

- **A C4を当て切る。** 構成は今のまま。decisions/0004 の決まりを全部当て、はみ出しを直した
- **B 柱。** 縦の4列。盤を縦いっぱいにし、駒台を盤の上下の帯に置き、棋譜と検討を盤の右に続ける
- **C 机。** 上は盤と駒台だけ。下に棋譜の流しと検討の表
- **D 記録。** 今に近い構成で帯を1本にまとめ、手の移動を棋譜の見出しへ移し、棋譜の行の余りにコメントと変化の手を出す

2周目（D を土台に、今の検討のドックの見た目を載せる。設定は4画面とも描いた）。

- **D2 今のドックを1段に。** タブ・検討の状態・道具を1段にまとめ、読みの量は下の帯へ。窓が低いときは、読みの量もタブの段へ上げる。プリセットは1行1件
- **D3 今のドックのまま。** 枠つきの箱、タブの段、状態と道具の段、脚注。プリセットは1件を2段で

2周目で変えたこと。

- 明るい表示をやめた
- 手の移動は、棋譜の下いっぱいの帯に4つ（1464×917 で 75×40px。1周目は 34×28px）
- 銅の塗りは、局面の「いま」（いまの手・最善手）だけ。選んだファイル・タブ・プリセットは灰青の塗り
- エンジン管理は、詰み探索を上に固定し、プリセットの一覧だけを送る
- 棋譜を開く前の画面は、印・題・本文・ボタンの大きさを窓の大きさから決める

何を諦めるかは cases.mjs の `give`、`giveEngine`。文脈を持たない agent に見せて直した（作業フォルダの critique.md）。

## 中身

| ファイル | 役割 |
| --- | --- |
| cases.mjs | 案の名前、説明、諦めるもの、並べる画面と状態 |
| build.mjs | 案の画面を1ファイルに組む |
| build-data.mjs | 見本の棋譜・読み筋・プリセット・設定の中身・知らせ |
| proto/ | 案の画面の描画と見た目（base・cases が1周目、round2 が2周目） |
| assets/ | 駒台の帯の画像、先手・後手の記号の書体（作り方は同じ場所の .py） |

盤・駒台・駒は製品の画像（`src/assets/`）をそのまま使う。棋譜と読み筋は、手元のエンジンの自己対局から作った。人名とフォルダ名は実在しない。

## 雛形（_template.md）から外した所

- **トークンの JSON を案ごとに作っていない。** 値は proto/ の変数に置いた。選ばれた案だけを、モード C で本体のトークンへ写す。案ごとに JSON を作っても、選ばれなければ捨てる
- **`ds:check --dir` を案にかけていない。** 上の理由で当てる JSON が無い。代わりに、製品の画面と同じ物差し（screens/measure.mjs）を全部の案・状態・窓に当てた。文字のコントラスト（4.5:1）と下限（11px）も同じ物差しで見る
- **書体と主色は案で変えていない。** 依頼が「色だけの違いにしない」だったので、構成・密度・重みを変えた
